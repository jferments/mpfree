## The node interface (`mpfree-node`)

One trait, `Node`, for anything that runs on the audio thread on a stereo bus: a synth, the sampler (later), a hosted plugin (later), an effect (the FX work builds `mpfree-fx` on it).

- `process(ctx, events, left, right)` once per block. `events` are `Timed { offset, ev }`, sorted, with offsets inside the block: `NoteOn`, `NoteOff`, `Pressure` (poly aftertouch), `Bend`, `AllOff`, `Param { id, value }` (automation, parameter locks, macro moves) `Expression { note, kind, value }` (one note's own slide, tone or release velocity; see [Tunings and per-note expression](#tunings-and-per-note-expression)) and `Control { ctl, value }` (a controller for the whole instrument, 0 to 1: the sustain, sostenuto and soft pedals, the mod wheel, breath and a foot controller, CC 64, 66, 67, 1, 2 and 11; `Ctl::from_cc` maps a MIDI controller to it). A node that handles the pedals itself says so with `hears(ctl)`; for one that doesn't (every engine today) the host holds its note-offs while a pedal keeps the notes (`mpfree_node::pedal::Pedals`): the track host per slot and the pad synth for the engine on the pads. A key struck again under the pedal ends the old note on the same frame and starts a new one. Plugins get the wheel, breath and foot as MIDI controllers and the pedals as held notes; the sandbox's shared memory (`EV_CONTROL`) and the offload wire (kind 8) carry it. MIDI in sends a keyboard's controllers to them once the MIDI thread wires `Instruments::control` and `Synth::control` ([Architecture and roadmap](synth-architecture.md#a-controller-event)).
- `set_tuning(&Tuning)` hands an instrument its tuning between blocks. The node copies it (plain data, no allocation), so it may run on the audio thread. The default does nothing, so effects and plugins ignore it.
- `sounding_voices()`, `cull_candidate()` and `cull()` are for load shedding: how many voices sound now, the voice the instrument would give up first if the host runs out of time (a `Cull`: its level now, relative to a full-velocity note, and whether its note has ended), and giving that voice up with the steal's fade. The host gives up the least audible voice across every instrument first (`Cull::audibility` counts a releasing voice 12 dB quieter); see [Load shedding](profiling.md#load-shedding-giving-up-voices-nobody-hears). Poly, FM and Wavetable offer the quietest voice by its amp envelope and gain, Analog the quietest card by its amp envelope and velocity (a cut card falls 40 dB in 10 ms and goes at -60 dB), Pluck and Keys by their level followers, Drums the quietest hit (none counts as releasing), the sampler by what each voice has played lately. Drawbar offers none (its wheels turn whatever the keys do, so a key given up saves little), nor does Squelch (one voice). The defaults (0, None, false) suit effects and plugins.
- `Ctx` carries the rate, the absolute frame of the block's first frame, the tempo, the transport position in beats, whether it plays, and an optional sidechain.
- `params()` describes every parameter with `ParamInfo`: id, name, group, range, default, unit, curve (linear, log, stepped, named choices, toggle) and a read-only flag for meters. A GUI page, Q-Link mapping, automation and p-locks can be built for any node from this list alone. `check_params` checks a list.
- `prepare(rate, max_block)` runs on the control thread and may allocate. `reset()` silences the node and keeps its parameters. `tail_frames()` and `latency()` tell the host how long the node rings and how much delay it adds. `rest_frames()` (default `u32::MAX`, never) is how long its input must be silent before it is as good as reset, so an effect chain may reset it and stop calling it until sound comes again (sleep on silence, [fx.md](fx.md)); a node that makes sound from silence or keeps time across it keeps the default. `can_lead`, `lead`, `lead_in` and `lead_out` (default: never) let a host feed an effect late and still hear it on time, as the mixer does with a reverb return a block late (see [fx.md](fx.md)).

Rules every node keeps:

- Stereo `f32`, in place. Instruments **add** into the buffers; effects transform them.
- 1.0 is 0 dBFS. No node clamps or saturates unless that is its job, so deliberate distortion stays possible. Instruments aim for about -12 dBFS peak for one full-velocity note at their defaults and fade every voice's end. The master node catches accidents with a limiter that counts overs and never errors or mutes.
- No allocation, free, lock, block or panic in `process`.
- The same output, sample for sample, for any block size from 1 to `MAX_BLOCK` (8192) frames. Control-rate work is aligned to the absolute frame, never to the block's start.
- Parameter values are plain units, clamped, never refused; each node smooths its own continuous parameters (`Smooth`).
- A node must not output non-finite samples. If one does, the host resets it and counts it.
- `mpfree_node::pressure` is the shared pad-pressure shaper every engine runs pressure through (see [Pad pressure](#pad-pressure-poly-aftertouch)).

## Poly (`mpfree-synth`)

A subtractive synth:

- **Oscillators:** two per voice, saw, pulse, triangle, sine or supersaw, read from the voice core's band-limited tables (`osc.rs`, wave 2 of the synth library, 19 Nov; [Synth architecture](synth-architecture.md#3-the-shared-voice-core)): 17 levels half an octave apart, the level picked from the pitch so every harmonic stays under Nyquist, at least 16 samples per cycle of a high note's few harmonics, read linearly with a 32-bit phase. The pulse is two saws a width apart. The worst alias went from -49, -44 and -37 dB at C5, C6 and C7 (PolyBLEP) to -78, -84 and -90 dB; the triangle is at -94 to -99 dB ([Synth quality](synth-quality.md), A1). **Supersaw** is seven saws on the detune and mix curves Adam Szabo measured on the original (2010), with their own phases set at random on each note; **Saw detune** and **Side saws** (ids 24 and 25, the Supersaw group) set the curves, and the stack is scaled by its power so it plays about as loud as one saw. Octave, semitone and fine tune, pulse width; a square sub one octave down (PolyBLEP, as before); white noise. The tables take about 340 KB, built once by the first `Poly::new`.
- **Table wave** (19 Nov, wave 2 of the synth library: the Wavetable synth folded into Poly; [Synth architecture](synth-architecture.md)): either oscillator's **Wave** can be **Table**, which plays one of the Wavetable synth's tables ([Wavetable synth](wavetable.md): the ten factory tables or the user table) through the same band-limited levels, at a **Position** through its frames (0 to 100 %, crossfading between the two nearest), bent by a **Warp** (Off, Bend, Sync, Mirror, FM) by its **Warp amt** (ids 4 to 7 for oscillator 1, 26 to 29 for oscillator 2; `TABLE_IDS`). What moves the positions: the filter envelope (**To position 1**, **To position 2**, **To warp**, ids 44, 45 and 47), velocity (**Vel to position**, id 46), LFO 1 (**To position 1** and **To position 2**, ids 68 and 69), pressure and the routes (targets **Position** and **Warp**, 15 and 16) and Age (it pulls the two oscillators' positions apart, as it does their pulse widths). The read is the voice core's table oscillator (`table_osc.rs`), which the Wavetable synth shares since the fold: Poly's 32-bit phase, an unbent read indexed by a shift, a bent one through an f32 phase held inside the frame; each stack crossfades from the last control step's frames to this one's, so a moving position never steps. The FM warp reads the other oscillator: on one oscillator, the other's raw output; on both, each reads the other's last sample (`render_fm_pair`). The level comes from the fastest stack's pitch times the warp's speed-up, so a sync warp picks a lower level. Every older sound has no Table wave: its voices skip all of it (a flag per oscillator set at the control step), render as before to the bit and cost about 1 % more on the gate. Played as the Wavetable cases are (both oscillators on Basic), Poly's Table wave costs about a third less than the Wavetable synth: 665k instructions a block at 8 voices with unison 4 (Wavetable 1,025k) and 1,698k at 16 with unison 8 (2,656k). Its aliasing is the Wavetable synth's to the tenth of a dB (lab A1: position 100 at −65, −60 and −54 dB at C5, C6 and C7; the sync warp at 50 % −45, −39 and −33, since the jump at each sync is not smoothed on either engine). The Table page shows both oscillators' tables, each as a stack of frames with the one it plays bright, and says in place when a setting does nothing ("Table wave only", "warp is off").
- **Unison:** 1 to 8 copies per voice (8 since the fold, as the Wavetable synth had; Voice page since 19 Nov: the supersaw's knobs filled the Osc page), detuned symmetrically and spread across the stereo field. Each voice has a left and a right filter, so the spread stays stereo.
- **Drive, filter and distortion:** a `tanh` **Drive** into a zero-delay-feedback ladder (LP 24) or a trapezoidal state-variable filter (LP 12, BP 12, HP 12), then a **Distortion** after it, the same `tanh` stage with its own amount (0 dB of either is fully clean). Both are there since live test 3 ("Drive has almost no effect"; Jay, 13 Nov 17:58Z: "add both types of drive and distortion"): the drive before the filter is the classic analog filter overdrive, warmth the filter then shapes, but a low cutoff takes out what it adds, so on Grit Bass (260 Hz) the harmonics from the 5th up go only from about 2 % to 5 % of the power at 18 dB; the distortion after the filter keeps its grit whatever the cutoff (21 %; `grit_bass_distortion_is_heard_through_its_low_cutoff`). Grit Bass's grit is its distortion (18 dB, pressure +6 dB); the other presets keep the drive they were made with. Pressure can push either (Poly's targets Drive and Distortion). Each stage keeps the level the same way, with its own `DriveLevel`, and the two corrections multiply into the voice's gain. Each keeps the voice's level (live test 2: "Drive seems to make synths quieter"; the old stage divided by the gain's square root and took up to 14 dB off a full voice at 24 dB). It drives the mix as if one full oscillator fed it (`dsp::mix_level` from the unison stacks, oscillator, sub and noise levels; `dsp::drive_scales`), clipping at that oscillator's peak (`DRIVE_REF`), and `dsp::DriveLevel` sums the power into and out of the drive and, once a control step, folds `sqrt(in / out)` (smoothed over about 40 ms, at most 18 dB either way) into the voice's ramped gain, so the correction costs two multiply-adds a frame and never clicks. Every Poly and Wavetable preset stays within 2 dB of its undriven level from 3 to 24 dB of drive, and of distortion (`turning_the_drive_up_keeps_every_preset_about_as_loud`); a drive or distortion of 0 is bit-identical to none. **DC blocker** (19 Nov): an uneven wave through either stage makes DC (Lead's 40 % pulse into 9 dB of drive put it at −44 dBFS on the lab's phrase), so Poly's output goes through the voice core's one-pole high-pass at 5 Hz (under 0.1 dB at C1) while a voice sounds with drive or distortion set, or added by pressure or a route. It keeps what the buffer held before the voices added to it apart (`DcBlock::run_added`) and lets go of what is left of its state below about −400 dB at each control step (`DcBlock::settle`, on fixed frames, so the output is the same however blocks are cut); once every voice has ended and its state has let go it stops, so the silence after is exact (`a_driven_sound_puts_out_no_dc_and_ends_in_exact_silence`). A sound with neither never runs it and renders as before to the bit. It costs about 3,600 instructions a block on x86 (two channels, a frame at a time), about 6 to 7 % of Lead, Acid, Grit Bass and Singing Lead. The drum voices keep the old stage (`drive_sq`): a hit reaches it well under full level, where it lifts the hit. Cutoff follows the filter envelope, key tracking, velocity, the LFO and pad pressure (see [Pad pressure](#pad-pressure-poly-aftertouch)).
- **Envelopes:** filter and amp ADSR from the voice core (`voice::Adsr`, since 19 Nov), with exponential segments whose times mean what they say: Attack reaches full level in its time, Decay covers 99 % of the way to Sustain, Release falls 60 dB. Poly's release aims at -0.01 (`Adsr::analog_release`, the curve it always had), so a voice ends just after its release time (1.02 times) and costs no more than before. A retrigger starts from the current level, so it never clicks. Before, Attack reached full level at 32 % of its label (it aimed past full level with a coefficient for 99 % of the way), so sounds saved then are converted on load: attacks times 0.319, releases times 0.983, decays as they are (`poly::upgrade`, preset format 2, [Presets](presets.md#the-file)). The lab's P6 rows went from 69 % early to 2 % (attack) and from 15 % off to 0 % (release, now measured to -60 dB).
- **Velocity:** **Velocity to level** is a range in dB (0 to 40, 8 by default) on the voice core's square-law curve (`voice::VelCurve`, worked out once when the knob moves). It was a share (60 % by default: a velocity-1 note at 0.4 of full plus a square law), converted on load to the range that puts velocity 1 at the same level (60 % is 8.0 dB; 100 %, which went down to -84 dB, becomes 40). Mid velocities play up to about 1 dB louder than before; the lab's L6 curve error went from 0.73 dB to 0.02. Velocity to cutoff is unchanged.
- **LFO:** sine, triangle, saw, square or sample-and-hold, free (0.05 to 30 Hz) or synced to the transport (4 bars to 1/16 triplets, phase-locked to `Ctx::beats` while playing), to pitch, cutoff, pulse width and level.
- **LFO 2** (19 Nov, ids 120 to 128, its own page): each voice's own, the voice core's `voice::Lfo` with a sample-and-hold seed per slot. Shape, Rate or Sync as LFO 1, **Fade in** (1 ms to 10 s; the lowest setting is no fade), **Retrigger**, and To pitch (12 semitones), To cutoff (5 octaves), To width (45 %) and To level (a 100 % dip). Retrigger on starts it at each note; off, a free one starts at a random place for each note (a pad's notes drift apart), and a synced one follows the song's position while it plays, so every note is in step with the beat. A legato note keeps it running.
- **Play routes** (19 Nov, ids 130 to 141, the Routes page): four, each **From** (Off, Velocity, Pressure, Tone, Mod wheel, Breath, Foot, Key, Random), **To** (pressure's targets) and **Depth** (-100 to 100 %, shown in its target's unit as pressure's depths are, `pressure::full_scale`). The voice core does the reading (`voice::Route`, `Source::read`): velocity, key (0 at C4, ±1 five octaves away) and random (one value a note) are taken when a note starts, pressure and tone follow the note, and the mod wheel, breath and foot controller (`NodeEvent::Control`) glide over the expression smoothing (5 ms) so a wheel's steps don't zip. Most targets add source × depth × full scale beside pressure's slot. **Level**, **LFO 1 amount** and **LFO 2 amount** are gates instead, with a resting place: at a positive depth the source at rest lets 1 − depth through and at the top all of it, and a negative depth takes it away as the source rises (`pressure::swell_gain`, `pressure::lfo_gate`; a key or random source is read 0 to 1 there). A route on LFO rate follows the highest sounding note's, as pressure's does, since the LFO is shared. **Route 1 is the mod wheel on Vibrato at 50 % by default**, half a semitone each way at Vib rate with the wheel at the top, so every preset answers a keyboard's wheel, old ones too (a value a preset doesn't name takes its default). Pressure got three targets with them: LFO 1 amount, LFO 2 amount and Pan (each voice moves, its unison copies with it).
- **Age** (19 Nov, id 76, the Voice page, Q-Link 2 there): the voice core's Character (`character.rs`), Analog's sixteen voice cards with the same offsets and the same drift ([Analog](#analog-mpfree-synth-analog)). A note starting on a fresh voice takes the next card in turn, so a repeated chord lands on different cards; the same note again keeps its voice's card, as does a legato note, and in Mono each new note takes the next. At 100 a card's offsets have standard deviations of 4 cents on each oscillator (the sub follows oscillator 1), 0.084 octave of cutoff, 8 % of the attack, decay and release of both envelopes, 2.5 % of pulse width (added on oscillator 1, taken off oscillator 2, as on Analog) and 0.5 dB; each card's two oscillators drift 2 cents rms with a 5 s time constant. Age scales all of it. At 0, the default, none of it runs and the drift stands still: every preset without it renders as before to the bit, and the gate's Poly cases cost the same within 0.2 %. Above 0 a voice takes the fuller path (`voice_control_as::<true>`) and its pitch is worked out every step, since the drift moves it: Worn Brass, 8 voices, is 243k instructions a block against Brass's 210k. The lab's P10 rows: 16 notes at Age 100 spread within 0.07 cents of what the cards and the drift say, half as far at Age 50, not at all at 0; the drift is 2.0 cents rms and wanders at most 8.5 cents from its place in 30 minutes.
- **Voices:** poly (1 to 16), mono or legato, glide, bend range. A stolen voice fades out over 3 ms in one of 4 spare slots. Stealing takes the quietest releasing voice, then the oldest held one. Mono and legato keep a note stack.
- **Presets:** Init, Grit Bass, Acid, Supersaw (unison saws), Dust Pad, Pluck, Brass, Sub Bass and Lead; with routes and LFO 2, **Singing Lead** (a delayed vibrato on LFO 2, tone to cutoff, velocity to drive) and **Drift Pad** (each note at its own pan and a few cents off from Random, a free triangle LFO 2 on each note's cutoff and width, the wheel on cutoff); on the Supersaw wave, Super Lead, Super Pad, Super Stab and Super Stack (a factory sound with the Ensemble and a dotted-eighth delay, its macros on Detune, Mix, Octave and Effects); with Age, **Worn Brass** (Brass's two saws at Age 80, each chord a little different).

**Antialiased drive.** The drive and the distortion take `tanh` averaged from one input to the next, worked out from its antiderivative `ln cosh` (first-order antiderivative antialiasing, `dsp::DriveAa`; Parker, Zavalishin and Le Bivic, DAFx 2016). It costs an `exp` and a `ln_1p` a sample where the plain stage had a `tanh`, and delays the driven sound by half a sample. A saw at 24 dB of drive aliased at -42, -36 and -30 dB at C5, C6 and C7, and now at -50, -45 and -38; the distortion went from -39, -34 and -27 to -45, -40 and -35. Still short of -60: running the stage at twice the rate is the next step if listening asks for it.

Timing: oscillators, drive, filters, distortion, the amp envelope and the steal fade run every frame. Smoothing, the LFO, the filter envelope, pressure, glide, pitch and the filter coefficients run once every 16 frames, on frames divisible by 16. Each voice's gain is ramped across a step, so a pressure swell has no zipper.

Cost (after round 7's device bench): each voice renders a control step in passes (gains, each unison stack, sub and noise, drive, filter, distortion, out), so the choice of wave, filter type and drive is made once per step, not once a frame. A centred voice (one stack, or no spread) works out one side and uses it for both, since its left and right are the same to the bit. Pitch, pan and filter coefficients are only worked out again when their inputs move. The output is the same to the bit as before; `cargo run --release -p mpfree-synth --example poly_cost` prints a hash per preset to check that after any change. Under qemu, the ARMv7 build runs 12 to 37 % fewer instructions per preset (Init 30 %, Supersaw 20 %, Dust Pad 12 %). The tables (19 Nov) changed the sound, so the hashes changed with them; on the x86 instruction gate they cost what PolyBLEP did, from 9 % less (Supersaw, Sub Bass, Init with unison 4) to 4 % more (Brass, whose vibrato moves the pitch every step). The routes, LFO 2 and pressure's newer targets run only while one of them does something (`voice_control_as::<true>`; a route from the wheel rests while the wheel does, so the default route costs nothing until the wheel moves). Without them a voice takes Poly's plain path (`voice_control_as::<false>`, the code it had before), every older preset renders bit for bit as before, and the gate's Poly cases moved by 1.5 % or less (Brass 0.3 %, Sub Bass 1.2 %, the 16 Instrument pads 1.5 %). A table read is one load of a sample and its step and one multiply-add, with no float-to-integer conversion; the level is found by stepping from the last one. The supersaw's seven saws run through `mpfree_simd::table_sum` ([NEON kernels](simd.md)): the NEON kernel on the MPC, its plain twin (the loop it had before) everywhere else, the same samples either way; under qemu every Super preset sounds the same to the bit with the kernels on and off (`tests/simd.rs`).

## FM (`mpfree-synth`, `Fm`)

A six-operator FM synth in the DX7's mould. It is DX7-style, not a bit-exact clone: the numbers come from published descriptions of the DX7 (the operator level table, the envelope rate formula, the keyboard scaling curves), and where the original is not public (the LFO speed curve, the pitch envelope's tables, detune) the values are close approximations.

- **Operators:** six sines, each with a ratio (coarse 0 to 31, fine) or a fixed frequency, detune, an output level (0 to 99), a four-rate, four-level envelope, velocity sensitivity, keyboard level scaling (break point, left and right depth and curve), rate scaling and amplitude modulation from the LFO. Each operator can be switched off.
- **Algorithms:** the DX7's 32 ways of wiring them, with feedback 0 to 7 on one operator or, for algorithms 4 and 6, around a loop of two or three. Feedback averages the last two samples, as the DX7 does, so it stays stable at 7.
- **Envelopes:** in decibels, falling at a constant rate, with the attack curving over as it nears its level. Rates and levels from 0 to 99 mean what they mean on a DX7.
- **Global:** a pitch envelope, an LFO (triangle, saw down, saw up, square, sine, sample-and-hold; speed, delay, pitch and amplitude depth, key sync), transpose, oscillator key sync, poly (1 to 16) or mono with a note stack, bend range, pad pressure (see below) and an output level.
- **Level:** one carrier at full level is about -12 dBFS. A voice with more carriers is scaled by 1/sqrt(carriers), so changing the algorithm doesn't jump the volume. The output level glides while notes sound and jumps straight to a new value when nothing sounds, so loading a preset never starts with a swell.
- **Voices:** a stolen voice fades out over 3 ms in one of 4 spare slots, like Poly.
- **Presets:** Init (one sine), Glass Keys, Bell Tower, Rubber Bass, Drawbars, Brass Section, Log Drum, Silk Pad and Steel Pluck. Each plays a chord between -11 and -6 dBFS peak.
- **DX7 banks** (`dx7`): reads a player's own .syx files, a 32-voice bank (4104 bytes) or a single voice (163 bytes), checks the checksum and maps every byte onto FM parameters; it can also write a bank back. Names are 10 characters, as on a DX7, and the bank has no output level, so imported voices play at 0 dB. Only voice data is read; nothing is sent to any device. MPFree ships no Yamaha voices.

Timing: operators run every frame. Envelopes, pitch and the LFO run once every 16 frames, on frames divisible by 16, with operator gains ramped across each step.

A knob (`set_param`) reworks only what it feeds. An operator or global knob reads the voice settings again; a pressure shaper setting (mode, threshold, curve and so on) works out the 128-step pressure curve; a pressure slot's target or depth works out just the slots. Before 12 November every knob also worked out the curve, which costs more than everything else together: on a desktop a knob turn took about 1.55 µs, now 0.15 µs (0.07 µs for a slot), against about 9 µs to render 32 frames of 8 voices. That matters when a Q-Link, a macro or an LFO in the mod matrix moves an FM parameter every few frames.

**On the Synth tab** FM has its own pages: Algo (algorithm, feedback, transpose, level, voices), Mod (LFO and pitch envelope), Pressure (see below), Op 1 to Op 6 (each operator's frequency, level, envelope and velocity; the Q-Links turn output, coarse, fine and velocity) and Kbd 1-2, 3-4 and 5-6 (keyboard scaling, two operators a page). Every FM parameter is on exactly one page.

Every FM page has a visual strip, drawn from the values:

- **The algorithm** as six boxes: carriers (green) along the bottom over the output line, each modulator (blue) a row above what it modulates, joined by down-across-down lines like the DX7's panel, and the feedback loop on the right when feedback is above 0. A switched-off or silent operator is faded. The layout is worked out from the algorithm's wiring, so all 32 draw the same way (`fm_visual::algorithm_layout`).
- **Algo page:** the algorithm and the six output levels as bars, carriers green.
- **Op pages:** the algorithm with that operator ringed, and its envelope as the engine runs it (L4 up through L1, L2 and L3, held, then the release), with its role in the caption ("modulates 1 · output 58").
- **Kbd pages:** the algorithm with the two operators ringed in their curves' colours, and their keyboard level scaling across A-1 to C7 in dB (the card's scale is the smallest of ±12, 24, 48 or 96 dB that holds both).
- **Mod page:** the pitch envelope (on a ±2, 12, 24 or 48 semitone scale, so a small scoop still shows) and the LFO's wave after its delay.

A tap on a box opens that operator's page; a tap elsewhere on the algorithm card opens Algo. `cargo run --locked -p mpfree-synth-ui --bin mpfree-synth-preview` draws the samples `synth-fm-algo`, `synth-fm-mod`, `synth-fm-op`, `synth-fm-kbd` and `synth-fm-pressure`. FM isn't in the pad player yet; Poly is the pads' synth for round 6.

## Drums (`mpfree-synth`, `Drums`)

A drum synth with a model per pad. Sixteen pads, each one of sixteen models: the first engine's eleven (**Kick, Snare, Clap, Closed hat, Open hat, Tom, Rim, Cowbell, Cymbal, Zap, FM perc**) and wave 3's five (**808 kick, Conga, Woodblock, Bell, Shaker**). The code is `drum.rs` (the pool of 32 hits, notes, chokes, releases, the parameters), `drum/classic.rs` (the first engine's voice, unchanged) and `drum/current.rs` (the new voices); the 808 kick's body is Bass's (`body808.rs`, shared to the bit).

**Two voice sets, picked per kit** by the kit's **Voices** (id 302, Classic or Current). Classic is the first engine to the bit: it is the default, so a kit file without the line, an old project and `Drums::new` play exactly as before (checked by hashing every old kit's render against main before the change). Current is the new voices; the five factory kits set it (`kit.voices = Current`). A wave 3 model always plays its Current voice; in a Classic kit it has no accent, variation or gating.

**Parameters.** A pad's first fourteen fields keep their ids, `pad * 16 + field` (`drum_params::pad_id`): Model, Tune, Decay, Tone, Snap, Noise, Sweep, Sweep time, Drive, Level, Pan, Vel > tone, Vel > level, Choke. The twelve newer ones sit at `512 + pad * 32 + (field - 16)`: Accent, Variation, Plays (One-shot or While held), Claps, Gap, Room, Ratio, Strike, Spread, Ring, Grain, Attack. The kit's are Level (300), Pad 1 note (301), Voices (302) and the Hits on meter (310). Ids from 1024 are the drum effects'. `drum_params::knobs(model)` lists each Current drum's own knobs with their labels there (Snap is "Click" on a kick, "Punch" on the 808 kick, "Slap" on a conga; Sweep is "Sigh" on the 808 kick and "Bend" on a tom), `qlinks(model)` its four Q-Links, and `SHARED` the nine every drum shows (Model, Level, Pan, Choke, Vel > level, Vel > tone, Accent, Variation, Plays): at most 16 on a page.

**The Current voices:**

- **Kick:** a sine body (50 Hz) with a cubic sweep, Tone a waveshaper, a high-passed noise click.
- **808 kick:** Bass's 808 body at 48 Hz: the punch (the circuit's attack shift, up to 24 semitones for 6 ms at Punch 100) and the sigh (from 58 to 48 Hz over 300 ms at the defaults: Sigh 3.28 semitones, Sigh time 300 ms), Tone a low-pass, the trigger pulse leaking through, and Bass's soft drive.
- **Snare:** two body modes (Ring brings the head's overtone up) under band-passed noise (Snappy); **Rim**, a short 500 Hz body and click.
- **Clap:** 1 to 8 bursts (Claps) a jittered Gap apart, then a Room tail.
- **Hats and cymbal:** the 808 cymbal's six squares (205.3, 304.4, 369.6, 522.7, 540 and 800 Hz at Spread 50, 47.98 % wide; Spread moves them apart around their middle), each edge smoothed over four samples (`dsp::poly_blep4`) and the sum through a one-pole at 10 kHz, against noise (Noise). The cymbal takes the paper's three bands (band-passes at 3,440 and 7,100 Hz at Tone 50, and a high-pass after the high one), each decaying in turn; a hat takes the high band and a high-pass. **Cowbell:** the 540 and 800 Hz squares through a band-pass at 2,640 Hz, a 30 ms attack band over the ring.
- **Tom and Conga:** Pluck's modal bank (`modal::ModalBank`) on a membrane's modes (8 for a tom at 120 Hz, 6 for a conga at 200 Hz, its modes pulled nearer harmonic), struck at Strike by a half-sine stick pulse whose length follows Tone and the hit; a hard hit bends the head down by Bend over Bend time; the conga's Slap is a noise burst. **Woodblock** and **Bell:** a bar's modes (800 Hz) and a hand bell's (600 Hz) the same way.
- **Zap** (90 Hz) and **FM perc** (220 Hz, Ratio its modulator): a body with a sweep, FM perc's index on Tone. **Shaker:** beads (Grain) over hiss, swelling in over Attack.

**How a hit plays (Current):**

- **Velocity and accent:** a hit's *bite* is 1 at full velocity and falls with Vel > tone; Accent adds up to 4 dB and 0.35 bite above velocity 91 (a smooth step to 122). Every filter moves an octave and a half across the bite, clicks and sticks with its square or cube, the stick pulse shortens and the drive pushes harder, so a hard hit is brighter, not only louder.
- **Variation:** each hit on a pad goes the other way from the last, by 0.1 to 0.5 dB and 0.5 to 2.5 cents at 50 %, with up to 3 % more or less decay and 4 % bite; at 0 the hits are the same to the bit.
- **Decay:** each part's share of Decay is set so the whole hit is 60 dB down on the label, a quiet part starting lower and the drive's lift on the tail counted (`decay_share`).
- **Drive:** soft, scaled to keep the hit's peak; the 808 kick uses Bass's curve.
- **Plays:** While held fades a hit over 50 ms on its note-off (or a note-on at velocity 0); One-shot ignores note-offs.
- **Chokes and retriggers** fade the old hit on a smooth step over 5 ms (Classic: 3 ms, as before); AllOff fades every hit over 30 ms.
- **Control steps** (the sweeps, the bend, and landing any envelope under -400 dB on zero so none reaches the processor's slow tiny numbers) come every 16 frames counted from the hit's start, so the output is the same for any block size.

32 hit slots; nothing allocates after `prepare` (`tests/no_alloc.rs` runs a Current kit too).

**Level:** at full velocity every factory pad peaks under -3 dBFS on either side (the Current hits sit 2 dB under the levels they are tuned at, for headroom, and a kit plays within about a dB of its Classic loudness); the kits' pads sit within 6 dB of their kick (20 ms windows) except two very short closed hats (see [Synth quality](synth-quality.md), D7).

**On the Synth tab** Drums has a Kit page (Level, Pad 1 note, Voices) and a page per pad. The pad pages come from the values (`pages::plan_values`): the pad's model and the kit's Voices pick its fields (`drum_params::page_fields`) and Q-Links (`page_qlinks`). A Current drum shows `SHARED` in Feel and Mix boxes and its own knobs under their labels; a first-engine model in a Classic kit shows the fourteen fields as before, Tune, Decay, Tone and Snap on the Q-Links, and the fields that model leaves at nothing faint ("this drum doesn't use it"). Accent, Variation and Plays are faint in a Classic kit ("kit voices are Classic"). Changing a pad's Model or the kit's Voices plans the pages again (`view::relays_out`). `pages::drum_page(pad)` gives the page of a pad, so the app can follow the last pad hit; `qsets::on_pad_values` turns the factory Hit Q-Link set into the drum's own four. The preview draws `synth-drums-kick`, `synth-drums-boom`, `synth-drums-hat` and `synth-drums-kit`. `Drums::pad_name(pad)` gives the model name for pad labels.

Its visual strip has four cards. **Kit**: a box per pad, laid out as the pads are (pad 1 bottom left), tagged with its sound (BD, SD, CP, CH, OH, TM, RS, CB, CY, ZP, FM, 8K, CG, WB, BL, SH) and coloured by what it is made of (green a tuned body, amber noise over a body, blue metal); the pad shown is ringed, a silent pad faded, and a tap on a box opens that pad's page. **Hit**: the pad's body, noise (a clap's bursts over its tail) and click over time, each at its level in the mix, until the longest is 60 dB down. **Sweep**: the body's pitch sweep over 250 ms, against the knob's 48 semitones ("no body to sweep" for the hats, clap, cowbell and cymbal). **Levels**: every pad's level, the pad shown in white. On the Kit page Hit and Sweep show pad 1. `drum::hit_shape` works the shapes out with the same code that builds the hits the engine plays (`build`), and a test renders a kick and finds the body's fall and the sweep's pitch as drawn.

## Pluck (`mpfree-synth`, `Pluck`)

Plucked strings and struck bars: two physical models behind one set of pages, picked with **Model**.

- **String** is a Karplus-Strong string (the Jaffe-Smith extension): a delay line one period long with a one-pole damping filter and a first-order allpass in the loop. The tuning takes the filter's phase delay into account, so notes from C1 to C7 play within 2 cents (within 6 at C1 for the darkest presets). A pluck fills the line with a burst of noise shaped by **Pick** (brightness of the burst) and **Position** (a comb: plucking near the bridge is thin, near the middle hollow). **Brightness** sets the loop filter between 12 and 112 harmonics of the note.
- **Mallet** is a modal bank: up to eight two-pole resonators per voice at a **Material**'s mode ratios (Marimba, Vibes, Bell, Glass, Kalimba, Steel drum), struck by a half-sine mallet pulse. The bank, the pulse, the material tables and their helpers are a shared part since 19 Nov (`modal.rs`: `ModalBank`, `Pulse`, `pulse_len`, `pulse_spectrum`, `strike_place`, `stretched`, `mode_t60`, `mode_share`), so the drums can build toms, congas, woodblocks and bells on it; the move kept every Pluck preset's output the same to the bit (`engine_cost pluck`), and `modal.rs` has its own unit tests (a mode's pitch within 0.05 Hz and its fall of 60 dB within 0.5 dB at its T60, out-of-range modes silent, `retune` against a fresh `set`, the pulse's shape and spectrum). **Hardness** is the pulse length (a harder mallet reaches higher modes); **Strike** is where the bar is hit, **Stretch** spreads the ratios, **High damp** shortens the upper modes.
- **Decay** is the ring at middle C (higher notes ring shorter, lower ones longer); **Release** is how fast a note damps once its key is let go (1.5 s by default, so pad taps ring). **Vel > tone** makes soft notes darker. Transpose, Fine, Voices (1 to 16), Bend range, Level, Pan and Spread (alternate voices left and right).
- **Notes:** playing a note that is still ringing re-plucks it in its own voice, adding to what sounds, as a real string does. Past the voice limit the oldest note (released ones first) fades out over 3 ms. Pressure is ignored.
- **Level:** every preset peaks between -16 and -9 dBFS at full velocity across C2 to C6.
- **Presets:** Init, Nylon, Steel String, Harp, Koto, Muted Bass (strings), and Marimba, Vibes, Bell, Glass, Kalimba and Steel Drum (mallets).

Timing: the strings and resonators run every frame; pitch (transpose, fine, bend) runs at a control step of 16 frames aligned to the absolute frame. The delay lines (one per voice, 4096 frames at 48 kHz) are allocated in `prepare`.

**On the Synth tab** Pluck has three pages: String (with the model, decay and release; Q-Links Decay, Brightness, Pick, Position), Mallet (Q-Links Hardness, Strike, Stretch, High damp) and Voice. The preview draws `synth-pluck-string` and `synth-pluck-mallet`.

Its visual strip has three cards for the model it plays, all for middle C. A string: **Pick** (the string pulled up where it is picked), **Harmonics** (the first 16, in dB, at their average level over many plucks, since each pluck's noise burst gives them random levels around it) and **Decay** (harmonics 1, 2, 4 and 8 falling in dB, higher ones sooner, more so when darker). A mallet: **Mallet** (the pulse, as long as the mallet stays on the bar), **Modes** (the material's modes on a log scale of the note, as struck: placed by Strike, weighed by the pulse's spectrum) and **Decay** (the first four modes). `pluck::partials` works them out with the engine's own formulas (shared helpers, the output unchanged to the bit), and tests render notes and find each harmonic's and mode's decay, and the harmonics' average levels, as drawn. One finding: Position's comb works within the burst's one period (the first frames are not subtracted), so its notches are partial; plucked at the middle, the even harmonics come out about 7 dB under the odd ones on average rather than gone.

## Wavetable (`mpfree-synth`, `Wavetable`)

Two table oscillators that scan through stacks of single-cycle frames, with warps (Bend, Sync, Mirror, FM), unison, a sub and noise, Poly's filter, a mod envelope and LFO that move the positions, and pad pressure. Ten factory tables are built from formulas; a player's WAV tables and a pad's sample can become user tables. Tables are band-limited at 17 half-octave levels, so high notes don't alias. The ten factory tables are built once, by the first `Wavetable::new` (the pad player makes it before the sound starts): about 0.9 billion ARMv7 instructions under qemu, most of them FFTs, so it adds to start-up time, never to a block. The full description, the memory and cost numbers and the demo are in [Wavetable synth](wavetable.md).

## Keys (`mpfree-synth`, `Keys`)

An electric piano and a clav, picked with **Model**: a struck steel tine beside a magnetic pickup (**Tine**), a struck steel reed in an electrostatic pickup (**Reed**), or a string struck and held by a metal tangent over two magnetic pickups (**Clav**, from the synth library's wave 1, 18 Nov). The tine and reed follow the measurements and models collected in [Electric pianos](../research/electric-piano.md): the vibrating part moves almost as a sine, and the pickup makes the tone. The clav follows [Keys](../research/keys.md#3-algorithms) (Gabrielli et al. 2013): a string with a comb at each pickup.

- **Voice (tine).** Rebuilt 19 Nov against recordings of a real tine piano (15 keys from F1 to C7, five velocity layers each; see [Electric pianos](../research/electric-piano.md#measured-tine-piano-19-nov)). Three two-pole resonators: the fundamental (Decay at middle C, 12 s by default as the recordings rang 11 and 19 s, falling as f^-0.75, the slope of measured Q factors; heard, not as the tine moves: the pickup compresses a wide swing, so its sound falls slower than the tine, and `tine_decay_comp` shortens the resonator by the pickup's gain slope over the note's first 40 dB so a hit on middle C rings as labelled, the same factor on every key) and the cantilever's two bending modes, the bell and the tick over it. Their ratios are the measured ones (`TINE_RATIOS`: the bell 7.15 times the note in the bass, 7.35 through the middle, 6.3 at the top; the tick 20.6 in the bass to 17.5 from C5), moved by up to 1.5 % per key. The hit kicks the bending modes directly, past the hammer's low-pass (the bell is there whatever the hammer), at a random moment within the contact (at least a 1 ms span) so a chord's bells don't start in phase. The bell as heard against the note on a full hit is -50 + Bell/2 dB (Bell 40: the measured -30 dB), 0.12 dB more per point of Hardness over 50, 20 dB an octave less over C6 (`tine_bell_db`), and a softer hit rings it as the fourth root of its drive (about 6 dB from the softest to the hardest, as measured). The tick is 0.14 of the bell at Hardness 50 (measured 15 to 20 dB under it) and 10 dB more or less at the ends (`tine_tick`): a hammer's tip filters what it strikes the more the higher it is. The bell rings 0.65 s at D4 (measured 0.55 to 2 s through the middle), shorter as f^-0.9, at most 1.5 s; the tick a quarter of that (`tine_mode_t60`).
- **Voice (reed).** A small modal bank of two-pole resonators. A reed has its fundamental in two parts, long and short, so the decay is not a single exponential; its second mode as a pair 0.1 % apart, so it beats; and its third mode. Each strike moves the upper modes by up to 0.3 % and 1.3 dB at random, and each key has a small fixed offset in its voicing.
- **Voice (clav).** A single-delay waveguide string (4096 samples: down to C1 with the release drop at 48 kHz) read through a four-point Lagrange interpolator, with a one-pole low-pass and a gain in the loop. `clav_loop` designs the two from two decays: the note's (Decay's law, shortened by **Mute** to 15 % at full) and its band's top, which dies in 6 % of that time; the pole is capped so what lies under the note dies within four times the note's decay. The mute's felt damps what is over 1 kHz (for a note above it, its octave): that dies in 0.02^Mute of the note's time. The loop's delay is the period less the low-pass's own delay at the note, so the note is in tune. Letting go, the yarn damps the string: the delay grows by **Release drop** (0 to 6 semitones, 3 by default) over 3 ms, so the note falls in pitch as it stops.
- **Hammer and tangent.** A half-sine push. For the tine and reed it has unit area (the fundamental rings at the strike's level whatever the hammer; a tine's, the hit's drive): 0.4 to 4.5 ms at full velocity by **Hardness**, longer for softer notes as v^-0.47 (Hunt and Crossley contact, exponent 2.8), never more than half the note's period. The clav's tangent is metal on a string: 0.08 to 0.88 ms by Hardness, the same velocity law, up to four times longer under Mute, never more than a third of the period (`keys::clav_contact`); its height makes the fundamental the strike's level at middle C and lower by the square root of the frequency below it (a low note has more harmonics under the push). A shorter contact reaches higher. **Vel > tone** sets how much velocity lengthens it.
- **Pickup.** A Hammerstein model, as measured on magnetic pickups: a static curve of the displacement, then its change from frame to frame (Faraday's law; a capacitor's current), divided by the note's angular frequency so every note comes out at the same level. Tine: the flux `1/(1+u²)`; **Voicing** moves the rest point from the field's axis (0: the octave above the note dominates) to 0.6, near the curve's inflection at 1/√3 (100: nearly pure). **Bark** sets how far a full-velocity hit swings across it, 0.4 to 8 field widths on a log scale (`tine_bark`: 1.5 at the default 45), and the hit's drive scales that (`tine_drive`: the voice core's square law over 66 dB times Vel > tone, 40 dB at the default 60), so a soft hit barely bends the curve and a hard one swings across the axis; low notes swing wider, by 1/(1+(f/280 Hz)²) against middle C (`tine_register`). These are fitted to the recordings: a Lorentzian fit of each velocity layer's harmonics gave the swing. The output is divided by the pickup's gain at that swing (`tine_pickup_gain`: the fundamental and the harmonics it makes), plain across the velocities (Velocity's square law is a level's) and weighted as the loudness meter hears it across the keys, at velocity 100, so Bark changes the colour of a hard hit, not its level, and every key plays as loud; the flux's change is taken without subtracting two nearly equal values (`-(u-p)(u+p)/((1+u²)(1+p²))`), so a soft note stays clean in f32. Reed: the capacitance `1/(1-y)`, the reed held off the plate by a soft limit at 0.9 of the gap; Voicing moves its rest point from 0.4 to 0. **Bark** sets how far a full-velocity hit swings across the curve, and low notes swing wider ((261.6 Hz / f)^0.5, limited to 0.5 to 1.6), so they bark sooner. Putting the sum of the modes through the curve intermodulates them, as the real pickup does. Clav: each pickup hears the wave less its reflection, a comb with notches on every fifth partial (the neck pickup, at 0.2 of the string, as measured) or every fourteenth (the bridge, at 1/14, our reading); **Pickup** is Neck, Bridge, Both (half each) or Out of phase (half each, one turned round: what they share cancels, so it is thin). A leaky integrator (2 Hz) turns the string's velocity into where it sits over the pickup, through an off-centre curve `u - 0.2u²` that Bark drives (`keys::clav_swing`: the same over every pickup, half Out of phase). Each note is voiced when struck (`clav_voicing`): its partials up to 6 kHz through the combs and the tone switch, weighted as the loudness meter hears them, set its level, so every pickup and switch plays about as loud (at most 12 dB of make-up).
- **After the voices.** The tines first pass a phase rotator of their own (the clav's six all-passes, below): a hard hit's pickup pulses spread in time, the spectrum unchanged, so an eight-note full-velocity chord peaks 1 to 5 dB lower at the same loudness. It runs from a tine's strike to the first control step with none left. The voices sum to a mono bus, then: key noise (a filtered noise burst on each strike and a softer one on each release, **Key noise**), the pickup network's high-pass (30 Hz tine, 120 Hz reed), a tilt **Tone** around 900 Hz (up to ±9 dB treble against ∓3 dB bass), then for a tine a tanh **Drive** (Poly's shape, scaled so a hard chord on the bus is full scale; while it drives, the reed's output coupling after it, as a hard hit's lopsided pulses leave an offset once driven) and for a reed an asymmetric preamp curve that always colours a little and that Drive pushes, then an output coupling (20 Hz) that keeps the curve's offset from the speaker. **Tremolo** at **Trem rate**: **Pan** follows a rounded square between the speakers at equal power; **Amp** a sine on the level, which for a reed works before the preamp so the tone moves with it. The reed's output gets 5.6 dB of make-up gain. The clav strings have their own bus first: the **Clav tone** switch (Soft, Medium, Treble, Brilliant: a two-pole Butterworth high-pass and low-pass each, 30 Hz and 2 kHz to 400 Hz and 14 kHz), a phase rotator (six first-order all-passes at 100, 300 and 900 Hz, as broadcast processors use: it spreads the string's sharp pulses in time without changing the spectrum, so chords peak about 4 dB lower at the same loudness), and a preamp that passes the sound unchanged up to 8 dB under full scale and rounds what goes past toward 2 dB under. It runs only while a clav string sounds.
- **Notes.** A ringing note struck again uses its own voice and adds to what sounds (the clav's string starts afresh). Past Voices (1 to 16, 12 by default) the oldest note, released ones first, fades out over 3 ms. Letting go damps the note over **Release**. Pressure is ignored.
- **Level.** **Velocity** (0 to 48 dB, 32 by default) is the range from the softest note to the hardest, on the voice core's square-law curve; the strike's own height only sets how hard the pickup is driven. Each model's voicing across the keys (`KEY_CURVE`, dB at C1 to C7, a straight line between) is fitted to the factory sounds' loudness at velocity 100, so single notes from C1 to C7 stay within 3 dB (L11; the tine's refitted for the new tine, 0.8 to 2.7 dB over its presets). The presets are matched to about -26.5 LUFS on a held middle C at velocity 100 (the tine presets kept within 0.2 dB of their level before the new tine), and an eight-note full-velocity chord stays under 0 dBFS (L2) on every preset.
- **Against the recordings.** Harmonics 2 to 8 against the note, 50 and 300 ms in, over the recordings' 15 keys and five velocity layers: Init is 9.1 dB rms from them (23.7 before the new tine), about the recorded instrument's own scatter from key to key, with no bias (+0.1 dB). Ballad was 15 dB too dull on average and 26 dB on the hardest layer (its hard notes barely changed from its soft ones); it is now 4 dB warmer than the recordings by design. Bright Tines is 2 dB brighter, the barking presets 3 to 8 dB.
- **Presets (34):** Init, Soft Tines, Bright Tines, Barking Tines, Bell Keys, Hollow Tines (voiced near the axis), Pan Tines, Ballad, Dusty Keys, Mellow Tines, Hard Tines, Long Tines, Lo-fi Tines and Stage Tines (tine); Reed, Reed Bite, Trem Reed, Soft Reed, Dirty Reed, Bright Reed, Pan Reed and Mellow Reed; Clav, Funk Clav (bridge, treble), Muted Clav, Soft Clav (neck, soft), Thin Clav (out of phase), Brilliant Clav, Driven Clav, Stab Clav (a short note with a big drop), Trem Clav and Pan Clav; and two sounds with effects and macros of their own ([Presets](presets.md#factory-presets-as-files)): Phase Tines (a slow phaser and a short plate) and Wah Clav (an envelope wah and a dotted-eighth echo).

Timing: the resonators, strings, pickups and buses run every frame; pitch (transpose, fine, bend), the tremolo, the release drop and retuning run at a control step of 16 frames aligned to the absolute frame, so any block size gives the same output to the bit. Each voice runs across the control step on its own (its state stays in registers), summed in the voices' order, then the buses run frame by frame. Nothing is allocated, even in `prepare`; the clav's strings are 64 KiB together. **Cost:** 121k instructions per 128-frame block for Init with 8 voices, 177k with 16, 198k for Reed with 16, 196k for Dusty Keys with 16, and for Clav 169k with 8 and 251k with 16 (callgrind, x86; CI's instruction gate). The tine's rebuild (19 Nov) made it 3 to 4 % dearer (the tines' phase rotator, the per-note pickup gains at a strike) and the reed 10 % cheaper (each model in its own loop). As ARMv7 code (the MPC's, counted under qemu with `tools/inst_arm_cost.py`) the tine and reed were 124k, 174k, 217k and 195k before the clav (not counted again yet). For comparison Poly Pluck with 8 voices is 209k and Pluck Harp with 16 is 249k. With the MPC calibration file the bench estimated Init at 8 voices near the synth budget's worst block (18.7 % of 20 %), in line with Poly; a device run should set the default voice count.

**On the Synth tab** Keys has five pages: Strike (Model, Hardness, Bell, Decay, Release), Tone (Voicing, Bark; Tone, Vel > tone and Velocity), Clav (Pickup and its Tone switch; Mute and Release drop), Amp (Tremolo, Trem rate, Trem mode, Drive, Key noise) and Voice. Its Q-Link sets are Strike, Tone, Clav (Mute, Release drop, Hardness, Bark) and Amp. Hardness and Bell are in the Tone group, but the Strike page takes them (`pg_with` in `pages.rs`): a preset file names each parameter by its group, so moving them to another group would drop them from presets already saved. Faint controls say why: Bell and Voicing "tine and reed only" while the clav plays, the Clav page's four "clav only" otherwise.

Its visual strip has four cards, all for middle C, drawn by `inst_visual` with the engine's own formulas, and two more while the clav plays. **Hammer**: the force over the contact for a soft hit (velocity 40) and a full one, over 2.5 ms, a little over the longest contact middle C allows (half its period); Hardness and the velocity set the length (`keys::contact_secs`, or for the clav `keys::clav_contact`, captioned "tangent"), the strike its height (a tine's, its drive: `keys::tine_drive`). **Decay**: the fundamental of C2, C4 and C6 falling in dB (the reed's two parts summed; the clav's with its mute), 1.5 times middle C's ring long. **Pickup**: the tine's flux, the reed's capacitance or the clav's curve across the range the voice can reach, the stretch a velocity-100 hit swings across drawn bright, and a dot where Voicing and Bark put the rest point (`keys::pickup_shape`, with `keys::tine_drive` and `keys::tine_register` for the tine, `keys::clav_swing`). **Tremolo**: two cycles of the left and right gains for Pan, one curve for Amp (`keys::tremolo_gains`, which the engine calls too). **Pickups** (Clav page): C2's first 20 partials as the pickups and the tone switch pass them, on 40 dB (`keys::pickup_response`, `keys::clav_tone_gain`), so the notch over the pickup shows. **Mute** (Clav page): how long each of middle C's first 16 partials rings against the open string's fundamental, on a log scale (`keys::clav_ring`, from the loop's own losses). The preview draws `synth-keys-strike`, `synth-keys-tone` and `synth-keys-clav`.

`cargo run --release -p mpfree-synth --example keys_demo [out.wav]` writes `~/mpfree-work/keys-demo.wav` (273 s): every preset in turn, 8.5 s each, playing four chords from velocity 40 to 127 over a bass note, a velocity ladder on C2 and C4, and a melody in the top octaves.

## Drawbar (`mpfree-synth`, `Drawbar`)

Two organs and the rotating speaker they are played through. **Model** Tonewheel is the tonewheel organ, built from the measurements, papers and service documentation collected in [Tonewheel organs and rotary speakers](../research/tonewheel-organ.md); **Model** Combo is a 1960s transistor combo organ (19 Nov, the synth library's wave 2), on the divide-down bank Strings uses ([Organs, winds, choirs](../research/organ-wind-choir.md)). Velocity, pressure, bend and slides are ignored, as on both organs. The tonewheel's bullets come first, then the combo's.

- **Wheels.** 91 wheels turn all the time, each tuned as the organ's gears make it: 20 turns a second × one of twelve gear ratios × its teeth (2 to 128, then 192 for the top seven, which take the gears of the note a fourth up). **Wheels** Gears puts those small offsets from equal temperament (G# 0.71 cents flat, the top octave up to 1.9 cents sharp) on top of the project's tuning; Exact plays the tuning as it is. A key never starts an oscillator: it sets how much of each running wheel is heard, so no two notes start in phase, and a wheel two keys share (one key's 4', the next octave's 8') sums once instead of beating. The lowest octave of wheels is nearly square (1×, 3× and 5×), as cut on the organ.
- **Drawbars.** Nine, at -12, +7, 0, +12, +19, +24, +28, +31 and +36 semitones, each 0 to 8 at 3 dB a step, taking the nearest wheel (so the fifths are 2 cents flat of pure and the 1 3/5' about 14 cents sharp, as on the organ). The 16' folds back up an octave in the lowest manual octave (C2 to B2), and anything past the top wheel folds down an octave.
- **Click.** Each drawbar has its own key contact. Closing, each waits a random moment (up to 3 ms at **Click** 100) and then switches its running wheels in over 0.3 ms (at 100) to 6 ms (at 0), and at higher Click half of them bounce open for a moment. Letting go opens them the same way, half as spread and twice as slow. There is no added noise: the click is the sound of running sines switched abruptly.
- **Leakage.** Each wheel is heard in its compartment partner, 48 wheels (four octaves) away: off at 0, -40 dB at 40 (the default, setBfree's figure), -26 dB at 100.
- **Percussion.** A decaying second (**Perc harm** Second, the 4') or third (Third, the 2 2/3') harmonic, falling 60 dB in 1 s (**Perc decay** Fast) or 4 s (Slow), at a drawbar's full level (**Perc volume** Normal) or 6 dB under (Soft). It is single trigger: it fires only when a key goes down with no other key held, and re-arms when every key is up, but a chord struck together gets it on every note. It takes the 1' drawbar's contact, so the 1' is silent while percussion is on, and Normal lowers the drawbars by 3 dB.
- **Vibrato and chorus.** The scanner: a delay line read at the taps of the organ's 19-section ladder (44.7 µs a section), a scanner at **Scanner** Hz (6.9 by default) sweeping back and forth across the first 9, 13 or 19 taps for V1, V2 or V3 and crossfading between neighbouring taps as its plates do, then a 7 kHz low-pass. C1 to C3 are the same depths mixed with the dry sound (0.6 of each). V1 swings about ±4 to 14 cents and V3 about ±12 to 30 cents, depending on the note.
- **Drive and Tone.** Drive is the smooth curve u/√(1+u²) with a bias, so it adds even harmonics, followed by a 10 Hz DC blocker; it is scaled so a signal at 0.4 comes out at 0.4 whatever the drive, and at 0 it is nearly linear (more than 50 dB below the note). A sharp-cornered curve aliased audibly on full drawbars, so it was replaced. **Tone** is a tilt around 900 Hz, up to ±9 dB treble against ∓3 dB bass.
- **Rotary speaker.** A 4th-order (Linkwitz-Riley) split at 800 Hz. The horn and the drum are each a source turning on a circle (19.2 cm and 22 cm), heard by two microphones (**Spread** sets how far round the cabinet the second stands; 0 is mono) through a delay that follows the source's distance (the Doppler shift; Hermite reads for the horn, linear for the drum). Each rotor's level follows where it faces (35 % quieter facing away for the horn, 30 % for the drum), the horn's treble falls from 9 kHz facing the microphone to 3 kHz facing away, the horn gets one cabinet reflection (1.1 ms, 0.3) and leaks 15 % of its sound unmodulated. Speeds and inertia are setBfree's: horn 40.32 and 423.36 rpm, speeding up with a 0.161 s time constant and slowing with 0.321 s; drum 36 and 357.3 rpm, 4.127 s up and 1.371 s down. **Speed** Stop lets both coast to a standstill wherever they are. **Rotary** Off crossfades to the dry sound over 15 ms, in mono.
- **Notes.** Up to 64 keys down or letting go at once; past that a new key takes the place of the one let go longest. A key struck again while its contacts are still opening closes them from where they are. **Keys held** (read only) shows the keys down. `active_voices` counts the keys still sounding, then one while the speaker and filters ring out, so the host keeps the instrument running through the tail (`tail_frames` is 0.2 s).
- **Model.** Tonewheel or Combo. Switched while keys sound, the two cross over linearly in 30 control steps (10 ms at 48 kHz); while nothing sounds it jumps. Contacts, percussion, drive, tone, the speaker and the output are shared; Leakage and Wheels are the tonewheel's only, and Flute, Reed and Reed wave the combo's. The tonewheel's path is untouched: every tonewheel preset renders the same bits as before the combo came (checked on all 12, at three block cuttings and in 24-TET).
- **The combo's bank.** The Strings bank (`bank::Bank`, moved out of `strings.rs` for this, Strings still the same to the bit) with two buses, the flute and the reed. Each drawbar plays the note of its footage, a note of the scale and not a harmonic: the 2 2/3' of A4 is E6 at 1318.5 Hz, not 1320 (`drawbar::combo_note`). Above note 107 a footage breaks back an octave, as the top-octave dividers end there, and below 0 it folds up. In a tuning with pure octaves the octaves are locked (the lab's O6: 0 cents from exact); in any other each note is tuned itself. Only the notes some key uses are rendered.
- **Flute and reed.** The flute is the saw integrated twice, t(t−½)(1−t) scaled to a peak of 1: close to a sine, every harmonic at 1/k³ (the second 18 dB down, the third 29), then a 9 kHz low-pass that also keeps its top harmonics from folding back (−76 dB at C7). The reed is a band-limited saw (**Reed wave** Saw) or square (Square: odd harmonics, trimmed by 0.63 to sit level with the saw, its octaves locked as a flip-flop divider leaves them), thinned by a 200 Hz high-pass, given a +5 dB peak at 1.6 kHz (Q 0.9) and cut by a 6.5 kHz low-pass (Q 0.8). These are our readings of the Vox Continental's "sine-like" flute and "sawtooth-like" reed ([combo-organ.com](https://combo-organ.com/Vox/Single/index.htm); more in [Organ, wind and choir](../research/organ-wind-choir.md#1-what-makes-a-great-one)): we have no circuit values for its filters. All three shapes start in step with the saw, so a note's flute and reed add: with the cubic the other way round, both voices together lost 6 dB at C6.
- **Voices.** **Flute** and **Reed**, 0 to 8 at 3 dB a step as a drawbar is, each multiplying every drawbar; both at 0 is silence, as with both voice drawbars in on the original. A drawbar at 8 with a voice at 8 is 0.063 into the mix, so 888000000 with both voices sounds about as loud as the tonewheel's Init (−21.9 against −21.3 LUFS at C4).
- **Keyboard scaling.** The flute rises 0.1 dB a semitone below C4 and falls 0.1 dB a semitone above C5; the reed, thinned below and lifted by its peak above, is tilted 0.2 dB a semitone the other way; both are held below C1 and above C7. One note then sounds within 0.9 dB (flute), 1.6 dB (saw reed) and 2.2 dB (square reed) from C2 to C6 (LUFS, the lab's L11).
- **Combo percussion.** The same single-trigger percussion, through the flute at its own level whatever the Flute drawbar.
- **Combo vibrato.** A delay line read with a four-point Hermite, its delay swung by a sine from 2 frames to 2 + 2A, where A = (2^(c/1200) − 1) × rate / (2π f) frames bends the pitch c cents either way at f Hz: 10, 20 and 30 cents for V1 to V3 (our estimate: the originals' depth trims are not documented) at the rate the Scanner setting gives (shown as **Rate**). So the swing is the same on every note, where the scanner's depends on the note. C1 to C3 mix the dry sound back as the tonewheel's do (0.6 of each), though the originals had vibrato only. The centre follows the depth, so the chorus's comb starts as high as it can, and the line is fed only while the combo has a share.
- **Not built yet:** the Continental's bass section (its reversed-colour lowest octave), its second manual, and the other combos' tab sets and boosters.
- **Level.** One key at the defaults (Init, C4) peaks at -15.6 dBFS; one key on every tonewheel preset peaks between -19 and -11.7 dBFS, and a six-note chord between -9.7 and -1.8 dBFS. Each combo preset's held C4 is within 2.3 dB of Init's, its six-note chord between -8.5 and -2.2 dBFS and its eight-note chord at full velocity under -0.8 dBFS.
- **Presets** (drawbar settings as players write them, 16' first): Init (888000000), Jazz Perc (888000000, third percussion, C3), Gospel (888800000, Fast speaker, C3, some drive), Full Organ (888888888), Rock Drive (888600000, Drive 70), Ballad (008800000, V3), Flute (008000000, V1), Church (868868446, no speaker, C1), Reedy (008080800, odd harmonics), Bright Perc (800000888, second percussion), Hollow (808000000, speaker stopped, V2) and Soft Bass (850000000, an octave down, no speaker). On the combo, all but Combo Rotary without the speaker, each voice as Flute/Reed: Combo (608800000, 5/8, V1 at 6 Hz), Combo Flute (008600000, 8/0, V2), Combo Reed (808866660, 0/8), Combo Square (008860000, 4/8 square, V3 at 7 Hz), Combo Vibrato (008800000, 6/6, V3 at 5.5 Hz), Combo Garage (808855550, 3/8, V2, Drive 45), Combo Rotary (808400000, 7/5, C2, the speaker on Slow) and Combo Perc (008400000, 8/3, third percussion, V1).

Timing: wheels, the bank, the voices' filters, the scanner or the combo's vibrato, drive, tone and the speaker run every frame; contacts, percussion, the rotors' speeds, the model's crossover and retuning run at a control step of 16 frames aligned to the absolute frame, with each wheel's and bank note's level moving smoothly across the step, so any block size gives the same output to the bit (tested on both models and across switches). Nothing is allocated, even in `prepare`. **Cost:** a sounding wheel is a phasor turned by a fixed rotation each frame (four multiplies), started from the wheel's own phase when it comes in and pulled back to unit length once a step, about 10 instructions a wheel-frame; a silent wheel only counts its phase; a key whose contacts have all closed skips them; with no key and no tail the engine returns after its control step. That makes the cost depend on the wheels heard, not the keys: 134k instructions per 128-frame block for Init with 8 keys, 175k for Full Organ with 8, 169k for Gospel with 16 and 132k for Church with 8, and about 7k when silent (callgrind, x86; CI's instruction gate; 0.4 to 1.7 % over the counts before the combo came). As ARMv7 code (counted under qemu with `tools/inst_arm_cost.py`, before the combo) they are 143k, 184k, 178k and 134k. The combo costs the notes its bank plays: 154k for Combo with 8 keys (three footages, both voices, vibrato) and 182k for Combo Reed with 8 (seven footages); as ARMv7 code its bank renders four notes at a time on the NEON kernels ([NEON kernels](simd.md)), 138k and 151k against 194k and 207k with them off, the same samples; its device numbers wait on the device round. The speaker is about a third of it. With the MPC calibration file the bench estimates Init at 8 keys at 9.7 % of the synth budget's 20 % worst block and Full Organ at 14.9 % (Keys Init at 8 voices: 18.1 % in the same run).

**On the Synth tab** Drawbar has four pages: Drawbars (all nine, then a column with Model and the combo's Voices, Flute and Reed as drawbars with Reed wave over them; the Q-Links take the 4', 2 2/3', 2' and 1', since the 16', 5 1/3' and 8' usually stay out), Percussion (Percussion, Perc harm, Perc decay, Perc volume, Vibrato, Scanner shown as Rate), Rotary (Rotary, Speed, Spread with Click, Leakage, Drive, Tone and Wheels in a section called Tone; the Q-Links take Drive, Tone, Click and Spread) and Voice. On the tonewheel the Voices are faint ("combo only"); on the combo Leakage and Wheels are ("tonewheel only"). Its Q-Link sets are Low bars, High bars, Tone (Drive, Tone, Click, Leakage), Play (Scanner, Spread, Fine, Level) and Combo (Flute, Reed, 8', 4'). Its visual strip has four cards. **Drawbars**: the nine as bars, amber below the note (16', 5 1/3'), white the note and its octaves, grey the other harmonics, as an organ's drawbars are brown, white and black; the caption is the registration. **Wave**: one cycle of the 16', the drawbars' sines at their levels (`drawbar::bar_level`), the 1' left out while percussion is on; on the combo, each drawbar's flute and reed at their levels, before the voicing, the 16''s octaves half a cycle on as its dividers leave them (`drawbar::combo_wave`). **Percussion**: its level against a drawbar at 8 over 4.5 s, so Fast and Slow compare on one scale (`drawbar::perc_level`). **Rotor**: the horn's and the drum's speeds over 10 s after Speed is switched to where it is now, from Slow to Fast or from Fast to Slow or Stop (`drawbar::rotor_ramp`, with the engine's speeds and time constants). The preview draws `synth-drawbar`, `synth-drawbar-rotary` and `synth-drawbar-combo` (Combo Square).

## Squelch (`mpfree-synth`, `Squelch`)

A mono acid bass: one oscillator into a resonant four-pole diode ladder, with a decaying filter envelope, accent and slide, built from the circuit analyses collected in [Acid bass](../research/acid-bass.md). Pressure and per-note expression are ignored.

- **Oscillator.** A sawtooth with a polyBLEP at its reset. **Wave** Square is not a second oscillator but the saw through a limited-gain shaper, as on the original: `tanh` of six times the saw, with its threshold a little off centre, so the reset edge stays sharp, the middle transition is an S-curve, the two halves differ and some even harmonics come through. A change of Wave crossfades over about 10 ms.
- **Filter.** The diode ladder's nodal model: four capacitor voltages, the input pair's current driving the first (its capacitor half the others'), a diode pair between each pair of neighbours and one from the last to a fixed point, every pair's current through `tanh` of the voltage across it. Its linear part is Stinchcombe's transfer function to the third decimal (tested within 0.5 dB). It is solved each sample with zero-delay feedback: each pair's `tanh(d)/d` (a Padé form, `1/|d|` past ±3) is taken from the previous frame, which leaves one linear system, solved by elimination from the top with every division done once a frame. The frequency is prewarped so the ladder's resonance lands on **Cutoff** (30 Hz to 5 kHz; the original tops out near 2.5 kHz).
- **Resonance.** The output fed back to the input, k from 0 to 18.5. The bare ladder oscillates past 17 (tested: it grows at 17.6 and dies at 16, at the cutoff within 6 %); with a note through it the input pair's compression keeps it at the edge, so at 100 the harmonic nearest a mid or high cutoff rings out (more than 25 dB up at 1.2 kHz) rather than a free whistle. The feedback goes through a 120 Hz one-pole high-pass (our reading of the measured loop high-pass), so low cutoffs ring far less (under 8 dB at 80 Hz). Resonance thins the bass, as on the original; half of that loss (√(1+k)) is made up in the amplifier.
- **Envelopes.** The filter's envelope jumps to full at each new note and falls exponentially to a tenth over **Decay** (200 ms to 2 s), or over **Acc decay** (200 ms by default) on accented notes. **Env mod** sweeps up to 4 octaves above the base and lowers the base by a quarter of the sweep, as turning it up does on the original. **Key track** moves the cutoff with the note around C3 (0 by default; the original doesn't track). The volume envelope rises in 3 ms from wherever it is, falls to -60 dB over **Amp decay** (3.5 s by default) while the key is held, and closes in 8 ms when it is let go.
- **Accent.** A note at or above **Accent at** (velocity 100 by default) is accented. Its filter envelope goes into the amplifier through a 1.55 ms lag (up to 1.5 times more level at **Accent** 100), and into the cutoff two ways mixed by Resonance, as the original's dual pot does: directly (a sharp rise and fall, up to 2 octaves) and through a capacitor charged through a diode with a 147 ms time constant (a smooth swell, weighted twice). The capacitor empties with a 200 ms time constant (our reading), so accents close together build on each other, more with more resonance (tested: of four accents 125 ms apart, the fourth's cutoff peaks at least 15 % higher than the first's at Resonance 100, and within 5 % of it at 0).
- **Slide.** A note played while another is held glides there over **Slide** (10 to 500 ms, 60 ms by default; an exponential glide of three time constants, as the original's RC) without starting the envelopes, and keeps the accent of the note it slid from. Letting go of it glides back to the key still held; letting go of the last closes the gate. Up to 16 held keys are remembered.
- **After the filter.** The amplifier, then a 47 Hz one-pole high-pass (the original's weak low end: -5 dB at 32 Hz), then **Drive**: the smooth curve u/√(1+u²) with an off-centre rest point, so it adds even harmonics, scaled so the level stays near the clean one (tested: harmonics 6 to 25 more than 6 dB up, the peak within 6 dB), then a 10 Hz DC blocker. **Level** and **Pan** at the end.
- **Oversampling.** Below 64 kHz the oscillator, filter, amplifier and drive run at twice the rate and come down through a polyphase IIR half-band (six all-pass sections, mpfree-fx's design: flat to 0.4 of the rate, -80 dB from 0.6). Without it, Distorted on C6 had its loudest alias at -24.8 dB, and with it -32.6 dB; Screamer on C7, -32.4 and -43.2 dB.
- **Level.** One unaccented note on C2 peaks between -16.8 and -11.9 dBFS on every preset, an accented one between -15.6 and -6.3 dBFS, and an accented line stays under -1 dBFS.
- **Presets:** Init, Acid Line (the classic squelch: Resonance 85, a fair sweep, short decay), Deep Bass (low and round), Square Acid (the square through a nearly closed, very resonant filter), Distorted (Drive 70), Rubber (long decay and 140 ms slides), Plucky (Amp decay 400 ms), Acid Lead (Key track 70, an octave up, some drive) and Screamer (Resonance 100, Accent 100).

Timing: the oscillator, ladder, amplifier, drive and half-band run every sample; pitch, bend, slide, the envelopes, the accent's capacitor and the cutoff run at a control step of 16 frames aligned to the absolute frame, with the pitch, the ladder's frequency and the level moving linearly across the step, so any block size gives the same output to the bit. Nothing is allocated, even in `prepare`. With no key and no tail it returns after its control step, and once the tails fall under 10⁻⁶ the states are set to exact zero. **Cost:** 59k instructions per 128-frame block for Acid Line playing a sixteenth-note line with accents and slides, 64k for Square Acid and 62k for Distorted (callgrind, x86; CI's instruction gate); as ARMv7 code (counted under qemu with `tools/inst_arm_cost.py`) 61k, 66k and 63k. That is under half of Drawbar Init with 8 keys (134k) or Keys Init with 8 voices (117k). With the MPC calibration file the bench estimates each at 9.1 % of the synth budget's 20 % worst block (the same in four runs), and about 3 % of a period on average.

**On the Synth tab** Squelch has three pages: Synth (Wave, Cutoff, Resonance, Env mod, Decay, Accent; the Q-Links take Cutoff, Resonance, Env mod and Decay), Play (Slide, Accent at, Acc decay, Amp decay, Key track, Drive; the Q-Links take Slide, Acc decay, Amp decay and Drive) and Voice (with Level and Pan). Its Q-Link sets are Filter (Cutoff, Resonance, Env mod, Decay), Accent (Accent, Acc decay, Slide, Amp decay) and Tone (Drive, Key track, Fine, Level). Its visual strip has three cards. **Wave**: two cycles of the saw, or of the square the engine's shaper makes from it (`squelch::square_of`). **Filter**: the ladder's response (`squelch::response`: Stinchcombe's transfer function with the feedback through the loop's high-pass) where the filter rests between notes, with a dot there, and dashed where a plain note's envelope takes it. The loop's high-pass is why the peak is small at low cutoffs, as on the original. **Sweep**: the cutoff over four sixteenths at 120 BPM, played plain and played accented, in octaves above where it rests (`squelch::cutoff_sweep`, which steps the envelope and the accent's sweep capacitor as the engine does), so the accents' build-up shows. The preview draws `synth-squelch` and `synth-squelch-play`.

`cargo run --release -p mpfree-synth --example squelch_demo [out.wav]` writes `~/mpfree-work/squelch-demo.wav` (39 s): every preset in turn, 4.24 s each, playing two bars of the same sixteen-step line at 125 BPM, with accents (velocity 127) and slides, gates 3.5/6 of a step as on the original's sequencer; in the second bar the cutoff sweeps up two octaves and back. It prints the timeline and each preset's peak.

## Analog (`mpfree-synth`, `Analog`)

A vintage analog poly: a card per voice, each with two oscillators, a resonant filter, two envelopes and an amplifier, notes handed to the cards in turn, with poly-mod and a bucket-brigade chorus. It is built from the datasheets, papers and makers' notes collected in [Vintage analog polysynths](../research/vintage-poly.md). [Poly](#poly-mpfree-synth) already does clean subtractive synthesis; Analog is about what makes the old instruments sound old. Pressure and per-note expression are ignored.

- **Voice cards** (the voice core's `character.rs` since 19 Nov, shared with Poly's Age; Analog renders the same to the bit). Sixteen cards, each given fixed unit-normal offsets when the engine is made (a seeded generator, clamped to ±2.5, so every instance and every run is the same): both oscillators' tuning, the cutoff, the envelopes' times, the pulse width and the level. **Age** scales them; at 100 their standard deviations are 4 cents, 0.084 octave (about 6 %) of cutoff, 8 % of each time, 2.5 % of pulse width and 0.5 dB (our reading of a maker's "+/- 5-10 cents variation per voice"). Age also scales drift: each oscillator follows its own Ornstein-Uhlenbeck walk, 2 cents rms at Age 100 with a 5 s time constant, stepped each control step (tested: over 5 s a held note wanders between 0.5 and 20 cents, never more than 1.5 cents in 100 ms; at Age 0 under 0.01).
- **Taking turns.** A note goes to the next free card after the one used last, so a repeated chord lands on other cards (tested: four notes in a row take cards 0 to 3). A note still sounding keeps its card; with none free the card let go longest ago is taken, then the oldest held. **Voices** limits the cards in use (8 by default). **Unison** starts every card in use on one note, spread evenly across ±25 cents at **Detune** 100; letting go of the note goes back to a key still held (up to 16 are remembered). **Glide** moves each card from the last note it played (three time constants over the time; tested: a third of the way in, it is 1 − e⁻¹ of the way there), so in Poly chords smear into each other as on the old instruments.
- **Oscillators.** Two per card, each **Saw**, **Pulse**, **Saw+Pulse** (0.6 of each) or **Triangle**, band-limited with polyBLEP steps placed a sample late: each step's correction is split between the sample before it, held back and not yet heard, and the sample after, so a step anywhere in a sample (a wrap, a pulse edge, a sync reset) gets both halves. **Sync** restarts oscillator 1 at oscillator 2's wrap, with the jump's own step. A square **Sub** an octave under oscillator 1 and white **Noise** complete the mixer, whose sum past one full source is brought down by its power (two full oscillators are 3 dB up, not 6). The oscillators run on while a card is silent, so each note starts at another phase.
- **Poly-mod.** Each card's filter envelope (**PMod env**, ±100: 4 octaves of pitch, 45 % of pulse width or 4 octaves of cutoff) and its oscillator 2 at audio rate (**PMod osc 2**: 2 octaves of pitch, 45 % of pulse width or 3 octaves of cutoff) go to oscillator 1's pitch, its pulse width and the cutoff, as the three **PMod >** switches choose, as on the Prophet-5's Poly-Mod (tested: on a triangle, PMod osc 2 at 60 puts more than 30 % of the rms off the note's harmonics, against under 5 % at 0). The global **LFO** (Sine, Triangle, Saw, Square or S&H, 0.05 to 30 Hz) goes to the pitch (**Vibrato**, up to 100 cents), both pulse widths (45 % each way) and the cutoff (2 octaves each way), faded in over **LFO delay** after a note played with no other key held.
- **LP 24.** Four OTA stages, each `dv/dt = ω·tanh(x − v)` (the input pair saturates, unlike the transistor ladder's `tanh(x) − tanh(v)`), the output fed back with k up to 4.1 at **Resonance** 100. It is solved each sample with zero-delay feedback: each stage's `tanh(d)/d` (a Padé form, `1/|d|` past ±3) from the previous frame makes it a one-pole of share `G/(1+G)`, one division a stage, and the feedback is solved from the output written as `A·u + B` (one more). Four equal stages oscillate at k = 4; k 4.1 is past that, so with no input it whistles near the cutoff (tested: from a burst of noise at Resonance 100 and a 1 kHz cutoff, the strongest tone is within 100 cents of 1 kHz and 30 dB over its neighbours; 4.2 pulled it down to 919 Hz). The passband falls to 1/(1+k) as on the original; half of that in dB, √(1+k), is made up in the amplifier (tested: Resonance 100 loses 4 to 10 dB at 80 Hz). The slope is tested between 18 and 32 dB an octave.
- **LP 12, BP 12, HP 12.** A trapezoidal state-variable filter, damping from 2 at Resonance 0 to 0.06 at 100. Its damping grows with the square of the band-pass's level the frame before, so a loud resonance squashes rather than running away (our reading of an OTA filter's limits; with the integrators' inputs through `tanh` instead it went unstable). The band-pass keeps half its resonant peak in dB. Tested against the saw's own 1/n slope: the low-pass's slope between 8 and 16 dB an octave, the high-pass flat above the cutoff and 20 dB down below it, the band-pass 10 dB over both sides.
- **Cutoff.** **Cutoff** (20 Hz to 18 kHz), the filter envelope (**Env amount** ±100: 5 octaves either way, scaled down for soft notes by **Vel > filter**), **Key track** (at 100 an octave per octave around middle C), poly-mod, the LFO and the card's offset add in octaves, clamped to 16 Hz to 0.45 of the rate (at most 20 kHz) and prewarped. **Drive** raises the input up to 3 octaves into the stages and scales the output back by the same.
- **Envelopes.** The CEM3310's curve: the attack charges toward 1.3 times the peak and stops at it (the datasheet's 6.5 V asymptote and 5 V peak), so it is an RC curve cut before it flattens (tested: 0.675 of the peak halfway, within 0.06); decay and release fall exponentially to 1 % over their time, from 1 ms to 20 s. A new note starts the attack from where the envelope is. **Vel > amp** scales the level by velocity (50 by default).
- **Chorus.** A bucket-brigade delay modelled by its clock: a triangle sweeps the clock, so the delay, stages over twice the clock, sweeps as its reciprocal, `mid / (1 + swing·tri)`, between the mode's ends. **Slow** 0.51 Hz and **Fast** 0.83 Hz sweep 1.4 to 5.6 ms; **Vibe** 9.75 Hz sweeps 3.2 to 3.8 ms (the Juno-60's modes as the community measured them, and Juno-XD's depths). Left and right are swept in antiphase from one delay line, with a 9 kHz two-pole low-pass before it and a 7.5 kHz one after each side, a hiss at 0.15 % of the signal's own level (followed over 50 ms) and the wet 1.62 dB under the dry; the whole is trimmed so switching it on is not much louder (tested: within 3 dB of the dry rms on every mode, and the difference of the sides over 5 % of the level). A change of mode moves the rate and depth over 50 ms.
- **After the cards.** A 10 Hz DC blocker, the chorus, then **Level** and **Pan**.
- **Level.** One note at velocity 100 peaks between -17.1 and -10.0 dBFS on every preset (tested: -22 to -6), and an 8-note chord stays under 0 dBFS (worst -0.3 dB, Poly Brass).
- **Presets:** Init (one saw through the four-pole), Poly Brass (two detuned saws through LP 12 with a quick filter swell), Warm Pad (slow saws and the Slow chorus), Sync Lead (oscillator 1 synced and swept by PMod env, Unison on 2 cards, delayed vibrato and glide), Chorus Strings (Saw+Pulse with the LFO on the width, Fast chorus), Square Keys (a pulse and the sub, plucked), Clang Bell (PMod osc 2 with oscillator 2 an octave and a fifth up), Unison Bass (4 cards), Slow Sweep (the LFO on a resonant cutoff), Hollow Pulse (BP 12 and Vibe) and Worn Cards (Age 100).

Timing: the oscillators, the filter and the amplifier run every sample at the host's rate (no oversampling: the oscillators are band-limited and the filter's nonlinearity is mild); pitch, the envelopes, the LFO, drift and the cutoff run at a control step of 16 frames aligned to the absolute frame, with pitch, pulse width, cutoff and level moving linearly across the step, so any block size gives the same output to the bit (tested on four setups). Nothing is allocated after `new`. Once every card has stopped it lets the chorus and DC blocker ring for 20 ms, then clears them and returns at once until the next note (tested: exact silence after the release, chorus on or off). **Cost:** 265k instructions per 128-frame block for Init with 8-voice chords, 321k for Warm Pad (the chorus adds about 55k), 203k for Poly Brass (the two-pole is cheaper than the four-pole's five divisions a sample) and 466k for Worn Cards on 16 voices (callgrind, x86; CI's instruction gate). Poly Init with 8 voices is 192k. On this build host Analog Init's mean time per block was 6 to 17 % over Poly Init's; the bench's MPC estimates were too noisy here to quote (Poly Init itself read from 27 to 30 % of the synth budget between runs), so Analog needs its own run on the device before its voice count is settled.

**As ARMv7 code** (the MPC's, counted under qemu with `tools/inst_arm_cost.py`): Init 278k, Warm Pad 340k, Poly Brass 238k and Worn Cards 476k, against 195k for Poly Init with 8 voices. That is 1.43, 1.75, 1.22 and 2.45 times Poly Init. Almost all of it is the engine's own code: the only library call that shows is `tanf` for the filter's coefficient, once a control step per voice (about 7k a block), so there is no cheap ARM-only gain like the effects' `rem_euclid` and `floor`. An estimate, until the device measures it: round 7 measured an 8-voice Poly at 7 to 8 % of a period on average and 17 to 18 % on its 99th-percentile block, and Poly Init has run 30 % fewer ARMv7 instructions since. If the cycles follow the instructions, Analog Init with 8 voices comes to about 8 % on average and 18 % at p99, inside the synth's 20 %; Warm Pad's chorus takes it to about 22 % at p99, and 16 voices (Worn Cards) to about 30 %. So 8 voices is about as many as the default can hold, and 16 is for the device to confirm.

**On the Synth tab** Analog has five pages: Osc (both oscillators, Sync and the mix; the Q-Links take Osc 1 PW, Osc 2 PW, Osc 2 fine and Osc 2), Filter (the Q-Links take Cutoff, Resonance, Env amount and Drive), Envelopes (F attack, F decay, A attack, A release), Mod (LFO rate, Vibrato, PMod env, PMod osc 2) and Voice (with Output; Age, Glide, Detune, Level). Its Q-Link sets are Filter (Cutoff, Resonance, Env amount, Drive), Env (F attack, F decay, A attack, A release), Mod (LFO rate, Vibrato, PMod env, PMod osc 2) and Voice (Age, Osc 2 fine, Detune, Level). Its visual strip has five cards. **Osc**: two cycles of oscillator 2, and oscillator 1 against it at its interval, restarting with each of oscillator 2's cycles when synced. **Filter**: the response at Cutoff (`analog::filter_gain`: the four-pole's with the feedback at Resonance, or the two-pole's with its damping), with a dot there, and dashed where the filter envelope's peak takes it. **Env**: the amp and filter envelopes with the CEM3310's attack (`analog::attack_shape`), on a square-root time scale as Poly's. **LFO**: two cycles, faded in over its delay. **Voices**: each card's fixed detune for both oscillators at the Age set (`analog::card_cents`, from the same seeded draw the engine makes its offsets with). The preview draws `synth-analog-filter` and `synth-analog-voice`.

`cargo run --release -p mpfree-synth --example analog_demo [out.wav]` writes `~/mpfree-work/analog-demo.wav` (61 s): every preset in turn, 5.4 s each, over Am7, Fmaj7, C and G: held chords for the pads and keys, stabs for Poly Brass, a legato line for Sync Lead, eighths for Unison Bass, an arpeggio for Clang Bell, and one chord four times for Worn Cards, so each lands on other cards. It prints the timeline and each preset's peak.

## Strings (`mpfree-synth`, `Strings`)

A string machine, after the divide-down string ensembles of the 1970s: every key can sound, through registers of fixed filters, a swell, and the Ensemble. Built from [String machines](../research/string-machine.md) for the synth library's wave 1 ([architecture](synth-architecture.md), targets S1 to S9 in [synth quality](synth-quality.md#wave-1-targets-bass-keys-and-strings-stage-4)). Pressure and per-note expression are ignored.

- **The bank.** It lives in `bank.rs` (`bank::Bank`), shared with Drawbar's combo since 19 Nov, which also plays it as a square and as the cubic near sine (`bank::Shape`); Strings plays only the saw, through a path that makes one wave a note. One sawtooth for every note, 0 to 127, band-limited with a four-point B-spline step correction (`dsp::poly_blep4`; Välimäki, Pekonen and Nam 2012), whose worst alias at C7 is 16 dB under plain polyBLEP's. In a tuning whose octaves are pure (12-TET and every 12-note table) each note's phase is exactly twice the phase of the note an octave below plus half a cycle, as when the top octave is divided down: the octaves are locked, so an 8' and a 4' make one steady wave and two keys an octave apart never beat (tested: under 0.2 dB of movement), and the half cycle keeps their steps apart, so a chord's peaks stay low. Any other tuning (24-TET, a file) tunes each note itself. Phases follow from the absolute frame, so a note silent for a while comes back where it would have been. Only the notes some key is using are rendered: the bank costs what the keys use, not 128 oscillators.
- **Keys.** A key never starts an oscillator: it sets how much of the notes at 16', 8' and 4' (an octave down, its note, an octave up) reach the footage buses. Two keys that share a note (one key's 4', the next octave's 8') add on one oscillator. A footage above B7 folds back an octave, 6 dB down (it lands in phase on a note the 8' often plays). Each footage bus has a dark and a bright half: a key's velocity shares its level between them, and the dark half's low-passes sit an octave lower, so a soft key is darker as well as quieter (**Velocity**, 0 to 40 dB, 25 by default; 0 ignores velocity, as the old machines did). **Keyboard level scaling** keeps single notes within 3 dB of each other from C2 to C6 (L11): up 2.5 dB an octave below C3 and 1.5 dB from C3 to C5, against what the registers' filters and the ear take from low notes, and down 2 dB an octave above F#5.
- **Registers.** Violin, Viola, Cello, Contrabass, Horn and Trumpet, each a mix of the three footages through its own fixed filter (a high-pass, a body peak and a low-pass) and mixed at any level, together at constant power so a mix of several is about as loud as one. The filters run on the six buses, so their cost does not grow with keys. **Brightness** moves every low-pass an octave either way (never above 10 kHz, which keeps a C7's aliases 65 dB down); **Body** scales the peaks. Both glide, at most a twelfth of an octave a control step. The voicings are our reading of how these registers sound, not measured from one machine.
- **Swell.** **Crescendo** (silence to full, 2 ms to 8 s) and **Sustain** (60 dB down, 20 ms to 12 s) on the voice core's envelope (`voice::Adsr`), **Per key** or **Shared**: shared, one swell for every key, as on the paraphonic machines; a chord swells in together and the last chord fades, while a key let go with others still held stops in 30 ms. Within 2.4 % of their labels both ways (S7).
- **Bow noise**, band-passed at 3.2 kHz, follows how loud the keys are.
- **The Ensemble** (`mpfree_fx::Ensemble`, [fx-modulation.md](fx-modulation.md#ensemble)) on the output through its mono path; **Ensemble** is its mix (100 % by default, wet only, as on the machines, so the first sound comes about 6 ms after the key), with Lines, both rates, Depth (both sweeps against the ensemble's own 12 and 5 cents) and Width.
- **Playing it.** Sustain and sostenuto are heard here (`Node::hears`, `pedal::Pedals`). The soft pedal lowers the level 6 dB and darkens half an octave; the mod wheel adds up to 8 cents to the fast sweep (vibrato); breath or foot sets the volume (a square law). Bend moves the whole bank. **Octave** (±2) and **Transpose** move the keys; the bank does not move.
- **Level.** One key at velocity 100 peaks between -20.6 and -15.3 dBFS on every preset, and an 8-note chord at full velocity stays under -3 dBFS (Bowed, the loudest). A 6-note chord is within -0.6 to +1.6 dB of its notes' power sum (S9).
- **Presets** (26): Init (Violin and Viola), Classic Strings, Bright Strings, Cello and Viola, Full Ensemble, Orchestra, Brass Ensemble, Slow Swell, Staccato Strings, Swirl Strings, Dark Strings, High Strings, Low Strings, Paraphonic 70s, Disco Strings, Ballad Pad, Lo-fi Strings, Wide Strings, Mono Ensemble, Dry Divider, Bowed, Horn Section, Brassy Lead and Vox Strings; and two sounds with effects and macros of their own: Hall Strings (a large room) and Space Strings (a worn tape echo and a long plate).

Timing: the bank, the registers' filters and the noise run every sample; the swells, the keys' levels on the bank, bend and the filters' settings run at a control step of 16 frames aligned to the absolute frame, each note's level ramping across the step, so any block size gives the same output to the bit (tested at three cuttings). A tenth of a second after the last note is gone the bank and the ensemble stop running, so a Strings track at rest costs next to nothing and its output is exact silence. Nothing allocates in `process`. Load shedding offers no voice: a key shares its notes with the keys an octave away, and the Ensemble costs the same either way.

**Cost** (callgrind, x86, 128-frame blocks; CI's instruction gate): `Strings Init` 154k instructions a block with 1 key, 222k with 6 and 388k with 49; `Strings Orchestra` (five registers) 284k with 6 (within 0.8 % of the counts before the bank moved to `bank.rs`). The cost is not flat in the keys held as on the hardware (S5): the bank renders the notes heard, so one key is mostly the Ensemble (138k on its own as an effect) and 49 keys about 2.5 times one key. A flat bank, all 128 notes always, would cost more than the 49-key case at every key count, so the worst case, every key held, is what the budget has to hold. On the MPC the bank renders four notes at a time on `mpfree-simd`'s NEON kernels ([NEON kernels](simd.md#the-third-and-fourth-kernels-the-divide-down-bank-four-notes-at-a-time)), with the same samples: as ARMv7 code under qemu, Strings Init takes 162k instructions a block with 6 keys against 186k with the kernels off, and 248k with 49 against 327k; one key is unchanged at 131k. Its device numbers wait on the device round.

**On the Synth tab** Strings has four pages: Registers (the six registers as faders and Octave; the Q-Links take Violin, Viola, Cello and Contrabass), Tone (Brightness, Body and Bow noise; Crescendo, Sustain, the swell's Envelope and Velocity; the Q-Links take Brightness, Crescendo, Sustain and Bow noise), Ensemble (Amount, Lines, Width; Slow rate, Fast rate, Depth; the Q-Links take Amount, Depth, Slow rate and Width) and Voice (Transpose, Fine, Bend range, Level and the Keys held meter). Its Q-Link sets are Registers (Violin, Viola, Cello, Horn), Swell (Brightness, Crescendo, Sustain, Bow noise) and Ensemble (Amount, Depth, Slow rate, Width). Its visual strip has three cards. **Tone**: the registers' mix as heard (`strings::tone_response`: each register's filters at its level, Brightness and Body), captioned with the registers up. **Swell**: a held key's level on a 60 dB scale (`strings::swell_curve`, the engine's own envelope), let go after its crescendo, so the fade meets the bottom at Sustain. **Ensemble**: each line's delay over one slow cycle with the fast sweep on it (`strings::ensemble_lines`, from the Ensemble's own `delay_ms`). The ensemble's controls dim with "ensemble is off" at Amount 0.

## Bass (`mpfree-synth`, `Bass`)

A one-voice bass for synth basses, 808s and reeses, built from [Bass](../research/bass.md) for the synth library's wave 1 ([architecture](synth-architecture.md), targets B1 to B11 in [Synth quality](synth-quality.md#wave-1-targets-bass-keys-and-strings-stage-4)) on the shared voice core (`voice::NoteStack`, `Glide`, `Adsr`, `velocity_gain`). Code: `bass.rs`, `bass_params.rs`, `tests/bass.rs` (16 tests).

- **Bodies.** **Synth**: the oscillator (Saw, Pulse, Triangle or Sine) with its sub, fifth and noise into the ladder. **808**: a sine (or a triangle) with no filter, shaped by its pitch drop, the drive and Tone. **Reese**: two copies of the oscillator, one **Detune** cents up and one down (0 to 100, 27 by default), each at 0.7, through a two-pole high-pass at twice the note (20 to 400 Hz) so their beating never empties the low end, over the sub (a clean sine in its presets), into the ladder.
- **Locked oscillators.** One 32-bit phase counter turns once every four cycles of the note. The oscillator reads four times its phase, the fifth six times (exactly 3:2) and the sub a table per main cycle (a square one or two octaves down, a pulse a quarter wide two down with no DC) or a sine one octave down or on the note, so the sub and fifth stay in phase with the oscillator as a divider's do. Steps are band-limited with polyBLEP; a sub's steps fall on the oscillator's wraps and take the same correction at their own height. **Start**: a note out of silence starts every oscillator at 0° (the default: the sine and the triangle rising from zero), at 180°, or where it was (**Free**); a note over one still ringing never jumps (B4: the largest step in the first four frames is -75 dBFS at worst, on 808 Kick Bass).
- **Pitch.** **Punch** shifts the note up to an octave for its first 6 ms (a quadratic fall); **Drop** (0 to 24 semitones) starts the note that far up and lands exactly on it at **Drop time** (5 ms to 1 s) on a cubic fall, so it is in tune from then on (B3: 12 semitones over 200 ms on C4 is 1.9 % from its amount, on time, and settles to 0.0005 cents). A legato note takes no new drop unless **Retrigger** is on. Glide by **Time** (the voice core's) or by **Rate** (Glide is then how long an octave takes; V7: an octave in 300 ms takes 0.3 % less and lands within 0.002 cents), on **Legato** notes or **Always** (from the last note, held or not). **Priority** Last, Low or High. Bend, and vibrato from the mod wheel or pressure (up to 50 cents at 5.5 Hz).
- **The ladder** (Synth and Reese): Analog's OTA-style four-stage ladder, each stage `tanh` of its input less its state with `tanh(d)/d` taken from the previous sample, solved with zero-delay feedback; k up to 4.1, so it whistles at Resonance 100; half the passband's loss to resonance made up. `bass::ladder_response` is its small-signal curve, for the picture and the tests. **Filter drive** (0 to 100) sets how hard the oscillators push it (0.35 to 4 times), with the output scaled back: grit, not volume. The cutoff (20 Hz to 12 kHz) follows its envelope (an attack-free decay over **Filter decay**; 4 octaves at **Env amount** ±100), **Key track** around C3, and pressure (up to 3 octaves).
- **Amplifier.** The voice core's ADSR (times that mean what they say) and velocity curve (**Velocity**, 0 to 40 dB, 12 by default). **Vel > tone** darkens a soft note: at 100 the softest note's cutoff and Tone are two octaves down.
- **After the amplifier.** **Drive** (0 to 100, up to 30 dB into the curve): **Soft**, the smooth curve u/√(1+u²) with an off-centre rest point (0.3), so it adds the second and third harmonics that let a bass be heard on small speakers; **Hard**, a Padé `tanh`, even, towards a square. Both are scaled so a full oscillator's peak stays where it was (`bass::drive_gains`). Then **Tone**, a two-pole low-pass (200 Hz to 16 kHz), and **High-pass**, two poles at the output rate (10 to 500 Hz, 15 Hz by default), which also takes the drive's DC.
- **Level across the keys.** The ear, and loudness meters, take less from low notes, so under C3 the level rises 2 dB an octave (3.5 for the 808's sine), after the drive so it doesn't change the tone; each body has its own trim (Synth 0, 808 -5, Reese +1.5 dB), so the presets sit near the same loudness. L11 (C0 to C3, under 3 dB) is met on all 34 presets (0.6 to 2.9 dB).
- **Oversampling.** Below 64 kHz the oscillators, ladder, drive and Tone run at twice the rate and come down through Squelch's polyphase IIR half-band. The worst alias of the plain saw and pulse at C7 is -80.4 dB; at Drive 100, -63.7 dB at C5 (B10 met), -58.8 at C6 and -54.0 at C7.
- **Level.** One note at full velocity peaks between -16.2 and -2.5 dBFS (Low Note Lines, whose notes sit where the level rises); Init at velocity 100 peaks near -12 dBFS.
- **Playing it.** One note at a time. Pad pressure moves the cutoff, the drive or a vibrato, as **Press to** picks, by **Pressure**; it reads the pad's pressure directly, not through the shared shaper (Pad pressure, below), which it may take later. The sustain pedal is the host's fallback (`pedal`); the mod wheel adds vibrato.
- **Presets** (34): Init, Round Mono, Pluck Bass, Resonant Sweep, Square Sub, Rubber Bass, Funk Bass, Synth Pop, Power Bass, Fat Saw, Thin Pulse, Soft Triangle, Noisy Bass, Glide Bass, Low Note Lines, Growl Press, Press Wah (the synth body); Sub Sine, Sub Triangle, 808, Long 808, Distorted 808, 808 Slide, 808 Kick Bass, Short 808, 808 Vibrato (the 808 and the plain subs); Reese, Dark Reese, Wide Detune, Soft Reese, Growl Reese, Reese Sweep; and two sounds with effects and macros of their own: Amp Bass (a crunchy amp into a bass cabinet) and Tube 808 (a tube drive).

Timing: the oscillators, ladder, drive, Tone, half-band and high-pass run every sample; glide, the envelopes, pitch, the cutoff and the levels run at a control step of 16 frames aligned to the absolute frame, the pitch, cutoff, level and drive moving linearly across the step, so any block size gives the same output to the bit (tested). A tenth of a second after the release ends nothing runs until the next note. Nothing allocates (tested). Its tuning: 0.004 cents worst on the plain patch (T1), 0.07 cents from C0 to C3 on the synth body and 0.05 on the 808 (B1). B7 (the low end mono) is met on every preset; B5 (100 to 400 Hz at least -12 dB against below 100 Hz) on 22 of 34: not on the plain subs, the clean 808s, Soft Triangle and Soft Reese, which are meant to be pure low end, nor on Distorted 808 (-16.7 dB) or Tube 808 (-25.5 dB). L5 (tone against velocity) is met on 24 of 34, not on the same plain sounds.

**Cost** (callgrind, x86, 128-frame blocks; CI's instruction gate), playing Squelch's sixteenth-note line: `Bass Init` 93k instructions a block, `Bass Reese` 128k (its pair and their high-pass), `Bass Distorted 808` 65k (no ladder). For comparison Squelch Acid Line is 59k. The MPC's numbers come with the device round (B11).

**On the Synth tab** Bass has five pages: Source (Body, Wave, Pulse width, Reese detune; Sub, Sub mode, Fifth and Noise as faders; Octave and Start; the Q-Links take Sub, Fifth, Reese detune and Pulse width), Filter (Cutoff and Resonance, the filter envelope's Amount and Decay, Key track and Drive in; Cutoff, Resonance, Env amount, Filter decay), Shape (Drop, Drop time and Punch; the amp's ADSR as faders with Velocity to level and Velocity to tone; Drop, Drop time, Decay, Release), Play (Glide, its Mode and When; Priority and Retrigger; Transpose, Fine, Bend range; pressure's Moves and Amount; Glide, Fine, Bend range, Pressure) and Output (Drive and its Mode; Tone, High-pass, Level; Drive, Tone, High-pass, Level). Controls that do nothing are drawn faint with the reason: the filter's on the 808 ("not on the 808"), Reese detune off the reese, Pulse width off the pulse, Sub mode with no sub, Drop time with no drop, the glide's Mode and When with no glide, Drive mode with no drive, the pressure's Amount with it off, Decay at full sustain. Its Q-Link sets are Synth (Cutoff, Env amount, Drive, Glide), 808 (Drop, Decay, Drive, Tone) and Reese (Detune, Cutoff, Resonance, Sub). Its visual strip has four cards. **Wave**: one cycle of the sub (four of the oscillator) with the sub and fifth on it (`bass::wave_shape`). **Filter**: the ladder's curve (`bass::ladder_response`) where it rests, with a dot there, and dashed where the envelope's peak takes it; empty on the 808. **Drop**: the pitch over the drop and punch (`bass::drop_curve`), 24 semitones at the top. **Drive**: a sine through the drive (`bass::drive_shape`) against the clean sine, dashed. The preview draws `synth-bass` (Rubber Bass, Source) and `synth-bass-808` (Long 808, Shape).

## Wind (`mpfree-synth`, `Wind`)

Blown instruments as digital waveguides, played by the breath: a clarinet, a sax and a flute, built from [Wind instruments](../research/wind.md) for the synth library's wave 2 ([architecture](synth-architecture.md), targets O3 and O4 in [Synth quality](synth-quality.md#wave-2-targets-wind-stage-4)) on the shared voice core (`voice::NoteStack`, `Glide`, `Adsr`, `Lfo`, `Voices`, the voice core's square law). Code: `wind.rs`, `wind_params.rs`, `tests/wind.rs` (21 tests), `examples/wind_calibrate.rs` (measures the two tables below).

- **The bores.** A delay line as long as the note's period with a loss at the open end: a one-pole low-pass, inverting as an open end does (0.97). The sound is what the bell lets out (the wave reaching it less what it sends back), with a 5 Hz DC blocker per voice. **Clarinet**: a cylinder closed by a reed, the line half a period long, so it sounds the odd harmonics. **Sax**: a cone, taken as a pipe open at both ends driven a third of the way in (the missing tip of the cone is the short side; our derivation, as the [research](../research/wind.md#3-algorithms) says), so the reed sits between two delays in parallel and every harmonic sounds; a shorter tip let the prototype jump to its octave. The split at a third weakens the harmonics near every third one (the 3rd sits about 30 dB under the note at C4, the 6th 40 dB), so the sax is darker and less buzzy than a real one; **Tone** brightens the rest. A split nearer the tip that still speaks on its note is the next thing to try. **Flute**: a pipe open at both ends blown across an edge; the jet takes half a period to cross the mouth hole, the field deflects it, and `tanh` (a Padé form) says how much goes in.
- **The reed and the jet.** The reed is Smith's table, `ρ = 1 − (hc − h)/(hc + 1)` between 0 and 1, with its two corners rounded by a parabola over ±0.1 (`reed_reflect`), so the reed curls shut and feeds no harmonics past the output's Nyquist. **Reed** sets the closing point `hc`, 0.3 to 0.65; the mouth pressure runs from 1.35 to 2.0 times `hc` as the breath goes from none to full, on the falling side of the reed's air curve where it speaks. A harder reed would play louder, so its level is taken out as `(hc / hc at Reed 45)^1.37` (measured, the same for both reeds). **Edge** aims the flute's jet off centre (0 to 1.2 in the curve's units), which brings in the even harmonics; the jet's gain is set so the curve's slope at its aim is 1, so Edge changes the colour, not how easily it speaks. The flute's mouth pressure runs from 0.25 to 1.0 of the jet's full speed.
- **Tone.** The loss filter's corner is a number of harmonics of the note, so every key keeps the same share of its top: **Tone** goes from the bore's darkest to its brightest (clarinet 2.5 to 14 harmonics, sax 2.5 to 8, flute 2.2 to 6.1), the breath moves it (two octaves a unit of breath for the reeds, half an octave for the flute, about velocity 100 at Breath 85), and it never falls under the bore's floor (3, 2.5 and 2.2 harmonics: darker, a soft reed on a soft breath could not speak) nor over 14 kHz (a bright reed on a high note would alias).
- **In tune.** Each delay is read with cubic Lagrange interpolation and takes off the low-pass's phase delay at the note. What is left, the valve's own phase, moves with the breath, Tone and Edge; it is taken off from `SHARP_CENTS`, a table measured by the example (the clarinet, the sax and the flute at Edge 0, 50 and 100; Tone 0, 50 and 100; nine breaths; averaged over C3, C4 and C5). Every bore is within 0.17 cents from C2 to C6 at velocities 30 to 127 (O4) and 0.13 cents across T1's keys.
- **The breath.** Each voice's breath is its envelope (**Attack** 15 ms, **Decay**, **Sustain**, **Release** on the voice core's `Adsr`) times its source, all scaled by **Breath** (85 %): the note's velocity, or a breath controller (CC 2), the mod wheel or a foot pedal on MIDI in (**Breath from**). A controller counts only once it has moved: until then velocity plays the note, so a breath-controller preset still plays from the pads. Pad pressure adds to the breath through slot 1 (below). The tongue's puff (half again at **Tongue** 100, falling over 18 ms), the vibrato and the growl ride on it. The breath sets the mouth pressure, the tone, the pitch correction and the level alike.
- **The level.** The voice core's square law over **Velocity** (how much quieter the softest breath is: 0 to 40 dB, 24 by default), after each bore's own level is taken out by `NORM_DB` (the example's second table; within 0.01 dB), so a harder breath is louder and brighter by design and a note at no breath is exact silence. Each octave below middle C plays 0.4 dB louder and each above 0.4 dB softer, because the ear (and a loudness meter's weighting) hears the low notes quieter: L11 is 1.0 to 2.0 dB on every preset. With more than one voice each plays at `1/sqrt(voices)`, so a full chord stays under full scale (L2: −8.2 to −1.1 dBFS).
- **Starting a note.** A bore starting from silence is primed: its lines start at a share of the mouth pressure (0.1, plus 0.15 at Tongue 100; twice that for the sax; the flute's jet deflected by 16 times it on its first pass), so the note speaks in a few periods instead of building up from nothing (60 ms at C4 unprimed for the reeds, four times that at C2). At C4, velocity 127, it speaks within 3 dB of where it settles in 21 ms (clarinet), 25 (sax) and 30 (flute) (O3).
- **Noise and growl.** **Noise** is the breath's turbulence, band-passed (a high-pass near 500 Hz, a low-pass near 4 kHz): in the mouth pressure for the reeds, in the jet and, a little, in the air heard outside for the flute; a tongued start adds a burst. **Growl** flutters the breath at 31 Hz, 0.45 deep at 100, jittered, as a player singing into the horn. **Vibrato** (Depth, Rate 1 to 9 Hz, Delay with a fade-in as long again, on the voice core's `Lfo`) moves the breath and the pitch in each bore's mix (the flute mostly in the breath, the sax mostly in the pitch); the mod wheel adds to its depth unless it is the breath.
- **Playing.** One voice by default. A key over a held key slurs (the breath carries on, only the pitch moves) or is tongued again (**Legato**); either way its velocity becomes the breath, at once when tongued and gliding there with a 25 ms time constant when slurred, since from the pads velocity is the only way to blow harder or softer (a controller that has moved keeps the breath instead). The pitch glides by **Glide** (time or rate, the voice core's `Glide`) and never faster than 10 ms, as fingers move; **Priority** last, low or high. **Voices** up to 8 for chords, with four spare slots so a stolen voice fades over 3 ms; **Spread** alternates them left and right (a single voice stays centred).
- **Pressure.** Four slots on the shared shaper (ids 48 to 63), targets Breath (100 % is the whole breath, added to the note's), Vibrato (1 semitone), Tone (2 octaves brighter), Growl (all of it), Noise (all of it) and Pitch (12 semitones). Slot 1 is Breath at 60 % by default, so a held pad swells and opens the note. `Wind::pressures` gives each sounding voice's pressure for the Pressure page.
- **Oversampling and silence.** Below 64 kHz the bores run at twice the rate and come down through Squelch's polyphase half-band; the worst alias at C7 is −83 dB (clarinet at Tone 100), −64.5 (sax at Reed and Tone 100) and −70.7 (flute) (A1). A gain ramped to nothing settles at exactly 0, filter states under 1e-20 are flushed, a voice silent for 0.1 s stops running, and with none sounding the output is exact silence. The delay lines are allocated in `prepare`; nothing allocates while sounding (tested).
- **Presets** (20): Init (the clarinet); Warm Clarinet, Jazz Clarinet, Dark Clarinet; Tenor Sax, Breathy Sax, Growl Sax, Soprano Sax; Concert Flute, Breathy Flute, Pan Pipes, Recorder, Ocarina, Bamboo Flute; Reed Section (6 voices, spread) and Flute Choir (4 voices); Wind Controller Sax (from a breath controller); Pressure Swell (pressure is the breath); and two sounds with the Room and four macros (Breath, Vibrato, Tone, Noise): Hall Flute and Smoky Sax.

## Choir (`mpfree-synth`, `Choir`)

A choir: sung vowels, up to eight singers on every note, through the Ensemble. Built from [Organs, winds, choirs and tape](../research/organ-wind-choir.md) for the synth library's wave 2 ([architecture](synth-architecture.md), targets O1, O2, O8 and O10 in [Synth quality](synth-quality.md#wave-2-targets-choir)) on the shared voice core (`voice::Voices`, `NoteStack`, `Glide`, `Adsr`, `velocity_gain`) and the shared per-note expression (`expr`). Code: `choir.rs`, `choir_params.rs`, `presets/choir.presets`, `tests/choir.rs` (29 tests).

- **Singers.** Each note has 1 to 8 singers (**Singers**, 3 by default), each a band-limited sawtooth (`dsp::poly_blep4`) with a 32-bit phase, started at a random phase and at their own moment in the first 30 ms. Their pitches are spread evenly so their spread's standard deviation is **Detune** (0 to 50 cents, 10 by default; Ternström found listeners accept a scatter of about 14 cents in a unison section), each moved a little more at random. Each singer has their own **Vibrato** (0 to 100 cents, 14 by default, at **Vib rate**, 3 to 8 Hz, 5.2 by default, after Mann's 5.1 Hz in choral singing), its rate 7 % and depth 25 % apart from the next singer's, coming in over 400 ms after **Vib delay**; and their own **Drift**: a flutter (up to 8 cents, about 6 Hz) and a slow wander (up to 8 cents, about 0.35 Hz), the small uneven pitch changes that give a section its chorus (Ternström). A note's singers are scaled by the square root of middle C over its pitch, so the harmonics' level per hertz is the same at every pitch.
- **The voice.** The singers summed (harmonics falling 6 dB an octave), then a first-order shelf turning at twice the note (100 Hz to 2.5 kHz): **Brightness** ±18 dB above the turn, velocity down to 40 dB × **Vel > tone** (60 % by default) × how soft the note is, the soft pedal −15 dB, and pressure to swell half its level change. The level is made up for it with the share of the voice's loudness above the turn (`1/√((1−h) + h t²)`, exact for a one-pole split), so Brightness changes the colour, not the loudness. **Breath** is white noise, gated louder in the open 60 % of the first singer's cycle, then shaped by a leaky integrator at 20 Hz to fall as the harmonics do; gated after the shaping, the shaped noise's strong lows were moved up onto the note's harmonics and grew 8 dB from C2 to C6.
- **The vowel.** Five band-passes in parallel (Simper's zero-delay state-variable filter), each at a formant's frequency, level and bandwidth from the Csound manual's table (five voices, five vowels). Each is lifted by its frequency, so its peak has the table's level on the falling source and its skirts fall 12 dB an octave (on a flat source a parallel bank leaves a fizz above the formants: an "oo" had −15 dB above 1.5 kHz, now −23 dB, set by the real third formant). The first formant against the other four (+, −, −, −, −), picked by measuring all sixteen sign patterns over the table's 25 vowels: the worst false notch is −27.6 dB and the valley between the first two formants is within 2.2 dB of an all-pole tract's. **Vowel** (0 to 100) blends the table vowels in log frequency and bandwidth and in dB; the knob glides over 20 ms. **Section** picks the table voice; **Mixed** blends bass under D3, tenor at A3, alto at E4 and soprano from C5. As a note rises past the vowel's first formant, the formant rises with it (a power mean of order 8 of the formant and the note), as sopranos tune it (Joliveau, Smith and Wolfe 2004; Henrich, Smith and Wolfe 2011), and the second follows by the cube root of the first's ratio, staying 15 % above the first and under 0.9 of the third; every formant is at least half the note wide, its level lowered to keep its power, so a high note's few harmonics fall on a smooth curve.
- **Even loudness.** `VowelTable` works out, for each Section (Mixed too) at every 5 % of Vowel and every three semitones from C1 to C7, the trim that brings the voice's loudness (its harmonics through the bank, weighted as loudness meters weigh them) to the Alto's "Aah" at middle C, and the breath's own trim (its whole spectrum through the bank), both within ±12 dB. A blend of two table vowels is not as loud as either (up to 6.5 dB apart before), nor is a Mixed note between two sections. It takes about 11 ms on the workstation, once a process (`VowelTable::shared`). On the plain patch every vowel and blend at C3, C4 and C5 is within 0.6 dB, and C2 to C6 within 0.6 dB; breath at 100 is within 0.7 dB across the keys and vowels.
- **Vowel move.** **Start** (−100 to 100 %) starts each note that far along the vowels and opens into Vowel over **Start time** (10 ms to 4 s, on a square law); **Morph** swings the vowel by up to half its value either side, at **Morph rate** (0.02 to 8 Hz), one swing for every note; pressure (**Press > vowel**, ±100 %, up to 50 % of the vowels at full pressure) and a note's Tone expression move it too.
- **Swell and playing.** The voice core's ADSR (**Attack** 250 ms by default, **Release** 900 ms) and square-law velocity (**Velocity**, 0 to 40 dB, 20 by default). **Press > swell**: an unpressed note is down by up to 12 dB and pressing brings it to full. **Mode** Poly (**Voices** 1 to 16, 8 by default, the oldest stolen with a 3 ms fade), Mono or Legato (last-note priority, back to a held key; **Glide** 0 to 2 s by time). Sustain and sostenuto are heard here (`Node::hears`, `pedal::Pedals`); the soft pedal lowers the level 6 dB and darkens; the mod wheel adds up to 40 cents of vibrato; breath or foot sets the volume (a square law). Bend and Slide move each note; pressure goes through the shared shaper.
- **The Ensemble** (`mpfree_fx::Ensemble`) on the output through its mono path, as on Strings; **Ensemble** is its mix, 75 % by default, so a chord on the Init sound has a stereo correlation of 0.52 (O8).
- **Level.** One key at velocity 100 peaks between −23.1 and −14.3 dBFS on every preset; an 8-note chord at full velocity stays under −3.1 dBFS (Soft Oohs, the loudest). The phrase's loudness sits between −25.9 and −22.6 LUFS (Choir Stab, short notes, −28.1).
- **Presets** (25): Init (an alto "aah", three singers), Aah Choir, Ooh Choir, Oh Choir, Eh Pad, Soft Oohs, Bright Aahs, Men's Choir, Sopranos, Straight Trebles, Low Chant, Choir Swell, Vowel Pad (a slow morph), Wah Voices (a fast one), Ooh to Aah and Aah to Ee (Start), Pressure Vowels, Choir Stab, Whisper Choir, Big Choir (8 singers, 16 voices), Dry Choir, Solo Voice (one singer, legato, a late vibrato), Vowel Lead (mono); and two sounds with effects and macros of their own: Hall Choir (a large room; macros Vowel, Detune, Swell, Space) and Space Choir (a worn tape echo and a long plate; Vowel, Morph, Swell, Space).

Timing: the singers, the tilt, the breath and the formants run every sample, four voices to a row (`LANES`), each row's formants through `mpfree_simd::formants4` ([NEON kernels](simd.md)): a NEON kernel on the MPC, its plain twin (the engine's own loop before) everywhere else, the same samples either way; under qemu every Choir preset sounds the same to the bit with the kernel on and off (`tests/simd.rs`). A voice's formants are worked out again only when its vowel moves by 0.02 % or its pitch by a cent. Rows with no voice are skipped, and a tenth of a second after the last one the Ensemble stops and the output is exact silence. Nothing allocates (tested). Tuning: within 0.001 cents on the plain patch (T1); worst alias −79.8 dB at C7 on "ee" (A1).

**Cost** (callgrind, x86, 128-frame blocks; CI's instruction gate): `Choir Init` 213k instructions a block with 1 key and 359k with 6 (three singers each), `Choir Big Choir` 619k with 8 keys of 8 singers. ## Pad pressure (poly aftertouch)

The MPC One's pads send pressure for each pad while it's held. Players who have per-note pressure rarely give it up, and most complaints about it are about feel: it fires by accident, jumps when a note starts or ends, moves in coarse steps, or can't be tuned. So every engine shapes it the same way before it reaches a sound. The research and the reasoning are in the design doc [Poly aftertouch for MPFree synths](https://claude.ai/artifact/7SWqijpsJoBR2LjEHkNU3m).

**The shaper** (`mpfree-node`, `pressure`) runs once per voice every 16 frames. The sampler can use it without depending on the synths.

1. **Hold-off** (0 to 100 ms, 30 by default): for this long after a note-on the value holds still, so the strike itself doesn't modulate. A fresh voice holds at 0 and then glides in; a voice retriggered while it sounds keeps its value, so it doesn't dip.
2. **Threshold** (0 to 50 %, 8 by default): below it the output is exactly 0, so a resting finger does nothing. The scale starts again from 0 at the threshold, with no step.
3. **Full at** (30 to 100 %, 85 by default): the raw pressure that gives the full effect.
4. **Curve**: Soft, Linear, Firm (the default) or Hard, powers 0.6, 1, 1.6 and 2.5. Steps 2 to 4 are a 128-entry table worked out when a setting changes.
5. **Rise and fall** (0 to 200 ms each, 8 and 40 by default): one-pole smoothing, quicker up than down.
6. **Release**: Hold (the default) keeps the value the voice has at its note-off; the 40 ms fall means a lifting finger has barely lowered it. Follow keeps following the pad. Fade falls to 0.
7. **Mode**: Per note (the default), Highest (every voice follows the highest pressure among the held notes, so a chord swells together without jumps) or Off. Off makes pressure do nothing: a level swell then plays at the preset's full level.

**Slots.** Each engine has four slots, each a target and a depth of -100 to 100 %. A depth reads in its target's unit on the Synth tab (`mpfree-synth`, `pressure::full_scale`):

| Target | 100 % is | Poly | FM |
|---|---|---|---|
| Cutoff | 4 octaves | yes | |
| Resonance | 100 % | yes | |
| Level | a 24 dB swell | yes | yes |
| Vibrato | 1 semitone (Poly: its own sine at Vib rate, 5.5 Hz; FM: its LFO, without the LFO delay) | yes | yes |
| LFO rate | 2 octaves faster; the LFO is shared, so it follows the highest pressure | yes | yes |
| Pitch | 12 semitones | yes | yes |
| Drive, Distortion | 24 dB more | yes | |
| Width (pulse) | 45 % | yes | |
| Sub, Noise | 100 % of their level | yes | |
| LFO 1 amount, LFO 2 amount | how much of the LFO gets through: a positive depth lets 1 − depth through at rest and all of it at full pressure, a negative one takes it away (since 19 Nov) | yes | |
| Pan | all the way to one side; each voice moves, with its unison copies (since 19 Nov) | yes | |
| Position, Warp | 100 % of a Table wave's position (both oscillators) and of its warp amount (since 19 Nov, the fold) | yes | |
| Brightness | 24 output-level steps (18 dB) on every modulator | | yes |
| Tremolo | a 100 % dip, at the LFO's rate | | yes |
| Feedback | 7 steps | | yes |

**Level is a swell, never a boost.** A positive depth lowers the voice by the depth at zero pressure and plays it at the preset's level at full pressure; a negative depth ducks it as you press. Pressure on level never pushes a patch past the level it was designed at, so it causes no unintended clipping. Deliberate grit goes through Drive or Distortion.

## Tunings and per-note expression

**Tunings** (`rust/mpfree-tuning`). A `Tuning` turns a note number, fractional for bends and slides, into Hz. The default is 12-TET with A4 = 440 Hz, worked out with exactly the operations every engine used before (`440 * exp2((note - 69) / 12)`), so every factory sound is unchanged to the bit: all 38 `engine_cost` and 14 `poly_cost` hashes match main on x86 and on ARMv7.

- **Equal tunings:** any number of steps to the octave, each key one step, A4 on key 69 at any pitch from 100 to 1000 Hz (`Tuning::equal(steps, a4)`).
- **Table tunings:** each key from MIDI -64 to 191 has its own pitch. A note between two keys lies between their pitches on a log scale, so a slide or bend moves evenly from one key's pitch to the next.
- **Built in** (`Builtin`): 12-TET, 5-limit just intonation, Pythagorean, quarter-comma meantone and 24-TET quarter tones. The table tunings take a root (their 1/1, which keeps its 12-TET pitch) and an A4, so "just intonation on A at A4 = 432" is one call. `Builtin::tuning` never allocates (the degrees are a fixed array, `Builtin::degrees`), so the audio thread can switch tunings; it gives the same table, to the bit, as the scale through `scala::tuning`.
- **Scala files** (`scala`): `.scl` scales (cents or ratios, any period, so Bohlen-Pierce works) and `.kbm` keyboard maps (middle key, reference key and frequency, a map per repeat with `x` for unmapped keys). With no map, keys follow the degrees from middle C at its 12-TET pitch, as Scala does. Two differences from Scala, so a note never vanishes: every key follows the map whatever its first and last keys say, and an unmapped key sounds between its neighbours.

Poly, FM, Wavetable and Pluck play every note through their tuning; a sounding note moves to a new tuning on the next control step. FM's fixed-frequency operators stay fixed. Drums ignore tunings (a kit is pitched per pad).

**Per-note expression** (`NodeEvent::Expression`, `mpfree_node::Expr`):

- **Slide:** the note's own pitch offset, -48 to 48 semitones, added to the bend. Only voices playing that note move, so one note of a chord can slide (a sus4 resolving, a pitch lock on one note). Engines glide to each new value over 5 ms (`expr::EXPR_MS`), so a stream of values never zips; a sender ramps a long slide itself.
- **Tone:** 0 to 1, MPE's timbre axis. The engines keep it per voice; routing it to destinations, as pressure is, comes next with a Synth tab page.
- **Release:** release velocity, 0 to 1, for the note's coming note-off. The native engines don't use it yet.
- A value sent before a note-on (as MPE controllers do) is kept for that note and starts it in place. A note-off puts the note back to neutral for its next note-on; the releasing voice keeps its values. AllOff and reset clear every note. With nothing sent, nothing changes to the bit.
- **CLAP plugins** get them as CLAP note expressions: a note's slide is its tuning expression (with the bend added when the bend goes that way), its tone is brightness, and its release velocity goes in its note-off. A new note now also starts at a bend held from before it. The plugin sandbox carries `Expression` across (protocol version 2).

A tuning per track slot is in the track host (`TrackHost::set_tuning`, see [Track host](track-host.md)); nothing calls the host yet.

**Not yet.** Tone routing in the native engines, and MPE from MIDI input: MIDI in ([MIDI in and out](midi-io.md)) plays notes and poly pressure on the armed track, but does not read pitch bend or CCs yet (so no per-note bend or CC74 for MPE), and nothing sends Tone. The sequencer and the arp can send slides now. Choosing a built-in tuning or a tuning file is on the Synth tab's options (see [In the pad player](#in-the-pad-player-rustmpfree-app)).

- `mpfree-tuning`, 16 tests and a no-allocation test (built-in tunings and rooted scales): every built-in tuning on every root at five A4s matches its scale through `scala::tuning` to the bit, and is worked out with no allocation; the standard tuning is the old formula to the bit across notes -200 to 300; equal tunings, A4 and clamping; just, Pythagorean and meantone intervals are pure where they should be; notes between keys lie between their pitches; every note gives a finite frequency; unmapped keys lie between their neighbours; `.scl` reading (cents, ratios, comments, trailing text, Windows line ends) and its errors with line numbers; a 12-TET file matches the standard tuning; a `.kbm` places degrees, the reference pitch and unmapped keys; short maps; map errors; a scale repeating at a twelfth; a rooted scale (12-TET, 7 notes, 1 note, Bohlen-Pierce, on four keys and pitches) is the linear map on that root to the bit.
- `tests/no_alloc.rs`: a counting allocator watches 4000 blocks of random notes, pressure, bend, per-note slides, tones and release velocities, tuning changes, parameter changes over every parameter, AllOff and a reset, and sees no allocation or free. It runs every engine.
- `dsp` unit tests: oscillator bounds, envelope stages, low-pass and high-pass responses.
- **Held notes never run on denormals** (18 Nov, with flush-to-zero; see [Synth architecture](synth-architecture.md#flatter-worst-periods-lever-5)). Both envelopes (`dsp::Env` for Poly, Analog and Wavetable; `voice::Adsr` for Bass and the newer engines) land on exact 0 under −400 dB on a decay to a sustain of 0, where before the level sank on through the denormals for as long as the key was held (unit tests in `dsp.rs` and `voice.rs`). Bass and Squelch let their amplifier land on 0 and flush the stages after it every control step, so a note held at no level puts out exact zeros (`a_note_held_at_no_level_ends_in_exact_zeros_not_denormals` in `tests/bass.rs` and `tests/squelch.rs`, on 808 and Synth bodies and three Squelch presets). Keys sets a mode that has died away to exact 0 while its note still sounds (a unit test holds a Long Tines chord for 14 s and finds no mode in the denormals; before, the bending modes got there in under a second).

## The Synth tab (`rust/mpfree-synth-ui`)

The instrument page for the MPC One's 1280x800 screen, on `mpfree-ui`. It works for any `Node`, so hosted plugins and effects get the same page.

- **Frame** (`view::LAYOUT`, layout spec 4c as Play, Looper and Arrange): the instrument card (`synth-inst`: swatch, engine, track and kind) over the presets list in a 220 px column on the left; the title bar (preset name and the pages as tabs) over the page's sections, 884 x 598 px, in the middle; and the app's shared Q-Link column (`qlinks`, `mpfree_ui::qlink::QLinkColumn`, 128 px) on the right. The app fills the column from `SynthPanel::qlink_cards()` and passes a drag on a card back as `qlink(n, detents)`. Jay picked this frame and the section design from the mockups on 14 Nov ("Build it as drawn"); the rules are in the doc "Instrument and effect page design rules", which the FX tab follows too.
- **Pages.** A native engine names its pages and what its Q-Links turn (Poly: Osc, Table, Filter, Env, LFO, LFO 2, Voice, Routes, Pressure; FM: see above). Any other node gets pages from its `ParamInfo` groups: consecutive groups share a page up to 12 controls, and a group bigger than 16 is split. Every parameter is on exactly one page.
- **Sections** (`sections`, `section_plans`). A page is a set of labelled sections, each with one job, laid out by a layout spec over the section keys (`row(filter:52*, col(fenv:*, follow:200):48*)`). A section is a view only: it never renames an engine's parameter groups, since preset files name parameters by group. `section_plans::plan` holds a plan for every page of the thirteen native engines; a test checks that every parameter of every page has a place in its plan. Any other node gets a section per run of a group (`sections::by_group`), three to a row, with attack, decay, sustain and release as faders. A parameter a plan leaves out goes into a last "More" section, so nothing is lost.
  - **Colour by job** (`Job`): Source (oscillators, tables, strings) cyan, Tone (filter, drive, tone) coral, Shape (envelopes, dynamics) lime, Motion (LFOs, modulation) pink, Voice (voicing, tuning, output) grey. They are the theme's `track` 6, 5, 8 and 7 colours and its `text_dim`. The section's name is in caps in its colour, over a tint of it; its drawings recolour their curves to shades of it. The Q-Link colours appear only on the Q1 to Q4 badges, in the knobs' own colours (`mpfree_ui::draw::KNOB`) under every theme, so a badge matches its card in the column.
  - **Size by importance** (`Tier`): a page's one or two hero knobs are 88 to 112 px, the Q-Linked ones and those a plan marks main 62 to 80 px, the rest 48 to 60 px, and trims 40 to 48 px. Knobs shrink within their tier to fit, then lay their name and value beside them.
  - **The control for the value** (`section_view::Kind`): knobs only for continuous values; a choice of up to 8 as buttons when they fit (on one or two lines), otherwise a chip with ‹ ›; a whole number of up to 48 steps as a stepper (− value +); a toggle as a pill; envelopes and mixers as faders; Drawbar's bars as drawbars, pulled down to add them; routing rows (pressure slots) as sliders, two to a line; read-only values as meters.
  - **Drawings inside their sections**, above the controls they show. The cards each engine's section above calls its visual strip are drawn this way now, each in the section it is about: the same cards as before (`inst_visual`, `kit_visual` and the FM, Poly, Pluck, Wavetable and pressure builders), found by title. A card that draws two curves (amp and filter envelope) can give one to a section (`draw_trace`). A section gives its drawings a band at least 56 px tall when its controls still fit under it at their least: knobs beside their names, or stacked at their smallest, whichever is shorter (in a narrow section, knobs beside their names wrap onto more lines). Otherwise the section shows only its controls.
  - **Links.** A section about another page has "Open ›" by its name (the filter envelope's amount on Filter opens Envelopes), and a section that is only a drawing opens the drawing's page. A box of a drawing (an FM operator, a drum pad) opens its page.
  - **Inactive controls** (`view::inactive`) draw at half strength, and the section's heading says why ("Pulse width · pulse waves only", "Detune · Unison only").
  - **For the FX tab:** a section can hold several drawings side by side (`SectionBox::cards`) and an on or off switch in its heading (`SectionBox::switch`) that dims the whole section while it is off.
- **Control.**
  - A finger dragged up or down a knob turns it; 320 px is the whole range. A fader drags over its own track (a drawbar down), a slider sideways.
  - A tap on a button picks it; a tap on a chip's ‹ › or a stepper's − + steps it; a tap on a pill flips it. A finger that slides off before it lifts changes nothing.
  - A tap selects a control, and the wheel then turns it. With the app's wheel navigation the wheel picks controls in the sections' order (`SynthPanel::order`) and a push opens the one picked.
  - Q-Links 1 to 4 turn the controls with the Q badges. A detent is one step for whole numbers and choices, and 1/100 of the range along the parameter's curve otherwise.
  - SHIFT + wheel steps through the pages.
  - `SectionView` reports `Select(param)` on a finger down, `Value(pos)` as a knob, fader or slider moves, `Step { index: param, delta }` from a button, arrow, stepper or pill, and `Tab(n)` for a link (`n` indexes the panel's list of pages linked).
- **Q-Link sets** (`qsets`). A sound carries named sets of four controls, so the Q-Links can play it from any screen without opening its editor. Each engine has curated sets, in the order a player reaches for them:

  | Engine | Sets |
  |---|---|
  | Poly | Tone (cutoff, resonance, filter env amount, drive), Env, Filter env, Motion (LFO rate, LFO to cutoff, LFO to pitch, unison detune), Mix, Osc |
  | FM | Algo (algorithm, feedback, transpose, level), Levels 1-4, Ops 5-6 (levels and coarse), Ratios 1-4, Mod (LFO) |
  | Wavetable | Tables (both positions and warps), Tone, Env, Mod env, Motion, Mix |
  | Pluck | String, Mallet, Play |
  | Drums | Hit (tune, decay, tone, snap), Body, Mix, on the pad hit last |

  Any other node, such as a plugin, gets one set per Synth tab page (at most 8). Drums' sets name pad 1's parameters; `qsets::on_pad` moves them to the pad hit last, and `qsets::pad_relative` keeps a knob learned on another pad as pad 1's, so it follows the pad too. `qsets::save` writes the sets as `qset = <id> <id> <id> <id> <name>` lines for a preset file (`-` for a free knob), and `qsets::load` reads them back from a whole preset file: an id the node no longer has, or a meter, loads as a free knob. `qsets::to_banks(sets, params, owner)` makes the sets into `mpfree-mod` banks for `Bindings::set_page_sets` (one bank per set, each knob turning its parameter on `owner`, the sound's `Owner::Inst(track)`, over its whole range). After a learn (`Bindings::take_sets_edited`), `qsets::from_banks(info, banks, params, owner)` reads them back to save with the sound: a knob learned to anything that can't travel with the preset (an effect, a macro, another track's sound) is saved free, and a Drums pad's knob as pad 1's. Wiring this into the app's Q-Link column is the app's; nothing on screen changes yet.
- **The app's part.** The app owns the node on the audio thread. It builds a `SynthState` from the node (`SynthState::from_node`) and adds the panel with `SynthPanel::add(ui, "Synth", state)` after its own `header` and `hint` widgets. It passes touches (`SynthPanel::event`), Q-Link turns (`qlink`) and wheel turns (`wheel`, `step_page`) to the panel, and applies each `SynthAction` it gets back: `Set { id, value }` becomes `Node::set_param`, and `Preset(i)` loads the preset, after which the app calls `SynthPanel::load` with the node's new state. The panel updates its own copy of a value at once, so the screen keeps up with a finger.
- **Colours follow the theme.** The sections' job colours come from the theme as they paint (`Job::color`). The panel builds its controls, cards and boxes without the theme, so it picks each colour by what it means, written as the default theme's colour for it: `widgets::QLINK_COLORS` (Q-Links 1 to 4, and the curves' blue, green, amber and violet), `TEXT`, `TEXT_DIM`, `TEXT_FAINT` and `ON_FILL` (text on a coloured box). When the widgets paint, `widgets::themed(theme, colour)` swaps each for the shown theme's own: the Q-Link colours for `track` 1 to 4, the rest for `text`, `text_dim`, `text_faint` and `on_accent`, keeping their transparency. Any other colour is left as it is, and the instrument's swatch goes through `Theme::content` like a kit colour. So the default theme draws exactly what the panel wrote, and the colours named on this page (a blue modulator, a green carrier, a white amp envelope) are the default theme's; Console, Synthwave and Spaceship draw their own. The FX tab, which uses these widgets, follows the theme the same way. A new colour in a panel should be one of these, or `Theme::content` for a colour that belongs to the music (a kit's, a track's).
- **Preview.** `cargo run --locked -p mpfree-synth-ui --bin mpfree-synth-preview` draws the sample screens to PNG files in a new folder `~/mpfree-work/synth-preview-<UTC>`. It opens no device. `--theme console` (or `synthwave`, `spaceship`) draws them in that theme.
- **Tests.**
  - Q-Link sets: every engine's curated sets turn real knobs (no meters, switches or choices, nothing twice in a set), Drums' sets follow the pad, the sets save and load with a preset, old or odd preset lines load safely, the sets go to Q-Link banks and come back unchanged (Drums on any pad too), and a learn on the Q-Links saves with the sound only when it is the sound's own parameter.
  - The anti-aliased drawing, value text, page plans and visual curves (every curve stays in its box for every parameter at its minimum and maximum). All 32 algorithms lay out with no boxes overlapping, carriers on the bottom row and every modulator above what it modulates.
  - `tests/panel.rs` runs a Ui at 1280x800 with a real Poly. It checks that dragging knobs and faders, tapping buttons, chips, steppers and pills, the Q-Links, the wheel and presets reach the node; that every Poly parameter can be reached and set; that the Q-Link cards name what the badges mark; that a section's "Open ›" and a box of a drawing open their pages; that the Pressure page draws the curve and live bars and reads depths in their targets' units; that FM draws its algorithm, rings the page's operator and opens an operator's page from a tap on its box; that Keys, Drawbar, Squelch and Analog draw each picture in its section; that a node without a plan gets a section per group; that every sample screen's sections and controls lie inside the page without overlapping, with buttons a finger can hit, and redraw only the panel after a turn; that every section heading fits its name, link and note for every preset and every parameter at its ends; and that under Console, Synthwave and Spaceship no sample screen shows a default-theme text colour, nor a Q-Link colour outside the badges and cards.

## In the pad player (`rust/mpfree-app`)

The pad player (`play` and `app`) carries all thirteen native engines: Poly, FM, Drums, Pluck, Wavetable, Keys, Drawbar, Squelch, Analog, Strings, Bass, Wind and Choir; one of them has the pads. `src/synth.rs` holds them all on the audio thread; the Synth tab shows the one on the pads. Round 6 brought Poly; FM, Drums, Pluck, Wavetable and the pad layouts came in round 8; Keys, Drawbar, Squelch and Analog with the instruments thread (PR #390, 15 Nov); Strings and then Bass with the synth library's wave 1 (18 Nov), and Wind with wave 2 (19 Nov), each last in the list so saved picks keep their place.

- **Picking it.** The kit list ends with "Synth: Poly" (or "Synth: FM", "Synth: Strings" and so on, by the engine on the pads). Picking it with the wheel or a tap puts the synth on the armed track (`sampler::TrackKits`, [Kits on tracks](sampler-architecture.md#kits-on-tracks-the-pad-player)): its clips play the synth, and so do the pads while it is armed. Opening the Synth tab changes nothing that plays; on a track that plays a kit the hint line says how to put the synth on it. Picking a drum kit puts that on the track, and the notes the pads held on the synth end with their release; other tracks on the synth play on.
- **The Synth tab's options** (MENU on the Synth tab, `app/synth_pads.rs`): "Track N instrument" (the selected track's own instrument: Kit, the thirteen engines, then plugin synths; see [Track host](track-host.md#in-the-app)), Scale (Off, the built-in scales and the owner's), Scale root, Pad layout (for the bank playing), In key rows, Tuning (12-TET, Just (5-limit), Pythagorean, Meantone 1/4 comma, 24-TET quarter tones, then the tuning files), Tuning root (the note the table tunings and files are pure on; "(not used)" for the equal ones) and A4 (380 to 480 Hz, 1 Hz a step), then the Play rows as before. Every engine but Drums plays through the tuning; held notes follow on their next control step. The tuning is worked out on the audio thread without allocating (`TuningPick::tuning`), and the pads' log line adds it when it isn't 12-TET at 440 Hz ("tuned Just (5-limit) on D, A4 432 Hz"). On an engine switch the old engine's notes get their note-off and finish their release while the new one plays; each engine keeps its own preset. The shared synth's engine is still kept and restored with the options, but no row sets it since the Instrument row took its place: a track that wants another engine gets its own.
- **Tuning files** (`load_tuning_files` in `main.rs`, `TuningFile` in `synth.rs`): at start the app reads `files/tunings/` in the data store (`Store::list`, read only; names `[a-z0-9._-]`, 1 MiB a file), takes each `NAME.scl` that parses, in name order, at most 64 (`MAX_TUNING_FILES`), with `NAME.kbm` beside it when there is one, and logs `tunings: found dorian (7 notes, with its .kbm), just (12 notes)` and one `left out` line, with the reason, per file it can't use (a scale or map that doesn't parse, a map with no scale). Text that isn't UTF-8 is read lossily, since many published files are Latin-1 and only their descriptions use it. All parsing happens there, before the sound starts. A file with a map keeps the tuning the map gives (`scala::tuning`, which allocates, done once); one without keeps its scale, and the audio thread moves it to the picked root and A4 with `Scale::rooted`, which never allocates and gives the same table, to the bit, as `scala::tuning` with a linear map on that root (a test checks it, and that a `.scl` spelling just intonation plays exactly as the built-in one). The synth holds the list (`Synth::set_tuning_files`, before the sound starts) and the menu's list is built from the synth's, so a pick (`TuningPick::file`, an index) always names the file that plays; a pick the synth doesn't have falls to the built-in tuning and the settings and log line say so. The Tuning row cuts names to 20 characters; with a map, the root and A4 rows read "set by its .kbm". With a file picked, the built-in tuning underneath is 12-TET.
- **Kept in the project** (`App::synth_settings` and `App::open_synth` in `app/synth_pads.rs`; Jay, 13 Nov: a song's key and tuning are the song's, so they don't follow you from one project into the next): every option above and each bank's layout, in the project's `synth` part under `[options]`, by name (a scale by its name, a tuning file by its file name), so a list that grows or shrinks doesn't move a pick. A change with the controls is an edit for the unsaved-work check (`App::take_project_edit`, `ToUi::Edited`); switching banks isn't, since the bank playing isn't kept. An open puts every option back over the defaults (an option the project lacks, or a scale or file that's gone, is the default and said in the log, never the last project's) and reaches the synth as an `Effect::SynthPads`. New project starts chromatic in C at A4 = 440 Hz. They are no longer kept in Prefs ([Storage spec](storage-spec.md)).
- **Notes.** With no scale, pad 1 plays C3 and each pad after it a semitone higher, so the pads play C3 to D#4, in every bank. With a scale the pads follow `mpfree_scale::pads` (see [scales.md](scales.md#the-pads-mpfree_scalepads)): each bank has its own layout, out of the box A Chromatic (the scale lit), B In key, C Chord pads and D In key an octave up. A chord pad plays three or four notes. SHIFT + wheel on the Play page moves the pads by an octave, from C0 to C6 at pad 1 (with a drum kit it still moves the kit). With no scale the pads light C in purple, the other white keys in light blue and the black keys in dark blue; with a scale the root (or the home chord) is purple, the scale's notes light blue and the rest dark blue, all colours Akai's app was seen sending. The screen labels each pad with its note, or its chord ("iv7 Dm7"), and the header chip reads "FM · D Dorian · Chord pads · D3 to D4" (or "Poly · C3 to D#4" with no scale).
- **Drums.** A kit, not a keyboard: pad 1 plays the kit's Pad 1 note (on the Synth tab's Kit page, C2 by default) and each pad after it a semitone higher, whatever the scale, layout, bank or octave; SHIFT + wheel does nothing. Each pad is labelled with its sound ("Kick", "Closed hat") and lit in the kit's colour, the chip reads "Drums · Boom Kit", and the Synth tab shows the page of the pad hit last (`mpfree_synth_ui::pages::drum_page`). A new Pad 1 note, a pad's sound or another kit sends the pad grid and the arp the new names and notes. Every other engine plays the pad layouts as Poly and FM do. Of them, Poly, FM, Wavetable and Wind take pad pressure through the shared shaper (and show it on a Pressure page).
- **The layout owner's part.** `App::synth_toggle_layout` (the quick switch, Chromatic to In key and back) and `App::synth_bank` (a bank's layout) hand the synth new settings; which button or touch does each is the Hello MPC thread's to place.
- **Playing.** Note Repeat, Latch, Full and Half Level and the velocity curve work as for drums: the note engine hands the synth each note-on and note-off on its exact frame. Pad pressure goes to every note its pad plays. Two pads can share a note (two chords): a shared note takes the harder press and ends only when the last pad holding it is let go.
- **The Synth tab.** It sits between Clips and Looper. Q-Links 1 to 4 turn the page's marked knobs while it shows, and the shared Q-Link column names them (`refresh_qlinks` fills it from `SynthPanel::qlink_cards`; a drag on a card turns it too); elsewhere Q-Link 1 is still the level. The pads heading (Chromatic or In key) sits over the presets, under the instrument card (`play_page::synth_with_pads`, through `view::PRESETS_SLOT`). The wheel turns the selected knob. SHIFT + wheel, - and + step the pages. A touch, Q-Link or wheel change goes to the audio thread and applies from the next period. After a preset load the audio thread sends the node's values back; every 250 ms it sends the meters and each voice's pressure (for the Pressure page's live bars) when they change.
- **Step locks** (sequencer S1 locks, 17 Nov 2026; [step-pads.md](step-pads.md#locks)): a clip's lock on the synth (`Owner::Inst` on a track that plays the synth) reaches `Synth::lock` on its frame as a `Param` event. `synth.rs` keeps the value under each lock in a `locks::Under` table (64 parameters a synth, keyed by engine and id): a run of locked steps comes back to the sound's own value, a knob turned while a lock holds becomes what its end comes back to, and a preset loaded while one holds takes its value as the sound's own. An engine switch puts the locked values back first. A lock that finds the table full doesn't play and is counted.
- **Sound.** Each period the sampler and the synth render into their own tracks of the pad player's mixer ([`mixing.rs`](../../../rust/mpfree-app/src/mixing.rs)), whose master fader is the Level and whose Master safety keeps the output under full scale. Every engine plays on the synth's track. An engine not on the pads renders only while a note of its own still rings. The synth's render uses fixed buffers and never allocates (a test watches it with a counting allocator, through engine, scale, bank and tuning changes). A block with a non-finite sample is dropped, that node reset and the reset counted. STOP fades every engine out over 10 ms and resets them, so no release rings on.
- **The log.** At the start, `synth: Poly, preset Pluck, as kit list entry N (C3 to D#4)`. Then a line when the pads move to the synth, by an octave or to another layout (`pads: FM synth, D Dorian, Chord pads (bank A), D3 to D4 (pad 1 = D3; …)`), one on an engine switch (`synth: FM on the pads, preset Glass Keys`), one per preset (`synth: preset 4 of 9, Supersaw`) and one per knob once it rests for a second (`synth: Filter Cutoff 2.5 kHz`). Every 30 s a second status line gives the synth's engine, render time per period (mean and largest, also as a share of a period), notes, the most voices at once, notes dropped and resets. The sampler's line times the sampler alone.
