# Sampler architecture

**Status:** as built on 22 Nov 2026, with the target of the sampler refactor: see [As built, and where it is going](#as-built-and-where-it-is-going). Written on 10 Nov 2026 as a proposal for the owner's review; the proposal's sections stay below, each with an **As built** note where what was built differs. This is the engineering plan behind the [sampler design](sampler-design.md) and the [feature map](sampler-features.md). Mockups of the screens are in the [mpfree-claude repo](https://github.com/jferments/mpfree-claude/tree/main/sampler) together with the sampler skill tree.

It says which crates hold what, which thread does what, how data moves between them without ever blocking the audio thread, what is stored on disk, how each algorithm works in outline, and how each part is tested before it reaches the MPC.

## Principles

1. **The audio thread only mixes.** It reads capture, renders voices, writes playback and copies into fixed buffers. It never allocates, frees, locks, logs, touches files or waits on another thread. This is already MPFree's rule; the sampler keeps it with tests (below).
2. **Everything heavy is a background job.** Loading, decoding, analysing, stretching, rendering and saving run on worker threads and publish results when done. The sound you have keeps playing.
3. **State lives in one place.** The project model (sources, regions, pads, chop sets) is owned by the *control* thread. The audio thread gets immutable snapshots of what it needs; the UI gets change notices. Nobody else mutates the model.
4. **Every change is a command.** UI, hardware and MIDI all send the same commands to the control thread. Commands are logged for undo and are the only way to change a project.
5. **Testable on the workstation.** Every crate except the device backends runs and is tested on x86 and as 32-bit ARM under qemu, as today.

Principles 1, 2 and 5 hold, with the gaps in 2 listed under [As built](#as-built-22-nov). Principles 3 and 4 were not built as written: there is no control thread, and changes are not commands yet. The refactor keeps the model on the screen thread and puts sampler commands in front of it (step 12).

## As built, and where it is going

The sampler was built in rounds (steps S1 to S7, rounds R1 to R7). An outside review on 20 Nov 2026 led to a refactor in four phases, which the owner started on 20 Nov (phase 1) and 22 Nov (phase 2). This section says what was built, where it differs from the proposal, and the target the refactor works towards.

### As built (22 Nov)

- **No control thread.** Each kit's model (`mpfree_sampler::model::Project`) lives on the screen thread, in the Sample page (`SamplePage::projects`). The pad player builds every kit before the sound starts and hands the projects over once (`Player::take_projects`). An edit builds the kit's engine view again on the screen thread and sends it to the audio thread in a `ViewSwap`; the old view comes back in the same box and is freed on the screen thread.
- **Changes are method calls, not commands yet.** The Sample page calls the model's methods (`Project::map_to_keys` and the rest) directly. Each returns an undo step. Undo is per kit, kept in memory and not saved.
- **Background work: the job service and two threads of their own.** The [job service](#the-job-service-step-7)'s sound lane (`mpfree-sound-1`) works out a sound's view (peaks, mono mix, onsets, tempo, root note, and the pitch track when asked for; `mpfree-app/src/views.rs`), the hits of a sound a Stretch grain pad plays (`mpfree-sampler/src/hits.rs`), its octave copies (`bandlimit.rs`), Warp's stretched copies (`warp::Worker`), Process, Put on audio track's copy and Normalize's reads of every frame. Its file lane (`mpfree-file-1`) reads and decodes Load, a kit file and a project's kits. Two have their own thread still:
  - `preview-load`: the browser's preview, which mustn't wait behind a kit or a project opening;
  - `autosample`, which plays a copy of the synth in time.

  All of them run off the sound's cores; the sound lane at idle priority, the rest at background priority. The work on the sound shown or edited goes first.
- **No heavy work left on the screen.** Before phase 1 the grain start scanned the whole sound and Normalize copied it; before step 7d Map to keys worked out a sound's analysis on the spot; before step 7e Put on audio track copied the sound and converted its rate there. None of them does now.
- **Memory.** There is no arena: sounds come from the system heap. A load, a stretched copy, an auto-sample and, since phase 1, Put on audio track (on the job service since step 7e) refuse to start when they would leave less than 256 MB free (`memory::room_in`; see [Sample memory](#sample-memory)).
- **Sounds by id.** In the model a sound's id is a 64-bit FNV-1a hash of its rate, channels and samples (`SourceId`). The project folder names each sound by a 128-bit hash of its bytes ([browser.md](browser.md#projects)), so a project holds each sound once on disk. In memory, two kits with one sound can hold two copies, and each analysed sound keeps a whole mono copy for snapping markers (`SourceView`).
- **Kits are not instruments yet.** The pads play the armed track's kit (`Player::select`), and automation names a pad by track and pad number (`Owner::Pad`). The instrument node ([`node.rs`](#as-an-instrument-node-noders)) is used only by tests.

### The target

The engine stays as it is. Two new pieces sit around it: sampler commands, which every control goes through, and one job service, which does all heavy work away from the screen and the sound. There is still no separate control thread: commands run on the screen thread, as the page's edits do today, and never do heavy work themselves.

- **Sampler commands** (step 12). A `SamplerCommand` value, applied to a kit in one place that checks it, makes the change, groups the undo step and asks for any work. Each command names its kit by the instrument id of the [instrument redesign](instruments.md), never by track. The touch screen, Q-Links, MIDI learn, locks and later scripts all call it.
- **One job service** (step 7), in place of the threads each kind of work had of its own. One set of priorities, one memory account and one way to cancel, with two kinds of worker:
  - sound work (views, pitch, hits, octave copies, stretching, Process);
  - file work (loading sounds, opening kits), so a long analysis never holds up a load.

  The sound being edited comes first, and a newer job for the same sound replaces an older one. Each result carries the sound, the settings and the edit it was worked out for, and is thrown away (and counted) if any of them changed. Every job checks memory before it starts. Nothing falls back to working on the screen: an action waits, saying so, or says why it can't.
- **Sounds held once** (step 8). One store per project, each sound once by a 128-bit id, with its analysis beside it. Kits point at sounds, and old ids still load. The view's spare mono copy goes. The files on disk don't change.
- **Grains shared by musical priority** (step 9). Before each part of a period the 256 grains are shared out in ranks: a new hit's first grains, then held pads and the master Grains FX, then ringing tails and the oldest clouds, which thin first. Nothing is cut without a fade.
- **Shown to the musician** (step 10). When the sampler thins grains, steals voices or drops events, a short warning in plain words. The counts stay on Dev > Debug.
- **The engine in modules** (step 11): events, voices, grains, routing, master effect and counters, with offline renders bit for bit the same.
- **Kits as instruments** (phase 3). A kit gets a lasting instrument id and takes notes like any instrument, and automation names a pad by instrument and pad. Grain settings become `mpfree-mod` parameters.

### The job service (step 7)

Built so far: the service (`mpfree_sampler::jobs`, `mpfree-sampler/src/jobs.rs`), with the views and pitch on it (step 7a), a sound's hits and octave copies (step 7b), Warp's stretched copies and Process (step 7c), Map to keys waiting for its sounds' views there (step 7d), Put on audio track's copy (step 7e), Normalize's reads of every frame (step 7f), and on the file lane Load, kit files and a project's kits (step 7g). The browser's preview keeps its own thread (it mustn't wait behind a kit or a project opening), and so does auto-sample.

- **Lanes.** `Lane::Sound` (`mpfree-sound-1`) works out from sounds in memory; `Lane::File` (`mpfree-file-1`) reads files, so a long analysis never holds up a load. A lane's workers start with its first job and run where `Config::on_start` puts them. In the app (`sample_page::jobs_config`) both are off the sound's cores, and the sound lane is at idle priority (`mpfree_lanes::os::idle_job`), as the stretch and Process threads were: its work is long and nobody waits on it frame by frame, so the screen goes first ([concurrency.md](concurrency.md#the-control-side-and-helper-threads)). The file lane is at the normal priority. The program has one service (`Jobs::shared`), given its config at the start of `main` (`jobs::configure`, `sample_page::jobs_config`); the Sample page uses it (`SamplePage::jobs`). A test's page makes one of its own, so a test that holds it holds no other.
- **Order and keys.** A job has a `Key` (its kind and its sound's id) and waits at its `Order`: `First` (the sound shown or edited), `Last`, or `After` another key. A newer job with the key of one waiting takes its place; one running is told to stop (`Running::cancelled`). `Jobs::promote` moves a waiting job to the front, or says it is running, so a view asked for again is never worked out twice.
- **Memory.** A job says what it holds (`Job::needs`). It starts only when `Config::room` (in the app, `memory::room_in`) says that much more leaves the 256 MB floor, on top of what the running jobs hold (`Jobs::reserved`). Otherwise it never runs, and its client is told why. A view needs its mono mix twice over (made, then moved into the view) and its peaks (`views::view_need`: 545 MB for a 25-minute stereo take); a pitch track, its sound brought down to 8 kHz (`views::pitch_need`); a sound's hits, its samples as floats and their mono mix (`hits::need`); its octave copies, under its length as floats (`bandlimit::need`). Hits or copies refused are left out for now, as when they aren't found yet (voices play without them), and the next view built for the sound asks again.
- **Warp's copies** (`warp::Worker`, `Worker::on`). A copy's job is keyed by its region and tune, whatever the tempo and pins, so a copy asked for at a newer tempo, or after the pins moved, takes the place of the one waiting, and one running stops within 8192 output frames. The one taken over comes back `Done::Cancelled` at once, and only the last is made: a run of tempo turns keeps one job a region (`tests/warp.rs` `tempo_turns_keep_one_stretch_a_region_and_only_the_last_is_made`). A copy that still comes after its pad changed (another tune) is thrown away, never put in the copies it plays from, counted and logged ("sample: a stretched copy came after its pad changed: thrown away (1× so far)"; Dev > Debug "Sampler: stretched copies thrown away (pad changed)"). The page checks memory before it asks, as before, and the service again as the copy starts, with the jobs running then: either refusal leaves the pad repitching and says why (`Done::Refused`).
- **Process** goes on the sound lane too, one at a time, with its memory checked again as it starts; Stop and a refusal end it as before.
- **Map to keys** needs the note heard in each sound that isn't a keygroup yet. A sound whose view isn't worked out goes first on the sound lane (`Views::get`), and the press waits (`SamplePage::map_waits`, a `Mapping`): the log says so once ("sample: kit 1 (Tones): map to keys waits for 1 sound to be worked out"), and so does the hint line. Each tick (`SamplePage::map_later`) maps the bank once every sound is in, as one undo step as before. The kit changed meanwhile (another kit shown, or any edit to it) drops the press and says so ("not mapped to keys: the kit changed while its sounds were worked out"). A sound whose view waits for memory (`Views::is_refused`) can't give its note, so it maps nothing and says why ("not mapped to keys: Tone's waveform waits for memory, so its note isn't known yet"). Nothing is worked out on the screen: `Views::full` is gone.
- **Put on audio track** copies the sound the slices span out as floats, and changes its rate when the sound's isn't the tracks', on the sound lane (`copy_for_audio`), never on the screen: the press logs and tells "Copying Take 1 out for an audio track", and the sound reaches the sound loop on a later frame (`SamplePage::take_to_audio`, drained by `Player::take_actions`). The job is keyed by its sound and span, so pressing again while it waits doesn't make two. Its memory is the copy, and when converting a second copy and the converted floats twice over (`sample_page::to_audio_need`), checked by the service as it starts in place of the screen's check (phase 1 step 5's stopgap, now gone); refused, it says why ("sample: Take 1 not put on an audio track: not enough memory: needs about …"). A sound never changes once made, so a copy is right whatever is edited while it is made. On the 25-minute take of phase 1 step 5, that is 178 ms of copying and 5.2 s of converting off the screen.
- **Normalize** reads a short region (up to `SCAN_FRAMES`, about 6 s) where it is, and a long one from its sound's summary, on the screen as in phase 1: neither copies, and neither takes a millisecond. What read every frame of a long region on the screen now does it on the sound lane (`SamplePage::peak_off_screen`, keyed by the layer, so a second press takes its place): a sound with no summary, a fallback still counted, logged ("sample: fallback: pad A5's peak read from every frame off the screen: its sound has no loudness summary (1 so far)") and shown; and a sound whose waveform, and so its summary, waits for memory, which Normalize no longer waits for, since reading the frames needs none ("sample: pad A5's waveform waits for memory, so its peak is read from every frame instead, off the screen"). A Normalize already waiting for its summary goes the same way once its waveform is refused (`normalize_later`). The peak lands on a later tick (`SamplePage::peaks_in`) as an undo step of its own, while the region is exactly as it was pressed on; one changed since is let go ("sample: pad A5 not normalized: it changed before its peak was found").
- **Loads and kits** (step 7g) run on the file lane, one of each at a time (keys `load`, `kit` and `open`): the browser's Load and Load to pad (`SamplePage::load_file`, first in the lane), a kit file (`open_kit_into`) and a project's kits (`open_part`). Each still checks every sound against the 256 MB floor as it decodes it (`memory::decode_need`), as before, and a newer one of a kind takes the place of one waiting; one running finishes and is let go, as a load replaced always was. A long analysis on the sound lane never holds them up (`a_load_lands_while_long_work_holds_the_sound_lane`). One that stops before it finishes says so ("the kit Drums wasn't loaded (it stopped before it finished)").
- **Refused views.** A view refused for memory keeps its flat line and its summary stays pending, so the grain start waits for it as it waits for any view; Normalize reads every frame instead (step 7f, below). The log says why once ("sample: Take's waveform waits: not enough memory: needs about …; asked for again every 5 s while it is loaded"), and the view is asked for again every 5 s (`views::RETRY`) until it fits or the sound leaves the kits.
- **Nothing on the screen.** A worker that can't start is counted (`Counts::spawn_failed`) and logged, and its jobs wait for the next try, which comes with the next job. The views never work anything out on the screen, not when the worker can't start nor for Map to keys. `Jobs::in_place` runs jobs on the caller, for tests only.
- **Counted and shown.** Dev > Debug shows "Sampler: work refused for want of memory" and "Sampler: background workers that couldn't start" once either has happened (`SamplePage::jobs_counts`).
- **Tests:** `mpfree-sampler` `jobs::tests` (order, replacing, stopping a running job, promote, cancel and retain, the two lanes, the memory account, in place, starting and stopping workers); `mpfree-app` `views::tests` (the views on the sound lane, a refused view that says why once and is asked again, one that comes once memory is free); `gui::tests` `map_to_keys_waits_for_its_sounds_notes_to_be_worked_out_off_the_screen` (waits and maps, a kit changed meanwhile, a sound refused for memory), `normalize_on_a_long_take_waits_for_its_summary_and_finds_the_same_peak` (its waveform waiting for memory, pressed before and after: the same peak, off the screen; a region changed meanwhile) and `put_on_audio_track_sends_the_slices_sound_for_an_audio_track` (nothing sent while the service is held, then the sound; refused for memory); `sample_page::tests` `put_on_audio_tracks_copy_converts_a_sound_at_another_rate_and_moves_its_cuts`.

**What stays as it is:**

- Rust, and today's crates.
- One grain engine for the pads and Grains FX.
- Sounds that never change once made, and engine views built off the audio thread and swapped in whole.
- The fixed voice pool, the grain arrays made up front, and the two-core split.
- Regions, layers and slices that never touch the sound, and undo per kit.
- The one Sample page.
- The grain level law, which gets measured, not replaced.
- Warp's stretch.
- The recorder.
- `mpfree-mod` as the one modulation system.

## Threads

| Thread | Priority | Core | Period | Owns |
|---|---|---|---|---|
| Audio | `SCHED_FIFO` 70, memory locked | 3 | every ALSA period (128 frames, 2.9 ms) | The `Engine`: voice pool, mixer, rolling buffers. Reads capture, writes playback |
| Control | normal, high nice | 1 | event-driven, at most every 1 ms | The `Project` model, the command queue, the undo log; turns hardware and UI events into commands |
| Workers (2) | normal, low nice | 0 and 1 | job queue | Loading, decoding, analysis, stretching, rendering, saving, recording to disk |
| UI | normal | 0 | redraw at most every 33 ms, only what changed | The `Ui` from `mpfree-ui` and the sampler screens |
| Input | normal | 1 | blocking reads | Controller MIDI and touch events, forwarded to Control (pad hits also go straight to Audio, see below) |

**Pad latency path.** A pad hit must not wait for the control thread. The input thread sends the hit to the audio thread directly on a dedicated ring (`PadHit { pad, velocity, time }`), and a copy to Control for the UI and recording. The audio thread looks the pad up in its own snapshot. This keeps the pad-to-sound path as short as the pad player's today; round 4 measures that path on the device.

**As built:** there is no control thread and no shared pair of workers. The model lives on the screen thread (`mpfree-screen`). The audio thread runs at `SCHED_FIFO` 70, on core 3 when Prefs "Sound cores" says so, and half the drum voices can run on a lane on core 2 ([`Engine::split`](#performance-budget)). Background work runs on the job service and five kinds of thread of its own ([As built](#as-built-22-nov)); step 7 moves the rest onto the service.

## Data flow

```text
                 commands (rtrb, bounded)                     snapshots (rtrb of Arc-like handles)
   UI ──────────────► Control ───────────────────────────────────────────────────► Audio
   Input ───────────► Control         ▲                                               │
   Input ── PadHit ───────────────────┼───────────────────────────────────────────►  │
                                      │ jobs                                          │ events (rtrb, try_send, drop + count when full)
                                      ▼                                               ▼
                                   Workers ──── results ────► Control ────► UI    Control (meters, playheads, takes)
                                      ▲
   Audio ── capture ring (rtrb, 2 s) ─┘  (recording to disk)
```

Every queue is a bounded single-producer single-consumer ring (`rtrb`). The audio thread only ever uses non-blocking `push`/`pop`; when a ring to the UI is full it drops the message and counts it, as the pad player does.

### Snapshots, not shared mutation

The audio thread holds an `EngineView`: for each pad, the layers and regions it needs, already resolved into plain numbers and handles to sample memory. When the model changes, Control builds a new view for the changed pads off the audio thread and sends it. The audio thread swaps it in at the start of the next period. The old view is returned through a ring to Control, which drops it there, so the audio thread never frees memory. (`basedrop`'s collector does the same job for shared sample buffers.)

A playing voice keeps its own handle to its sample buffer, so replacing or deleting a sample while it plays is safe: the buffer is freed only when the last voice stops.

**As built:** the screen thread stands where Control is drawn. It builds a kit's view and sends it in a `ViewSwap`, and the old view comes back in the same box to be freed there (`Player::swap_view`).

### Sample memory

| Item | Plan |
|---|---|
| Format in RAM | Interleaved, 44.1 kHz, as `model::Pcm`: `i16` when every sample is a 16-bit value exactly (a 16-bit WAV or AIFF, and what is cut from one), else `f32`. A mono source is stored mono and read with a channel flag. See [16-bit sounds](#the-voice) under the voice |
| Pool | One `mlock`ed arena reserved at start-up (size from settings, default 1 GiB, measured on the device), carved into buffers by a simple allocator on the control thread. No allocation from the system heap per sample, so memory use is predictable and never pages. Not built: see the floor below |
| Handles | `SampleRef` = index + generation into the arena, reference-counted; the audio thread only increments and decrements counts, and frees go back through a ring |
| Long sources | First version: everything in RAM. Later (S8): sources over a size limit stream from disk with the first second resident. Not built: the refactor's step 22 |
| Floor (as built, 14 Nov) | There is no arena yet: sounds come from the system heap. So the pad player refuses a load that would leave less than 256 MB free (`MemAvailable`; `mpfree-app` `memory.rs`): a Load or preview from the browser, each of a project's sounds as it opens, a stretched copy (the pad repitches instead) and an auto-sample (its `Plan::estimate`). The refusal says what it needed and what was free, in the log and in place of the hint. See [profiling.md](profiling.md#memory-floor-refuse-a-load-rather-than-be-killed) |

On a 32-bit process the address space is about 3 GB. A 1 GiB arena, the rolling buffers (about 85 MB), the UI (under 64 MB) and the engine (under 64 MB) fit with room to spare.

                 slice_sets: Vec<SliceSet> /* each slice's own settings, by number (R4 part 5) */ }

                  fade_out_ms: Option<f32>, to_end: bool }

## Recording

```text
 audio thread, every period:
   capture[128 frames] ──► input rolling buffer (ring, 2 min)        (always)
   master[128 frames]  ──► master rolling buffer (ring, 2 min)       (always)
   if a take is armed:  ──► take ring (rtrb, 2 s) ──► writer worker ──► arena buffer (+ WAV on disk for long takes)
   threshold armed:     detect crossing on capture (peak of block > level) → mark take start = onset − pre-roll
```

- **Rolling buffers** are plain ring buffers of `f32` in the locked arena, written with a wrapping index. A "skip back N seconds" or "last N bars" command from Control copies the span out on a worker while the ring keeps going; the ring is long enough (2 minutes) that the span cannot be overwritten during the copy for any span up to 1 minute.
- **Threshold** compares the block peak with the level on the audio thread (cheap), and the exact onset inside the block is refined later by the analysis.
- **In-time takes** start and stop on bar lines computed from the transport's sample-frame position, so the take is an exact number of bars.
- **Capture device.** The time engine's looper opens it (`looping.rs`, `LineIn`), and the sampler reads the same period from `LoopHost::input`. Planned: open `pcmC1D0c` (the ACVA capture PCM, observed stereo S32_LE at 44.1 kHz, 128-frame periods), link it to playback so both start together, and read one period per playback period. Capture and playback xruns are counted separately.
- **What is built (step CAP, `record.rs`).** The line input reaches the sampler, not yet the master: `record::input(seconds, rate)` makes a stereo rolling buffer with its bar lines, as a `Feed` (the audio thread's end) and an `Input` (the screen thread's). The pad player keeps 75 s (about 26 MB) and only while the line input is on (below). Bar lines come from the transport's spans each period and are marked in the buffer's own frames (`bar_lines`, the latest 256: two minutes of 4/4 bars up to 512 BPM), so the buffer's frame count need not equal the transport's. A `Recording` starts now, over a threshold with pre-roll, or on the next bar line, and ends on a press, on silence, after a number of frames, or on the n-th bar line after its start; it copies itself out of the buffer as it grows (the screen thread polls it about 30 times a second), so it is not limited to the buffer's length; the longest take is 3 minutes. A stop while it waits records nothing. `Input::last_frames` and `Input::last_bars` are Skip back; `Pick` keeps both channels, the left, the right or a mono mix. `Project::put_source` puts the sound on a pad as one undo step. The threshold is found by the poll on the screen thread rather than on the audio thread, which only appends; the pre-roll comes from the buffer, so nothing is lost. Resampling (step RESAMP, below) feeds the same buffer from a point in the mix; `RollingWriter::restart` (`Feed::restart`) marks where a new source begins, and readers stop there as if everything before had been overwritten (`oldest`, `copy`), so Skip back and a pre-roll never mix two sources. A bar line can be marked ahead of the audio (a point in the mix hears the block late); `Input::bars_back` and `last_bars` use the latest line that has come in, and a take on the next bar waits for its audio. A press (`Recording::stop`, `Take::stop_at`) ends a take at once, also before a length it had not reached. A recording that ends on a length or a bar line has a `Tail` (`Recording::with_tail`): `Cut`; `Ring(RingOut)`, which goes on past its cut (`Take::cut_at`) until it has been at or under a level for a quiet time and ends after the last frame over it, at most `max` frames on (`Take::ring_out`); or `Loop`, a loop of exactly its length without a seam (`Looped`): if its source was sounding in the quiet time before it started, the music was going round and its start already holds the ringing of the time before, so it is cut on its length and done there; otherwise it rings on for at most one more of its own length (`Take::ring_out_once_round`), and the ringing is folded onto its start (round and round when longer than the loop), or, when it still sounds a whole length on, the music went on round and the take is that second time round, which starts with the first's ringing (`tests/record.rs`). Takes to disk are a later step.

## Playback engine

### A period, in order

1. Swap in any new `EngineView`, apply parameter changes and voice commands from the rings.
2. Handle pad hits (from the dedicated ring and the sequencer): choose layers, steal or choke voices, start voices.
3. Render each active voice into its pad's bus (block-wise, 128 frames, or split at sample-accurate event times).
4. Pad buses through pad FX, then into the master; master into playback.
5. Copy capture and master into the rolling buffers; push take frames.
6. Push meters, playheads and grain positions to the UI ring (at most once per UI frame's worth of periods).

### The voice

- **Position:** 32.32 fixed point (integer frame and fraction), increment from pitch × rate ratio. Fixed point avoids `f64` drift on long loops and is cheap on ARMv7.
- **Interpolation:** 4-point Hermite at or below a sound's pitch and up to two semitones above it; past that, a band-limited sinc read (below); the stretch engine's own sinc in offline rendering. Reads clamp to the region's ends.
- **Clean pitching** (`bandlimit.rs`; the sampler review's decision 2, Jay, 16 Nov). A voice reading its sound `r` times faster than the output's rate moves everything up by `r`, and what lands above the output's Nyquist frequency folds back as aliasing: with Hermite, a 15 kHz tone an octave up came out as a 14.1 kHz tone at −9 dB, and a 96 kHz file's 30 kHz content at −10 dB. Once a voice's step passes `CLEAN_ABOVE` (two semitones up; up to there what folds lands above 19.35 kHz) it reads band-limited for the rest of its life (`Voice::bl`, switched on the exact frame, so the sound doesn't depend on block size): each output frame is a sum of the frames around the position weighted by a Kaiser-windowed sinc (8 zero crossings a side, β 5) stretched by `r`, so the cutoff sits at the output's Nyquist frequency at any speed; the weights are normalised. The kernel is a table (128 entries per crossing, value and slope, read with a 16-bit fixed-point place, so a weight is one multiply and add and there are no bounds checks), and the read walks out both ways from the position at once. The stretch never passes 2, so a read costs 16 to 32 taps a frame: past an octave a voice reads an **octave copy** of the sound instead (`Octaves`: low-passed by a half-band filter, 47 taps, β 7, and halved, up to 5 octaves; together less memory than the sound), at `r / 2^k`. Copies are made when a pad could pass an octave (keys, a tune or 16 Levels reaching that far, pressure on pitch): at once for sounds up to 2^15 frames, on the [job service](#the-job-service-step-7)'s sound lane for longer ones up to 2^23. A voice uses the copies only if they were there when it started, so a voice never changes what it reads mid-note; one that starts before them, or that a live tune (`PadLive`, `ProgramLive`, which the view doesn't count) takes past an octave on a pad without copies, reads the sound with the sinc stretched twice, so what folds stays above about 16 kHz up to 2.5 times the speed and comes lower past that. An offline bounce should wait for the copies (`Source::make_octaves`). **Vintage** (`Pad::vintage`, saved with the kit, the Play page's Vintage row) keeps the Hermite read whatever the pitch. At or below two semitones up, clean and Vintage are the same bit for bit. Grains read the same way (R7 step A4, see Granular engine). Measured (`tests/clean_pitch.rs`): the 15 kHz tone an octave up −77 dB clean, the 96 kHz file's 30 kHz −145 dB, 8 kHz two octaves up (from a copy) −90 dB; a tone inside the band keeps its level within 0.3 dB. To hear it, `cargo run --release -p mpfree-sampler --example clean_pitch -- OUT` writes a sweep and a bright saw an octave up and a 96 kHz saw, each clean and Vintage (the sweep past Nyquist: −58 dB clean, −12 dB Vintage). Cost on the workstation: the read is 3 to 5 times Hermite's per frame; with the envelope and filter, a held clean voice costs about twice a held Hermite one in `--afford` ("Sampler, pads held pitched up"). The 20-pad bench case has 3 of its 16 sample pads past two semitones, so its count rose by about 11 % (blessed). On the MPC, the next device round measures it.
- **Other rates** (`Source::at_rate`, `mpfree_stretch::convert_rate`; decision 2 too). A sound at another rate than the output's is converted to it as it comes in: the browser's Load (the sound and the sounds its sidecar brings), a kit folder and a project's kits as they open. Otherwise a 48 kHz sound is read 1.09 times faster for ever (never a plain hit, so it counts against the full voices), and an 88.2 or 96 kHz one pays for the band-limited read. The conversion is the stretch crate's windowed sinc (24 zero crossings a side, β 8, about 80 dB of stop band, the cut at 97 % of the lower rate's Nyquist frequency), with a table of 2,048 or fewer phases when the rates share enough (48, 96, 88.2, 32 and 22.05 kHz all do) and the plain resampler otherwise. A tone keeps its level within 0.05 dB; from 48 kHz the band to 20 kHz is kept within 0.5 dB and what folds lands above 20.6 kHz or is 60 dB down; from 96 kHz, 30 kHz folds at −70 dB or less (`mpfree-stretch/tests/convert_rate.rs`). Everything placed on the sound moves to the same moments (`Rescale`: region, loop and crossfade, fades, warp pins, chop markers, a project's stored scenes), rounded to the nearest frame and kept playable (`mpfree-sampler/tests/rate.rs`); a project's undo history is forgotten when its sounds convert. The file on the stick is never changed. A minute of stereo takes 0.08 s from 48 kHz and 0.15 s from 96 kHz on the workstation (0.5 s for a rate sharing nothing, such as 44,099 Hz), on the load's own thread; the MPC is slower, by an estimated 5 to 10 times. Each sound converts once per load, so kits sharing a sound share its copy, and only while the copy (twice its size while it is made) leaves the memory MPFree keeps free; one without room stays at its own rate, still at its pitch, and the log lists it. The log says what was converted ("converted from 48 kHz to 44.1 kHz").
- **16-bit sounds** (`model::Pcm`, `dsp::Sample`; the sampler review's engine item 5). `Source::new` keeps a sound as `i16` when every sample is `k / 32768` for a whole `k` (`dsp::as_i16`; a −0.0 isn't), so a 16-bit WAV or AIFF, and anything trimmed, sliced or cut from one, takes 2 bytes a sample instead of 4: about 10 MB a minute of stereo, not 21. Every other sound (24-bit, float, a recording, a converted or stretched copy) stays `f32`. The id is the hash of the floats, as before, so projects and kits find their sounds as they did. Every read is generic over the sample type, so the engine reads either with the same code: the Hermite read and the plain copy (`render_plain_from`, `render_voice_from`), the band-limited read (`bandlimit::read2`), grains (`grain_clip::GrainClip`, read as `mpfree_grain::Clip` reads floats), the jump of a live edit, the preview, the screens' peaks (`PeakPyramid::build_from`, `columns_from` through `mpfree_analysis::Samples`) and the mono mix the hits and the note are found in. An `i16` reads as `x / 32768`, exactly the float a 16-bit WAV decodes to, so a 16-bit sound plays bit for bit as its floats did (`tests/sixteen_bit.rs`: plain, tuned down and up, a fifth and an octave and a half up through the copies, Vintage, forward and ping-pong loops with crossfades, reversed with fades, filtered with an envelope, grains, mono and stereo; `no_alloc.rs` plays 16-bit layers and grain clouds in its busy kit). The hot loops scale once instead of once a sample (`Sample::raw` and `SCALE`, a power of two, so the result is the same). Octave copies and stretched copies stay floats. Saving writes a 16-bit sound straight from its samples (`wav::write`). Cost, in instructions per block under callgrind against the same sound as floats: 16 held looping pads +0.3 %, the drum kit's plain hits +3.6 %, 16 pads pitched up through the band-limited read +17 % (each tap converts its sample); sounds held as floats cost what they did. The memory pages (`Held::samples`, `mpc-import`'s estimate, an auto-sample's size) count the bytes each sound really takes.
- **Loop:** forward or ping-pong between loop start and end, with an equal-power crossfade of N frames precomputed as a short table at region change.
- **Envelopes:** AHDSR as a per-sample multiply with a per-block recomputed segment rate (exponential segments as one multiply per sample).
- **Filter:** a topology-preserving state-variable filter (LP/HP/BP and Notch, 2-pole; 4-pole as two in series), coefficients updated per 16-frame sub-block when modulated; and from sampler R5.6 a Ladder with Drive, a Vowel and a Comb (see Filter types below).
- **Declick:** a 64-frame fade on a hard stop (`KILL_FRAMES`) and a 32-frame fade on a steal or choke (`STEAL_FRAMES`). A Gate pad let go fades by its own release, which is exponential: at the Play tab's shortest (1 ms) it steps more sharply than a steal, and at 0 ms (from a file) it is one frame and clicks (the lab's S4, below).
- **Measured** (`mpfree_fxlab::sampler`, the sampler review's engine item 7): pitched reads, what must fold away, loop seams, voice stops and the filter against its analog prototype, held by a ratchet (`tests/sampler.rs`, `quality/sampler.tsv`) on every workspace test run. The numbers and what they found: [FX quality, The sampler](fx-quality.md#the-sampler).
- **Pressure:** each pad has one pressure route (`Pad.pressure`: a `PressureTarget` and a depth from −1 to 1). `Event::Pressure { pad, value }` (0-127, from the pad's polyphonic aftertouch) moves that pad's playing voices; a voice that starts later begins unpressed. Pressure is smoothed with a 5 ms one-pole. Full pressure at depth 1 gives +12 dB level (the gain glides over each 16-frame sub-block, so it never clicks), +12 semitones pitch (sample voices change their step; granular voices change the grain pitch), +4 octaves of filter cutoff (needs the pad's filter on), ×16 grain density, ×8 grain length, the grain position moved by the whole region (wrapping), or +100 % spray. A negative depth moves the other way. Built and tested (`tests/pressure.rs`); it also runs in `tests/no_alloc.rs`.
- **Voice allocation:** a fixed pool (start at 64, set by measurement). Stealing order: same pad's oldest voice if the pad's polyphony is exceeded; when the pool is full, the oldest releasing voice, then the oldest voice of the pad holding the most voices, so a pad hit over and over (Note Repeat on a long sound) gives up its own voices before another pad's sound is cut short (`a_full_pool_takes_from_the_busiest_pad_first`; Jay's round 4 log had 1,592 steals in 2,545 hits, mostly long sounds stacked by repeats). **Plain voices** (Jay, 16 Nov: more drum hits at once rather than cutting them): a voice whose next frames are a plain copy of its sound at a fixed gain (forward at the sound's own speed from a whole frame, no loop, fades, filter or pressure, its amp envelope holding its sustain, no kill fade or stolen tail under way: `plain_now`) renders through `render_plain`, a multiply and an add a sample, bit for bit what the full loop gives (`a_plain_voice_renders_as_the_full_loop_does`); any other frames go through the full loop, so a plain voice that starts following a live level, is released or is stolen just takes the full loop for those frames. A hit whose settings make it plain from its first frames (one-shot, at its own pitch, envelope open, no filter, pressure, wow, fades or channel pick, the tape running: `Voice::light`) may take a voice past `Engine::set_full_voices`; any other hit past that limit takes the place of a full voice, by the same order as above. The bench's "Sampler, drum kit" cases put 24 plain voices at about a tenth of what they cost through the full loop. The pad player's pool is 64 voices (`sampler::POOL_VOICES`), at most 24 of them full (`kit::MAX_VOICES`, what the whole pool was), and its kit pads hold 4 each (`sampler::KIT_POLYPHONY`), so with Note Repeat every pad can hold four sounds; a sound loaded from the browser onto an empty pad gets the kit pads' polyphony and centre level (`sampler::kit_pad_with`), so it plays as loud as theirs. Under load the app may give up voices too (`Engine::cull_candidate`, `Engine::cull`; counted in `Stats::culls`): the least audible one here, by what it has played lately (`Voice::heard`: its last output sample at the end of each render, held and falling 16 % a render, starting at its gain), releasing voices counted 12 dB quieter; auditions, voices already fading and the lane's share while it is away are left be ([profiling.md](profiling.md#load-shedding-giving-up-voices-nobody-hears)).

### Live settings and the hard stop

What the synth thread's sampler node (#152) asked for, so a node parameter, a p-lock, a macro or a modulation can move a pad without a new view.
- **`Event::PadLive { pad, field, value }`** sets one of a pad's settings while it plays (`PadField`): Level (dB), Pan (−1 to 1, each layer's own pan adds to it), Tune (cents), Cutoff (Hz), Resonance (0 to 1), the amp envelope's Attack, Decay and Release (ms), the Slice a sliced pad plays (0 = slice 1, rounded; see Sliced pads below), and, from sampler R5 part 4, the LFO's depth (−1 to 1), the pitch envelope's start (semitones) and its decay (ms) (see Movement below). The value replaces the pad's own (NaN gives the pad's own back), clamped to the field's range (`PadField::clamp`). A cutoff on a pad whose filter is off gives it a 2-pole low-pass. A cutoff set this way also replaces 16 Levels' cutoff.
- **`Event::ProgramLive { field, value }`** moves every pad at once (`ProgramField`): dB on every level, cents on every tune, octaves on every cutoff. Below 0 octaves, a pad without a filter gets a low-pass too, so the whole kit darkens. 0 or NaN is no offset.
- **`Event::PadLock { pad, field, value }`** is a step's lock on the same fields (the sequencer's `Event::Lock` on a pad's sound, sequencer S1 locks; see [step-pads.md](step-pads.md#locks)), in a table of its own: a field plays its live value where one is set (the scene crossfader goes over a lock), else its lock, else the pad's own (`Live::row`). NaN ends the lock. A new view keeps the locks. A locked Decay also makes the sound decay to silence (sustain 0), as the Play page's Decay knob does, so a lock shortens a sound that plays out. `Engine::pad_lock_value` reads one back.
- **New voices** start with all of them. With none set, a voice starts exactly as before, bit for bit (the bench's golden sounds don't move).
- **Playing voices** follow Level, Pan, Cutoff, Resonance and the program's three offsets: `retarget` points each one at its new values, and the voice glides there with a one-pole (10 ms) stepped every 16 frames, linear within the step for the gain and in octaves for the cutoff. A voice works from the pad's own settings as they were when it started, so a new view (`set_view`) never jumps it; an edit (`edit_view`, below) moves them. Tune, Attack, Decay and Release reach new voices only. A warped layer keeps its pitch: its tune lives in its stretched copy.
- **The tables** are fixed (`[[f32; PadField::COUNT]; 128]`, 12 fields, for live values and another for locks, and 3 offsets). `Engine::set_view` puts the pads' live fields back to their own; the locks and the program's offsets stay. Both events go through the event queue, so they land on their frame for any block size, and split they apply while both halves of the voices are home.
- **`Engine::stop_all()`** is the hard stop for a reset or a panic. Every voice and its grains go idle at once, the master effect's grains stop and forget what they hold, and the events waiting are dropped. It never allocates. Split, a half still away on a late lane stops as it comes back. `Event::AllOff` stays the gentle one (a release).
- **Tests** (`tests/live.rs`): a level change lands on its frame and plays the same in blocks of 1, 37, 128 and 1000 frames, gliding without a jump. A p-locked hit plays as a pad set that way would (within 1e-4). Playing voices follow pan, the program's cutoff (down and back up) and level, and the program's tune (playheads read twice as fast an octave up). NaN and a new view give the pad's own back. A locked hit plays as a pad set that way, and a live value goes over the lock; a lock stays through a new view and moves a sound still ringing; a locked Decay shortens a sound that plays out. Split or not, a busy performance with live changes plays the same (bit for bit on the lane's own core). After `stop_all` nothing plays or waits, even with the lane's half away. The no-allocation tests (`no_alloc.rs`, `split_no_alloc.rs`) send live changes, clear them and stop everything in their busy sessions.

### The event queue and let-gos (sampler plan, phase 1 step 2)

A let-go is never lost, however full the queue (20 Nov 2026; before, a full queue refused let-gos like anything else, the callers didn't look, and the note hung).
- **The queue** holds `MAX_EVENTS` (256) events of every kit, sorted by frame, events at the same frame in the order they came. `schedule_for` returns false only for a kit out of range or an event the full queue refuses.
- **With the queue full**, in order: a pressure or live value (`Event::Pressure`, `PadLive`, `ProgramLive`) whose kit, pad and setting already has one waiting merges with the newest of them (the newer of the two stays; one that comes with an older frame than the one waiting gives way to it); then any event may take the place of a value that has a newer one for its pad and setting behind it (`make_room`, a scan of the queue that runs once until a value goes in again). Both count in `Stats::merged_values`.
- **Let-gos** (`Event::lets_go`: `NoteOff`, `KeyOff`, `TakeOff`, `AllOff`) that still find no place wait aside (`wait_late`), in a table with one place for every pad number, key and take of every kit (`LET_GO_PLACES`, 513 a kit, offsets as `u32`) and one for all notes off, with the list of places in use; both are made in `with_kits`, so the table can't run out and never allocates (about 0.5 MB for 128 kits). The render lands each on its frame, after the queue's events for that frame, exactly as from the queue (`land_late`; the part of the block ends there too). Two let-gos of one place land together on the later frame, so a hit queued between them is let go of late, never left playing; a hit queued for the frame a waiting let-go lands on moves one frame later, so it still comes after it. Counted in `Stats::late_let_gos`; `Engine::late_waiting` says how many wait. `stop_all` forgets them with the queue.
- **Everything else** the full queue refuses: false, `Stats::dropped_events`, and for a hit (`Event::is_hit`: `NoteOn`, `Key`, `TakeOn`, `Audition`) also `Stats::refused_hits`. A step's lock (`PadLock`) doesn't merge: each step's value is heard.
- **In the pad player**, `Player::hit_kit_at`, `key_at` and `take_at` return false for a hit the queue refused, so a refused hit counts as silent, not played. The Dev tab's Debug page has "Queue full: let-gos kept aside · values merged" (amber when either is above 0) next to "Events dropped", and the 30 s status line's `sampler:` part gives all four counts. All notes off and STOP (`Player::stop_all`) apply at once and never use the queue.
- **Tests** (`tests/let_gos.rs`, under a counting allocator): 41 notes held across two kits' pads, a keygroup's keys and the take, the queue filled with values that can't merge, then all let go at once: every voice is releasing within the period, nothing is refused and nothing allocates. Let-gos waiting aside land to the sample where they would from the queue (one in the next render, not a frame early). Pressure on a held pad fills the queue and a let-go takes the oldest value's place; a knob's newer turn merges and an older one gives way. A hit the full queue refuses is counted, and all notes off scheduled on a full queue lands on its frame. Two let-gos of one pad waiting aside land together on the later frame; a hit on the frame of a waiting let-go plays on. `held_voices` counts what a let-go would release.

### Edits reaching a sounding voice

The sampler review's engine item 4 (R2): before, a voice kept the settings it started with, so a loop point dragged on a held pad was heard only on the next hit. `Engine::edit_view(view)` swaps in an edit of the kit playing now, as `set_view` does (the old view back to the caller, live values cleared), and then each playing voice whose layer in the new view still plays the same audio (same pad and layer index, same `Arc` of samples, channels and rate) follows it (`follow_edit`). It never allocates. `set_view` stays for another kit, whose pads are other pads, so its voices finish as they began.
- **Loop points** at once, kept inside the region the voice plays (`follow_loop`). A loop that moved ahead of the voice is reached on this pass; one moved behind it (the voice past its new end, or a ping-pong voice going back below its new start) takes the voice into the loop at once: forward, at the same place in the loop, wrapped; ping-pong, turning at the end. The jump's step is not heard: the read before and after it is taken (Hermite, pre-gain), and the difference is added back to the read and faded out over `JUMP_FRAMES` (64 frames), so the sound stays continuous through the filter (`tests/edits.rs`: the largest step at a jump of 2000 frames is under a 32nd of it; without the fade it is the whole jump). A loop taken away lets the voice play on to its end; one added while it is held starts it looping. The crossfade follows, kept within the loop's half and before its start.
- **Level, pan, cutoff and resonance** glide there as live settings do (`retarget`, 10 ms one-pole): the voice's own values (`Follow::own_db`, `own_pan`, `own_fc`, `own_res`, and its unit gain from the layer's gain under the hit's own, `Voice::hit_gain`) move to the new view's. A low-pass turned on comes in from open (22 kHz); one turned off opens. Another filter type or pole count, and a cutoff 16 Levels set, stay.
- **Tune** at once, as a knob step would: the voice's step scales by the layer's new step over the one it plays (`Voice::layer_step`), so a keygroup's semitones and 16 Levels' tune stay on top; past two semitones up it reads band-limited from that frame on, as a glide would. A warped voice's speed stays the tempo's.
- **A granular voice** takes the layer's new grain settings (`Voice::layer_grain`), keeping what its hit added (a keygroup's semitones, 16 Levels' position).
- **What stays:** the region's start and end, fades, play mode, direction, envelope, filter type, pressure route, the sound itself, and Vintage. An edit of those, or another sound on the pad (another `Arc`), is heard from the next hit.
- **Split:** the voices on the lane's share follow when they are home; if the share is away (late) when the edit comes, it follows when it comes back (`Engine::edit_lane`, a flag per kit, cleared by a `set_view` of that kit).
- **In the app** `sampler::Player::swap_view` uses `edit_view` for the playing kit (each Sample tab edit sends the kit's view again, about once a frame while dragging), and `select` (another kit) `set_view`. The instrument node (`node.rs`) still swaps with `set_view`: its views are new sounds or another kit as often as edits.
- **Tests** (`tests/edits.rs`): a held loop, forward and ping-pong, jumps into a loop moved behind it and stays there, with the step spread over at least 32 frames; a loop moved ahead is played through to its new end and then looped; the same edit as another kit (`set_view`), or another sound on the pad, leaves the voice as it began, sample for sample; level goes 12 dB down gliding, and pan hard right silences the left; a cutoff edit darkens a held sound, and a low-pass turned on comes in from open; a tune of a semitone plays 2^(1/12) frames a frame from where it was; a grain cloud gets denser; split, voices on both cores follow. `no_alloc.rs` swaps an edit of its busy kit in and out every 40 blocks. In the app, `sampler::tests::an_edit_reaches_the_sound_still_playing_and_another_kit_does_not`.

### Movement: the pad's LFO and pitch envelope (sampler R5 part 4)

A pad has an LFO (`PadLfo`: one of the grain LFO's `LfoShape` waves, a free rate of 0.01 to 40 Hz or a cycle of 1/8 to 64 beats, a target, a depth of −1 to 1, Retrig), a pitch envelope (`PitchEnv`: a start of up to ±24 semitones, back to the pad's pitch over 1 ms to 10 s) and two velocity routes (`vel_to_cutoff`, 0 to 1: a soft hit up to 4 octaves darker; `vel_to_pitch`, ±12 semitones: the softest hit that far below the hardest). All default to off, and a pad that uses none plays bit for bit as before (`a_pad_with_no_movement_plays_exactly_as_before`).
- **Per voice** (`Motion`, in `Voice`): worked out every `FILTER_STEP` (16) frames in `motion_step`, as pressure is, and only while `Motion::on` (a voice with nothing moving costs one branch a frame and keeps the plain fast path, `plain_now`; a light voice needs none). The LFO's wave times its depth gives `x`: on **Pitch** 1200 `x` cents, on **Cutoff** a factor 2^(4`x`) on the cutoff (with pressure's, through `retune`'s key cache, so a filter that doesn't move costs no `exp2`/`tan`), on **Level** a gain 1 − (|d| − `x`)/2 (from full to 1 − |d|), on **Pan** a quarter-sine balance; level and pan glide across each step, linear per frame. The pitch envelope's cents fall by `env_k` a step (to a ten-thousandth, e^−9.21, over the decay) and stop below 0.01 cents. Velocity's cents and cutoff factor are fixed at the hit (`motion_for`: soft = 1 − velocity). Pitch changes go through `retime` with the voice's other cents, so the band-limited read and the octave copies follow; a warped layer and a grain voice keep their pitch (`Motion::pitched` false).
- **Phase.** With Retrig on, each hit starts the wave at 0. Off, a hit joins one shared wave (`Engine::free_phase`): on the transport's beats when the LFO is synced and the transport rolls (`Engine::set_beat`, once a period from the first span of the block: `Player::set_beat` in the pad player), else on the engine's frame count at the hit's frame (`event_frame`), so hits on different pads at one rate agree. Hold and Drift draw a new value each cycle from a generator seeded from the clock.
- **Tempo.** A synced LFO's rate follows `set_tempo` and each lane's tempo (`Motion::retempo`).
- **Live and edits.** `PadField::LfoDepth` follows playing voices (`retarget`), so a scene's morph or a knob reaches a held sound; `PitchEnv` and `PitchDecay` reach new hits (`motion_for` reads the live row). An edit (`edit_view`, `follow_edit`) gives a playing voice the new LFO shape, rate, sync, target and depth at once, keeping its phase; the pitch envelope and velocity routes are the hit's.
- **Saved** in the pad's `lfo` and `pitch_env` scopes and its `vel_to_cutoff` / `vel_to_pitch` keys; older kits open with all of it off. `Project::check_pad` refuses values out of range.
- **On screen:** the Play tab's Movement section (below) and two more rows on Mod.
- **Tests** (`tests/movement.rs`): a pad with none plays exactly as before; a vibrato's pitch swings by the depth at the rate; the pitch envelope starts an octave up and lands back on the pad's pitch; velocity lowers the pitch and darkens the sound; tremolo and pan move the level and the sides; a cutoff LFO opens and closes a filter; Retrig off joins one wave, and synced it lands on the transport's beats; a live depth and live pitch envelope; an edit reaches a playing voice. `lfo_pitch_envelope_and_velocity_routes_save_and_open` (`tests/save.rs`).

### Mono, Legato and Glide (sampler R5.5)

A pad with keys can play one note at a time (`Pad::mono`, a `Mono`: `on`, `legato`, `glide_ms` 0 to 2000 (`GLIDE_MS`), `glide_held`), as a mono synth's keys do and as the MPC's keygroup Mono, Legato and Portamento do. It applies to notes on the pad's keys (`Engine::key`, `key_off`, `Event::Key`/`KeyOff`, and pads that play notes); a hit on the pad itself, and a pad without keys, play as before (`ViewPad::mono` needs both).
- **Keys held** (`HeldKeys`, fixed size, `MONO_KEYS` = 10 a pad, oldest forgotten past that; `Engine::mono_keys`, `PADS` a kit): a key pressed is the newest (`mono_on`); letting go of the newest goes back to the newest still held, at its own velocity (`key_off` → `mono_play`); letting go of an older one changes nothing; `Event::AllOff` forgets them all.
- **A new note** (`mono_play`): without Legato, or with no other key held, the pad's voices stop (`kill`, the usual short fade) and the note starts through `note_on`. With **Legato** and another key held, `legato_to` moves the sounding voices instead: a sample voice's step is scaled by the interval (`plain_step`, `base_step`, `retime`), so its envelopes and its place in the sound go on; a grain layer's cloud moves with its own glide (`glide_held`, `Region::grain_glide_ms`); a warped voice keeps its pitch and only takes the note. If no voice sounds (a one-shot that ended), it starts the note.
- **Glide** is the voice's `Motion::glide_cents`, stepped with the LFO and the pitch envelope every `FILTER_STEP` frames in `motion_step`: it starts at the interval from where the pad's pitch is (`mono_pitch`: a sounding voice's note plus what is left of its glide, else the pad's last note, `Engine::mono_at`) and goes to 0 in a straight line in cents (`Motion::glide`), so every interval takes the glide time. **Glide on** Every note glides to each note, even after a let go; Held keys (`glide_held`) only to a key played while another is held. A sliced pad (a slice a note) never glides or holds legato.
- **Saved** in the pad's `mono` scope (`on`, `legato`, `glide_ms`, `glide_held`); older kits open with it off. `Project::check_pad` refuses a glide out of range, and the engine's view clamps it.
- **On screen:** the Play tab's Pitch section (below).
- **Tests** (`tests/mono.rs`): the last key plays and letting go goes back to one still held; without Mono the keys play together; Legato goes on at full level where a new start comes in from silence, both ways; Glide is halfway in pitch halfway through its time; Every note glides from a note let go, Held keys jumps; Mono needs keys; All off forgets the keys. Save: `tests/save.rs` `mono_legato_and_glide_save_and_open`.

### Filter types: Notch, Ladder, Vowel and Comb (sampler R5.6)

Beside low, high and band pass, `FilterKind` has four more (the sampler review's gaps, the R5 plan's 5.6; saved as `notch`, `ladder`, `vowel` and `comb`, with the Ladder's `drive_db`, which older kits open as 0). All run per voice in `finish` after the gains, their settings from `retune` every `FILTER_STEP` frames through its key cache, as before.

- **Notch** (`Svf::process`, `x − k·v1`): the state-variable filter's band-stop, 2-pole or two in series for 4.
- **Ladder** (`dsp::Ladder`, one per voice, both channels): four TPT one-pole stages in a loop, solved without a delay in the loop (Zavalishin), feedback `k` = `LADDER_K` (4.2) × Resonance, so it sings from about 0.95. The feedback, not the sound, goes through `soft_clip` (a Padé fit of tanh, flat from ±3), so the singing settles at a steady level (about −10 dBFS) while an ordinary sound passes the loop straight; the output's make-up `1 + k/2` (`ladder_makeup`) gives back half the bass a resonant ladder loses. Its small-signal response is `m / ((1 + s)⁴ + k)` (`ladder_db`, which the Play page draws).
- **Drive** (`Filter::drive_db`, 0 to `MAX_DRIVE_DB` = 24 dB, the Ladder's only): before the loop, the sound times the drive's gain through a quintic smoothstep (`drive_curve`, slope 1 at 0, flat from 15/8 with its first two derivatives 0 there) at twice the rate: an IIR half-band each way (the 6-section elliptic design of mpfree-synth's Squelch and mpfree-fx's oversampler, `DriveOs`), each sample the curve's average over the step from the last (first-order ADAA; the antiderivative is a polynomial, so between ±1 the quotient is worked out as a polynomial in both ends, exact and with no division, `drive_average_u`). A scale after it (`drive_norm`, worked out when Drive changes) keeps a −12 dBFS sine at its RMS. Off at 0 dB (no curve, no cost); turned on mid-note it starts from its states settled on the current sample (`DriveOs::seed`), so it doesn't click. A playing voice follows a Drive change at once (`follow_edit`). Drive isn't a `PadField`, so locks and Q-Links don't reach it yet.
- **Vowel**: two `Svf` band-passes in parallel (each `k·v1`, peak 1), the second at 0.6 (`FORMANT_2`), at the formants of the vowel the cutoff picks (`vowel_formants`: Peterson and Barney's male averages for oo, oh, ah, eh and ee, spread on a log scale from 200 Hz to 5 kHz and glided between in pitch; `vowel_name`). Resonance narrows them, Q 5 to 12.5 (`vowel_resonance`), and a gain after them, `1.1 / sqrt k` (`vowel_gain`, kept in `Voice::vowel_gain`), gives back what narrower bands take, so a 110 Hz saw comes out within a few dB of its level at any resonance and a sine right on the first formant 8 to 12 dB over. `vowel_db` draws it.
- **Measured** (the FX lab, S5 and S6; [fx-quality.md](fx-quality.md#the-sampler)): each new type against its analog prototype within 1 dB (the Vowel 1.03 dB, warped near 8 kHz); Drive's worst alias, a 5 kHz sine at 0 dBFS through an open Ladder, −84 dB at 12 dB and −44 dB at 24 dB (the bare curve at the base rate: −18 dB), 2.5 kHz −109 and −65 dB. Cost (the instruction gate): "Sampler x16 held, driven ladder" 1.54 M instructions a block against 0.57 M for "Sampler x16 held" (resting 2-pole low-passes; the ladder case's envelope moves its cutoff too, so a driven ladder voice costs a little under 2.7 times; the Padé curve with its ADAA in 64-bit floats cost 1.92 M), "Sampler x16 held, vowel" 0.65 M, "Sampler x16 held, comb" 0.87 M (its envelope gliding the delay). A voice with a plain low-pass costs about 1 % more for the dispatch. The Comb (S5 and S7): within 0.05 dB of its prototype at resonance 0.5 and 0.34 dB at 0.9; its lowest peak 0.05 cents from the cutoff at 220 Hz and 0.3 cents at 3.3 kHz (a delay between frames); at full feedback pink noise comes out 2.2 dB and white noise 3.9 dB under dry (the Hermite read takes a little of the top each time round, so the ring is a little darker than an ideal comb's, like a plucked string), and a sine right on a peak 18.2 dB over (it makes no aliases of its own: a delay and a sum).
- **Tests** (`tests/filters.rs`): the notch takes out its cutoff and leaves the rest; the ladder falls 24 dB an octave and is as its picture; at full resonance it sings at its cutoff at a steady level; Drive adds harmonics and keeps the level, and turned up on a held note doesn't click; the vowel moves from oo to ee and a saw through any vowel keeps near its level; the comb rings at its cutoff (whole and between frames), its picture matches the engine, it rings on after its sound ends with no step and stops once quiet, and a choke stops it; `the_new_filters_and_drive_save_and_open` (`tests/save.rs`); the curve's average (`dsp::tests`).
- **Comb** (`dsp::Comb`, both channels): `y = x + g·y(t − D)`, `D` one cycle of the cutoff (`rate / cutoff`, 2 frames to one cycle of `COMB_MIN_HZ` = 20 Hz), read between frames with the 4-point Hermite the sample read uses, feedback `g` = `COMB_FEEDBACK` (0.97) × Resonance, so it rings at the cutoff and its overtones (at full feedback about 230 cycles to −60 dB: a second at 100 Hz). After the loop `sqrt(1 − g²)` (`comb_gain`) keeps white noise near its loudness at any feedback, and a one-pole DC blocker at `COMB_DC_HZ` (10 Hz) takes out the loop's peak at 0 Hz, which would lift rumble and any offset 18 dB. `comb_db` draws it (Cutoff's value and the section chip name the note it rings at, "220 Hz · A3"). The delay glides to each new cutoff over the `FILTER_STEP` frames until the next `retune`, so the envelope or a knob sweeping it doesn't step.
  - **Its line, allocated once:** each voice slot's `Comb` is made with the pool (`Pool::new`, a power of two long, 4096 frames of both channels at 44.1 or 48 kHz: 32 KB, 2 MB for the app's 64 voices) and stays with the slot: a new note takes it out of the old voice (`mem::take`) and `Comb::reset` forgets what it held without clearing it (a read past what was written since gives silence), so nothing allocates or clears 32 KB on a hit.
  - **Ringing on:** a comb voice whose sound or amp envelope ends goes on as its ringing (`Voice::ringing`, `ring_out`, out of line, from the frame the sound ended), until a whole cycle is under `COMB_QUIET` (−80 dBFS), so a hit's ring isn't cut where its sample stops. A cut (a choke, a steal, a stop) fades over the usual kill frames and resets the comb, so it doesn't ring on; `victim` takes ringing voices first, as releasing ones. A granular voice's comb stops with its grains.

### Kits in one engine

The sampler review's decision 1 (a kit per track, R3) needs several kits sounding at once. The first step is in the engine: `Engine::with_kits(rate, voices, kits)` plays up to `MAX_KITS` (128, one per sequencer track) kits from one voice pool. `Engine::new` is one kit, kit 0, and every call without a kit addresses kit 0, so an engine of one kit (the instrument node, the tests) works as before.

- **Each kit has its own** view (`set_kit_view`, `edit_kit_view`, `kit_revision`), live values, locks and program offsets (`Live`, one a kit), and Cycle turns. A new view for one kit clears that kit's live values only; an edit of one kit moves that kit's voices only.
- **Events name their kit:** `schedule_for(kit, offset, event)` and `apply_for(kit, event)`. One queue holds every kit's events, in the order they come (a let-go is never refused: [The event queue and let-gos](#the-event-queue-and-let-gos-sampler-plan-phase-1-step-2)), and applying one sets the kit being played (`Engine::at`) for the hit paths. A kit out of range gets nothing.
- **A voice knows its kit** (`Voice::kit`) as well as its pad, so a lift, pressure, a second hit on a toggle or latch, mute groups, chokes, links, polyphony, auditions and live chop act within the kit; kit 1's pad 3 never cuts kit 0's pad 3.
- **Stealing looks at every voice**, whatever its kit: a releasing voice first, then the oldest voice of the pad holding the most, counting each kit's pads apart (`Engine::held`, a table of kits x 128 made with the engine and zeroed again after each count, so it never allocates; an engine of one kit counts in a table on the stack, as it always did).
- **The output:** `PadOut::pad(kit, pad)` gets each voice's kit with its pad, so a host can send each kit to its own track's channel. `render` mixes every kit into the one pair. The master grain effect takes its settings from one kit's view (`set_master_kit`, kit 0 until set).
- **For the whole engine,** from any kit: `Event::AllOff`, `Freeze` and `Tape`, the tempo, `stop_all`, culling.
- **Readers per kit:** `kit_playheads`, `kit_pad_voices`, `kit_latched_pads`, `kit_grains_of`, `kit_pad_live_value`, `kit_pad_lock_value`, `kit_program_live_value`, `marking_kit`; the old names read kit 0.
- **Tests** (`tests/kits.rs`): two kits from one pool sound in their own pairs bit for bit as each would alone; a mute group, a lift and a group cut stay within a kit; live values, locks, offsets, a new view and an edit belong to their kit, and a kit out of range gets nothing; stealing takes kit 1's pad holding two voices before kit 0's older one; AllOff from any kit releases them all. `no_alloc.rs` (`kits_never_allocate`) plays four kits from 12 voices with hits, lifts, live values, locks, view swaps and edits of one kit while the others play, and the master following another kit, routed and mixed. The bench's "Sampler, 4 drum kits, 64 voices" keeps the pool full across four kits.

### Kits on tracks (the pad player)

R3's second part puts every kit in the pad player's engine at once, each on the tracks that play it.

- **What each track plays** is an entry of the list of kits: a kit (the Grains kit among them) or the synth after them (`sampler::TrackKits`, in the audio loop; a track with its own instrument or on MIDI Out plays that instead, as before). Every track plays kit 1 until a pick, so a project from before plays as it did.
- **Only a pick changes it:** the list of kits (Play's PADS PLAY or the Pads tab's Kit; the top bar's kit chip until the Play, Pads and Sequencer redesign) and SHIFT + wheel on Play set the armed track's entry (PAD BANK did too until part 2b made it the kit's pages). Opening a page never does (the sequencer thread's point, 17 Nov 17:43Z): the Synth tab on a track that plays a kit says on the hint line how to put the synth on it (`synth_tab_hint`), and the Sample tab no longer takes the pads back from the synth.
- **The pads play the armed track's entry.** Arming a track moves them there at the next period (`kit_follow`), as a pick would, without changing what any track plays. "The synth has the pads" now means "the armed track plays the synth" (`synth_on`). The pads held at a change let go where they were playing; nothing else stops, since other tracks may play the old kit or the synth.
- **Notes carry their track** (`time::Pads::hit_at(track, pad, ...)`, `Out::track`), so `SeqPads` plays each clip's notes on its track's kit (`Player::hit_kit_at`, `release_kit_at`, `pressure_kit_at`), on the synth for the tracks that play it, and a lock (`Owner::Pad(t, pad)`) on track t's kit. A key a route sends to a track that isn't armed plays that track's kit too. Only the hits of the kit the pads show flash them.
- **Every kit in one engine:** `Player::new` builds `Engine::with_kits` with every kit's view; `Player::select(k)` is the pads' kit (the hits with no kit, the keys, the playheads shown) and the master grain effect's settings (`set_master_kit`). A Sample tab hit plays its own kit's pad, whichever kit the pads play.
- **The mixer:** kit 1's pads A1-A16 play into the 16 pad channels and on to Drums, as before; a pad lent a channel (any other pad, R3 part 4a, below) plays into it; kit 1's other pads (PAD BANK B to H) play straight into the Drums track (`mixing::Pads`, `DRUMS_DIRECT`), so they go through its inserts, sends and fader, and the looper's dry drums take them in (`MixHost::drums`; `kit_ones_pads_past_16_play_into_the_drums_track`). Another kit plays into the channel of the first track that plays it (`TrackKits::homes`, `MixHost::pads_homed`: track t's channel is `mixing::track_channel(t)`, the one its own instrument uses: Drums for track 1, R3 part 4b below), and that channel shows in the Tracks view while it does (`MixHost::channels_in_use`). Tracks sharing a kit share its channel; a kit no track plays (heard from the Sample tab) sounds on the pad channels. Pad mutes are kit 1's A1-A16 alone: on a track that plays another kit the step grid shows no mutes (`PlayPage::pad_strips`) and its speakers, like TRACK MUTE's pad keys (`mute_key`, `no_mutes`), say so and mute nothing.
- **Lent pad channels (R3 part 4a).** The mixer has `mixing::PAD_STRIPS` pad channels: kit 1's 16, then `LENT` (48) lent to any other pad that is given effects of its own (`mixing::PadChannels`: each lent channel's holder, and each kit's pads' channel, fixed size, so lending and giving back never allocate). `MixHost::lend_pad(kit, pad)` lends one when the Pads tab's Effects row asks for the pad's chain (`Panels::open_pad_mix`): it starts plain, its output the kit's track (`MixHost::kit_track`; `route_lent` moves it when the kit's home does, unless the user sent it to a submix), and the chain editor and the mixer's Pads view name it by its pad and kit ("B5 · Kit 2", `mixing::lent_name`, `MixHost::strip_name`). `MixHost::give_back_plain` gives back every lent channel with no effects and every saved control at its default, when the editor lets a pad go and before a save (`MixHost::mixer_text`). `Pads::pad` plays a pad with a lent channel into it (its own bit in `Pads::played` for the looper's dry drums, when its kit plays into Drums). Saved as `lent ps16 1 20` lines in the mixer part (`project::mixer_text_lent`, `MixLoad::lent`; a line for a pad with its own channel, past the kits, or for a channel held already, is left out: `PadChannels::hold`); a lent channel left out of a project opens at its defaults (`project::untouched_channel`). With all 48 lent, the Effects row opens nothing and says so (`modpanels::no_channel`). Tests: `mixing::tests::a_pad_is_lent_a_channel_into_its_kits_track_and_gives_it_back_plain`, `project::tests::a_lent_pad_channel_is_saved_and_opens_lent_to_its_pad`, the smoke test `a_pad_past_a16_is_lent_a_channel_and_gives_it_back_plain`.
- **Drums is track 1's strip (R3 part 4b).** A track has one strip whatever it plays: track 1's is Drums, so its own instrument, a kit homed on it and kit 1 all play there, and every other track's is its own channel past the engines' (`mixing::track_channel`, agreed with the sequencer thread, 18 Nov). The parameter addresses use the same numbers (`mpfree_param::track_strip` and its inverse `strip_track`, with `ENGINE_STRIPS` asserted equal to `mixing::TRACKS`), so a clip's "this track's strip" lane on track t reaches `track_channel(t)`, and a knob turned on Synth, Loop or Audio is no track's (it used to record as a lock of tracks 2 to 4). The mixer track that was track 1's own (`TRACKS`) is kept but no track's. The Drums strip is named "Track 1" while track 1's own instrument plays there (`mixing::TRACK_1`: the name has no room for both words; kit 1's pads still sound there). **Old projects open exactly as before:** the mixer part's `track1` line says where track 1 plays (`t0`, or `t4` for its old own channel). A project saved before part 4b has none; it keeps track 1 on the old channel when track 1's own instrument played there (`MixLoad::track1_own`, from the instruments part) or the channel has settings (`project::untouched_channel` false), named "Track 1 (old)" (`MixHost::old_first`, `Instruments::set_first_channel`), and the open's log line says why and counts it (`MixHost::old_first_opens`). Otherwise nothing of track 1's played there, and it moves to Drums with no change to the sound. A `track1` line naming another strip opens on Drums and says so. **Old clips' strip moves** (the sequencer thread's review): before part 4b a clip on track t (2 and up) whose lane or lock named "this track's strip" (`OnTrack::Strip`, `OnTrack::Insert`) reached mixer track t (Synth for track 2, Loop for 3, Audio for 4). On opening a project with no `track1` line, `project::old_strip_targets` rewrites each such lane to name that strip (`Target::Fixed`, `f:t1.fx1.2`), in the clip and its Original, so it moves what it did; a lane that would clash with one already on that strip is left (counted). Step locks can only name their own track's strip: strip locks are kept and now reach it (most came from the step lanes, which meant the track's own), and insert locks, which only a knob on another strip's effect made, are dropped. Each kind is counted on the open's line (`OldStripTargets::line`). Test: `project::tests::an_old_projects_strip_moves_on_track_2_keep_their_strip`. What follows track 1's strip: the instruments (`Instruments::channel`), kits homed on track 1 (`Pads`), the own channels shown and thrown (`MixHost::own_channels_in_use`), stems by track (`export::track_stems`: track 1's own instrument shares Drums with kit 1, so it gets an Only pass when a kit-1 track sounds too), freezes (`takes::feed`, `Feed::Drums`: Drums freezes track 1 and the tracks on kit 1), the chain editor's Notes stage (`ChainHost::track`) and the step lock lanes (`gui`). Tests: `mixing::tests::track_1s_channel_is_drums_and_the_rest_their_own`, `an_old_project_keeps_track_1_on_its_old_channel`, `project::tests::the_mixer_knows_where_track_1_played`, `instruments::tests::track_1s_instrument_plays_into_drums_or_its_old_channel`, `mpfree_param` `a_tracks_strip_is_drums_for_track_1_and_its_own_for_the_rest`, `export::tests::stems_by_track_come_from_the_track_s_strip_or_a_replay` (track 1's own instrument sharing Drums), `takes::tests::feeds_and_what_freezes`, `rt_safety` (Poly on track 1 shows on the Drums strip).
- **Stems by track** follow: each track on the pads plays into its kit's strip (or Synth), and only tracks that share a strip get a replay (`export::track_stems`).
- **Saved** in the project's `track-kits` part (`TrackKits::text`, `project::track_kits_parse`): `track 2 kit 3`, `track 4 instrument 1` (the shared synth by its id in the project's list of instruments; a part saved before instruments had ids says `track 4 synth`, still read: [instruments.md](instruments.md#2a-as-built); another track's own instrument by its id too, beside the track's kit: [instruments.md](instruments.md#4a-as-built)), numbered from 1; written only once a track plays another kit than kit 1. A project without it opens with every track on kit 1.
- **On screen:** under each track's name on Arrange, "Kit" (kit 1), "Kit 2" and on, or "Synth" (`ToUi::TrackKits`).
- **UNDO and REDO of a track** take its kit with it: `TrackKits::follow` sets aside the entry of a track UNDO took away (out of the list of kits and never a spare, `TrackKits::set_aside`) and gives it back on REDO; the entries aside are neither played nor saved, and are dropped once REDO can't bring the track back (see [browser.md](browser.md), New track with this kit).
- **Tests:** `sampler.rs` (each track's entry, the kits' homes and the part's text; two kits sound at once), `mixing.rs` (a kit plays into its track's channel, which shows while it does), `export.rs` (tracks on strips of their own need no replay), `project.rs` (the part is kept and comes back; one that doesn't read is said), `rt_safety.rs` (in one period kit 1, kit 2 and the synth each play their own track's notes with no allocation, and only kit 1's hits flash), the GUI's `a_track_on_another_kit_shows_no_pad_mutes_and_says_why`, and the smoke tests (a kit picked is the armed track's and the pads follow arming; opening the Synth tab changes nothing until the synth is picked; the random walks check the grid's mutes against the mixer's on kit 1's tracks only).

### A kit's 128 pads on the 16 (PAD BANK)

R3 part 2b makes PAD BANK A to H the pages of the armed track's kit, its pads 1-16 to 113-128 (Akai's names A1-A16 to H1-H16, `app::kit_pad_name`).

- **One page for the pads** (`App::pad_page`, `set_pad_page`), whatever the kit, as Akai's MPC has one pad bank: arming another track or picking another kit keeps it. PAD BANK with a kit on the pads turns it (main.rs's `Effect::Bank`, SHIFT or a second press for E-H as before); with the synth it still picks its pad layouts, with STEP SEQ its pages, with TRACK MUTE its banks of tracks, and STEP SEQ held gives the pads back to the kit with PAD BANK its pages. The log says `pad bank B: pads B1-B16 of Drums (no sounds yet)`.
- **The app maps the pads:** `App::kit_pad(slot)` is 16 x page + slot with a kit on the pads (the slot with the synth's layout). A press feeds the arp that kit pad and keeps it (`kit_held`), so the release, the pressure and the recorded NoteOff reach the pad it pressed even if the page turned while it was down. `pressed_event` records the kit pad, STEP SEQ's sound is any of the 128, live erase takes the kit pad, and 16 Levels play their pad with any page (the engine takes the level as pad % 16).
- **The player and the engine:** `Player`'s sounds are a u128 per kit (`sounds`, `has_sound`, `page_sounds`); hits, releases, pressure, locks and auditions reach pads up to 128, and `kit_latched_pads` is a u128.
- **The 16 pads show the page:** their colours are the page's sounds (`page_sounds`), the latched lights and the arp's are the page's, and a hit from the clips or the arp on a pad of another page plays unseen (`pad_cell`). `ToUi::PadDown`, `PadUp` and `PadFlash` name the 16 pads; `ToUi::PadPage` tells the screen the page, which names its pads, heads the pads panel "Pads · Bank B", and edits kit pad 16 x page + n on the Sample tab. Beats' lanes take any of the kit's pads with notes or sounds, then the page's empty ones (`PlayPage::pad_page`).
- **Names:** the Sample tab names pads by their own bank ("B5" is pad 21), no longer the kit's letter, and edits, sends to and puts phrases on any of the 128. The Pads tab shows the bank of the pad picked, and says which ("bank B"). ERASE + a Beats lane's speaker clears that pad's steps on any bank.
- **The Pads tab's banks** (part 3): `PadMap::banks` draws a strip of the kit's banks A to H over the pads, a dot per pad with a sound (`PadsState::banks`), the bank shown outlined; a tap is `PadsAction::Bank`, which the app sends as `FromUi::PadBank` and turns as PAD BANK does. `ToUi::PadPage` moves the Sample and Pads tabs to the same pad of the new bank (`SamplePage::set_pad_page`), so the pad they edit is one the pads play. A tap on the tabs that plays a pad goes to the pads as one of the 16 when the pad is on the bank shown (it records and lights as a hit), and as `FromUi::Audition` when it isn't (a pad reached with SHIFT + wheel), which only sounds it. Chop to pads runs on across the banks too (B1 after A16; see Chop below).
- **New kits** (part 3): `sampler::Player::with_user_kits` keeps `USER_KITS` (8) empty kit slots after the kits and Grains, each an empty project and view ("Kit N"), so the kits' places and the synth's after them never move at run time (the engine has no per-kit render loop: an empty slot is only its arrays). `KitView::user` marks them; the list of kits shows one once it is in use (sounds, a track playing it, or on the pads) and ends with **New kit**, which picks the first spare slot (`FromUi::Kit`), so the armed track plays it as any pick does. SHIFT + wheel passes the spare slots (`kit_turned`). A kit loaded from the browser goes into the pads' kit unless another track with a clip plays that kit (`Player::kit_for_load` in the GUI): then into the first spare slot (`SamplePage::open_kit_into`), and the armed track moves to it, so loading never changes another track's sound; with none left the load is refused and says why. The Sample page saves the user kits with the others (their names too) and the track kits part says which tracks play them, so a project brings them back in their slots.
- **The Kit of row** (part 3, mockup 5; "Pads of" since the redesign's board 7, with the Perform set's chip at its right end, `KitTracks::perform`: [looper.md](looper.md)'s Perform view): `widgets::KitTracks` on the Pads tab (`pads_tab::KITS`), which the GUI fills (`refresh_kit_tracks`: the tracks that play kits and are armed, have clips or play another kit than kit 1, and synth or instrument tracks with clips, faint). A tap on a track is `TimeAction::Arm`; **+ Kit track** sends `TimeAction::AddTrack` and, on the time state that shows the new track armed, picks the first spare user kit for it (`FromUi::Kit`), as the sequencer thread asked (the arm changes only once the time state comes back).
- **Mutes:** only kit 1's pads A1-A16 have pad strips (part 4 gives any pad a channel), so past A16 the speakers and TRACK MUTE's pad keys say so and mute nothing (`gui::no_pad_mutes`).
- **STEP SEQ's lights** take the kit's colour for any of its pads, and on the synth's line its pen's pad's colour (the old lookup indexed the 16 resting colours by the sound, which the line's 255 overran).
- **Tests:** the app's `pad_bank_pages_the_kit_and_a_held_pad_lets_go_where_it_pressed`, the player's `a_kit_plays_its_pads_past_16`, main.rs's `the_page_shows_its_own_pads_and_says_what_it_holds` and the mute keys' line on bank B, the GUI's `pad_bank_b_shows_the_kits_next_sixteen_pads_and_the_sample_tab_edits_them`, and the smoke session's `pad_bank_b_records_and_plays_the_kits_next_pads`. ### In the pad player

From round 6 the pad player (`mpfree-app`, `src/sampler.rs`) plays through this engine instead of its round 3 mixer. The `drums` step keeps the old mixer.
- Each kit in `kits.bin` becomes a project with one engine view, built before the sound starts, and every view goes into the engine as its own kit ([Kits on tracks](#kits-on-tracks-the-pad-player)). Picking a kit only selects it, so nothing is built, allocated or freed in the audio loop, and sounds already playing finish.
- Levels match the old mixer: pads are raised 3.01 dB to undo the centre pan, and velocity is sent as `round(127·√(v/127))`, so the engine's squared level law comes out linear.
- A Grains kit plays the first kit's sounds as granular pads while they are held. Pressure moves density, grain size, position or pitch, one per row of pads.
- Pad pressure from the controller goes to the engine as `Event::Pressure`, and Note Repeat's note-offs go to it as `Event::NoteOff`.
- **Pads on the mixer.** `Engine::render_routed(frames, out)` renders each pad apart: every voice adds its sound into its own pad's pair from a `PadOut` (the mixer's pad channels, `mpfree_fx::Mixer::pad_input`), so each pad gets the mixer's fader, pan, mute, solo, sends, inserts and output. Events, voices and grains run as in `Engine::render`, and the pads' pairs add up to what it renders (`tests/routed.rs`). The engine never clears a pair (the mixer clears its own after each block). A pad with no pair (`None`) still plays, into a scratch buffer, so its voices end on time. The master grain effect works on the mixed pair, so it runs only in `Engine::render`; on the mixer a granular insert on the pads' track does its job. `sampler::Player::render_routed` passes it on for every kit: kit 1's 16 pads on pad channels 0 to 15, each going to the Drums track, and another kit's onto its track's channel (`MixHost::pads_homed`). `render_dry` stays for tests and previews. Routed renders run in `tests/no_alloc.rs` too.
- The 30 s status line adds the engine's render time per period (mean and max, and as a share of the 2.9 ms period), steals, dropped events, and peak and skipped grains. On the RK3288, these figures set the voice and grain limits.

### As an instrument node (`node.rs`)

`SamplerNode` is the sampler as an `mpfree_node::Node`, so a track holds a kit or a keygroup program the way it holds Poly or FM, and the sequencer, the pads and the arp play it with notes. Piece 4 of the plan "Four synth features" (2026-11-11).
- **Notes.** On a drum kit (Pads or 16 Levels), note `Pad 1 note + n` hits pad `n` (pad 1 is note 36 by default, as on Drums), its pressure goes to that pad, and its note-off lets go of that pad. A note outside the pads goes to the keygroups, so a kit with a keygroup pad still plays it. On a keygroup program every note goes to the keygroups as itself. Every note goes through `Engine::schedule`, so it lands on its frame for any block size.
- **A note-off follows its note-on**, even if the kit or "Pad 1 note" changed in between. A note held again first lets go of where it went before.
- **New sounds** (new samples, an edited pad, another kit) come in as an `EngineView` built on the control thread and sent with `SamplerControl::send_view`. The node takes in at most one at the start of a block and hands the view it replaces back through `SamplerControl::take_old`, to be dropped on the control thread. If nobody has taken the old views back, the node keeps the replaced view and takes no new one until there is room. Two views can wait each way (`VIEW_QUEUE`); a full queue gives the view back to send again. Playing voices finish as they started.
- **Kit settings** use Drums' kit ids: Level (300, in dB, smoothed over 10 ms from its frame), Pad 1 note (301) and the read-only Voices on meter (310). Tune (302, semitones) and Cutoff (303, octaves) move every pad at once, playing voices too (`Event::ProgramLive`); a Cutoff below 0 gives pads without a filter a low-pass, so the whole kit darkens.
- **Pad settings.** Pads 1 to 16 each have Level, Pan, Tune, Cutoff, Resonance, Attack, Decay and Release, at ids `pad * 16 + field` as Drums lays out its pads (`node::pad_id`, `node::field`), grouped "Pad 1" to "Pad 16". They are **offsets on the pad's own settings**, the ones edited on the Sample tab, so at their defaults a pad plays as it is, and a preset, a p-lock ending or a modulation at rest goes back there:

  | Setting | Range | Default | Sent to the engine as |
  |---|---|---|---|
  | Level | −60 to +12 dB | 0 | own level + offset |
  | Pan | −100 to +100 % | 0 | own pan + offset / 100 |
  | Tune | −24 to +24 semitones | 0 | own tune + offset × 100 cents |
  | Cutoff | −8 to +8 octaves | 0 | own cutoff × 2^offset; with the filter off, a low-pass from 22 kHz below 0 and nothing above |
  | Resonance | −100 to +100 % | 0 | own resonance (0 with the filter off) + offset / 100 |
  | Attack, Decay, Release | 1 to 10 000 % | 100 % | own time × offset / 100, a time of 0 taken as 1 ms |

  A setting at its default sends NaN (the pad's own). Each change goes to the engine as an `Event::PadLive` on its frame; playing voices glide to Level, Pan, Cutoff and Resonance, and Tune and the envelope reach the next hit. The node reads the pads' own values with `EngineView::pad_own` when a view comes in, and puts every offset that isn't at its default onto the new view's pads in the same block. Pads past 16 play but have no settings on the node yet. On 16 Levels the settings of the one pad apply, and a Cutoff offset replaces the Levels' spread of cutoffs.
- `reset` is the hard stop (`Engine::stop_all`): every voice stops at once, the notes waiting are dropped and the held ones forgotten. The settings stay.
- **Tests.** `tests/node.rs`: the node plays a phrase of hits, a held gate, pressure, a repeat and all notes off identical to the engine fed the same events, in blocks of 1, 7, 16, 64, 128 and 1000 frames; notes find their pads and note-offs follow them across a "Pad 1 note" change, also one inside a block; a keygroup program plays every note as itself; views swap in one per block, come back, and wait when the return queue is full; Level lands on its frame for any block. `tests/node_live.rs`: a phrase moving every pad setting and both kit offsets plays identical to the engine given the live values on the same frames, in blocks of 1, 7, 64, 128 and 1000; every setting moved and set back to its default leaves the kit playing bit for bit as it is; each setting works from the pad's own (with and without a filter, an attack of 0); a new view gets the offsets on its own settings; reset stops at once and keeps the settings; the id layout. `tests/node_no_alloc.rs`: 2000 busy blocks (notes on, off and again on pads and keys, pressure, Level, Pad 1 note, kit Tune and Cutoff and pad settings inside blocks, all notes off, reset, views swapped in while voices play and settings are on) under a counting allocator: `process` makes no allocation and no free.

### The Wave tab (`mpfree-sampler-ui`)

The first of the pad editor's tabs, as in the Wave mockup. It shows one layer of one pad: the overview (the zoom in its corner) and the Keep card (`recorder::KeepCard`, over the wave's right end since Jay's device notes of 20 Nov 2026: capture from the recent audio sits with the wave, drawing what a tap keeps from a `Strip` of Sample Recall's buffer the page reads each frame, `SamplePage::keep_wave`), the waveform across the page with Start, End and loop markers, the fades, bar and beat lines from the source's tempo, the region's settings in a panel under it with the pad's Sound section beside them, and four Q-Link cards in the column at the right.
- **The panel** (Jay, 17 Nov: "feel like an instrument, not a menu"; layout spec 4i). `panel.rs` draws a `SettingList` as labelled sections when its `panel` is set: each row gets a `Control` (`Look::Choice`, `Knob`, `Chip`, `Stepper`, `Toggle` or `Button`, and whether it is faint) and the `Panel` says which rows go in which section's lines. - **A quick Normalize, and memory checks** (sampler plan, phase 1 step 5, 20 Nov 2026). Before, Normalize read a 16-bit sound through a float copy of the whole region, about 530 MB at once for a 25-minute stereo take, on the screen thread, on the MPC's 2 GB with no swap. Now nothing is copied:
  - `Region::peak` reads the frames where they are (`PeakSearch::read`, unscaled and scaled once, the same value as before).
  - A region over `SCAN_FRAMES` is searched in its sound's loudness summary (`Region::peak_from`), which gives the same peak to the bit. The summary holds each block's lowest and highest sample to within half of 1/32767 (`PeakPyramid::range`), so each block has a most its loudest frame could be (`PeakSearch::most`: the slack added; infinite for a block held at full scale; 0 for a silent block of a 16-bit sound, whose silence is exact). The 4096-frame block that could be loudest is read first, down through its 1024-, 256- and 64-frame blocks (the one that could be loudest first, `descend`) to the frames; every other block is passed over unless it could still beat the loudest frame found. In Mono sum the bound is `(min L + min R) / 2` to `(max L + max R) / 2`, an upper limit only, so the loudest blocks are read until none could beat them (all of a sound whose sides cancel).
  - The app (`SamplePage::level`, for a pad's layer or a take on the page) uses `peak` up to `SCAN_FRAMES`, else `peak_from` once the summary is there. Before it is (`Summary::Pending`), the Normalize waits (`levelings`, at most `MAX_SEATS`; a second press on the same layer replaces it): "sample: pad A5 normalizes once its sound's loudness summary is worked out". It lands when the summary comes (`normalize_later`, polled with the seats) as an undo step of its own, only while the region is exactly as it was pressed on; a changed one is let go ("sample: pad A5 not normalized: it changed before its sound's loudness summary was worked out"). A sound with no summary was read frame by frame on the screen, a fallback counted, logged and shown on Dev > CPU by engine as "Sampler: Normalize read every frame (no summary)"; since phase 2 step 7f it is read on the job service, still counted and shown ([the job service](#the-job-service-step-7)). A take's log line now reads as a pad's ("sample: Take 1 normalized: its peak …").

  - Measured on the build container (4 cores, release; `tests/normalize_no_alloc.rs`, run with `cargo test --release -p mpfree-sampler --test normalize_no_alloc -- --ignored --nocapture`), on a 25-minute 16-bit stereo take (66 150 000 frames, 264 MB): Normalize from the summary took 0.21 ms in Stereo, 0.17 ms in Left, 0.18 ms in Right and 0.18 ms in Mono sum, with no allocation. - **The wave as it plays** (`warp_tool::bend`, `mpfree_ui::wave::Waveform::set_bend`). While the layer stretches and has pins, the page's wave is drawn as it plays: a bend is a list of (frame as drawn, source frame) points, the drawn frame of a pin being the region's start plus its beat at the warp tempo, one to one outside the region, and the wave reads each column's peaks through it (`bend_through`). So a pinned hit sits on its beat line, and dragging a pin's tab moves it the way the finger goes. Everything else on the wave is in drawn frames: the other tools' marks, the loop, the playheads (the engine reports a stretched voice's place in the source, which the page maps through the bend) and a tap, which goes back to a source frame (`warp_tool::source`). With no pins, repitching or off, the bend is empty and the wave is as recorded.
- **Bars and hits.** The beat lines count from the region's start at its warp tempo (`warp_tool::beats`, `Beats::per_beat` lines between beats once they are 12 px apart, so the grid shows when zoomed in); a layer that isn't warped shows the beats at the tempo turning Warp on would give it. The hits the source's onsets found (`WarpTool::hits_of`, at the Hits setting's sensitivity, worked out once per source and setting) are 2 by 8 px ticks along the wave's foot (`Waveform::set_ticks`), lit with this tool and faint with the others.
- **Pins.** A pin is a marker with a numbered tab (`warp_tool::markers`); with another tool it is a faint line with no tab (`Marker::line_only`), so the tab strip stays the tool's own. A tap on the wave pins the hit nearest the finger (within half a grid step, else the frame tapped) to the nearest grid line, or picks its pin if it has one; with Warp off or on Repitch it says why instead (`OFF_NOTE`, `REPITCH_NOTE`). Dragging a tab moves the pin along the grid to the beat under the finger; it stops short of its neighbours (`Warp::pin_room`), and a touch that doesn't move only picks it. **Pin hits** pins each hit within 0.45 of a grid step of a line onto it, the nearest where two reach one line (`Warp::pinned_to_grid`): a loop played loosely made tight. **Remove pin** and **Clear pins** take them off.
- **The Warp section** (`WarpTool::section`, layout spec 4i), under the wave in place of the Mode, Gain and fades and Options sections, beside the Sound section, in two parts that fit the 242 px band: **Warp** (Warp, Warp tempo, which can be typed; Grid, 1/4 to 1/32; Shift and Process, shown as **New sound's pitch** and **New sound** with the button **Make it**, so the pitch can't pass for a live one beside the Sound section's Tune), its note saying what Warp does now, or with a pitch set what a tap makes ("new sound: 2 st up, tap Make it"); and **Pins** (Hits: Strongest, Most, All, the onset picker's sensitivity; Pin, the one picked, and Pin beat, a grid step a click; Pin hits, Remove pin, Clear pins), its note the number of pins. The rows are `warp_tool::Row::ALL`, so the wheel walks them and its push presses the buttons; a faint one says why (`Control::why`). A new tempo drops the pins it leaves no room for.
- **Process** (the button beside **Shift**, −24 to +24 semitones, the tool's own setting; on the screen New sound and New sound's pitch): `WaveAction::Process { pad, layer, semitones }`, and while one runs ("Stop · 40 %", `WaveTab::set_processing`) `WaveAction::StopProcess`. The app makes the job (`process_of` in `sample_page.rs`): a stretched region goes from its warp tempo to the project's through its pins; a repitched one is stretched by the same ratio and moved by the semitones the tape speed would (12 · log2(project / warp tempo)), so the new sound plays as the region did; then Shift on top. A region that isn't warped, or is at the project tempo without pins, with Shift at 0 would come out the same and is refused with a line saying so. `warp::Process::spec` gives the owned job, which runs on the [job service](#the-job-service-step-7)'s sound lane (at idle priority like the warp copies, 8192 output frames between looks at Stop), after a memory check (the input copy, the stretch's working copy and the result). Done, `Process::finish` puts the new sound in the region's place (`Project::use_processed`), one undo step; the log says `sample: pad A5 processed into a new sound, stretched from 92.0 to 120.0 BPM: Break 92 x0.77, 4.0 s, in 0.41 s`. Stopped or failed, nothing changes (`sample: pad A5 not processed (stopped)`). One runs at a time.
- **Q-Links.** 1 picks a pin, 2 nudges its beat (a 64th of a beat a detent; SHIFT, a 960th), 3 fine-tunes the warp tempo (a tenth of a BPM; SHIFT, a hundredth) and 4 scrolls (a sixteenth of the wave's width a detent) when zoomed in. The wheel zooms round the pin picked.
- Repitching, the pins stay but the wave and the sound play straight through. Moving the start with Trim keeps the pins on their hits (a pin's beat counts from the region's start).

### The Slice tool (`mpfree-sampler-ui`)

The one Sample page's step 3 (Jay, 18 Nov 2026, "Build it as drawn"; mockup https://claude.ai/artifact/NSGLzNnVy5zTA3ykWmpGzU): a tool of the Wave page (`wave_tab::Tool::Slice`, picked on the tools strip or by Chop to pads) in place of the pad editor's old Chop tab, which is gone (`chop_tab.rs`). It cuts what the page shows (a pad's layer, or a take kept on the page; Start to End) into slices and puts them on pads. Its settings (the method and its setting, the cuts, the slice picked, the first pad, Put on, Phrase, live chop) are `slice_tool::SliceTool`'s; what it chops is a `ChopState`, which the page's `WaveState::chop` carries (`ChopState::from_project` for a pad, `ChopState::of_take` for a take, its pad `wave_tab::TAKE`), with Files and New kit as the app offers them (`SamplePage::build_state`). It gives `WaveAction::Chop(ChopAction)`; the app acts on it as the Chop tab's actions were (`SamplePage::act_chop`).
- **The panel** (layout spec 4i, as the mockup draws it), in the band beside the Sound section: **Slice** (330 px: Method as a ‹ › chip and Snap to zero as a switch; the method's setting as a knob whose steps follow the method and Slice, the slice picked, as a chip; Split, Merge and Clear) and **Put on** (420 px: the pad map, `Look::Pads`, over Map, `Row::Bank`, as a ‹ › chip reading the pads it shows, "A1–A16"; the offered places as a `Look::Grid` two to a row; Phrase as a switch; Chop, `Look::Primary`, naming the pads it fills). The Slice note says how many slices and how they were made; the Put on note which pads with a sound the button would replace, or why it can't go now (New kit not offered, too many slices; `SliceTool::put_note`). The wheel walks the rows in the panel's order (`Row::ALL`: the map and Bank before Put on).
- **Where the slices land** (step 3b, as drawn). `SliceTool::lands` gives each slice's pad and whether that pad plays it now (`SliceTool::slice_pad`: on Pads or Keys, the pad `r.start + k` when its first layer plays exactly the slice, uncut, a keygroup for Keys; on 1 pad, the one pad when it plays the slices' span cut at the same frames; never on New kit, Audio track or Files). `ChopState::plays` is what each of the kit's pads plays of this sound (its first layer's span and cuts, and whether it is a keygroup), read with the rest of the state. The wave draws them as a lane along its foot (`mpfree_ui::wave::LaneCell`, `Waveform::set_lane`, 30 px, the wave drawn in what is left; a touch on the lane is a touch on the wave), each in its slice's colour (the theme's series colours, `Theme::track`, which colour the cuts too), lit once on. The **pad map** (`SliceTool::map_cells`, `panel::PadCell`) shows a bank's 16 pads as the MPC's pads sit (pad 1 bottom left, `panel::cell_rects`): each slice's number in its colour, the picked one outlined, pads with a sound raised. The bank shown is the one the slices start in, or the one its ‹ › turned to (round from H to A; `map_bank`, for that pad, dropped when the first pad moves another way). The chip turns the map alone and is named by the pads it shows, not "Bank B", so it isn't taken for the pads' bank (Jay, 12 Nov: no two look-alike settings that do different things; the spec owner's ask): turning the pads' bank would take the page off the pad being chopped, since PAD BANK moves the Sample tab to the same pad of the new bank (`SamplePage::set_pad_page`), and the map then follows that pad. A tap on a pad (`EventKind::Cell`, `SliceTool::cell`) starts them there, held back so the last fits, or says they start there already. On New kit the map shows the new kit's pads from A1 and is faint; on Files it is faint and empty.
- **The Sound section follows the slice** (step 3b). With Slice picked and the slice picked on its pad (`WaveTab::sound_follows`), the app shows that pad in the Sound section (`SamplePage::build_play_state` sets `PlayState::slice`; `SamplePage::follow_sound` rebuilds it when the slice picked, the cuts or the pads change), titled "Sound · slice 3 → A8". Its knobs give `PlayAction::Pad` for that pad, which `act_play` applies as on any pad (one undo step a turn). The Grain part is faint there (`SLICE_GRAINS`): grains are set on the pad's own Wave page. The buttons are rows of the list (`Row::Split`, `Merge`, `Clear`, `Chop`; `Button::row`, `Row::button`), so the wheel walks them and its push presses them; a faint one says why (`SliceTool::button_why`).
- **Methods.** Transient (the source's onsets, at a sensitivity from 0 to 100 %), Beat (on the source's own beat grid, the bar lines the Wave tab draws, every 16th, 8th, beat, 2 beats or bar; offered only when the source has a tempo), Grid (2 to 128 equal slices), Silence (one slice per sound, at a threshold from −72 to −12 dB), Pitch (below), Manual and Live (below). Cuts are at least 10 ms apart and from the region's ends; at most 128 slices (`MAX_CUT_SLICES`, as many as a kit's pads and a sliced pad's slices).
- **Hand edits.** Dragging a slice's marker, Q-Link 3, Split (the slice picked, near its middle) and Merge (with the slice before) change the cuts and turn the method to Manual, so changing the method's setting never silently undoes them; Clear takes every cut away (one slice, Manual). Beat, Grid, Pitch, Split and hand moves snap to zero crossings unless Snap is off; transient onsets already sit just before each attack. The first marker is the pad's Start and END its End: they stay put (Trim moves them), and a touch says so.
- **The chop is kept for the sound.** Trying methods changes no pad, but once a touch, a Q-Link, the wheel or a live cut changes the method or the cuts, the tool hands them to the app (`WaveTab::take_kept`), which keeps them as the sound's chop (`Project::keep_chop`: one `ChopSet` named `KEPT_CHOP` a sound, replaced each time). Like the scenes, keeping is not an undo step; it counts as unsaved work, is saved with the kit (`kept.N.source`, `.mode`, `.markers` in the sampler's text), and moves with its sound when the sound is converted to another rate. Coming back to the sound (another pad or tool and back, a moved Start or End, the project opened again), the tool shows the kept cuts inside the region (`ChopState::kept`) in place of chopping again, with its method, unless none of them falls inside it (a chop kept on another part of the sound, such as one of its slices on a pad of its own, stays for that part); a project opened on the same sound and region shows its own kept chop too. A chop the tool makes by itself (a sound's first Transient chop) is not kept. Without a kept chop, another pad or a moved Start or End chops again (a Manual chop keeps the cuts still inside).
- **Pitch** (R4.7, `ChopMode::Pitch`, saved as `pitch`): a cut where the note changes by the **Change** (1 to 12 semitones, shown "1 semi" to "11 semis" and "Octave"; the knob and Q-Link 1) or starts after a rest. The sound's pitch is followed once, the first time Pitch is picked on it, on the analysis worker: the tool says it waits (`WaveTab::wants_pitch`: no cuts yet, and nothing kept), the page asks `Views::follow_pitch` (queued after the sound's own view if that is still waiting), and the view comes back with it (`SourceView::pitch`, `SourceView::follow_pitch`) on a later `Views::take_done`; the tool then chops, and the page keeps that chop. `mpfree_analysis::pitch_track` takes the mono mix down to about 8 kHz (block averages), runs YIN every 10 ms on 40 ms windows (60 Hz to 1.5 kHz, a threshold of 0.2; a window more than 30 dB under the loudest is a rest), and mends a lone reading between two that agree (an octave slip or a miss). `PitchTrack::changes` groups readings into notes (within half a semitone of the first two; a note's pitch is the middle of its readings), drops notes shorter than 50 ms, and cuts at a note that is the Change less a quarter of a semitone or more from the note before (so a flat note still counts, and vibrato or a slide, which move a little at a time, don't), or that comes 50 ms or more after the last (a rest). A window hearing two notes reads one or neither, so each cut is then found to the millisecond in the window before (`PitchTrack::start`): each millisecond votes for whichever note's period the next two periods repeat at better (from a rest or noise: loud enough and repeating at the new note's period), and the cut is where the votes split best. On made-up notes the cuts land within 5 ms. Following costs about 0.2 s a minute of sound on the workstation, release build (several times that on the MPC, not measured), never on the screen thread. It is not kept in the analysis cache file: a project opened again follows it again when Pitch is picked.
- **Live** (Jay, 2026-11-12: live chop to pads). Picking Live keeps the cuts there; the Split button reads Start. Start clears the cuts and sends `ChopAction::Live { on: true }` with the region; the app plays the region once (an audition of the pad's layer) and tells the sampler to mark (`Event::LiveChop`). While it marks, every pad played live (by hand, through Note Repeat or the arp; `Player::live_hit_at`) becomes `Event::Mark` instead of a note, the Sample tab keeps the pad being chopped rather than picking the pad hit, and the engine records the audition voice's source frame at that sample (`Engine::audition_at`: the voice's own position, mapped back to the source when it plays a stretched copy), so a cut is exactly where the sound was, whatever the screen's lag. Marks travel back with the playheads (`Playheads::marks`, the last 8, about 25 times a second) and `SliceTool::live_marks` turns each into a cut: onto the nearest of the source's onsets within the **Pull to hits** window (Off, 10, 20, 40 or 80 ms; the onsets are picked at 60 % sensitivity when Start is pressed), else onto a zero crossing if Snap is on; a cut outside the region, closer than 10 ms to another or past 128 slices is dropped. The take ends when the audition ends (the playheads were marking and aren't), on Stop, on another method, tool (`SliceTool::leave`), pad, region or tab, or when another audition starts; the log says how many cuts it made. Live plays a pad, so on a take kept on the page Start is faint and says to put the take on a pad first. Merge and Split work as on Manual and keep the method Live. Like every chop, the cuts are kept for the sound as they come, and reach pads only with Chop to.
- **Chop to pads** (`ChopAction::ToPads`, applied with `ChopAction::apply`, or `ChopAction::apply_take` for a take) adds a chop set (markers at Start, the cuts and End) and puts its slices on consecutive pads of the kit, across its banks (B1 after A16), as one undo step (`Project::chop_to_pads`). Each new pad is a copy of the chopped pad (level, envelopes, filter, choke, and its sound's gain, tune and channels) with one layer playing its slice once, named after the pad and numbered from 1. The first pad is the start of the first run of empty pads after the chopped pad that holds them all (`ChopState::used` covers the kit's 128 pads); with none, the pad after the chopped one, held back so the last slice lands on H16 at the latest. Q-Link 4 and the pad map move it anywhere in the kit, and Chop to pads keeps it for that pad, so chopping the pad again replaces the slices it made. While every slice is on its pad already and no phrase is asked for (`SliceTool::all_on`, by `slice_pad`), the button is faint and says so: chopping again would change nothing but put back the template's settings over edits made to those pads since (the Sound section follows a slice to its pad). The Put on note says which pads already have a sound ("replaces A5"). A chop's 128 slices at most fit on the kit's pads from A1.
- **Put on Keys** (one of Put on's places; the button then reads "To keys C2–D#2") does what Chop to pads does with each slice a keygroup of one note, from C2 (MIDI 36) up, and the kit's pads then play those notes (`Project::chop_to_keys`, one undo step), so the slices are on the pads and on a keyboard at once.
- **Put on Library** (offered once the app can write files; the one Sample page's step 6c named it as drawn, before that it was Files): the button reads "Save 15 slices" and exports the pad, its slices and a sidecar into the library instead of filling pads: see [Export and sidecars](#export-and-sidecars-mpfree-sampler-mpfree-app).
- **Put on 1 pad** (R4; the button then reads "Slices on A5") puts every slice on one pad instead (`ChopAction::ToPads { one_pad: true }`, `Project::chop_to_one_pad`, one undo step): the chopped pad itself, or the First pad picked (Q-Link 4, the Pads chip), as a copy of the chopped pad (as Chop to pads makes each pad) playing one region from the first slice's start to the last's end, sliced at the cuts (`ChopSet::sliced_part`), named after the chop, its Slice at 1 and its keys from C2 (`SLICE_KEYS_FROM`) a note a slice. The kit's pads keep playing their sounds and no other pad changes. See [Sliced pads](#sliced-pads-r4-mpfree-sampler).
- **Put on New kit** (R4.6; offered by the app, `ChopState::new_kit`; the button then reads "Chop to new kit" or "Phrase to new kit") puts the slices on an empty kit's pads from A1, not the chopped pad's kit, for a new track (`ChopAction::ToPads { new_kit: true }`, applied with `ChopAction::apply_to(from, to)`: `Project::chop_to_pads_of` adds the sound and the chop to the other kit as one undo group, so UNDO takes the sound out with the slices). The app works out what it can do (`Player::refresh_new_kit`, `SamplePage::set_new_kit`): Ok with the first spare user kit (`Player::spare_kit`, with its sounds on the Sample page), or Err with why (no empty kit left, 128 tracks, a new track still on its way), shown on the faint button. `SamplePage::act_chop` fills that kit, names it "<pad> chops", and hands the kit and the phrase to the app (`SamplePage::take_new_kit_track`), which asks the time engine for a track (`TimeAction::AddTrack`, as + Kit track does: `KitTrackAsk`) and, once it is there and armed, sends `FromUi::Kit` (the armed track plays the kit) then `FromUi::SamplePhrase`. A track that doesn't come in 3 s, or comes unarmed, leaves the slices on the kit and says so. The Sample tab then shows the kit's first slice; Q-Link 4 is faint (the slices start on A1).
- **Put on Audio track** (the one Sample page's step 6, as the MPC's Audio Track from Samples; offered where the app has audio tracks, `ChopState::audio`, which `SamplePage::build_state` sets; the button reads "To audio track") puts the slices on the song, not on pads: `ChopAction::ToAudio { pad, layer, name, bounds }`. `SamplePage::send_to_audio` has the source frames between the first and last bound copied out at the app's rate on the [job service](#the-job-service-step-7) (`Source::at_rate` on the span for a sound at another rate, its cuts moved with it; plan phase 2 step 7e), with the cuts made relative and the source's tempo, and sends `FromUi::SampleToAudio` when it comes (`SamplePage::take_to_audio`). The service checks the memory as the copy starts (sampler plan, phase 1 step 5, then step 7e; `memory::room_in`): the span as floats, and when converting a second copy plus the converted floats twice over; short, nothing is sent and the hint says why ("Not put on an audio track: not enough memory: needs about …"); the audio loop puts it on an audio track, a region a slice, as one undo step there (`audiotracks::TrackHost::bring`, [audio-tracks.md](audio-tracks.md#in-the-pad-player)). The sound goes as recorded (the pad's settings stay on the pad), and the pads and the page don't change. The map, its chip and Q-Link 4 are faint (no pad), the lane is empty, Pads reads None, and Phrase is faint (it is for pads; on an audio track the slices already play one after another, at the sound's own speed). A take on the page goes the same way and stays.
- **Phrase** (a switch beside Pads; offered when the source has a tempo and Put on is Pads, 1 pad or New kit, else faint, saying why when tapped) also gives the slices in time, for a clip; the button then reads "Phrase on A1–A15": see [Chop to a phrase](#chop-to-a-phrase-mpfree-sampler).
- **Q-Links** (the mockup's order): 1 turns the method's setting, 2 picks a slice, 3 moves its start (SHIFT: a frame a detent) and 4 moves the first pad (the mockup's fade for Q-Link 4 waits for per-slice fades). The wheel zooms round the slice picked; a tap on the wave picks the slice under it.
- **Tap to hear.** A tap on the wave also plays the slice under it once (`ChopAction::Audition`, which the app sends to the engine as `Event::Audition`), as the pad made from it will play it: the pad's level, pan, tune, channels, envelopes and filter, from the slice's first frame, with no loop or fades, whatever the region's play mode. The pad's own playing voices fade out first, so taps don't pile up. A test checks that the tap and the chopped pad sound the same. On a take kept on the page the audition's pad is `wave_tab::TAKE`, which `Player::audition` sends as `TAKE_PAD`: the engine plays the slice from the take its view holds, on the take's own voice (`a_slice_of_the_take_plays_on_the_takes_voice`).
- **A take** kept on the page is cut as a pad is (its cuts kept for its sound), and its slices go on pads straight from the page (step 3b; the bar's Chop to pads and the panel's Chop to both work on it). With no pad of its own it starts them at the first empty run from A1. `ChopAction::apply_take` makes each slice from the take as `apply` makes them from a pad (`ChopAction::place` with the take as the template) inside `Project::chop_take`, which also takes the take off the page and folds both into one undo group: UNDO brings the take back and empties the pads. On New kit, `ChopAction::apply_take_to` fills the other kit from the take and the app removes the take from this kit (`Project::remove_take`). On Files, `export::sound` exports the take and its slices as a pad's (`SamplePage::export_take`), and the take stays. Then the page shows the pad of the slice picked. Live still needs the take on a pad (Send to pad).

### Edit pad, the Play page (`mpfree-sampler-ui`)

How the pad plays its sound: `play_tab.rs`, the page called Edit pad on screen. It was the pad editor's third tab, then the Sample tab's Play sub-page; since the one Sample page's step 6b (Jay's card of 18 Nov 11:46Z, "Build it as drawn"; layout spec 4e) it is a page of the Pads tab, as the MPC's PROG EDIT opens its Track Edit.
- **Opening it.** The Pads tab's Pad list ends with an **Edit pad** row on every type (`pads_tab::Row::EditPad`, a button row reading "layers, keys, scenes, slices ›"): its tap or the wheel's push gives `PadsAction::EditPad`, and the app opens `Editor::Play`. PROG EDIT on the Pads tab does the same (`app::Effect::EditPad`, `ToUi::EditPad`, `SamplePage::toggle_edit_pad`), and on Edit pad goes back to the pads. On a pad with no layers (Instrument, MIDI out, no sound) the row is faint (`SettingList::faint`) and a tap, the push or PROG EDIT says why (`pads_tab::edit_pad_why`). The log says each time it opens or closes (`sample: Edit pad on pad A5`, `sample: Edit pad closed: the pads again`, from `SamplePage::open_editor`) and why PROG EDIT didn't open it (`sample: Edit pad not opened: …`), for the device check `sample-edit-pad` (step 6d).
- **The frame.** The Sample page's pad bar, Send to pad and Chop to pads, with a **‹ Pads** chip (`PadBar::back`, `play_tab::BACK`) in the place the Wave | Play switch had; its tap is `PlayAction::Pads`, back to the pads. A tap on the Pads tab in the top bar goes back too (the GUI's header tap, `SamplePage::open_editor(Editor::Pads)`). Chop to pads there asks for the Sample tab with the Slice tool and chops nothing unseen (`SamplePage::take_to_sample_tab`, `FromUi::Tab`). A pad hit picks that pad for it, as on the Sample tab.
- **Each tab keeps its page.** `Editor::on_pads_tab` splits the editors: the Pads tab's (`Pads`, `Play`) and the Sample tab's (`Wave`, `Auto`). `show_pads` and `show_sample` swap between them, each keeping the other's (`pads_editor`, `sample_editor`), and `open_editor` with the other tab's editor only keeps it for when that tab shows. The page is `PLAY_PAGE`, "Pads · Edit pad".

It edits the whole pad and its layers, never a layer's trim, loop or fades (that is the Wave tab's): `PlayAction::Pad` keeps the project's regions whatever it carries, and only the layer actions below change which layers there are and what sound each plays.
- **Sections** (the sampler review's decision 5, Jay 16 Nov: "Play in sections"). Chips across the page (`play_tab::SECTIONS`, the `SectionChips` widget, a line under each name saying what is in it now: `section_text`): **Layers**, **Amp**, **Filter**, **Pitch**, **Mod**, **Movement** (sampler R5 part 4), **Pad** and **Slices** (R4 part 5) (`play_tab::Section`). Each has its own rows (`Section::rows`; every `Row` is in exactly one, `Row::section`, `Row::place`) and its own four Q-Links (`Section::qlinks`). A tap on a chip opens its section with its first row picked (`PlayTab::open_section`); the section stays open across pads. The list's events carry the row's place in its section. **The page as an instrument** (Jay, 17 Nov; the layout spec's "panel under the wave"): each section lays the page out with its own picture across it (`Section::view`, `play_tab::layout`): the layer map on Layers, Mod and Pad, the envelope over the sound on Amp and Pitch, the filter beside its envelope on Filter, two cycles of the LFO's wave beside the pitch envelope on Movement (`play_widgets::MotionView`, which only shows: faint when the LFO or the envelope moves nothing on this pad, with a caption such as "LFO: sine on pitch, ±1.2 st at 5.0 Hz · pitch from +12 st over 200 ms"), and the keyboard on Pitch and Pad while the pad is a keygroup or the pads play notes. Under the picture the list is a panel (`SettingList::panel`, `PlayTab::controls` and `PlayTab::panel`), its section's rows as knobs, choice buttons, selectors, steppers, switches and the layer buttons in groups: Layers (how a hit picks, Vel fade) and Layer k (Sound, velocities, level, pan, tune, Add and Remove layer); Level and Envelope; Filter and Filter envelope; Pitch and Keys (Keys, Mono, Legato; Low, High and Root key; Key fade, Glide, Glide on); Velocity (Vel → level, start, cutoff and pitch) and Pressure; LFO (LFO to as five buttons, LFO wave, LFO rate, LFO depth, Sync to tempo, Retrigger) and Pitch envelope (Pitch env, Pitch decay); Pad and The kit's pads. A knob's drag steps its row as the arrows do; a faint control says why (`faint_why`). Beside the panel, on every section, the scenes are a panel of their own (`SCENES`). A layout file can set each section's layout under the page's name with `.amp`, `.filter` and so on after it, and `.keys` after that for the keyboard (`.pitch.keys`).
- **Mono, Legato and Glide** (R5.5; the engine is under Mono, Legato and Glide above). In the Pitch section's Keys part: Mono and Legato switches, Glide a stepper through Off, 10, 20, 50, 100, 200, 300 and 500 ms, 1 s and 2 s (`GLIDES_MS`), Glide on two buttons (Every note, Held keys). Without keys all four are faint ("Mono plays the pad's keys: turn Keys on"); with Mono off, Legato, Glide and Glide on are ("These play one note at a time: turn Mono on"); Glide on is while Glide is off. The part's note says what the keys do (`keys_note`), and the Pitch chip adds "mono" or "legato". Test: `the_pitch_section_plays_a_keyed_pad_one_note_at_a_time`; golden screen `pads-edit-mono`.
- **Movement** (R5 part 4; the engine is under Movement above). LFO rate steps a list of free rates (the grain LFO's, 0.05 to 40 Hz) or, synced, of note lengths from 4 bars to 1/32 with 1/4 dotted and 1/4 and 1/8 triplets (`LFO_SYNCS`), a step up faster either way; Q-Link 1 turns a free rate a sixth of an octave a detent (a 24th with SHIFT) and steps a synced one. **Sync to tempo** picks the note length nearest the rate heard at the project tempo, and off the rate nearest it (`synced`, with `PlayState::bpm`, which the app sets from its tempo). LFO to Off makes the other LFO rows faint; turning it on with a depth of 0 gives 10 %. Pitch env and Vel → pitch move a semitone a step (a tenth with SHIFT on a Q-Link), Pitch decay as the envelope times do (1 ms to 10 s). On a pad that keeps its pitch (every layer warped or granular, `keeps_pitch`) the pitch rows are faint, and Vel → cutoff is faint with no filter. The log names each change (`describe`). Test: `the_movement_section_runs_the_lfo_and_the_pitch_envelope`.
- **Layers.** The layer map draws each layer on a velocity axis (0 to 127), one row each, with a line at the last hit's velocity; with a Vel fade, each bar is cut down along the fade's curve inside its edges (`play_widgets::fade_cut`), so overlapping layers show their crossfade. Each lane's line says the layer's own level, pan and tune when they aren't at zero. Dragging a layer's left or right edge sets the lowest or highest velocity it plays (layers may overlap; the high edge can't cross the low one). A tap picks the layer: the envelope is drawn over its sound, the Layers section's layer rows edit it, and so do the Wave page's tools, Trim, Slice, Warp and Grain (`SamplePage::layer`; back to the first layer when another pad is picked). The Layers row says how matching layers play: Stacked (all), Cycle (round robin) or Random.
- **Adding and removing layers.** **Add layer** (a button on the Layers panel, `Row::AddLayer`, its tap `EventKind::Tab` with the row's place) asks for `PlayAction::AddLayer { pad, after }`: a copy of the picked layer just after it that takes the upper half of its velocities (`with_layer_added`; a layer of one velocity is copied onto the same one), picked once it is there; faint at 16 (`MAX_LAYERS`). **Remove layer** asks for `PlayAction::RemoveLayer`, picking the layer below; faint with one layer. The layer's **Sound** row steps through the kit's sounds (`PlayState::kit_sounds`, the project's sources, as the Pads tab's Sound row does) and asks for `PlayAction::LayerSound`, which plays the new sound from start to end and keeps the region's play mode, gain, tune and channels (`pads_tab::sound_region`); with one sound in the kit it does nothing rather than drop the layer's trim. Each is one undo step (`Project::set_pad` with no gesture), and the app writes a line for it (`sample_page::layers_text`: "layer 2 added, a copy of layer 1 (Break 92) on velocities 64-127, layer 1 now 1-63"). The picked layer's **Vel low**, **Vel high**, **Level** (−48 to +12 dB), **Pan** and **Tune** (whole semitones on the arrows, ±48) step it alone (`stepped_layer`), and `describe` names them ("layer 2 level +0.0 dB -> -2.0 dB").
- **Amp envelope.** Drawn over the picked layer's sound from its Start: attack is linear, decay and release fall exponentially to about −80 dB in their time, as the engine's envelope does (`env_level`). Sustain sits where the sound ends (or after the decay, if that is later) and Release follows it. Dragging A, H, D or R moves that time, S its level; the time axis holds still while a point is dragged. Times go up to 20 s; release is at least 1 ms.
- **Filter.** Its response on a log axis from 20 Hz to 20 kHz, as the pad's state-variable filter shapes it (`filter_db`; 4 poles are two 2-pole stages; the Ladder, the Vowel and the Comb by `ladder_db`, `vowel_db` and `comb_db`), its caption adding the Ladder's Drive, the vowel or the comb's note ("rings at A3"). Dragging the dot moves the cutoff. Turning the filter on while its cutoff is still at 20 kHz starts it at 2 kHz (a high-pass at 200 Hz), so the change is heard.
- **Filter envelope.** On the Filter section the envelope picture shows `Pad::filter_env` instead of the amp's, titled so, and its points drag it (`Key::FilterEnv`; its release may be 0). Its rows are Env depth (`Filter::env_octaves`, ±4 octaves), Env attack, Env decay, Env sustain and Env release; its hold is set on the picture only.
- **The rows**, by section: **Layers**: Layers, Vel fade (Off, 2 to 64: `Pad::set_vel_fade`, which also moves layers that meet to overlap by the fade), and the picked layer's Sound, Vel low, Vel high, Level, Pan and Tune. **Amp**: Level (−48 to +12 dB), Pan, Attack, Hold, Decay, Sustain, Release. **Filter**: Filter (LP, HP, BP or Notch, 2 or 4 poles, then Ladder, Vowel and Comb: `FILTERS`), Cutoff (a third of an octave a step; a Vowel's value names its vowel, "1.00 kHz · ah", a Comb's its note, "220 Hz · A3", `note_of`), Resonance, Drive (R5.6: a knob, 0.5 dB a detent, its arrows 3 dB; faint but on a Ladder, saying so), Env depth and the filter envelope's times and sustain. **Pitch**: Tune (whole semitones, ±48), Wow & flutter, Vintage, Keys (Off or On), Low key, High key and Root key, the kit's Key fade (Off, 1 to 24 notes, Mixed when the keygroups differ, "–" without one: `PlayAction::KeyFade`, one undo step). **Mod**: Vel → level, Vel → start, Pressure (Level, Pitch, Filter cutoff, and the grain targets for a granular pad) and its Depth. **Pad**: Polyphony (mono to 32 voices), Mute group (off, 1 to 16), Stops (the one-way chokes) and Also plays (the links), each Off or a list of pads, Latch (Off or On), and the kit's Pads play (their sounds, notes or 16 Levels), Pads from (an octave a step) and Levels by. A tap picks a row and its arrows step it; the wheel steps the row picked. Stops and Also plays step a pad at a time (up adds the pad after the highest, never the pad itself; down takes the highest out), but they are quicker from the pads: while either row is picked, a hit on another pad goes into the set or out of it (`PlayTab::takes_pads`, `PlayTab::pad_hit`; each hit its own undo step), the pad shown stays, and the app's hint says so (`SamplePage::press`, `SamplePage::play_takes_pads`).
- **Keys.** Turning Keys on makes the pad a keygroup over the whole keyboard, rooted at the note its first layer's sound is heard at (`SourceView::root_note`, else C4), with at least 16 voices for chords; Low key and High key narrow it. Pads play and Pads from are the kit's (`PlayAction::PadsPlay`, one undo step each): turning the pads to notes starts pad 1 at the C below the pad's root (C3 for a pad that isn't a keygroup). The bar says the pad's keys and what the pads play.
- **The keyboard (keygroup editor).** While the pad is a keygroup or the pads play notes, the Pitch and Pad sections show a keyboard across the page as their picture (`Section::view`, `KeyZones` in `keys_widgets.rs`; a layout file can override it as `<page>.pitch.keys` and `<page>.pad.keys`). Every keygroup of the kit is a bar over the keys it plays, in its pad's colour and named by its pad, with its root dotted; overlapping zones take lanes of their own (up to 4). The keys drawn are whole octaves around the roots, the picked pad's zone (up to two octaves either side of its root) and the pads' notes, at least three octaves, and arrows mark zones that go past them. The roots are tinted on the keys, and a bracket under them shows the 16 notes the pads play. The picked pad's zone has a stroke and handles: dragging its left or right edge sets Low key or High key, dragging the root dot sets Root key, each one undo step like the list's rows (`Key::Zone`). A tap on another zone picks its pad (`PlayAction::Pick`), and a key pressed plays the kit's keygroups at velocity 100 until it lifts (`PlayAction::Note`). The caption says the picked pad's keys and root, or how to make it a keygroup.
- **Q-Links** turn the open section's four rows (`Section::qlinks`): Layers the picked layer's level, pan, tune and Vel low; Amp attack, decay, sustain and release; Filter cutoff, resonance, Env depth and Env decay; Pitch tune, wow, Low key and High key; Mod all four; Pad voices, mute group, Pads play and Pads from. Times double every 8 detents, at least a millisecond each (SHIFT: 1 ms a detent); Cutoff moves a semitone a detent (SHIFT: a tenth); fractions 1 % (SHIFT: 0.2 %); levels 0.5 dB (SHIFT: 0.1); tune 10 cents (SHIFT: 1); a choice steps as its arrows do (`turned`, else `PlayTab::step`). A row with nothing to change shows its card faint with why (`faint_why`: the filter's rows while it is off, the keys' without a keygroup, Depth without a pressure target, Pads from and Levels by unless the pads play notes or 16 Levels), and its turn does nothing. A tap on a card picks its row. The app's hint names them (`PlayTab::qlinks_text`, refreshed when the section changes: `Player::sample_qlinks`).
- **Scenes.** A panel beside the section's controls on every section (`SCENES`, a `SettingList` panel of four rows, `SCENE_ROWS`, without the picked outline): Store A, Store B ("Store A again" once there is one) and Return to A as buttons (`EventKind::Tab`), and the crossfader as a slider (`panel::Look::Slider`, `EventKind::Value`; "A", "40 % to B", "B"). Return to A is faint until A is stored and the crossfader until both are, and the group's note says which to store first. See [Scenes](#scenes-mpfree-sampler).
- **Undo.** Each drag, Q-Link turn, wheel turn or run of taps on one row is one undo step; the app ends it when the finger lifts or the control rests.

### The Grain tool (`mpfree-sampler-ui`)

The one Sample page's step 5 (Jay, 18 Nov 2026; mockup https://claude.ai/artifact/NSGLzNnVy5zTA3ykWmpGzU): how a layer of the pad plays as grains (`PlayMode::Granular`, the `mpfree-grain` engine), as a tool of the Wave page (`wave_tab::Tool::Grain`, picked on the tools strip) in place of the pad editor's old Grain tab, which is gone (and with it the cloud picture and the touch pad). It edits the layer picked on the Play tab's layer map (`PlayTab::layer_of`, through `SamplePage::layer`, as the rest of the Wave page, Warp and Chop do), so each layer of a pad can be its own cloud; the pad bar says which ("· layer 2"). It edits that layer's region only: its mode and its grain settings (`GrainParams`); everything else is kept. Every edit is a `WaveAction::Region` keyed by its row (`Key::Grain(row)`), so the Wave page's undo, gestures and log carry it.
- **The grain window** (`grain_tool::span`, a `mpfree_ui::wave::GrainSpan` set with `Waveform::set_window`). On the wave: a box from the position, one grain long (the size at the project tempo, `WaveState::bpm`, for a synced size), and the band the spray scatters grain starts over round it, wrapping round the region, both in `GRAIN_COLOR`. Two tabs (`grain_tool::markers`) hold it: **GRAIN** at the position, its tab left of its line, and **SIZE** where the first grain ends, its tab right of its line (`TabSide::Before`, `TabSide::After`), so a short window never covers its own tabs. Dragging GRAIN sets the position (`moved_start`), SIZE the size (`moved_end`), and a tap on the wave moves GRAIN there. The other tools' marks (Start, End, the loop, a sliced sound's cuts) are faint lines with no tab (`Marker::faint`, `Marker::line_only`): the tab strip holds only the picked tool's tabs, so they never crowd GRAIN and SIZE. The wheel zooms round the window's start. **The grains playing** come in the cloud report (`SampleGrains`, each `GrainView`'s position across the region and its window's level): `WaveTab::set_cloud` keeps them and the wave draws a mark for each (`Waveform::set_grains`), round the wave's middle in the window's colour, as tall and as bright as the grain's window is open. They redraw with the cloud report, as the moving spray already did.
- **Picking Grain plays grains** (Jay's device notes, 20 Nov 2026: "the grain tab should automatically be in granular mode"). A tap on Grain on the tools strip, on a layer in another mode, is a region edit to `PlayMode::Granular` (`WaveTab::grain_on`, its own undo step); a tap on Grain while it is picked does it again after an undo. The Grain section has no Mode row (`Row::Mode` stays in `grain_tab` for its log order and other callers; the Trim tool's Mode section picks another mode). The app seats a layer turned granular with untouched grain settings (`GrainParams::default()`) at its loudest grain (the grain-long stretch with the most energy on the channels it plays) in the same edit (`SamplePage::seat_grains`), whether Grain or Trim's Mode made it granular. Nothing long runs on the screen thread for it (sampler redesign plan, phase 1 step 1; before, a 25-minute take asked for about 1.3 GB at once, two 8-byte numbers a frame plus a float copy of a 16-bit sound):
  - A region of up to `SCAN_FRAMES` (2^18, about 6 s at 44.1 kHz) is searched frame by frame, a quarter grain at a time, where its frames are, with no copy and nothing allocated (`Region::loudest_grain`; about a millisecond on the MPC).
  - A longer one is searched in its sound's loudness summary, the peak pyramid the views worker works out first (`Region::loudest_grain_from`, `PeakPyramid::rms`): stretches of whole summary blocks (the coarsest level with at least 8 blocks in a grain, 256 frames for the default 80 ms) slide a block at a time, the 8 loudest that don't overlap are kept in a fixed array, and around each the sound itself is searched an eighth of a grain at a time. In Stereo, Left and Right the summary's energy is the sound's (to its 16-bit rounding); in Mono sum it is only an upper limit (the sides can cancel), so the pick is the loudest of the 8 as measured from the sound. About a million reads and nothing allocated for a 25-minute take (0.7 ms on the workstation, where the frame-by-frame search takes 130 ms). Tests: `a_long_regions_grain_start_comes_from_its_summary_where_the_scan_would_put_it` (as loud as the scan's pick within 0.5 dB, and within a quarter grain of it where one spot is clearly loudest, on every channel pick, a trimmed region, a 16-bit sound and silence), `finding_the_grain_start_allocates_nothing_for_a_long_take`.
  - Before the summary is there (`Views::summary` is `Pending`, the first seconds after a long sound loads), the grains start from the first frame at once and the page keeps a `Seat` (at most 16): `SamplePage::seat_later` moves the start once the summary comes, joining the switch's undo step when nothing else was done since, only while the region is still exactly as the switch left it (Position untouched) and never while the pad (or take) has voices in the playing kit's playheads. A sound with no summary keeps the first frame: a fallback, counted (`seat_fallbacks`), logged and shown on Dev > Debug. Test: `a_long_take_turned_to_grains_moves_to_its_loudest_grain_when_its_summary_comes`.
  - The start is rounded to the Position row's 0.1 % step, as a turn would leave it, only while that step is under a quarter of the grain (`seat_step`); on a long region it is wider (1.5 s on a 25-minute take, against an 80 ms grain) and would move the start off the loud spot, so the spot stays exact.
  - Why: before, a fresh cloud froze on the sound's first 80 ms, which on a take or phrase is often a breath or silence: "barely audible" on the device. The engine's level is unchanged (a dense cloud plays at its source's level; see Granular engine, Level).
- **The Grain section** (`grain_tool::section`), under the wave in place of the Mode, Gain and fades and Options sections, beside the Sound section. A switch along its top (`GrainPart`: Grains, Shape, Grain filter, Keys, Grain LFO, Grain env, Presets; `PARTS_ROW`) picks the part shown, and the part's controls fill the 242 px band: one line (Grains: Scan, Spray, Size spray, Pitch spray, Level spray, Timing, Reverse, Stereo and Level knobs, a long name on two lines over its knob (`panel::Item::two_lines`, `panel::knob_name_lines`) so none is cut, then Spray shape, 124 px; Grain filter: its passes, 330 px, then Grain cutoff, Grain res, Filter spray; Keys: Size follows key, Scan follows key, Glide; Grain LFO: Grain LFO to, Wave, Rate, Depth, Sync; Grain env: Grain env to, Depth, Grain attack, Grain decay, Grain sustain), or two lines of selectors (Shape: Grain mode, Quality; Shape as ‹ value ›, Pitch quantise, Tempo sync) or of buttons (Presets, four a line). Quality is three buttons (Clean, Tape, Lo-fi). The names on the screen are `Row::short` (the log keeps `Row::label`): the grains' own filter, LFO, envelope and pitch say Grain, as the Sound section beside them has the pad's own filter, envelope, LFO and Pitch (Jay, 12 Nov: never two look-alike settings on one screen that do different things). `GrainPart::lines` keeps the rows the grain mode uses (`Row::used_in`), so a Stretch shows only a stretch's; the wheel walks the open part's rows (`GrainPart::rows`), and `GrainPart::of` finds a row's part. The part stays open across pads, layers and tools (`WaveTab::grain_part`, `open_grain_part`). The note at the section's top right (`WaveTab::grain_note`) says, in order: the mode, when the layer doesn't play grains ("Plays as Loop: tap Grain to play it as grains", `wave_tab::GRAIN_AGAIN`); the open part's own word (`grain_tool::part_note`: what the LFO or the envelope does or "off: pick what it moves", "set as each grain starts" or "off: pick a pass", the preset lit's about); else the cloud ("18 grains playing", "thinned to fit 64").
- **The Sound section's Grain part** (`sound_panel::Part::Grain`). The Sound section's fifth part turns Position, Size, Density and Pitch (`GRAIN_ROWS`, the Q-Links' rows) of the page's layer, faint while it doesn't play grains (`NOT_GRAINS`). A pad edit (`PlayAction::Pad`) keeps the layers' regions as they are, so these steps go back to the Wave page as region edits instead (`SoundPanel::grain_step`, the same `Key::Grain` steps as the Q-Links').
- **The grain rows** (`grain_tab::Row`). Mode, Grain mode (Cloud, Stretch, Repeat or Tone: which rows show, see Granular engine, Modes), Scan speed (−2× to 2×, Frozen at 0), Spray, Spray shape (Even or Peaked), Size spray (0 to 100 %), Pitch spray (±12 st), Level spray (0 to 100 %), Timing (how random the gaps between grains are: Regular, 5 % steps, Random; new regions and older projects start at 30 %), Shape (the grain's window, 0 to 100 % in 5 % steps: Square, Trapezoid, Triangle at 40, Hann at 60 where new regions start, Swell at 80, Pluck at 100; a region from before shows its window's old name, Tukey, Trapezoid or Percussive, until Shape is turned, and the first turn starts from where that window sits on the knob), Reverse (the share of grains played backwards), Spread (stereo), Quantise (Off, Major, Minor, Pentatonic, Fifths, Octaves or Chromatic: each grain's pitch lands on the scale), Tempo sync (Off, Density, Size, Both), Position, Size, Density (1 to 200 grains a second), Pitch (±36 st), Level (the cloud's gain, −24 to +12 dB, half a dB a step) and the grain filter's Filter (Off, Low pass, Band pass, High pass), Cutoff (20 Hz to 20 kHz, a sixth of an octave a step), Resonance (0 to 100 %) and Filter spray (Off to ±3 octaves). Arrows step a row; the wheel steps the row picked. Each row is on one part of the Grain section (`GrainPart::of`), the Q-Links' (Position, Size, Density, Pitch) on none: they are the Q-Links' and the Sound section's Grain part's.
- **Tempo sync.** Density synced steps in grains a beat (0.25 to 32) and Size synced in beats (1/64 to 4); turning either on starts at the beats nearest what plays at the project tempo (`GrainState::bpm`), and turning it off keeps the free density and size that were set. The region saves a `TempoSync` with `frames_per_beat` at 120 BPM at 44.1 kHz (`SAVED_FRAMES_PER_BEAT`), but the engine plays every synced cloud at its own tempo: a voice gets `Engine::frames_per_beat` when it starts and again whenever `Engine::set_tempo` changes it (`GrainVoice::set_tempo`), so a cloud playing follows a tempo change at once. Grains start on the transport's beat grid (`GrainVoice::render`'s `transport_frame`). SIZE's drag and Q-Link 2 step the synced size's beats.
- **Q-Links** turn Position (0.5 % a detent), Size and Density (a doubling every 8 detents) and Pitch (a semitone). With SHIFT, Q-Link 1 turns the spray and Q-Link 4 the pitch spray, and Q-Links 2 and 3 turn size and density finer (1 ms, 0.1 a second). Their four rows are on no part of the Grain section: the cards and the Sound section's Grain part show them.
- **Undo.** Each drag, Q-Link turn, wheel turn or run of taps on one row is one undo step, as with the other tools, and each writes one log line with what changed (`grain_tab::describe`, from `SamplePage::describe`). Opening another part ends the gesture.
- **What the Grain tool shows of the cloud** (R7 step B7). While the Grain tool is picked, the app's cloud box (`sampler::Cloud`, filled on the audio thread by `Player::fill_cloud`) carries `Engine::cloud_of(pad, layer)`: the spray the first voice's grains start in now (`GrainVoice::moved_params`, so movement and pressure show) and whether any voice is thinned (`Stats::thinned`: the cloud wants more than `MAX_GRAINS` at once and the voice spaces them out). `WaveTab::set_cloud` takes the number of grains playing and a `CloudNow`: the window's spray band follows the spray as played, and the note counts the grains and says "thinned to fit 64". The playhead on the wave is the voice's reading place (`Engine::kit_playheads`, a granular voice's scan position), so a scan, an LFO on position and a stretch in time show where they took the voice. When the voice stops, the band goes back to the spray set. The sample screens `grain` and `grain-thinned` (1.5 s grains at 120 a second, peaked, an LFO on spray) show them (`sample::cloud_reports` replays the last second's reports).
- **Cost.** The Grain tool reads the count and the cloud's state, never the engine's own grains: `Engine::grains_of(pad, layer, out)` copies them into a fixed slice without allocating. The Grain section's note shows how many grains play and, when a voice's cloud wants more than it keeps, "thinned to fit 64" (`mpfree_grain::voice::MAX_GRAINS`, per voice). The budget shared by all voices (`GRAIN_BUDGET`, 256) is not shown there; device round 2 measures it from the `--afford` lines.

### The Pads tab (`mpfree-sampler-ui`)

The tab is three columns: the pad map (440 px), the Pad list and the kit's sounds (340 px). - **Clips.** The time engine (`mpfree-seq`, `mpfree-play`) owns clips and doesn't launch them from pads yet, so the Pad list says "clip: none" and the map shows no clips. `PadsState::clips` is where the app puts each pad's clip name once the time engine has an accessor for it.

The app finds each pad's note with `keymap::sound_root` and calls `Project::map_to_keys` (see Keygroups below).
- **Pad types** (the Play, Pads and Sequencer redesign's step 6b, boards 2 and 6; the saved fields agreed with the sampler thread, `Pad::kind` below). `SectionChips` over the Pad list (`pads_tab::TYPE`, `smp-pads-type`) reads Sample, Loop, Instrument and MIDI out (`PadType`, read back from a pad by `PadType::of`), and a tap is `PadsTab::set_type`: one `PadsAction::Set` with no gesture, so one undo step, and a note on the hint line ("A13 is a MIDI out pad now"). **Loop is not a kind:** `as_loop` makes a Sample pad latched, every layer a whole-region Forward `sustain_loop`, warped (at `PadsState::bpm`, the project's tempo, where it had no warp) and `on_launch`; back to Sample turns `on_launch` off and leaves the rest. Loop on a pad with no sound says to Browse for one. **Instrument** sets `PadKind::Instrument` with the first of `PadsState::engines` (its id lowercased, "poly") at C4; **MIDI out** sets `PadKind::MidiOut` with the first of `PadsState::ports` (`OutPort`: the live outputs, with the name they show by and `mpfree_midi_ui::sends_nothing`'s words) and the channel and note a kit on that port sends for the pad: the port's profile pad (`OutPort::pads`, from `Profile::pad`), else `mpfree_midi::profile::KIT_NOTES` on channel 10. An empty pad made either takes the engine's or the port's name (`blank_pad`). The Pad list's rows follow the type (`rows`): a loop's Sound, Tempo (`Row::Tempo`: the warp's BPM, 0.1 a detent, with the bars it makes), Mute group, Level, Pan, Tune, Effects; an instrument's Engine and Note; MIDI out's Port, Channel (1-16) and Note; Q-Links follow too (`qlinks`, `qlinks_text` for the hint). `SettingList::footer` under the rows says what a hit does ("A hit sends note 49 on channel 10 to Volca Kick"), in `t.warn` when it would do nothing (no such engine, the port not plugged in, MIDI out off). The map's cells show the type in the corner (`PadCell::badge`, `type_tag`) and what the pad plays ("ch 10 · 49", "Poly C4", "2 bars"); `in_use` (a sound, or a type that needs none) is what counts a pad as used, for the bar's count, Map to keys and the Play page's names (`SamplePage::take_renamed` gives each pad's name and `type_tag`, which Play's rows draw under the name: `Lane::tag`). The app routes the hits (Pad kinds below). Tests: `the_type_switch_makes_a_sample_a_loop_and_back_one_undo_step_each`, `an_instrument_pad_picks_its_engine_and_note`, `a_midi_out_pad_sends_to_its_own_port_and_says_when_it_would_send_nothing`, `the_types_sample_screen_shows_a_pad_of_each_type`, and in the app `the_pads_tabs_type_switch_makes_a_midi_out_pad_the_sound_loop_routes`.
- **The Pad list.** Sound, Mode (One shot, Gate, Loop, Granular; Loop adds a loop where a layer has none), Polyphony, Mute group, Level, Pan, Tune and Effects, and on every type Edit pad last (see [Edit pad](#edit-pad-the-play-page-mpfree-sampler-ui)). Its rows step as on the Play tab (`play_tab::stepped`). ### Warp and stretch

- **High quality:** `mpfree-stretch` renders a stretched or pitch-shifted copy on a worker, at the project tempo for a warped region. When the tempo changes, the region keeps playing with the real-time stretch below until the new copy is ready, then crossfades to it at the next loop start.
- **Real time:** the granular engine in "stretch" mode (grain size 40-90 ms, overlap 4, scan speed = tempo ratio, pitch 0, position jitter 0), which is a form of synchronous granular stretching (close to WSOLA without the cross-correlation search). Cheaper and lower quality; good for live tempo moves and as a deliberate effect.

#### Warp (`mpfree-sampler::warp`)

- **Model.** A region's `warp: Option<Warp>` says the tempo it was played at (`bpm`, 20 to 999) and how it meets the project tempo (`WarpMethod`): **Stretch** keeps the pitch and changes the length; **Repitch** plays faster or slower like tape and leaves the region's tune out, which would pull it off the beat. Granular regions ignore warp (their grains have tempo sync). The Warp tool's section has **Warp** (Off, Stretch, Repitch) and **Warp tempo** (a BPM a step, or typed); turning warp on starts at the source's detected tempo, made exact when the region is whole beats of it.
- **Pins.** A warp's `pins` pin hits to beats: source frame `frame` plays on `beat`, counted from the region's start. Between two pins the sound stretches evenly; the start stays on beat 0 and the end where the warp tempo puts it (`Warp::beats`), so a loop keeps its length whatever the pins do. Pins are in order of frame and beat, at most 128, and nowhere make the region play more than 4 times faster or slower than its tempo (`Warp::pins_ok`, checked by `Region::check`). They count only when the region stretches: repitching, it plays straight through. When the Wave tab moves Start or End, each pin stays on its hit, its beat counted from the new start (`Warp::moved`); pins outside the region or that no longer fit go (`Warp::fit`, also on a new warp tempo).
- **Copies.** `Warps` holds the project tempo and the stretched copies made for it, keyed by source, region, length, tune and pin set (`CopyKey::pins`, a hash; 0 for none) (a stretch copy carries the layer's whole tune, up to two octaves, so the length stays on the beat), within a 200 MB budget: past it the least recently used copies no project wants at the tempo go, never one that is wanted. `Warps::missing` says what to make; `Worker` is a thread that makes them in turn and drops them when cancelled (a new tempo cancels the old tempo's copies within one step).
- **Playing.** `EngineView::build_warped` resolves a stretch region to its copy when it is made (loop points and slice taps mapped through the pins with `CopyMap`, fades scaled) and repitches it to the tempo until then; a repitch region always repitches. `Engine::set_tempo` (every period, with the transport's tempo; nothing allocates) moves the step of every warped voice at once, so a held loop follows a tempo change straight away; a copy made for another tempo repitches until the next hit plays the new one.
- **In the pad player.** The Sample page keeps the `Warps` and the worker; a new tempo from the transport rebuilds the views of kits with warped pads and asks for their copies, and each copy that comes back sends a new view and logs a line (how long it took and the memory the copies use). The audio loop calls `Player::set_tempo` before it renders.
- **Process.** `Process` stretches or pitch shifts one layer's region into a new source (to a tempo, by a ratio, by semitones) on a worker; `Project::use_processed` puts it in the layer's place with its loop, fades and warp tempo moved to match, as one undo step that also takes the new source away. A stretched region's pins are made part of the new audio (its hits land on their beats) and the new region has none. `Process::spec` gives the job's input owned, for a worker to start it (finding the hits is part of the work). The Warp tab's Process button reaches it (above).

#### The stretch engine (`mpfree-stretch`)

Our own Rust, not Signalsmith Stretch as first planned: no C++ to cross-build for the MPC, MIT like the rest, and the hit handling is ours to tune with the sampler's own hit finder.

- **Map.** A `TimeMap` says where each input frame lands: one ratio, a target length, or warp markers (input frame, output frame), each part between 0.1 and 10 times.
- **Stretch.** A phase vocoder: Hann windows of about 46 ms (2048 frames at 44.1 kHz; 256 to 16384 by setting), read where the map says and written at a steady hop of a quarter window. Bins are grouped round the spectrum's peaks and turn with their peak (identity phase locking, Laroche and Dolson), so partials stay whole.
- **Stereo.** Left and right go through one complex FFT and turn by the same angle, worked out on their sum (or their difference where the sum cancels), so the image and mono compatibility stay as they were (a left-only input keeps its right channel below -60 dB; an out-of-phase pair stays out of phase).
- **Hits.** The hit finder (`OnsetAnalysis`, the Slice tool's) finds the hits; a hit counts only if its brightness (the energy of the change from frame to frame) jumps at least 6 dB, because beating partials can fool the finder and a restart in a steady sound wobbles the pitch. Each hit is then played at its own speed from half a window before it to three quarters after, the stretch is taken up between hits, and the phases start again at the first window that reaches it, so the attack comes out sample for sample as it went in and lands where the map puts it (within 1.5 ms in the tests, the finder's own error).
- **Pitch.** Stretched by the pitch ratio, then read that much faster by a windowed-sinc resampler (Kaiser, 24 zero crossings), low-passed first when it reads faster. Formants move with the pitch, as on a sampler; keeping them is a later setting.
- **Steps.** `Job::new` finds the hits; `Job::run(frames)` does about that many output frames of work and reports progress, so the worker can stop between steps and the old sound plays until the new one is ready. Any step size gives the same output.
- **Cost.** On the workstation (one core of a 2.1 GHz Xeon) a stereo stretch runs at 50 to 70 times real time, a pitch shift at 18 to 40 (an octave up is the dearest: twice the vocoder work and the longest filter). The round 7 calibration puts the MPC at about 6 to 8 times real time for a stretch and 2 to 5 for a pitch shift, so a 4-bar loop at 120 BPM takes 1 to 4 s. Device numbers win; the stretch goes into the next device round.
- **Listening.** `mpfree-stretch` (a workstation tool in `mpfree-sampler`) renders examples from a WAV or a demo chord and beat: slower, faster, twice as long, slower without kept hits, up 5, down 7, up an octave and warped, with a report of each one's time (and an MPC estimate with `--calibration docs/dev/perf/mpc-one-calibration.txt`).

### Keygroups (`mpfree-sampler`)

- **Model.** A pad's `keys: Option<Keys>` (`lo`, `hi`, `root`, MIDI notes) makes it a keygroup: it plays every note from `lo` to `hi`, a semitone higher for each note above `root` (`Keys::all(root)` covers the keyboard, `Keys::one(note)` a single note). The kit's `pads_play` (`PadsPlay::Pads`, or `PadsPlay::Keys { from }` with pad 1 playing `from` and each pad a semitone up, `from` at most 112) says whether a hit plays the pad's own sound or a note; it is in the undo log like any edit. `Project::spread_to_keys` makes a pad a keygroup over the keyboard with chord voices and the pads playing from the C below its root; `Project::keygroups_for(note)` lists the pads that hold a note.
- **Map to keys (`keymap.rs`, `Project::map_to_keys`).** `keymap::note_in_name` reads a note from a name: a letter A to G, then `#`, `s` or `b`, then an octave of -1 to 9, standing alone as a word and at most G9 (the last one wins, so "Piano C3 then E3" is E3; "Break 92", "BD" and "C34" have none). Middle C is C4 (MIDI 60), as everywhere in MPFree. `keymap::sound_root(keys root, name, heard)` picks the note: the keygroup's root, else the name's note, else the pitch heard; when the name and the heard pitch are the same pitch class the heard octave wins (some libraries call middle C C3), and when they disagree the name wins. `Project::map_to_keys(&[(pad, root)])` gives each pad a zone reaching halfway to the next root up and down (`autosample::zones`; the lowest and highest to the ends of the keyboard; pads with the same root share a zone), at least 16 voices, and sets the pads to play notes from the C at or below the lowest root, as one undo step; an empty pad or a pad without a sound changes nothing (`tests/keys.rs`).
- **Engine.** `Event::Key { note, velocity }` and `Event::KeyOff { note }` play every keygroup holding the note; with the pads playing notes, `NoteOn`, `NoteOff` and `Pressure` for a pad are its note. A keygroup voice reads `2^(semitones / 12)` faster (a granular voice adds the semitones to its grains' pitch instead, so its timing stays put), keeps its note so each key lets go of its own, and counts against the pad's polyphony. A hit on a keygroup while the pads play their sounds plays it as recorded. `EngineView::has_pad` follows the mode, so the pad player's lights and `Player::hit_at` do too. A warped keygroup moves with the tempo on top of the note. None of it allocates (the `no_alloc` test plays keys every few periods).
- **Fades (`Pad::key_fade`, `Pad::vel_fade`, `model::edge_gain`).** A keygroup fades in over its first `key_fade` notes and out over its last (0 to 24), and each layer over its first and last `vel_fade` velocities (0 to 64), on an equal-power curve (note `n` steps inside an edge plays at `sin(n / (fade + 1) · π/2)`), so two zones or layers overlapping by the fade sum to the same power on every note. An edge at the end of the keyboard (0, 127) or of the velocities (1, 127) never fades, and a hit on the pad itself (its own sound, not a note) has no key fade. The engine works out each layer's level once, when the voice starts (`Engine::note_on`), so a fade costs nothing per sample and a fade of 0 plays bit for bit as before. With a velocity fade, Cycle and Random take turns within each set of layers that share their velocities (the round robins of one velocity) and every set the hit falls in plays, so auto-sampled round robins still alternate while their velocity layers crossfade; the turn counter wraps at 720720, which every set size up to 16 divides. **One step to a crossfade:** Map to keys and auto-sample leave zones and velocity layers edge to edge, and a fade alone would dip where they meet, so setting a fade also moves the edges that meet to overlap by it, centred where they met (`model::overlap_ranges`; running it again with another fade moves the same edges, 0 puts them back edge to edge; a gap or a stack is left alone). `Project::set_key_fade` does it for every keygroup of the kit as one undo step, `Pad::set_vel_fade` for a pad's layers, round robins together. The app writes `sample: kit 1 (Breaks): key fade 2 notes, the zones that meet crossfade over them`; a Vel fade change is a line of the pad's like any row. Saved with the project (`key_fade`, `vel_fade`; older saves open at 0). Tests: `tests/keys.rs` (the curve, levels measured at the edges, layers crossfading, round robins in sets, limits).
- **Not yet.** A MIDI keyboard into the sampler (the pad player has no MIDI input route to it yet; the Play tab's keyboard plays it on screen), a root's cents (Tune does it by hand) and the MPC's keygroup program import.

### Sliced pads (R4, `mpfree-sampler`)

One pad holds a whole break as up to 128 slices (Jay's decision 4(a), 16 Nov 2026), beside Chop to pads and Chop to a new kit: a whole break plays from one pad and one track. Plan: mpfree-claude `sampler/r4/plan.md`.

- **Model.** `Region::slices` holds the cuts, in source frames, strictly sorted, at most `MAX_SLICES - 1` (127, so 128 slices); empty means not sliced. Slice `i` runs from edge `i` to edge `i + 1`, the edges being `start`, the cuts inside `start..end`, then `end` (`Region::cuts`, `slice_count`, `slice_bounds`). A cut outside `start..end` is passed over rather than refused, so trimming a sliced region never fails: the slices it leaves out come back when the trim does. `Region::check` refuses cuts out of order, at 0, past the sound, or too many (`BadRegion("slices")`). The cuts move with the sound like every other point: `rescale` (another rate) and `use_processed` (a processed copy) map them. `ChopSet::sliced` gives the whole sound as one region with the chop's markers as its cuts; slice `i` then plays exactly as `ChopSet::region(i)`, the region Chop to pads puts on pad `i`. `Pad::slice` (0 = slice 1) is the slice a hit plays.
- **Which slice.** `PadField::Slice` (field 8, so a step lock is `pad * 16 + 8`) is a live setting like Tune: a step lock (`Event::PadLock`) or a knob (`Event::PadLive`) picks the slice, rounded to a whole one in the engine (so a scene's morph or a Q-Link never lands between slices), and NaN gives the pad's own back. It reaches new voices only. On keys (the pad's keys, or the kit's pads playing notes), a note plays slice `note - keys.lo` at the sound's own pitch, one note a slice, as Simpler and the MPC's slice programs do; notes past the last slice are silent. A slice past the last one, picked by a lock or knob, is silent too.
- **How a slice plays.** The engine looks the slice up once, when the voice starts (`Engine::start_voice`, from the view's `cuts`); nothing new happens per frame. The voice plays the slice's frames with the region's own fades, each at most half the slice. One-shot, Gate and Toggle work per slice; Loop plays a slice as Gate and the sustain loop doesn't apply. Reverse plays the slice backwards. Granular reads the whole region (a granular view has no cuts). Repitch warp plays the slices at the tempo like the whole region; a stretched copy's cuts go through the copy's time map (`CopyMap::at`), so each slice plays its part of the copy. The start offsets (velocity to start, 16 Levels of Start) apply within the slice.
- **Saved** with the project: a region's `slices = ` list and a pad's `slice = ` (older saves open unsliced). An older build reads a sliced pad as one whole region, so it plays the whole break.
- **Tests.** `tests/slices.rs`: every slice of a sliced pad plays bit for bit as Chop to pads' pad for it; a lock or a knob picks the slice, rounded, and NaN gives the pad's own back; a note on keys plays its own slice and past the last is silent; a sliced pad saves and opens with its slices; a trim passes over the cuts left outside and bad cuts are refused; a stretched sliced pad plays each slice of its copy. `tests/no_alloc.rs` plays sliced keygroups by note, locks and knobs (some past the last slice) without allocating.
- **Chop to one pad** (R4 part 2): the Slice tool's Put on at 1 pad, with a phrase of Slice locks when Phrase is on; see the Slice tool above and [Chop to a phrase](#chop-to-a-phrase-mpfree-sampler).
- **Screens** (R4 part 3, `mpfree-sampler-ui`). Wave draws a sliced region's cuts as slice markers (`MarkerKind::Slice`, labelled from 2) after the region's own, so the region's markers keep their indexes; they are the Slice tool's, so on the Wave page they are faint lines with no tab, which no finger moves (`a_sliced_region_shows_its_slice_lines_faint_with_no_tab`). Play's Pad section has **Slice** (`play_tab::Row::Slice`, a stepper: "3 of 16", 1 to the pad's last slice, `play_tab::slices` counting the most sliced layer's; faint, saying why, on a pad that isn't sliced), and the Pad chip's line ends "· 16 slices" (`slice_picks_the_slice_a_sliced_pad_plays`). The Pads tab's map says "16 slices · Loop" under the name (`a_sliced_pad_says_its_slices_on_the_map`). The Slice tool opens on a sliced pad's own cuts as a Manual chop when its sound has no chop kept (`ChopState::from_project`).
- **Settings per slice** (R4 part 5). `Region::slice_sets` gives slice `i` its own `SliceSet`: Pitch (semitones, ±24), Level (−48 to +12 dB), Reverse (that slice backwards, or forwards on a reversed region), a low-pass cutoff in place of the pad's filter's (20 Hz to 20 kHz; None keeps the pad's), Fade out (0 to 2000 ms in place of the region's, still at most half of what plays) and Plays to (its own end, or on to the region's end). A slice past the list plays as `SliceSet::DEFAULT`; `Region::set_slice_set` keeps the list free of default entries at its end, and `Region::check` refuses one out of range (`BadRegion("slice settings")`). The engine's view turns them into `ViewSlice`s when it is built (cents, a gain, a fade in the frames the layer reads), so a hit only reads one: `start_voice` applies its gain, pitch (repitching the slice, warped or not), reverse, end, fade and cutoff (a hit's own cutoff, from 16 Levels by Cutoff, wins). A pitch up prepares the octave copies for a clean read (`may_pass_an_octave` gets the highest). Saved as `region.slice_sets = yes` and one list a setting under it (`tune_st`, `level_db`, `reverse`, `cutoff_hz` 0 for none, `fade_out_ms` −1 for none, `to_end`), or `no`; older builds skip them. Chop to one pad onto the pad itself keeps them by number (`slice_pad` with the pad as template). The Play tab sets them (`PlayAction::Pad` keeps a region's `slice_sets` from what it carries, and the rest of the region from the project). Tests in `tests/slices.rs`: level and reverse change that slice alone (reversed, it plays as Chop to pads' reversed pad), pitch repitches it and Plays to takes it to the end, fade and cutoff shape it, and they are saved, kept by a chop onto the pad and checked; `tests/no_alloc.rs` plays slices with settings.
- **The Slices section** (R4 part 5, `play_tab::Section::Slices`). The Play tab's seventh chip, "8 slices" ("8 · 1 set" once slices have settings, "not sliced" otherwise). Its picture (`play_tab::SLICES`, a `Waveform`) shows the sliced layer's sound from its start to its end (`sliced_layer`: the most sliced), a fixed line numbered at each slice's start, the slice picked shaded and its line lit; a tap on the wave or a line picks the slice (`slice_at`). Its rows: **Slice** (the slice picked, `Row::SlicePick`: what the tab shows, not a setting), then the picked slice's **Pitch**, **Level**, **Reverse**, **Filter**, **Fade out** and **Plays to** (`Row::of_slice`, `stepped_slice`, `turned_slice`, `slice_text`), in sections Slice, Sound and Shape. Q-Links: Slice, Pitch, Level, Filter. The filter's top step is Off. Every row is faint, saying how to slice the pad, on a pad that isn't sliced. Test: `the_slices_section_sets_each_slices_own_settings`. Where the settings go was Jay's pick (18 Nov 03:02Z): a Slices section on the Play page, not a second page of the Chop panel, which the roadmap's mockup had.
- **Not yet** (R4 part 4): Slice in the step lock lanes beyond the step inspector's name. A hit always plays the pad's Slice, not the next slice in turn.

### Links and Latch (`mpfree-sampler`)

- **Links (`Pad::links`).** A hit on a pad also plays the pads it links to, at the same velocity, as the MPC's Simultaneous Play (user guide 3.6, p. 187, which allows four; here any of the other 15). `Pad::chokes` are its Mute Targets (the same page). `Engine::hit` plays the pad, then each link through `note_on` as a hit on it would (its layers, chokes, mute group, latch and polyphony), with the voice's `by` set to the pad hit; `Target::Own` matches voices by `by`, so lifting the pad lets go of its links' voices too, pressure on it moves them, and a linked pad hit on its own keeps its own voices. Links go one way and one step (a linked pad's own links aren't followed), a link to the pad itself is dropped when the view is built, and a link past the 16 pads is refused (`ModelError::BadPad`). The voices one hit starts never choke each other (`Engine::spare_from`: chokes and mute groups skip voices started by this hit), so a pad can link to a pad in its own mute group; the next hit chokes them as usual. Links apply to hits on pads only: with the pads playing notes or 16 Levels they do nothing. The fan-out copies the links into a fixed array, so it allocates nothing (`tests/no_alloc.rs` covers it).
- **Latch (`Pad::latch`).** A latched pad's voices ignore lifts (`Engine::release` skips them, for pads, keys and 16 Levels alike); the next hit with the same note lets them go instead of playing (`let_go`: a loop leaves its loop and plays its tail, grains stop and release, anything else releases), as `PlayMode::Toggle` always did for one region; the hit after that plays again. `Event::AllOff` lets latched voices go too. `Engine::latched_pads` gives the pads a latched hit keeps sounding, as 16 bits, and the pad player lights them (`Player::latched_pads`, in the pad light loop of `main.rs`). With Note Repeat, every repeat is a hit, so a latched pad turns on and off with each step.
- **Saved** with the project (`links`, `latch`; older saves open without them). Tests: `tests/links.rs` (links, one way and one step, no choking within a hit, notes, latch for gate, loop, grains, one-shots and keys, AllOff, a latched link), `tests/save.rs`, the Play tab's rows and pad hits in `mpfree-sampler-ui` `tests/play_tab.rs`, and the app's (`hits_on_pads_edit_stops_and_also_plays_and_latch_is_a_row`).
- **Full Level and Half Level** need nothing here: the pad player fixes a hit's velocity before it reaches the sampler (`App::velocity`), and 16 Levels of velocity keep their own.

### Pad kinds (`mpfree-sampler`; sampler R5 part 3, the redesign's step 6)

- **`Pad::kind`** (`PadKind`, agreed with the Play, Pads and Sequencer redesign thread, 18 Nov 2026): `Sample` (the default, every pad before it) plays its layers; `Instrument { engine, note }` plays one voice of a Synth tab engine (its id, as "poly") at a note; `MidiOut { port, channel, note }` sends a note to gear (channel 1 to 16). The sampler plays only Sample pads: `EngineView` leaves the others out, so a hit, a link or a lock on one plays nothing here, and the app sends its hits where they go (the redesign thread's routing, beside the synth host and MIDI out). A pad keeps its layers whatever its kind, so switching back loses nothing; a sound put on a pad of another kind (`Pad::replacing`: a take, a load, a recall) makes it a Sample pad again, and chopping gives Sample slices. A take, a Skip back or a recall going onto the next empty pad passes pads of another kind by (`taken` in `sample_page.rs`), and Flatten doesn't offer to record one.
- **A loop pad is not a kind:** it is a Sample pad with latch, a Forward loop, warp and `Pad::on_launch` (the Pads tab's Loop preset). `on_launch` makes a live hit wait for the project's launch line while the transport plays (R5.3b, the line from `TimeAudio` as agreed with the sequencer thread 18 Nov 09:13Z):
  - **Which hits wait.** The sound loop asks `waits_for_line` (main.rs) on the three live paths: the MPC's pads, the screen's pads and a keyboard's keys on a kit (`time::PadFrom::Pad(slot)` or `Key(kit pad)`). A hit or let-go waits when the pads play a kit (not the synth, not Free time's steps), `TimeHost::pads_wait` (the transport rolls and `PlayView::launch`, the project's launch quantise compiled into the view, isn't `Now`), and `sampler::Player::starts_on_line` (`EngineView::starts_on_line`: the pad has a sound and `on_launch`, the pads play pads, and live chop isn't marking that kit); or when something played on the same pad waits already, so a pad's events keep their order. Clip notes never wait.
  - **When they play.** `PadWaits` (`time/pad_wait.rs`, 64 fixed places, nothing allocated) keeps them in order: a hit plays on the next line the playhead plays, its let-go on the line after its hit's (held loops sound a whole line), anything after a waiting event no earlier than it. After `TimeHost::advance`, `TimeAudio::due_pads` walks the period's spans: each line (`Span::lines` at `LaunchGrid::line` of the span's bar) plays what is due there with its frame, except a count-in's (a hit made then waits for the record start, the first line after it). Launch set to at once plays the rest where it changed, a frame apart in order (the arp ends a note before it starts one on the same frame). A stopped span is STOP (sequencer review 18 Nov 13:56Z): `PadWaits::stop` drops the hits still waiting with their let-gos, plays the let-gos of hits that sounded, and remembers a pad still held so its let-go plays nothing when it comes (`lets_go_of_dropped`, checked first in `waits_for_line`); `due_pads` returns how many it dropped, and the sound loop counts them in the log (`note_stop_dropped`: "pads: STOP dropped 1 Loop pad hit(s) still waiting for the launch line (1 so far)"). A jump or a locate just changes which lines come next. A full table plays the hit at once, counted, logged and on the hint line.
  - **How they play.** `play_waited` runs the path the hit would have run when made, on its frame: `App::pads_at` (the armed track's arp, `mpfree_arp::Engine::set_at`) puts the press or let-go on that frame instead of the period's top, the clip recorder hears it there (`TimeHost::pad_pressed` with the offset), and the screen shows the pad down when it sounds (`awaiting`) and up with its let-go. The smoke `Session` mirrors it when it has a sounding kit.
  - **The light.** While a pad's hit waits (`PadWaits::hits_waiting`, the pads by their place on the page), the MPC pad blinks amber twice a second, as TRACK MUTE's waiting keys do, over its held or latched light (the light loop's `lit` keeps the colour each pad shows over its resting one), and `ToUi::PadsWaiting` gives the screen's pads (`MiniPads::waiting`) an amber outline (`t.warn`), as a cued clip has, until it sounds. Layout spec 4e (the sequencer thread lands its wording). A key's hit on a kit pad doesn't light a pad, as its hits don't.
  - **PAD BANK turned before the line** (sequencer review 18 Nov 14:16Z): each wait keeps the kit pad it was made on (`PadWait::kit_pad`, bank × 16 + place), and a let-go that waits behind its hit takes that hit's (`PadWaits::wait`). `play_waited` plays that pad (`App::pad_down_on`, `press_pad_on`), which `kit_held` then keeps, so the let-go made after the turn lets go of it (`pad_up`). The screen shows it down, and the light and outline show it, only while its bank shows (`hits_waiting(page)`).
  - Tests: `the_view_carries_the_projects_launch_line` (mpfree-play), `a_press_set_into_the_period_plays_on_that_frame_once` (mpfree-arp), `pad_wait`'s own tests, `a_loop_pad_starts_on_the_line`, `a_loop_pads_hit_waits_for_the_launch_line_and_plays_on_it` (the bar and beat lines to the frame, at once a frame apart, STOP dropping and playing a sounded hit's let-go), `a_loop_pads_hit_in_a_count_in_waits_for_the_record_start`, and the session's `a_loop_pad_hit_mid_bar_starts_on_the_next_bar_line` (to the frame, through the arp; the screen's outline; PAD BANK turned before the line still starting A1 and letting go of it; STOP dropping it, its let-go and the log line).
- **The pad player routes them** (the redesign's step 6b, `mpfree-app`). `sampler::pad_routes(project)` gives each pad of a kit its `PadRoute`: `Voice(engine, note)` (the engine found by `synth::Engine::from_folder`; an unknown one is None and plays nothing, as the Pads tab says) or `Midi { port, channel (0-15), note }`. The routes travel with the kit's new view (`ViewSwap::routes`) and `Player::swap_view` swaps them in, so the audio thread never builds or frees them; `Player::pad_route(kit, pad)` reads them. In `SeqPads` (`main.rs`) every hit, release and pressure of a kit pad, from a clip or played live, asks `routed` first (after the synth's own tracks): a MIDI out pad goes to `MidiOut::pad_to` (its own port, whatever the track's Plays on; from any of the 128 tracks, as MIDI out serves them all), an Instrument pad to `Synth::pad_voice_on`, `pad_voice_off` and `pad_voice_pressure`. The synth keeps a voice per track and pad (`pad_voices`, fixed size) and counts the holders of each engine's notes with the pads engine's own (`pad_holders`), so a note two pads (or a pad and the synth's pads) hold ends with the last. - **Each Instrument pad's own synth** (`pad_synths.rs`, `mpfree-app`; Jay's card, 18 Nov 2026 20:15Z, "Own pad channel, Synth tab's sound"). Every 32 periods the sound loop's `plan_pad_synths` (`main.rs`) runs `PadSynths::plan` over `Player::voice_pads` (every kit's Instrument pads, from the routes): a copy whose pad changed goes (it rings out), a new pad is asked for while fewer than 16 have one, and one made before its engine's design changed (`Synth::design_of`, bumped by `redesigned`) is asked for again and stays until the new one is in. The asks go to the instrument builder as track instruments' do (`InstrumentJob::pad`, the sound from `Synth::sound_of`); `MixHost::poll_instruments` puts what comes back in with `PadSynths::put` (never allocating), drops an unwanted one off the audio thread, and `take_pad_landed` gives the log its line. A copy the builder can't make (`PadSynths::failed`) isn't asked for again until its pad or design changes.
  - **Hits.** `pad_voice` (`main.rs`, from `SeqPads::routed` and `play_routed_pad`) plays a hit on the pad's copy (`note_on`, keyed by track and pad as the synth's `pad_voices` are) and ends any note the shared synth held for it; without a copy it plays the shared synth as before and counts it (`fell_back`). Let-go and pressure go where the hit went. A muted or silenced track ends its pads' copies' notes (`end_track`), STOP stops them, and their tuning is the Synth tab's.

  - **Rendering.** `MixHost::period` renders the copies after the tracks' instruments, while any is held or ringing, into the strip each slot's pad has now (`PadSynths::render` with a `Dest` per slot, the `Outputs` adapter mapping to `pad_input` or `track_input`). A slot renders only while it was sent something since the last period, rings or has voices sounding, so quiet pads cost next to nothing. The time is added to the instruments'. ### 16 Levels (`mpfree-sampler`)

- **Model.** `PadsPlay::Levels { pad, by }`: every pad of a bank plays pad `pad`, pad `k` (0 to 15) at step `k` of `by` (`Levels`). The steps are ours, not a copy of the MPC's: **Velocity** 8, 16, ... 127; **Tune** a semitone a pad with pad 9 as recorded (−8 to +7); **Cutoff** 100 Hz to 20 kHz evenly in octaves (a 2-pole low-pass when the pad's filter is off, else its own type and resonance); **Decay** 25 ms doubling every two pads (to about 4.5 s), falling to silence; **Start** `k / 16` of the region (a granular pad's grain position, `k / 15`). One undo step, like the other `pads_play` changes.
- **Engine.** A hit starts the pad's voices with that step (`Vary`), tagged with their level so each pad lets go of its own; Full Level doesn't flatten velocity levels. Nothing allocates (the no-alloc test swaps in views playing cutoff, decay and start levels).
- **Play tab.** Pads play goes round Their sounds, Notes and 16 Levels (of the pad on show); **Levels by** picks the step. A hit on any pad picks the pad the levels play, and the change writes a line (`sample: kit 1 (Breaks): the pads play 16 Levels of pad A5 by tune`).

### Tape (`mpfree-sampler`)

- **Wow and flutter.** A pad's `wow` (0 to 1; the Play tab's **Wow & flutter** row, 10 % a step) makes its pitch wander like a worn tape machine: two slow wobbles (0.53 and 0.29 Hz, 15 and 10 cents at full) and a fast flutter (7.3 Hz, 5 cents). Each voice starts its wobbles at its own place, so a chord doesn't wander in step. Granular voices keep their grains' pitch.
- **Tape stop and start.** `Event::Tape { stop, ms }` slows every voice to a halt (or brings it back up to speed) along a straight ramp of `ms` milliseconds, as a tape machine's motor would; below a quarter of the speed the sound fades out, so a halted tape is silent rather than stuck on one sample. Voices wait where they stopped and go on when it starts again, and a hit on a stopped tape waits silent too. It is the sampler's own tape: a tape stop on the whole mix would be a master effect.
- **Cost.** The speed and the wobbles move once per period (or between events), never per frame: each moving voice's step is worked out again from its base step, its pitch pressure and its speed (`retime`). A running tape with no wow leaves the output bit for bit as it was (the hash check over two busy workouts is unchanged), and the no-alloc test stops and starts the tape with wobbling pads.
- **Not yet.** A control for this pads-only tape stop: the Play page's Tape stop throw already stops the whole mix with the FX master tape stop, so this one waits until a pads-only stop is wanted. Repitch that follows the tempo is warp's Repitch; half speed is Tune −12.

### Chop to a phrase (`mpfree-sampler`)

- **What it is.** A loop chopped to pads plays back whole only if something hits the pads in the right places. `phrase::phrase(chop, first, count, frames_per_beat)` gives the slices as hits in beats of the sound's own tempo, from the first slice (`Hit { slice, beat, beats }`); the phrase lasts the slices' span in whole beats (within 0.05 of a beat it rounds, else up). As a clip, the loop then plays at any tempo with each slice as recorded (only the gaps move), and every hit is a note to move, mute, retune or swap: the MPC's chop-to-sequence idea, ours in the details.
- **The clip.** The Sample page makes it (`ChopAction::phrase`, then `phrase_clip`): one note per slice, on the slice's pad at velocity 127, at 960 ticks a beat, named after the pad ("Break 92 phrase"); the time engine checks it (`Clip::check`) when it lands. On one sliced pad (R4), every note is on that pad with a Slice lock on its step (`Lock { sound: Some(pad), addr: Pad(pad).8, value: slice }`), which reaches the pad just before its note (`time::tests::a_phrase_on_one_pad_plays_each_hit_with_its_slice_lock_first`).
- **Not yet.** Keys + phrase (the clip would need a track that plays notes), and a phrase from a chop already on pads.

### Saving with the project (`mpfree-sampler`, `mpfree-app`)

The kits are the sampler's part of a saved project (owner `sampler`, see `docs/dev/design/browser.md`).

- `save::to_text` writes every kit as `key = value` lines under `kit.K.`: its sounds by file name, its chop sets, its master effect, what its pads play, and every pad's layers, regions, loops, fades, warp pins, grain settings, envelopes, filter, pressure and keys. Each struct is taken apart field by field, so a field added to the model doesn't build until it is saved too. Numbers read back to the same bits.
- `save::from_text` gives the kits back with empty undo histories. A key it doesn't know is skipped and a missing one keeps its default, so older and newer builds' parts open. A missing or broken sound, a pad or chop the model refuses, a bad master effect: each is left out with a note, and the rest opens. Each file is read once, however many kits use it, and the kits share it in memory.
- `wav::write` keeps a sound losslessly in the smallest form that gives every sample back: 16-bit or 24-bit PCM when the samples are exactly that (a line-input take, a 16-bit import), else 32-bit float. Mono stays mono. Read back, it is the same `Source` with the same id. `wav::file_name` is the id (`1f0c2d3e4a5b6c7d.wav`), so the same sound is one file and a file already in the project is that sound.
- `wav::read` takes 8, 16, 24 and 32-bit PCM and 32 and 64-bit float WAV files, mono or stereo, plain or extensible, at 8 to 192 kHz, up to 64 Mi samples; a file cut short gives the whole frames it has.
- `sound_file::read` takes any sound file by what it holds, not its name: WAV (`wav::read`), AIFF (`aiff::read`) or FLAC. `aiff::read` takes AIFF and AIFF-C with 8 to 32-bit PCM (big-endian, `sowt` little-endian, `in24`, `in32`) and 32 or 64-bit float; compressed AIFF-C says which compression it refuses. FLAC is decoded by `mpfree-flac`, our own decoder (no new crates): 4 to 32 bits, every subframe type and stereo coding, an ID3v2 tag in front stepped over. Every frame header's CRC-8 and every frame's CRC-16 is checked, so a damaged frame is an error saying how far in it is, never noise. A file cut short loads the whole frames it has, and stray bytes between FLAC frames are stepped over; either way it comes with a note the log shows. A loaded sound is kept in a project like any other: a 16 or 24-bit FLAC or AIFF is saved as a WAV of the same bits, the same sound.
- Tests: `mpfree-flac` decodes seven files from FFmpeg's encoder (16, 24 and 32-bit; independent, left/side, side/right and mid/side; fixed, LPC up to order 32 and verbatim subframes; wasted bits; `tests/data/make.py` makes them) bit for bit against the signal they hold, plus hand-built streams for what FFmpeg never writes (variable blocks, 8, 12 and 20-bit, escaped residuals, a 33-bit side channel); cuts, damage, tags and stray bytes; and the browser's picture column by column.
- In the pad player, `SamplePage::save_part` gives the text and each sound once; the library's save writes the sounds the project hasn't got before the part (`Library::save_project_with`), so a part never names a missing file. `SamplePage::open_part` reads and decodes the sounds on a thread of its own; on a later tick each kit goes in its place, its view goes to the audio thread like an edit's, the Play page's names follow, and the pads switch to the kit the project was playing.
- The browser's Load puts a WAV, AIFF or FLAC file on the pad shown (one undo step); Load to pad holds it until the next pad hit (`SamplePage::load_file`). Both read and decode on their own thread (`sound_file::read`). A note (a file cut short) goes to the log before the sound lands: `sample: Loop: the file is cut short: its first 2304 frames`.
- Not yet: kit files on their own (`LoadKit`), the factory kits from the browser, MP3 and Ogg.

## Granular engine (`mpfree-grain`)

```text
 GrainScheduler (per granular voice)
   every block: accumulate density × block time; for each due grain:
     pos   = playhead + jitter(spray)            (playhead advances by scan_speed)
     pitch = base + pressure/knob mod + random(pitch_spray), quantised to scale if set
     len   = size (frames), dir = reverse? with probability, pan = random(spread)
     push Grain { pos, inc, remaining, window_phase, window_inc, gain_l, gain_r } into a fixed array
 Grain render: for each active grain, for each frame:
     s = hermite(buffer, pos); w = window_table[phase]; out_l += s·w·gain_l; out_r += s·w·gain_r
```

- **Fixed arrays:** each granular voice has up to 64 grains; there is a global grain budget across voices (start at 256, set by measurement). Past the budget, new grains are skipped, never queued, so the period is never at risk.
- **Windows** are 1024-entry tables (Hann, Tukey with a shape parameter, trapezoid, exponential, and one Shape control across them, R7 step B2), read with linear interpolation.
- **Sources:** a region (granular playback mode) or a circular live buffer of 4-8 s (granular effect). Freeze stops writes to the live buffer.
- **Sync:** density and size can lock to tempo divisions, using the transport's frame position.
- **Determinism:** randomness comes from a seeded generator per voice, so offline renders are reproducible in tests.

**Built (S6, workstation half):** `rust/mpfree-grain`, with the tool `mpfree-grain` in `mpfree-sampler` for listening to eight presets on any WAV. What it does, as built:

- `GrainVoice` has a fixed array of 64 grains. `Budget` counts the grains alive across all voices and refuses new ones past its limit.
- Grain sources are `Clip` (a region of a sample) and `LiveBuffer` (a circular buffer with freeze). Grains are placed so the whole read stays inside the readable span, so a grain is never cut short or reads outside its region.
- **The edges of a sound** (sampler plan, phase 1 step 4, 20 Nov 2026). A span under `MIN_SPAN` (8) frames can't be read. A source says whether its span can still grow (`GrainSource::grows`: a `LiveBuffer`, and the Grains effect's repeat slice of one, yes; a sample, no). On one that can't, the voice stops making grains, so it ends; before, a held grain pad on such a sound kept trying until it was let go. The sampler ends that voice at once (`grains` in `engine.rs`; silent, it never made a sound). A live buffer still filling waits, as before. Where a cloud reads (`base_offset`) is the position plus the scan's offset, round the span, except that the far right (100 %, nothing scanned) is the span's end, not its start. A still cloud (scan 0) no longer wraps a grain's start round the span either: spray past an end turns back from it (`fold`, a mirror), then the clamps fit each grain inside, so a forward grain ends on the last frame it can read (`end - 3`, for the interpolator's neighbours) and a reversed one starts from it, at any size and pitch. A scanning cloud still goes round. The Grains effect already held its Position below 100 % for this (`GrainFx::set_params`); its spray past the newest audio used to wrap to the oldest and now turns back, which moved the first quarter second of the bench's four dense Grains FX cases (blessed). Tests: `tests/grain.rs` `a_sound_too_short_to_read_stops_and_a_filling_buffer_waits` and `a_still_cloud_at_the_far_right_plays_the_end_of_the_sound` (forward, reversed, an octave up and both: every grain within its reach of the end; the playhead at 1; spray turned back; a scan goes round); `mpfree-sampler` `tests/granular.rs` `a_held_grain_pad_on_a_sound_too_short_to_read_ends_at_once`.
- Windows are Hann, Tukey, trapezoid and exponential, as 1025-entry tables. Pitch can be quantised to a 12-note mask. Density and size can lock to the transport's frame timeline (`TempoSync`), and synced grains start on exact frames whatever the period size.
- **Each grain keeps its window** (sampler plan, phase 1 step 3, 20 Nov 2026). Before, a voice had one table, rebuilt in place when Shape turned, so every grain playing (and every grain fading under a hit) jumped to the new shape mid-grain: a step in the output while Shape turned. Now a voice keeps `WINDOWS` (4) tables (`GrainVoice::windows`, 4 KB each, made in `new`: about 1 MB over the pad player's 64 voices) and counts the grains reading each (`users`, playing and fading). A grain notes its table as it is born (`Grain::win`) and reads it to its end; `mix` counts it out. A new shape (`set_window`) goes to a table that already holds it, else into the table new grains read if no grain reads it, else into a free one. With all four read (a fast sweep over long grains), the shape waits (`wanted`) and new grains keep the newest shape until a table frees, at most a grain's length later; the latest turn wins, and each wait counts in `Stats::window_waits`. `Engine::window_waits` sums the pads' voices and the master effect; the Dev tab's Debug page shows it as "Shape turns that waited for grains to end". A grain fading under a hit fades along its own window to its own peak. Writing a table costs what the one table did (1025 values, on the audio thread, only when Shape moves). Tests: `voice::tests::no_table_a_grain_reads_is_written_over` (3,000 periods of Shape turning every period over 1.5 s grains with hits: no grain's table changes, the counts match, and some turns wait); `tests/grain.rs` `a_new_shape_reaches_new_grains_only_with_no_step` (4 s grains, square against pluck from the same frame: the first 32 frames differ by under 0.01; a two-second sweep, a new shape each period, steps no more than the steady cloud) and `grains_fading_under_a_hit_keep_their_window` (0.19 apart before, 0 now).
- Pads play it through `PlayMode::Granular` in `mpfree-sampler`. Each voice slot has its own `GrainVoice`, and one `Budget` (`GRAIN_BUDGET`, 256) is shared by all of them. A region keeps its grain settings in every play mode. Tune adds to the grain pitch, reverse makes every grain play backwards, and the pad's envelope, filter, pan, chokes and polyphony apply as for any other voice. Lifting the pad stops new grains and releases.
- **The granular effect** (`GrainFx`) is an insert on a stereo signal. It keeps the last 0.5 to 30 s in a `LiveBuffer`, plays a `GrainVoice` from it, and mixes the grains back with an equal-power mix that glides over 10 ms. Freeze stops the buffer taking new audio, so the cloud keeps playing what it holds while the dry signal carries on. Audio reaches the buffer in fixed 64-frame chunks counted from the effect's first frame, so the output doesn't depend on the period size; new audio waits at most 1.5 ms before it can be granulated, and freeze takes in what is waiting first. **Feedback** (R7 step C1, `GrainFx::set_feedback`, 0 to 1, gliding over 10 ms) writes the grains back into the buffer with the input, so they play again in later grains: trails that build. In the loop the grains go through a one-pole high-pass at 40 Hz (nothing builds up at the bottom) and a soft saturation, straight up to a quarter of full scale and bending (tanh's rational fit) to at most half, so what goes back is never more than half of full scale on top of the input and the loop can't run away; loud trails grit up, as the plan's decision 4 wants. At 0 the buffer holds the input exactly, as before. At full, a loud trail holds near -16 dBFS and fades about 0.3 dB a second; at half it falls about 8 dB a second. Measured: [FX quality, step C1](fx-quality.md#step-c1-grains-effect-feedback-2026-11-18). **Repeat** (R7 step C2, `GrainFx::start_repeat(beats)` and `stop_repeat`, at the tempo `set_tempo` gives) is a synced stutter: from the frame it starts on, the last `beats` beats of the input play again every `beats` beats, in place of the input and the cloud. A second grain voice of its own reads that slice of the buffer (a `Slice` source: the buffer's audio, with only the slice open to new grains), one grain a repeat on the grid counted from the start, each a little longer than the repeat (by 3 ms, or a 99th of the repeat if longer) with linear fades of that length (`Window::Trapezoid`), so each repeat crossfades into the next and nothing clicks; the effect's Pitch, Reverse and level play through it, nothing random. The output crossfades over 10 ms from the input and the cloud to the repeat and back; the cloud rests from the first 64-frame chunk boundary after it is out of hearing, and starts afresh when the repeat stops; the repeat voice is let go at the first boundary after it has faded (both on chunk boundaries, so the output is the same at any period size). A new length while it repeats re-cuts the slice from the same start, so quarters to eighths to sixteenths roll the start of the beat. The buffer keeps taking the input (feedback rests, as the cloud is silent) unless that would overwrite the slice, when it holds, as when frozen, until the repeat ends. Measured: [FX quality, step C2](fx-quality.md#step-c2-grains-effect-repeat-2026-11-18). **Capture** (R7 step C3, `GrainFx::copy_held`, through `Node::copy_held`): the memory the cloud plays from goes out a piece a call, oldest first: all of it while frozen or held by a repeat, else the span the cloud reads (all but the oldest quarter, the reserve new audio is about to overwrite). The copy runs far faster than the writes (8,192 frames a period against 128), so the span stays whole; a reset under it (`LiveBuffer::clears`) or an overwrite all the same says Lost, never a mix of old and new (`LiveBuffer::frames` gives held frames as the two parts either side of the wrap). Tests: `mpfree-grain/tests/fx.rs` (exact, while audio comes in, lost) and `tests/no_alloc.rs`.
- **For now it sits on the sampler engine's master.** `MasterFx` in the project holds the mix and grain settings (undoable, with a knob turn merged into one step), and the engine view carries them. `Engine::make_master_fx` makes the effect with 8 s of memory (2.8 MB, off the audio thread), `Engine::set_master_fx` puts it in (it glides in from dry) or takes it out, and `Event::Freeze { on }` freezes it on an exact frame. It runs after the voices on every segment between events, and its grains come out of the engine's grain budget. This is an interim hook: the FX chain (`mpfree-fx`, on the shared `mpfree-node` interface) will own the mixer and master bus, and `GrainFx` becomes one of its nodes there. Tests: `mpfree-grain/tests/fx.rs`, `mpfree-sampler/tests/master.rs` and both no-allocation tests; the listening render is `master-freeze.wav` from `mpfree-grain`.
- **As an FX-chain node.** `GrainNode` (`mpfree-grain/src/node.rs`) wraps a `GrainFx` with 8 s of memory and its own budget of 64 grains, as an `mpfree_node::Node` (id `mpfree.grains`), so it can sit on an insert, a send return or the master chain; the FX picker offers it as **Grains** (Delay and reverb), with its pages, Q-Links and presets in `mpfree-fx` ([FX design](fx.md)). Its parameters are in plain units: Mix, Position, Spray, Timing, Reverse, Spread, Shape, Size spray and Level spray in per cent, Size in ms, Density in Hz, Pitch and Pitch spray in semitones; Freeze and Peaked spray are toggles (Freeze one a sequencer can set on an exact frame), Feedback (id 16, per cent, default 0) is the effect's feedback, Repeat (id 17, a choice: Off, 1/2, 1/4, 1/8, 1/16, 1/32) its repeat, Filter (id 18, a choice: Off, Low pass, Band pass, High pass), Cutoff (id 19, Hz, 20 to 20,000, default 2,000), Resonance (id 20, per cent) and Filter spray (id 21, per cent) each grain's filter (the Texture page's Filter section), Quality (id 22, a choice: Clean, Tape, Lo-fi; Main's Output section) the quality mode, Repeat starting on the next line of its own length on the transport's beat grid (`Ctx::beats`; at once while the transport is stopped) and stopping on the frame it is set Off, a new length while it repeats rolling the slice from the next line of the new length, a reset ending it (and with Repeat still on, the next starts on its line), and Grains is a read-only meter of the grains playing. `copy_held` gives its memory for a capture, and `node::voice_params` turns the values kept with it into the grain settings a pad plays to sound as the effect did: the Sample page puts the capture where a recording would land (`SamplePage::captured`, the Rec tab's target pad), as a granular region with those settings, one undo step. `prepare` allocates the memory; `process`, `set_param` and `reset` don't allocate. Parameter events land on their frame, the output is the same at any block size (to within 1e-4), and `reset` clears what it heard. Its tail is the memory plus one grain, once for each time round the feedback loop it takes to fall 60 dB; endless while it repeats or waits to (at any Mix: a repeat plays fully dry too), while frozen or with feedback of 99 % or more, and none when fully dry. Tests: `mpfree-grain/tests/node.rs` and `tests/no_alloc.rs`.
- Output doesn't depend on the period size, and the same seed gives bit-identical output. `tests/no_alloc.rs` covers render, start, stop, kill, parameter changes and live-buffer writes.
- Cost measured on the workstation (x86, one core, `cargo run --release -p mpfree-grain --example grain_bench`): about 67 million grain-frames a second on a stereo clip and 59 million on a live buffer, which is 4-5 % of a core for 64 grains at 44.1 kHz. The RK3288 figure is still to be measured, and it sets the budget.
- **Level** (R7 step A2, `GrainVoice::render`). Overlapping grains add up in two ways: grains of unrelated audio add in power (`n` of them are `√n` louder), grains reading the same audio in step (a time stretch, a held tone) in amplitude (`n` louder). Each grain sounds at full level (its pan's gains only), and the voice keeps, frame by frame, the sum of the grains' window levels `S1` and of their squares `S2`, and divides the cloud by `c·S1 + (1 − c)·√S2`. `c`, how far the grains are in step, is measured as the cloud plays: in one 64-frame part of every four (counted on the voice's clock) the voice keeps 50 ms averages of the output's power, of the grains' own powers summed, of `S1²` and of `S2`; every 8 frames, where the window power is over 0.25 and `S1²/S2` over 1.05, `c` = (output / summed − 1) / (`S1²/S2` − 1), held to 0 to 1, and `c` glides there over 50 ms. A voice starts with `c` guessed from its settings (1 for a stretch with no spray, pitch spray or reverse whose scan matches its pitch, else 0). The divisor never goes under a floor: 1 at an overlap of 1 or less, so lone grains keep their windows and the level they had; 0.3 from overlap 2 (linear between), so a gap between grains doesn't fill with hiss. The floor starts at 1 and falls over a quarter of a grain (at least 10 ms), so a cloud's first grains, and grains cut short by a live buffer that has only just started, aren't raised; once grains stop it glides back to 1 in 10 ms, so a tail fades as its last grains do. So a cloud plays at its source's level whatever its size, density, scan, spray or window, the window sum's ripple is gone (4.2 dB at the defaults before, 6 dB for flat-topped windows at overlap 2) and long grains speak about twice as fast. Before, each grain was scaled by 1/√overlap: right for unrelated grains on average, but a stretch with no spray came out up to 16 dB louder than a sprayed cloud. The Grains FX and the `mpfree.grains` node play through the same voice. Cost: the granular bench cases count 3 to 12 % more instructions.
- **Timing** (R7 step A3, `Params::timing`, 0 to 1, default 0.3). Each gap between free-running grains is anywhere from `1 - timing` to `1 + timing` density periods, uniform, so the density on average is unchanged; regular grains (0) arrive in lockstep, which buzzes at the grain rate and makes a frozen cloud comb (its level rising and falling as the density moves). The gaps come from a random sequence of the voice's own (`TIMING_SEED`), drawn once a grain whatever the setting, so the other settings' draws never move and timing 0 plays exactly as before. Synced density ignores it and stays on the beat grid. Regular grains (timing 0, free-running) keep their exact times (R7 step B5): the next is due one period after the last was due, not after the frame it started on, and a grain due between two frames starts on the next with its window and read already that part of a frame in (`Grain::phase0`, `spawn`'s `frac`), so their rate is exact and a cloud of short grains plays a tone in tune (on whole frames, a period of 100.2 frames rounded up to 101: 13 cents flat at A4). Other grains start on the frame, as before. The default density is 25 a second, so the default 80 ms grains overlap twice and, with gaps of at most 1.3 periods, the window sum never falls under the level's floor. Saved as `timing` with a region's and the master effect's grain settings; projects saved before open at 0.3. The `mpfree.grains` node has it as Timing (id 11, per cent). Measured: [FX quality, step A3](fx-quality.md#step-a3-timing-2026-11-17).
- **Cap, running start and pan** (R7 step A5). *Cap:* a voice keeps at most 64 grains, and a free-running cloud whose size and density want more (overlap over `CAP_FIT`, 54) spaces its grains out to their length over 54, so it thins evenly instead of skipping grains at random; `Stats::thinned` is true while it does. The length is the grains' real one (`fit_size`: the size, or shorter where a grain at the cloud's pitch would read past the sound, as `spawn` shortens it). Synced grains keep the grid and skip at 64. *Running start:* `start` sets the next grain to come with a few that a cloud running for a grain's length would have: one gap back at a time (timing draws, or the synced interval; at least `fit_size / START_GRAINS`, 8) while a grain born then would still sound, each made with that age (`spawn`'s `age`: that far through its window, reading from where the scan was, not wrapped round the span, since only what it still has to play is read: a cloud scanning from the start opens in step with what follows, not with the sound's far end), and the voice fades in over 4 ms. The level law above plays those few at the cloud's level, so a cloud speaks at once at any size and fills in to its density over the next grain; a swell is the amp envelope's. Starting with the whole cloud sounded the same and made short hits cost the whole cloud (the song +21 % in the instruction gate, against +2.6 %). The extra grains come out of the budget like any other. *Pan:* equal-power, `√2·cos` and `√2·sin` of `(pan + 1)·π/4`, so the centre is 1 and 1 and a spread cloud of unrelated grains keeps its level; at full spread the random pan leans to the sides (`|r|^0.5`), for a correlation of 0.44 that still folds to mono within 1.5 dB. Measured: [FX quality, step A5](fx-quality.md#step-a5-the-cap-width-and-onsets-2026-11-17).
- **Clean pitching** (R7 step A4, `mpfree_sampler::grain_clip::GrainClip`). A pad's grains read its sound through `GrainClip` (floats or 16 bits, the Hermite read bit for bit as `mpfree_grain::Clip`'s). The grain crate asks its source how to read each grain when the grain is born (`GrainSource::aim`, from the grain's speed, kept in the grain as an `Aim`) and reads it with `GrainSource::read_aimed` when the aim says clean; the default, which the Grains FX's live buffer keeps, is the Hermite read. `GrainClip` aims a grain clean past `CLEAN_ABOVE` (two semitones up), as a sample voice switches: the octave copy that brings the speed under `MAX_STRETCH` and the sinc's reach for what is left (`Reach::parts`), then reads with `bandlimit::read2`. So a grain whose own pitch spray takes it past two semitones reads clean and its neighbours don't, and grains at or under two semitones up play bit for bit as before. A Vintage pad's grains (`Voice::grain_clean` false) keep the Hermite read. A granular pad gets its sound's octave copies when its Pitch and Pitch spray (with tune, keys, 16 Levels and pressure, as for any pad) could take grains past an octave, and its voices read them if they were made by the time they started. Measured: [FX quality, step A4](fx-quality.md#step-a4-clean-pitching-2026-11-17); `tests/clean_pitch.rs` (15 kHz an octave up through grains: the alias −92 dB clean, −9 dB Vintage; two octaves up from the copies, gone). The Grains FX on a live signal has no octave copies and keeps the Hermite read for now. Cost: the band-limited read is 3 to 5 times Hermite's a frame, so a cloud pays for the grains that go past two semitones: the bench's 4 granular pads (Pitch spray ±5 st, so about 3 grains in 10) count 82 % more instructions, 20 pads 26 %, 20 pads with the master grains 17 % and the song 8 % (blessed). Vintage keeps the old cost; the device round measures it on the MPC (step A6).
- **Shape** (R7 step B2, `Window::Shape { shape }`, 0 to 1; the plan's decision 2, one knob). One control morphs the window through five named shapes, each joined smoothly to the next (`window::shaped`): **square** at 0 (linear fades of 1 % of the grain); the fades lengthen to a **triangle** at 0.4 (a trapezoid whose ramp goes from 0.01 to 0.5 of the grain); the triangle crossfades to **Hann** at 0.6; then the peak of a raised cosine (a cosine rise to the peak and fall after it, Hann with the peak in the middle) moves late to a **swell** at 0.8 (peak at 92 %: a slow rise, a fast stop) and sweeps back to a **pluck** at 1 (peak at 4 %), passing Hann again near 0.9. A small turn moves the window by less than 5 % of its height on average (`tests/grain.rs`). The voice reads it from its table like the other windows, so a Shape change costs one table fill (1,025 values). Hann stays `Window::Hann`, and the older windows stay as they were (a saved project plays the same); `Window::shape_value` places each on the knob (Hann 0.6, a trapezoid by its ramp, a Tukey by its fade length, the exponential at 1) so a turn starts from there. Saved as `window = shape` with `window_shape`; the Grain list's Shape row (Square, Trapezoid, Triangle, Hann, Swell, Pluck, with the per cent); the `mpfree.grains` node has it as Shape (id 12, per cent, default 60, which is exactly Hann). The level law plays every shape at the source's level (a square window's overlap counts as more, a pluck's as less). Measured: [FX quality, step B2](fx-quality.md#step-b2-one-shape-knob-2026-11-17).
- **Variation** (R7 step B1, `Params::size_spray`, `level_spray`, `spray_shape`). Every way grains differ has its own amount: position (Spray, with `SprayShape::Even` or `Peaked`: the offset is the even draw cubed, so 58 % of a peaked cloud's grains start in the middle fifth of its range, against 20 % of an even one's), size (each grain's length times `2^(size_spray · r)`, half to twice at 1; the cap fits to the mean, 1.08 times the size at full), pitch (Pitch spray), level (each grain from its full level to `level_spray` × 24 dB down, even in decibels), pan (Spread), direction (Reverse) and timing (Timing). Size and level draw from a random sequence of their own (`VARY_SEED`), twice a grain whatever the settings, so with none a cloud plays exactly as before and turning one moves no other grain. A grain's level goes into the level law's sums like its window, so a dense cloud keeps its source's level whatever the variation (the floor's dense end and the coherence measure's cover come down with the grains' RMS level, 0.42 at full, or the floor would hold a cloud of quieter grains under its level); a sparse cloud's grains keep their own levels. Saved as `size_spray`, `level_spray` and `spray_shape` (`even`, `peaked`); projects from before open with none. The `mpfree.grains` node has them as Size spray (id 13), Level spray (14) and Peaked spray (15, a toggle). Measured: [FX quality, step B1](fx-quality.md#step-b1-variation-on-every-dimension-2026-11-17).
- **Modes** (R7 step B5, `Region::grain_mode`, `GrainMode`; the plan's decision 1). A granular region has a grain mode, which sets what the Grain tool's section shows (`Row::used_in`, through `GrainPart::lines`) and where it starts (`grain_tab::mode_settings`, applied when the Grain mode row picks a mode, keeping the position and the level; one undo step, as a run of taps on any row). The grains underneath are the same in every mode. **Cloud**: every row; it starts scattered a little (spray 0.1, spread 0.5, 100 ms, random timing 0.3). **Stretch**: Scan speed, Position, Size, Density, Pitch, Shape, Spread and Level; it starts at scan 1 with 90 ms grains at 45 a second (overlap 4) and nothing random (no spray, pitch spray, reverse, size or level spray, regular timing), so its grains stay in step and the level law plays them as one (A2), and Scan and Pitch move speed and pitch apart. **Repeat**: Position, Density, Size, Shape, Pitch, Reverse, Spray and Level, tempo-synced (`set_sync`, Both); it starts at 4 a beat and a quarter of a beat long, scan 0 and regular timing, so it replays the spot under the position every sixteenth, with Shape 10 % (short linear fades) so the repeats don't click. **Tone**: Density (shown as the note, A2 · 110 Hz, a semitone a step from A0 to B5), Size (shown as cycles of the note, 1 to 16 in halves; the note's step keeps them), Position, Pitch, Shape, Scan speed, Spray, Pitch spray, Spread and Level; it starts at A2 with grains four cycles long, regular and frozen, so the grain rate is the note and the spot read (Position) and the grains' own Pitch are its colour. A Tone region's tune (the region's, layer's and pad's, a keygroup's semitones, a live tune, the program's tune) moves the density and shortens the size as much (`engine::pitched_grain`; `ViewLayer::tone`, `Voice::grain_tone`), so every note keeps its grains' cycles and its colour; pressure on pitch still moves the grains' pitch. A tone needs its grains exactly on time: see Timing (regular grains start between frames). A mode's hidden rows keep their values. The row picked stays picked if the new mode shows it, else the Grain mode row is. Saved as `grain_mode` (`cloud`, `stretch`, `repeat`, `tone`) with the region; projects from before open as clouds. A Stretch region whose sound has a tempo (`Region::warp`, the Warp tool's; its pins aren't used) keeps time: the engine's view puts the tempo in `Params::scan_tempo` (never saved), and the grain voice moves its scan the transport's tempo over that times as fast (held to 1/8 to 8), following tempo changes as synced clouds do; the Scan row says "· in time". A Stretch region keeps its sound's hits sharp (`crate::hits`): the view asks for the sound's hits (`hits::prepare`: `mpfree_stretch::hits` at the stretch's own sensitivity, 0.6, the onsets that really jump; at once for a sound up to 1.5 s, on the [job service](#the-job-service-step-7)'s sound lane for a longer one, never past 6.3 minutes), kept in a `HitCell` every clone of the sound shares (`Source::hits`; offline renders and tests call `Source::find_hits`). A voice takes them if found by its start (`Voice::hits`, as the octave copies) and gives them to its grains (`GrainClip::with_hits`, `GrainSource::next_hit`); the grain voice then stops forward grains at the next hit, starts one grain on each hit the scan reaches and fades the others out over 3 ms (`GrainVoice::render`, "Hits"). A live edit out of Stretch drops them.
- **Presets** (R7 step B6, `mpfree_sampler::grain_presets`). Eight starting points across styles (Glass pad, Frozen choir, Tape stretch, Stutter 1/16, Shimmer fifths, Grit cloud, Swarm, Sub drone), each a grain mode, every grain setting (from the defaults, movement off unless it moves), key tracking and glide (`GrainPreset`). `grain_presets::apply` puts one on a region: Granular play mode, the preset's mode and settings, keeping the sound, its points, the position and the level (`gain`), so it works on any sound at its loudness. Nothing new is saved: `grain_presets::matching` finds the preset a region equals as it is (`apply(r, i) == r`), so the Presets view (`Row::Preset` and `Row::PresetMore`, two lines of four buttons, `Look::Choice`, in every mode) lights the one a region equals and its chip names it, until a setting it sets moves: then none is lit and the chip says "your own settings". A tap on a button puts that preset on (`GrainTab::action`: a choice's tap is a `Step` from the line's lit button, or from the line's end when none is); the wheel on either line steps from the preset on to the next across all eight (from none, to the first or the last). One undo step a tap, or a run of steps, as any row. The stutter's synced grains are saved at 120 BPM's frames per beat, as a grain pad saves a sync, and play at the project tempo. Measured: every preset's loudness against the default cloud's (lab G14, [FX quality, step B6](fx-quality.md#step-b6-presets-2026-11-17)).
- **Keys and glide** (R7 step B4, `Region::grain_keys`, `GrainKeys`, and `Region::grain_glide_ms`). A key, a keygroup's semitones, 16 Levels' Tune and every tune (the region's, layer's and pad's, a live tune, the program's) move a granular voice through `engine::pitched_grain` with the layer's `KeyFollow` (`ViewLayer::follow`): a Tone region's density (its note, the size shortened as much), else the grains' pitch, and with key tracking the size shorter (`GrainKeys::size`, `size_ms / 2^(semis/12)`, not a synced size) and the scan faster (`GrainKeys::scan`, `scan × 2^(semis/12)`, in every mode). Glide (`ViewLayer::glide`, frames; 0 to `GRAIN_GLIDE_MAX_MS`, 5 s) moves a voice's semitones (`Voice::grain_hit`) in a straight line to the new key (`glide_to`, `glide_step`, `glide_left`), recomputing its settings from the layer's at the start of each render chunk (`grains`). On a mono pad (polyphony 1), a key played while a granular voice of the layer holds goes to that voice (`Engine::glide_held`: legato, no new start, the voice now plays the new note and hit pad, so the first key's release leaves it); otherwise a gliding layer's new voice starts from the pad's last key (`Engine::last_key`). A live edit of the key tracking reaches playing voices (`follow_edit`). Saved as `grain_keys.size`, `grain_keys.scan` and `grain_glide_ms` with the region; projects from before open with neither and no glide. The Filter and keys view's Size follows key (Cloud, Stretch), Scan follows key (Cloud, Stretch, Tone) and Glide (every mode) rows, after the filter's.
- **Movement** (R7 step B3, `mpfree_grain::motion`; `Params::lfo`, a `GrainLfo`, and `Params::env`, a `GrainEnv`). Each voice has one LFO and one envelope, each moving one setting (`MotionTarget`) by its depth (-1 to 1): **Position** by up to the whole span, wrapping; **Size** up to 8 times (`2^(3d)`, a synced size's beats too); **Density** up to 16 times (`2^(4d)`; a Tone's note four octaves; a synced density keeps its grid); **Pitch** up to 12 semitones; **Spray** up to the whole span, clamped; **Cutoff** (the grain filter's, R7 step C4) up to four octaves (`2^(4d)`). Both can move the same setting; their moves add. The LFO's shapes are sine, triangle, saw up and down, square, Hold (a new random value each cycle, held) and Drift (a new one each cycle, glided to over it by a half cosine); it runs at `rate_hz` (0.01 to 40) or, with `beats`, once every that many beats at the voice's tempo (`GrainVoice::set_tempo`, 120 BPM without one). The envelope rises linearly over its attack and falls exponentially over its decay to its sustain (99.99 % of the way there at the decay time) and holds while the voice plays. The voice keeps the settings as set (`params`) and as moved (`moved_params`): at the start of each 64-frame part of its clock it moves the LFO on and takes its value and the envelope's level, and the part's grains and settings (the scan, the fitted size, the level's floor) go by the moved settings, so a moving cloud doesn't depend on how the audio is cut into periods; `set_params` between parts moves the new settings by the values as they were. `start` starts both again. The LFO draws its random values from a sequence of its own (`LFO_SEED`), so with movement off (both targets Off, the default) or at no depth a cloud plays exactly as before. The sampler gives it a pad's region settings as they are (the engine's tempo is the voice's), so it plays from each hit; pressure moves the settings before it. Saved as `lfo.shape`, `lfo.rate_hz`, `lfo.beats`, `lfo.target`, `lfo.depth` and `env.attack_ms`, `env.decay_ms`, `env.sustain`, `env.target`, `env.depth` with a region's and the master effect's grain settings; projects from before open with both off. The Movement view's ten rows in every mode (LFO to, LFO shape, LFO rate, LFO depth, LFO sync, Envelope to, Env depth, Env attack, Env decay, Env sustain; `grain_tab::MOTION_ROWS`); a grain mode change keeps them. Measured: [FX quality, step B3](fx-quality.md#step-b3-movement-per-pad-2026-11-17).
- **A filter on each grain** (R7 step C4, `mpfree_grain::filter`; `Params::filter`, a `GrainFilter`; the plan's decision 4, grit in the engine). Off by default; Low pass and High pass (12 dB an octave, resonance peaking at the cutoff) and Band pass (its peak at full level at any resonance, which narrows it). Each grain gets its own filter when it is born, a state-variable filter in its trapezoidal form (Zavalishin, Simper; `Svf`), stable at any cutoff and resonance: its cutoff is the setting's (20 Hz to 20 kHz, held under 45 % of the rate) moved by the spray, a random distance up to three octaves either way at full spray (`FILTER_SPRAY_OCTAVES`, even in octaves), and its Q runs from 0.71 (flat to the cutoff) to 12 with the resonance, evenly in octaves. Its coefficients stay fixed for the grain's life, so it costs a few multiplies a frame. It filters what the grain reads, before its window, so its start from silence is under the window's fade-in and every grain still ends at zero. The cutoff draws come from a sequence of their own (`FILTER_SEED`), so with the filter off a cloud plays exactly as before, and with it on the grains read, pitch and pan as they would without it; `mix` keeps its unfiltered loops as they were and runs a filtered grain's reads through its `Svf` in a copy of them. The LFO and envelope can sweep the cutoff (`MotionTarget::Cutoff`), each grain taking the cutoff as moved when it starts. A hit's grain (Stretch) gets the cutoff unsprayed. Saved as `filter.kind` (off, low, band, high), `filter.cutoff_hz`, `filter.resonance` and `filter.spray` with a region's and the master effect's grain settings; projects from before open with it off. The Filter and keys view's Filter (four buttons), Cutoff (a sixth of an octave a step), Resonance and Filter spray rows (Stretch shows no spray: nothing random), before the keys'; a grain mode change keeps the filter (Stretch drops its spray). Measured: [FX quality, step C4](fx-quality.md#step-c4-a-filter-on-each-grain-2026-11-18).
- **Quality modes** (R7 step C5, `mpfree_grain::quality`; `Params::quality`, a `Quality`; the plan's decision 4, grit in the engine). How a voice's cloud is coloured on its way out, after the level law: Clean (the default), Tape or Lo-fi. Clean skips the stage (`GrainVoice::level::<true>` adds the part to the output as it always did), so it plays bit for bit as before. Otherwise `level::<false>` leaves the levelled part in the scratch and the voice's `Stage` colours it in place before it is added. Tape: a 256-frame stereo tape (about 2 KB a voice, room for the deepest wobble up to 96 kHz; scaled down to fit above) read at a delay moved by wow (0.6 Hz at ±0.3 % of the speed, 0.37 Hz at ±0.1 %) and flutter (7 Hz at ±0.05 %), the delay worked out at the edges of each 64 frames of the voice's clock and drawn straight between, read with four-point Hermite; then a `tanh`-shaped saturation (its 3/2 Padé fit, unity for small signals, 1 at 3) and a one-pole roll-off at 12 kHz. Lo-fi: a sample held for the rate over 11,025 frames, rounded (4 at 44.1 and 48 kHz), from the voice's clock, through 8-bit µ-law (µ 255, 127 steps a side; zero stays zero, full scale clips). A switch while the voice plays crossfades over 10 ms running both (`Stage::set`; one asked for during a crossfade follows it, `next`); a silent voice, or one killed, switches at once with nothing held (`Stage::jump`); a tape starting again fills from its first frame, so its delayed sound comes in without a step. In the Grains effect the voice's coloured output is what the feedback loop writes back, so a Tape trail wobbles more each time round. Nothing allocates. The Grain tool's Quality buttons (on its Shape part: Clean, Tape, Lo-fi), and the effect's Quality (id 22); a grain mode change and a preset keep it, and a capture takes the effect's. Saved as `quality` (clean, tape, lofi) with a region's and the master effect's grain settings; projects from before open Clean. Measured: [FX quality, step C5](fx-quality.md#step-c5-quality-modes-2026-11-18).
- **Reads in runs** (`GrainSource::read_run`, `read_aimed_run`). The voice asks the source for a grain's frames a part at a time (at most 64) rather than one at a time; `Clip`, `LiveBuffer`, the effect's `Slice` and the sampler's `GrainClip` check once that the run stays inside what they hold and then read with no edge test, and `GrainClip`'s clean run works out its copy, range and reach once and its fixed-point place without a 64-bit conversion (a library call on ARMv7). A run near the edges, past 2^31 frames (`buffer::SMALL_FRAMES`), or from a source without its own reads frame by frame (`read_run_each`); every way gives the same values to the bit. On the MPC's processor this takes about a sixth off a granular pad's and the Grains effect's instructions: [FX quality, speed](fx-quality.md#speed-grain-reads-in-runs-2026-11-18).
- **Measured in the lab** (`mpfree_fxlab::grain`, `tests/grain.rs` against `quality/grain.tsv`): level against the source across settings, the window sum's ripple, a frozen cloud's comb, pitched reads, the cap, width and onsets, each with the granular engine plan's target (sampler roadmap R7): [FX quality, The grain engine](fx-quality.md#the-grain-engine). The baseline there is what R7's sound work starts from.

## Analysis (`mpfree-analysis`)

| Analysis | Method | Output |
|---|---|---|
| Peak pyramid | Per channel min, max, RMS as `i16` at block sizes 64, 256, 1024, 4096 frames, built and drawn from floats or from a sound's own 16-bit samples (`build_from`, `columns_from`, any `Samples`) | `PeakPyramid`, kept in a saved project with the rest of the view as `<id>.a1.peaks` |
| Onsets | 1024-point FFT, hop 256 (5.8 ms); spectral flux on log-magnitude; adaptive threshold = median over ±8 hops × (1 + sensitivity); peak-picking with a 30 ms minimum gap; refine each onset to the nearest preceding low-energy frame | sorted frame positions with strength (so sensitivity can change without recomputing) |
| Tempo | Autocorrelation of the onset strength curve over 60-200 BPM, with a preference curve around 90-120 and octave checks; offered, not forced | BPM and confidence |
| Pitch | YIN on up to 24 windows of 100 ms within 24 dB of the loudest; voiced windows grouped by note, weighted by loudness × periodicity × steadiness (built: `mpfree_analysis::root_pitch`, also per slice via `SourceAnalysis::pitch_of`) | root note and cents, with confidence |
| Pitch track | The mono mix brought down to about 8 kHz; YIN every 10 ms on 40 ms windows (60 Hz to 1.5 kHz), 30 dB under the loudest a rest; a lone reading between two that agree mended (built: `mpfree_analysis::pitch_track`, for the Slice tool's Pitch method, on the analysis worker when first asked for; about 0.2 s a minute on the workstation) | a note a reading (or none), and where the notes change (`PitchTrack::changes`), each cut found to the millisecond |
| Zero crossings | On demand within ±N frames of a marker | nearest crossing with matching slope |
| Loudness | Peak, RMS; integrated LUFS later | numbers for normalise |

**Built: off the screen thread** (`mpfree-app/src/views.rs`, the sampler review's engine item 3). The Sample tab asks `Views` for a sound's `SourceView` each time it shows one. The first time, it gets `SourceView::pending` at once (a flat line of the sound's length, `ready` false) and the sound goes first on the [job service](#the-job-service-step-7)'s sound lane; the worker sends `SourceView::quick` (the peak pyramid and mono mix) and then `SourceView::finish` (onsets, tempo, root note; `ready` true), and the page is built again as each lands (`SamplePage::tick`). Measured on the workstation, release build, a minute of stereo: peaks and mono 27 ms, the rest 170 ms (onsets 127 ms, root note 37 ms, tempo 6 ms); three minutes: 83 ms and 470 ms. The MPC is several times slower (not measured). What waits on the analysis: the Slice tool chops again and the Warp tool finds its hits once it is ready, and the Wave tab's 16ths snap isn't dropped for want of a tempo before then. Map to keys waits on the [job service](#the-job-service-step-7) for the views it needs. Views are kept by source id (the hash of the audio) while the sound is in a kit, so a kit loaded again or a sound in two kits is analysed once; the rest are forgotten when the kits change.

**Built: kept with the project** (the sampler review's engine item 3, its last part). A save keeps each sound's view, once it is ready, in the project's `samples/` beside the sound: `<id>.a1.peaks` (`source::cache_file`; `SamplePage::cache_part`, written by the library's save as a `NewSample` like the sound, so once and whole). It holds the sound's id, frames and channels, the tempo and root note, the peak pyramid (`PeakPyramid::to_bytes`) and the onsets (`OnsetAnalysis::to_bytes`: the strength curve and every candidate, so Sensitivity still moves without analysing again), about 3 % of the sound's size as floats. Opening the project reads each sound's file on the open's own thread (`cached_views`, `SourceView::from_cache`), works out only the mono mix again (one pass over the sound), and hands the views to `Views::known`, so the Sample tab shows the sound ready at once and the worker never takes it. A file that is another sound's, cut short or of another layout is ignored and the sound is analysed as before. The analysis's version is in the file's name (`CACHE_VERSION`): a newer analysis doesn't find an older one's file, analyses the sound in the background as for a new one, and its next save writes its own.

## Files

```text
MyBeat.mpfree/
  project.toml          plain text, versioned (format = 1), written atomically (temp file, fsync, rename)
  undo.log              append-only command log, one record per line, fsync on each gesture end
  samples/
    3f9a…c2.wav         sources, named by content hash; WAV 24-bit or float, or .flac
    3f9a…c2.a1.peaks    analysis cache, version 1 (rebuildable; built: see Analysis)
    3f9a…c2.toml        name, tags, original file name, analysis version
  takes/                recordings not yet assigned (kept until the project is cleaned)
```

**As built:** a project is a folder of the library ([browser.md](browser.md#projects)): `project.txt`, one text part per engine in `parts/` (the sampler's is `parts/sampler.txt`), each sound in `samples/` named by a 128-bit hash of its bytes with its view beside it (`<id>.a1.peaks`), and earlier saves in `versions/`. A save is whole or nothing. There is no `undo.log`: undo isn't saved.

`project.toml` holds programs, pads, layers, regions, chop sets and settings, referring to sources by hash. A pad can be exported with a small sidecar (`Name.mpfree`) that carries its regions, chop sets and warp, so edits travel with the file (an owner complaint about the MPC): see [Export and sidecars](#export-and-sidecars-mpfree-sampler-mpfree-app).

## Real-time guarantees and how they are tested

| Guarantee | Test |
|---|---|
| No allocation or free in the audio path | `assert_no_alloc` around `Engine::render` in tests and in a debug build; a counting global allocator in CI fails the test on any allocation during render |
| No locks, files or logging in the audio path | Static test: the `engine` module may not use `std::sync::Mutex`, `std::fs`, `println!`, or `log` (grep-based, like the existing write-site test) |
| Bounded time | Worst-case render benchmarks (all voices, all grains, all filters modulated) on the workstation and on the MPC; the device result sets the voice and grain limits |
| No denormals | State that decays toward zero lands on exact zero under `dsp::TINY` (1e-20, far below hearing and far above the denormals under 1.2e-38): each voice's filter (`Svf::flush`, every 16 frames in the filter's retune, out of the per-frame loop, so the busiest sampler bench case counts 0.4 % more instructions), its pressure smoothing (`pressure_step`) and its loudness for culling (`Voice::heard`). The envelopes already end at −80 dB, and the grains and the master effect have no feedback. `tests/denormals.rs`: a held pad ringing out on silence through every filter type, 2 and 4 poles, 40 Hz to 18 kHz, with and without resonance, never puts out a denormal and is exactly silent at the end; `pressure_let_go_lands_on_exact_zero`. Before (R2, sampler review item 6), 16 pads through a 4-pole low-pass cost about 40 times as much ringing on silence as while their sound played (390 ms of the workstation's time a second of sound, against 9; 8.5 ms after), and 16 pads held after pressure was let go 7 times as much (35 ms against 5). The CPU's own flush-to-zero bit stays unset: Rust code assumes the default floating-point mode, so the sampler flushes in its own code, as the effects do |
| Same output on x86 and ARM | Offline renders hashed and compared, as M6 did for the groove |
| Deterministic | Seeded randomness; renders of a fixed command script are bit-identical run to run |
| Undo is exact | Property test: random command sequences, then undo all, compare with the start |
| Saves survive power loss | Kill-during-save tests on the workstation; the old file is always intact |

## Performance budget

| Item | Budget (first guess, to be measured on the RK3288) |
|---|---|
| Audio period | 2.9 ms; target render under 50 % (1.45 ms) with the full voice and grain load |
| One Hermite voice with envelope and filter | about 1-2 % of the period |
| 64 voices | about 40-60 % of the period, so the default pool may be 48, measured |
| One grain | a fraction of a voice (no filter); 256 grains about one third of the period |
| UI frame | under 15 ms on core 0; waveform redraw only for the changed columns |
| Pad to sound | no worse than the pad player's measured path |

If the budget fails on one core, the engine splits pad buses across cores 2 and 3 with a join before the master, as the earlier research proposed.

**Two cores (`Engine::split`, built).** `engine.split(mpfree_lanes::Config)` splits the voice pool in two: the first half stays on the audio thread, the second goes to a lane (`mpfree-lanes`, a worker that can be pinned to core 2 at SCHED_FIFO 69). Each part of a block (between events, at most 1024 frames) hands the second half to the lane, renders the first, then joins and adds the second half's voices into their pads' pairs in slot order. Everything that decides about voices stays on the audio thread while both halves are home: events, chokes, mute groups, polyphony and stealing see all the voices, and a new voice goes to the half that costs less (playing voices count 8 grains each, plus the live grains), so two granular clouds don't pile up on one core. The grain budget is shared before each part: each half keeps its live grains and gets half of what is free, so together they never pass 256. `render` and `render_routed` wait for the lane no longer than the block lasts; `render_until` and `render_routed_until` take a deadline, and the app's audio loop renders with `render_routed_until` and the period's one deadline for every lane ([Concurrency](concurrency.md)). The due events are taken off the queue's front once a block, not one at a time, and a voice borrows its sample's shared buffer for the render instead of cloning the `Arc`, so the two cores' voices of one sample don't trade its reference count back and forth each part. A lane that misses it leaves its voices out of that part (`Stats::lane_late`), and events wait in the queue until its half is back, so none are lost; the returning half catches up with the tempo and the tape. While its half is away, `Engine::stats` counts that half's skipped grains as they were when it left, so the count never goes back (before, it dropped by that half's share until the half came home: `tests/split.rs`). Parts under 16 frames, and parts where the second half plays nothing, render on the audio thread. `Engine::lane_stats()` gives the lane's counters. The output is bit for bit the same whether the lane runs on its own thread or in place (`Config::threaded` false), and the same as unsplit but for the voices' order of adding (under 1e-5, with the same steals): `tests/split.rs`. Neither thread allocates or frees: `tests/split_no_alloc.rs` counts both with mpfree-prof's counting allocator. On the workstation (`mpfree-bench --lanes`), the bench's 24-voice sampler case took about 83 µs a block on one core and about 52 µs split, with the worker spinning, as fast as two separate 12-voice engines; with the worker sleeping between blocks, about 70 µs, the wake-up being most of the difference. The device numbers are still to come.

**Measured on the MPC One (round 7, 2026-11-11).** The bench case "Sampler, 20 pads" (16 sample pads with two layers and a low-pass filter each, 4 dense granular pads, 24 voices, a hit every 4 blocks) took 1437 µs on average, 50 % of a period, against the sampler's 25 % budget; with the master grains, 72 %. Per voice that was far slower than on the workstation, and the reasons were ARMv7's: every sample voice frame called an out-of-line read eight times (a clamp and a channel `match` per tap) and converted a 64-bit integer to a float twice (a library call on ARMv7), every grain frame converted between `f64` and `i64` twice (two more library calls), and the live buffer behind the master grains divided a 64-bit number per frame. The voice now reads both channels straight from the data, once, away from the region's edges (`Voice::read2`; the clamped read stays for the edges), takes the fraction from the position's low 32 bits, retunes its filter only when the envelope or pressure has moved it (and the second stage only for 4 poles), and keeps its per-16-frame updates out of the per-frame loop; grains go through `i32` below 2^31 frames; the live buffer keeps its write head instead of dividing. The output is bit for bit what it was (an output hash over 3000 varied blocks, mixed, with master grains and routed, matches on x86 and on ARMv7 under qemu; `the_direct_read_matches_the_clamped_one` and `live_buffer_finds_every_held_frame_after_wrapping_and_clearing` keep it so). On the workstation the 16 sample pads now take 58 µs instead of about 140, and "Sampler, 20 pads" 115 µs instead of 174; under qemu on the ARMv7 build, which counts instructions more than it times the chip, the case drops 31 %, the master grains case 44 % and the dense grain effect 42 %. The bench now also runs the two halves apart: "Sampler, the 16 sample pads alone" and "Sampler, the 4 granular pads alone".

The worst blocks come from the grains: the four granular pads average 50 grains but reach the 256-grain budget, and a block with 256 grains costs about five times the average. The budget is the lever for the worst case and is to be set from the next device bench.

## Failure handling

- **xrun:** count it, show it in the header, keep going. Never stop the transport for an xrun.
- **Event queue full:** values merge, hits are refused and counted, let-gos wait aside and still land on their frame ([The event queue and let-gos](#the-event-queue-and-let-gos-sampler-plan-phase-1-step-2)).
- **Worker failure** (bad file, failed stretch): the job reports an error to the UI; the model is unchanged.
- **Arena full:** a recording or load is refused before it starts, with the space needed and the space free; the rolling buffers are never shrunk. As built there is no arena: the [memory floor](#sample-memory) refuses instead.
- **UI crash:** the engine keeps playing; the supervisor restarts the UI (later, when the UI is its own process).
- **Power loss:** the last saved project and the undo log replay to the last finished gesture. As built: a save is whole or nothing and earlier saves are kept, but undo isn't saved.

## Device safety

Nothing in the sampler writes to the eMMC. Recording, saving and caches write only to the project folder, which on the 3.10 test build is in RAM and later lives on the USB stick or SD card. Every round on the MPC runs the storage hashes before and after, as now. The capture PCM is opened only on the test build, where Akai's app is not running.
