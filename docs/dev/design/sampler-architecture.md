# Sampler architecture

**Status:** proposal, 2026-11-10, for the owner's review. This is the engineering plan behind the [sampler design](sampler-design.md) and the [feature map](sampler-features.md). Mockups of the screens are in the [mpfree-claude repo](https://github.com/jferments/mpfree-claude/tree/main/sampler) together with the sampler skill tree.

It says which crates hold what, which thread does what, how data moves between them without ever blocking the audio thread, what is stored on disk, how each algorithm works in outline, and how each part is tested before it reaches the MPC.

## Principles

1. **The audio thread only mixes.** It reads capture, renders voices, writes playback and copies into fixed buffers. It never allocates, frees, locks, logs, touches files or waits on another thread. This is already MPFree's rule; the sampler keeps it with tests (below).
2. **Everything heavy is a background job.** Loading, decoding, analysing, stretching, rendering and saving run on worker threads and publish results when done. The sound you have keeps playing.
3. **State lives in one place.** The project model (sources, regions, pads, chop sets) is owned by the *control* thread. The audio thread gets immutable snapshots of what it needs; the UI gets change notices. Nobody else mutates the model.
4. **Every change is a command.** UI, hardware and MIDI all send the same commands to the control thread. Commands are logged for undo and are the only way to change a project.
5. **Testable on the workstation.** Every crate except the device backends runs and is tested on x86 and as 32-bit ARM under qemu, as today.

## Threads

| Thread | Priority | Core | Period | Owns |
|---|---|---|---|---|
| Audio | `SCHED_FIFO` 70, memory locked | 3 | every ALSA period (128 frames, 2.9 ms) | The `Engine`: voice pool, mixer, rolling buffers. Reads capture, writes playback |
| Control | normal, high nice | 1 | event-driven, at most every 1 ms | The `Project` model, the command queue, the undo log; turns hardware and UI events into commands |
| Workers (2) | normal, low nice | 0 and 1 | job queue | Loading, decoding, analysis, stretching, rendering, saving, recording to disk |
| UI | normal | 0 | redraw at most every 33 ms, only what changed | The `Ui` from `mpfree-ui` and the sampler screens |
| Input | normal | 1 | blocking reads | Controller MIDI and touch events, forwarded to Control (pad hits also go straight to Audio, see below) |

**Pad latency path.** A pad hit must not wait for the control thread. The input thread sends the hit to the audio thread directly on a dedicated ring (`PadHit { pad, velocity, time }`), and a copy to Control for the UI and recording. The audio thread looks the pad up in its own snapshot. This keeps the pad-to-sound path as short as the pad player's today; round 4 measures that path on the device.

## Data flow

```text
                 commands (rtrb, bounded)                     snapshots (rtrb of Arc-like handles)
   UI ──────────────► Control ───────────────────────────────────────────────────► Audio
   Input ───────────► Control         ▲                                               │
   Input ── PadHit ───────────────────┼───────────────────────────────────────────►  │
                                      │ jobs                                          │ events (rtrb, try_send, drop + count when full)
                                      ▼                                               ▼
                                   Workers ──── results ────► Control ────► UI    Control (meters, playheads, takes)
                                      ▲
   Audio ── capture ring (rtrb, 2 s) ─┘  (recording to disk)
```

Every queue is a bounded single-producer single-consumer ring (`rtrb`). The audio thread only ever uses non-blocking `push`/`pop`; when a ring to the UI is full it drops the message and counts it, as the pad player does.

### Snapshots, not shared mutation

The audio thread holds an `EngineView`: for each pad, the layers and regions it needs, already resolved into plain numbers and handles to sample memory. When the model changes, Control builds a new view for the changed pads off the audio thread and sends it. The audio thread swaps it in at the start of the next period. The old view is returned through a ring to Control, which drops it there, so the audio thread never frees memory. (`basedrop`'s collector does the same job for shared sample buffers.)

A playing voice keeps its own handle to its sample buffer, so replacing or deleting a sample while it plays is safe: the buffer is freed only when the last voice stops.

### Sample memory

| Item | Plan |
|---|---|
| Format in RAM | Interleaved stereo `f32`, 44.1 kHz. A mono source is stored mono and read with a channel flag |
| Pool | One `mlock`ed arena reserved at start-up (size from settings, default 1 GiB, measured on the device), carved into buffers by a simple allocator on the control thread. No allocation from the system heap per sample, so memory use is predictable and never pages |
| Handles | `SampleRef` = index + generation into the arena, reference-counted; the audio thread only increments and decrements counts, and frees go back through a ring |
| Long sources | First version: everything in RAM. Later (S8): sources over a size limit stream from disk with the first second resident |

On a 32-bit process the address space is about 3 GB. A 1 GiB arena, the rolling buffers (about 85 MB), the UI (under 64 MB) and the engine (under 64 MB) fit with room to spare.

## The model

Sketches of the types, to fix the vocabulary. Names may change in code.

```rust
struct Source  { id: SourceId /* content hash */, frames: u64, channels: u8, rate: u32,
                 file: PathBuf, analysis: Option<AnalysisRef>, name: String, tags: Vec<String> }

struct ChopSet { id: ChopId, source: SourceId, name: String, mode: ChopMode, markers: Vec<u64> }

struct Region  { source: SourceId, start: u64, end: u64,
                 loop_: Option<Loop /* start, end, crossfade, mode: Forward | PingPong */>,
                 fade_in: Fade, fade_out: Fade, gain_db: f32, reverse: bool,
                 channels: ChannelPick, tune_cents: i32, mode: PlayMode, warp: Option<Warp>,
                 grain: Option<GrainParams>, colour: Option<Vintage> }

enum PlayMode  { OneShot, Gate, Toggle, Loop, Tape, Granular }

struct Layer   { region: RegionRef, vel: (u8, u8), xfade: u8, group: LayerGroup /* Velocity | Cycle | Random | Simult */,
                 level_db: f32, pan: f32, tune_cents: i32 }

struct Pad     { layers: Vec<Layer>, poly: Poly, choke: Option<u8>, choke_one_way: bool, links: Vec<PadId>,
                 amp: Ahdsr, filter: Filter, filter_env: Ahdsr, pitch_env: Option<Env>,
                 vel_to: VelocityMap, pressure_to: Option<Target>, snapshot: Option<Box<Pad>> }

struct Program { kind: ProgramKind /* Drum | Keygroup */, pads: [Option<Pad>; 128], name: String }
```

**Commands** are an enum (`SetRegionStart { region, frame }`, `AddMarker`, `Convert { chop, to }`, `AssignToPad`, `RecordStart`, ...). Each command applied to the model returns its inverse, which goes in the undo log. Live gestures (a knob turning) are merged into one undo step per gesture.

## Recording

```text
 audio thread, every period:
   capture[128 frames] ──► input rolling buffer (ring, 2 min)        (always)
   master[128 frames]  ──► master rolling buffer (ring, 2 min)       (always)
   if a take is armed:  ──► take ring (rtrb, 2 s) ──► writer worker ──► arena buffer (+ WAV on disk for long takes)
   threshold armed:     detect crossing on capture (peak of block > level) → mark take start = onset − pre-roll
```

- **Rolling buffers** are plain ring buffers of `f32` in the locked arena, written with a wrapping index. A "skip back N seconds" or "last N bars" command from Control copies the span out on a worker while the ring keeps going; the ring is long enough (2 minutes) that the span cannot be overwritten during the copy for any span up to 1 minute.
- **Threshold** compares the block peak with the level on the audio thread (cheap), and the exact onset inside the block is refined later by the analysis.
- **In-time takes** start and stop on bar lines computed from the transport's sample-frame position, so the take is an exact number of bars.
- **Capture device.** The time engine's looper opens it (`looping.rs`, `LineIn`), and the sampler reads the same period from `LoopHost::input`. Planned: open `pcmC1D0c` (the ACVA capture PCM, observed stereo S32_LE at 44.1 kHz, 128-frame periods), link it to playback so both start together, and read one period per playback period. Capture and playback xruns are counted separately.
- **What is built (step CAP, `record.rs`).** The line input reaches the sampler, not yet the master: `record::input(seconds, rate)` makes a stereo rolling buffer with its bar lines, as a `Feed` (the audio thread's end) and an `Input` (the screen thread's). The pad player keeps 75 s (about 26 MB) and only while the line input is on (below). Bar lines come from the transport's spans each period and are marked in the buffer's own frames (`bar_lines`, the latest 64), so the buffer's frame count need not equal the transport's. A `Recording` starts now, over a threshold with pre-roll, or on the next bar line, and ends on a press, on silence, after a number of frames, or on the n-th bar line after its start; it copies itself out of the buffer as it grows (the screen thread polls it about 30 times a second), so it is not limited to the buffer's length; the longest take is 3 minutes. A stop while it waits records nothing. `Input::last_frames` and `Input::last_bars` are Skip back; `Pick` keeps both channels, the left, the right or a mono mix. `Project::put_source` puts the sound on a pad as one undo step. The threshold is found by the poll on the screen thread rather than on the audio thread, which only appends; the pre-roll comes from the buffer, so nothing is lost. Resampling (step RESAMP, below) feeds the same buffer from a point in the mix; `RollingWriter::restart` (`Feed::restart`) marks where a new source begins, and readers stop there as if everything before had been overwritten (`oldest`, `copy`), so Skip back and a pre-roll never mix two sources. A bar line can be marked ahead of the audio (a point in the mix hears the block late); `Input::bars_back` and `last_bars` use the latest line that has come in, and a take on the next bar waits for its audio. A press (`Recording::stop`, `Take::stop_at`) ends a take at once, also before a length it had not reached. A recording that ends on a length or a bar line has a `Tail` (`Recording::with_tail`): `Cut`; `Ring(RingOut)`, which goes on past its cut (`Take::cut_at`) until it has been at or under a level for a quiet time and ends after the last frame over it, at most `max` frames on (`Take::ring_out`); or `Loop`, a loop of exactly its length without a seam (`Looped`): if its source was sounding in the quiet time before it started, the music was going round and its start already holds the ringing of the time before, so it is cut on its length and done there; otherwise it rings on for at most one more of its own length (`Take::ring_out_once_round`), and the ringing is folded onto its start (round and round when longer than the loop), or, when it still sounds a whole length on, the music went on round and the take is that second time round, which starts with the first's ringing (`tests/record.rs`). Takes to disk are a later step.
- **Auto-sample (step AUTOS, `autosample.rs`).** Builds a keygroup instrument by playing an instrument note by note, as the MPC's Auto Sampler, Elektron's Tonverk and Logic's Auto Sampler do. A `Plan` says the notes (lowest, highest, every 1 to 12 semitones), 1 to 8 velocity layers (`Plan::spread_velocities` spreads them Linear, Exp or Log), 1 to 4 round robins (layers × round robins at most 16, a pad's layers), the hold, the longest tail and the gap between notes, the silence level (−60 dB below the loudest), loops (off, forward or ping-pong), mono or stereo and normalize; `Plan::estimate` gives the time and memory first (the default, C2 to C6 every 3 semitones at 40, 90 and 127, is 51 takes: 3.6 min and 72 MB with 2 s tails, at most 5.3 min and 108 MB), and a plan past 256 MB is refused with the reason. A `Session` runs it a block at a time against any instrument: `cues(frames)` says which notes to send at which offsets, `feed(audio)` takes what came back for the same frames, so it drives one of MPFree's synths offline as well as external gear in real time, and records the same takes whatever the block size. It opens with a level and timing test (the middle note at the top velocity), stops with `State::NoSound` if nothing comes back, flags clipping without stopping, ends each note once it has been quiet for 100 ms after its note-off (or its tail runs out), and `cancel` sends All Notes Off and keeps the notes done. `build` trims each take 2 ms before its own attack (the first frame within 40 dB of its peak, so MIDI jitter never shifts a note) and 10 ms past where it went silent, with a fade; looks for a loop between upward zero crossings in the held part (after the attack, before the note-off) whose 20 ms around each end match (at least 0.9, preferring longer loops; an equal-power crossfade up to 30 ms) and leaves the take one-shot without one; and normalizes the whole instrument so its loudest take peaks at −12 dBFS (what MPFree's instruments aim for), so the layers keep their dynamics. Each note becomes a pad: a keygroup reaching halfway to its neighbours (the lowest and highest to the ends of the keyboard), 16 voices, its layers on their velocity ranges (each from just above the layer below to its own velocity, the top to 127), each layer's level set so a hit at the velocity it was played at sounds as recorded, round robins in Cycle, Loop mode when looped and Gate otherwise with the amp's release set to the takes' typical ring. `Project::put_instrument` adds the sources and pads and sets the pads to play notes from the C at or below the lowest, as one undo step (`tests/autosample.rs`, against a fake synth with latency, jitter, a release and round robins that differ). **Offline, MPFree's own synths:** `autosample::render` plays a session on any `Node` as fast as it renders, resetting the node before each new note (so no note glides from or rings into the one before, while a note's round robins still follow each other as played), and `Job` runs it and the build on a worker thread at normal priority, with progress, cancel and timings; the node is a fresh copy with the patch's values, never the audio thread's. Every engine (Poly, FM, Pluck, Wavetable, Drums) makes an instrument, and a sampled Poly plays every note at the synth's own pitch (`tests/autosample_synths.rs`). The workstation example `cargo run --release -p mpfree-sampler --example autosample -- OUT` samples a preset (`--engine`, `--preset`, `--layers`, `--rr`, `--loops` and so on) and writes the takes, the same phrase from the synth and from the sampled instrument (`synth.wav`, `sampled.wav`) and a report: the default plan on Poly's Pluck renders 119 s of audio in 0.19 s here and 0.06 s to build, which the MPC calibration puts at about 2.6 s (1.1 to 7.5 s) on the MPC. **The Rec tab's Auto-sample mode** (`mpfree-sampler-ui` `auto_tab.rs`, `auto_widgets.rs`; the Rec tab's fourth button): a picture of the keyboard with each note's zone (its root dotted) over the keys, the velocity layers on a 1 to 127 axis with where each is played, and while it runs the note playing, the notes done and a progress bar; a list of the plan (source, lowest and highest note, every, layers, layer spread, round robins, hold, tail, loop, channels, normalize, onto); the bar says what it makes, how long and how much memory before anything starts, and Start waits with the reason in the picture when the plan is refused or has nowhere to go. An instrument has a pad a note and a kit plays 16 pads, so the mode defaults to C2 to A5 every 3 semitones (16 notes) and puts the instrument on the first run of empty pads long enough, or over the whole kit (replacing, one UNDO puts it back). The source is the Synth tab's patch: the app builds a fresh node of the same engine with every value the Synth tab holds (`synth::fresh_node`; it plays exactly what the pads play, sample for sample, for every engine) and runs a `Job` on it; the audio thread is never asked for anything. When the job ends the instrument lands as one undo step and the kit's pads play notes; Cancel keeps the notes done (`tests/auto_tab.rs`; the whole flow in the app, with a real Poly patch, in mpfree-app). **External gear, in real time:** `Gear` plays a session on hardware through a MIDI out, its sound read back from the sampler's input (the line input's rolling buffer, `record::RollingReader`) by frame number as the audio thread writes it. `Gear::step` moves the session on a `GEAR_BLOCK` (256 frames) at a time as far as the input has come; each cue goes out (`Cue::midi`: note on, note off at release velocity 64, All Notes Off as controller 123, on the channel picked) once the input has reached its frame, never before, so the gear's sound always lands after the frame its take starts from. How late it lands (an audio period, the cable, the gear) is what the session's timing test measures: a gear session opens with two (`GEAR_TESTS`), and each take starts at its own attack anyway. `Gear::run` polls every millisecond and stops, cancelled, when the input changes source (`GearError::InputChanged`, from the buffer's restart count), stops moving for `GEAR_STALL_MS` (1 s, `InputStopped`) or is overwritten (`FellBehind`); either way it then lets go of the gear (the note sounding off, All Notes Off). `Job::start_gear` runs it on the worker thread with the same progress, cancel and build as the synth's, and `Finished::stopped` says why it stopped early. A mono plan records the average of the input's two sides. Tests: `tests/autosample.rs` (`gear_is_played_over_midi_and_recorded_from_the_line_input`, through the rolling buffer in 100-frame periods with the fake synth's latency and jitter; `gear_lets_go_when_the_input_changes_source_or_stops`, including the job on its thread). **In the app:** the Source row steps from the Synth tab's patch to "Gear · MIDI ch 1" to 16, offered only once the app gives a MIDI out (`SamplePage::set_gear` with a `GearOut`: its name and a `send` the job's thread calls); Start then gives `AutoAction::StartGear`, and the page starts the job on the line input's buffer, or says why not (no MIDI out, the line input off, or the Rec tab recording a point in the mix). The log says `sample: auto-sample Gear (MIDI channel 3 on MIDI Out (DIN)) started: …`, and `sample: auto-sample stopped: the line input stopped coming in; keeping the notes done` when the input goes. Opening the MIDI out for it is the app's MIDI wiring, after the owner's go on the MIDI out check (rule zero): until `set_gear` is called nothing is ever sent (`auto_sample_plays_external_gear_over_midi_and_records_it_from_the_line_input` in mpfree-app, with a fake synth answering the MIDI on the line input).
- **Writes to disk** only on the stick or SD card, never on the eMMC. On the 3.10 test build all paths are in RAM. The writer is the only code that opens a file for writing in the recording path, and the static test that lists write sites covers it.

## Playback engine

### A period, in order

1. Swap in any new `EngineView`, apply parameter changes and voice commands from the rings.
2. Handle pad hits (from the dedicated ring and the sequencer): choose layers, steal or choke voices, start voices.
3. Render each active voice into its pad's bus (block-wise, 128 frames, or split at sample-accurate event times).
4. Pad buses through pad FX, then into the master; master into playback.
5. Copy capture and master into the rolling buffers; push take frames.
6. Push meters, playheads and grain positions to the UI ring (at most once per UI frame's worth of periods).

### The voice

- **Position:** 32.32 fixed point (integer frame and fraction), increment from pitch × rate ratio. Fixed point avoids `f64` drift on long loops and is cheap on ARMv7.
- **Interpolation:** linear (cheap), 4-point Hermite (default), with sinc only in offline rendering. Reads at the edges use guard frames so there is no branch per sample.
- **Loop:** forward or ping-pong between loop start and end, with an equal-power crossfade of N frames precomputed as a short table at region change.
- **Envelopes:** AHDSR as a per-sample multiply with a per-block recomputed segment rate (exponential segments as one multiply per sample).
- **Filter:** a topology-preserving state-variable filter (LP/HP/BP, 2-pole; 4-pole as two in series), coefficients updated per 16-frame sub-block when modulated.
- **Declick:** 64-frame release on stop and 32-frame fade on steal or choke, as in today's `mpfree-sampler`.
- **Pressure:** each pad has one pressure route (`Pad.pressure`: a `PressureTarget` and a depth from −1 to 1). `Event::Pressure { pad, value }` (0-127, from the pad's polyphonic aftertouch) moves that pad's playing voices; a voice that starts later begins unpressed. Pressure is smoothed with a 5 ms one-pole. Full pressure at depth 1 gives +12 dB level (the gain glides over each 16-frame sub-block, so it never clicks), +12 semitones pitch (sample voices change their step; granular voices change the grain pitch), +4 octaves of filter cutoff (needs the pad's filter on), ×16 grain density, ×8 grain length, the grain position moved by the whole region (wrapping), or +100 % spray. A negative depth moves the other way. Built and tested (`tests/pressure.rs`); it also runs in `tests/no_alloc.rs`.
- **Voice allocation:** a fixed pool (start at 64, set by measurement). Stealing order: same pad's oldest voice if the pad's polyphony is exceeded, then the quietest releasing voice, then the oldest.

### Live settings and the hard stop

What the synth thread's sampler node (#152) asked for, so a node parameter, a p-lock, a macro or a modulation can move a pad without a new view.
- **`Event::PadLive { pad, field, value }`** sets one of a pad's settings while it plays (`PadField`): Level (dB), Pan (−1 to 1, each layer's own pan adds to it), Tune (cents), Cutoff (Hz), Resonance (0 to 1), and the amp envelope's Attack, Decay and Release (ms). The value replaces the pad's own (NaN gives the pad's own back), clamped to the field's range (`PadField::clamp`). A cutoff on a pad whose filter is off gives it a 2-pole low-pass. A cutoff set this way also replaces 16 Levels' cutoff.
- **`Event::ProgramLive { field, value }`** moves every pad at once (`ProgramField`): dB on every level, cents on every tune, octaves on every cutoff. Below 0 octaves, a pad without a filter gets a low-pass too, so the whole kit darkens. 0 or NaN is no offset.
- **New voices** start with all of them. With none set, a voice starts exactly as before, bit for bit (the bench's golden sounds don't move).
- **Playing voices** follow Level, Pan, Cutoff, Resonance and the program's three offsets: `retarget` points each one at its new values, and the voice glides there with a one-pole (10 ms) stepped every 16 frames, linear within the step for the gain and in octaves for the cutoff. A voice works from the pad's own settings as they were when it started, so a new view never jumps it. Tune, Attack, Decay and Release reach new voices only. A warped layer keeps its pitch: its tune lives in its stretched copy.
- **The table** is fixed (`[[f32; 8]; 128]` and 3 offsets). `Engine::set_view` puts the pads' fields back to their own, and the program's offsets stay. Both events go through the event queue, so they land on their frame for any block size, and split they apply while both halves of the voices are home.
- **`Engine::stop_all()`** is the hard stop for a reset or a panic. Every voice and its grains go idle at once, the master effect's grains stop and forget what they hold, and the events waiting are dropped. It never allocates. Split, a half still away on a late lane stops as it comes back. `Event::AllOff` stays the gentle one (a release).
- **Tests** (`tests/live.rs`): a level change lands on its frame and plays the same in blocks of 1, 37, 128 and 1000 frames, gliding without a jump. A p-locked hit plays as a pad set that way would (within 1e-4). Playing voices follow pan, the program's cutoff (down and back up) and level, and the program's tune (playheads read twice as fast an octave up). NaN and a new view give the pad's own back. Split or not, a busy performance with live changes plays the same (bit for bit on the lane's own core). After `stop_all` nothing plays or waits, even with the lane's half away. The no-allocation tests (`no_alloc.rs`, `split_no_alloc.rs`) send live changes, clear them and stop everything in their busy sessions.

### In the pad player

From round 6 the pad player (`mpfree-app`, `src/sampler.rs`) plays through this engine instead of its round 3 mixer. The `drums` step keeps the old mixer.
- Each kit in `kits.bin` becomes a project with one engine view, built before the sound starts. Picking a kit swaps views, so nothing is built, allocated or freed in the audio loop, and sounds already playing finish.
- Levels match the old mixer: pads are raised 3.01 dB to undo the centre pan, and velocity is sent as `round(127·√(v/127))`, so the engine's squared level law comes out linear.
- A Grains kit plays the first kit's sounds as granular pads while they are held. Pressure moves density, grain size, position or pitch, one per row of pads.
- Pad pressure from the controller goes to the engine as `Event::Pressure`, and Note Repeat's note-offs go to it as `Event::NoteOff`.
- **Pads on the mixer.** `Engine::render_routed(frames, out)` renders each pad apart: every voice adds its sound into its own pad's pair from a `PadOut` (the mixer's pad channels, `mpfree_fx::Mixer::pad_input`), so each pad gets the mixer's fader, pan, mute, solo, sends, inserts and output. Events, voices and grains run as in `Engine::render`, and the pads' pairs add up to what it renders (`tests/routed.rs`). The engine never clears a pair (the mixer clears its own after each block). A pad with no pair (`None`) still plays, into a scratch buffer, so its voices end on time. The master grain effect works on the mixed pair, so it runs only in `Engine::render`; on the mixer a granular insert on the pads' track does its job. `sampler::Player::render_routed` passes it on for the playing kit's 16 pads; the FX thread's wiring puts them on pad channels 0 to 15, each going to the Drums track. `render_dry` stays for tests and previews. Routed renders run in `tests/no_alloc.rs` too.
- The 30 s status line adds the engine's render time per period (mean and max, and as a share of the 2.9 ms period), steals, dropped events, and peak and skipped grains. On the RK3288, these figures set the voice and grain limits.

### As an instrument node (`node.rs`)

`SamplerNode` is the sampler as an `mpfree_node::Node`, so a track holds a kit or a keygroup program the way it holds Poly or FM, and the sequencer, the pads and the arp play it with notes. Piece 4 of the plan "Four synth features" (2026-11-11).
- **Notes.** On a drum kit (Pads or 16 Levels), note `Pad 1 note + n` hits pad `n` (pad 1 is note 36 by default, as on Drums), its pressure goes to that pad, and its note-off lets go of that pad. A note outside the pads goes to the keygroups, so a kit with a keygroup pad still plays it. On a keygroup program every note goes to the keygroups as itself. Every note goes through `Engine::schedule`, so it lands on its frame for any block size.
- **A note-off follows its note-on**, even if the kit or "Pad 1 note" changed in between. A note held again first lets go of where it went before.
- **New sounds** (new samples, an edited pad, another kit) come in as an `EngineView` built on the control thread and sent with `SamplerControl::send_view`. The node takes in at most one at the start of a block and hands the view it replaces back through `SamplerControl::take_old`, to be dropped on the control thread. If nobody has taken the old views back, the node keeps the replaced view and takes no new one until there is room. Two views can wait each way (`VIEW_QUEUE`); a full queue gives the view back to send again. Playing voices finish as they started.
- **Kit settings** use Drums' kit ids: Level (300, in dB, smoothed over 10 ms from its frame), Pad 1 note (301) and the read-only Voices on meter (310). Tune (302, semitones) and Cutoff (303, octaves) move every pad at once, playing voices too (`Event::ProgramLive`); a Cutoff below 0 gives pads without a filter a low-pass, so the whole kit darkens.
- **Pad settings.** Pads 1 to 16 each have Level, Pan, Tune, Cutoff, Resonance, Attack, Decay and Release, at ids `pad * 16 + field` as Drums lays out its pads (`node::pad_id`, `node::field`), grouped "Pad 1" to "Pad 16". They are **offsets on the pad's own settings**, the ones edited on the Sample tab, so at their defaults a pad plays as it is, and a preset, a p-lock ending or a modulation at rest goes back there:

  | Setting | Range | Default | Sent to the engine as |
  |---|---|---|---|
  | Level | −60 to +12 dB | 0 | own level + offset |
  | Pan | −100 to +100 % | 0 | own pan + offset / 100 |
  | Tune | −24 to +24 semitones | 0 | own tune + offset × 100 cents |
  | Cutoff | −8 to +8 octaves | 0 | own cutoff × 2^offset; with the filter off, a low-pass from 22 kHz below 0 and nothing above |
  | Resonance | −100 to +100 % | 0 | own resonance (0 with the filter off) + offset / 100 |
  | Attack, Decay, Release | 1 to 10 000 % | 100 % | own time × offset / 100, a time of 0 taken as 1 ms |

  A setting at its default sends NaN (the pad's own). Each change goes to the engine as an `Event::PadLive` on its frame; playing voices glide to Level, Pan, Cutoff and Resonance, and Tune and the envelope reach the next hit. The node reads the pads' own values with `EngineView::pad_own` when a view comes in, and puts every offset that isn't at its default onto the new view's pads in the same block. Pads past 16 play but have no settings on the node yet. On 16 Levels the settings of the one pad apply, and a Cutoff offset replaces the Levels' spread of cutoffs.
- `reset` is the hard stop (`Engine::stop_all`): every voice stops at once, the notes waiting are dropped and the held ones forgotten. The settings stay.
- **Tests.** `tests/node.rs`: the node plays a phrase of hits, a held gate, pressure, a repeat and all notes off identical to the engine fed the same events, in blocks of 1, 7, 16, 64, 128 and 1000 frames; notes find their pads and note-offs follow them across a "Pad 1 note" change, also one inside a block; a keygroup program plays every note as itself; views swap in one per block, come back, and wait when the return queue is full; Level lands on its frame for any block. `tests/node_live.rs`: a phrase moving every pad setting and both kit offsets plays identical to the engine given the live values on the same frames, in blocks of 1, 7, 64, 128 and 1000; every setting moved and set back to its default leaves the kit playing bit for bit as it is; each setting works from the pad's own (with and without a filter, an attack of 0); a new view gets the offsets on its own settings; reset stops at once and keeps the settings; the id layout. `tests/node_no_alloc.rs`: 2000 busy blocks (notes on, off and again on pads and keys, pressure, Level, Pad 1 note, kit Tune and Cutoff and pad settings inside blocks, all notes off, reset, views swapped in while voices play and settings are on) under a counting allocator: `process` makes no allocation and no free.

### The Wave tab (`mpfree-sampler-ui`)

The first of the pad editor's tabs, as in the Wave mockup. It shows one layer of one pad: the overview, the waveform with Start, End and loop markers, the fades, bar and beat lines from the source's tempo, the Region settings and four Q-Link cards.
- The tab never owns the project. The app builds a `WaveState` from the project and a `SourceView`, and applies the `WaveAction`s it gets back with `WaveAction::apply`.
- Each drag or Q-Link turn is one undo step: the tab gives every change of the same drag or turn the same gesture id, and the app calls `lift` when a finger lifts or a Q-Link is let go.
- Markers can't cross: Start ≤ loop start − crossfade, loop start < loop end, loop end ≤ End. Fades shrink to fit. Every move gives a region that `Region::check` accepts (the test makes 2000 random moves).
- Markers snap to the nearest zero crossing (the default), to sixteenths of the source's tempo, or not at all. A Q-Link moves its marker one pixel of the current zoom per detent, snapping in the direction of the turn. With SHIFT it moves one frame per detent, unsnapped. The wheel zooms round the marker last moved or touched.
- Region rows: mode, loop (off, forward, ping-pong), crossfade, gain (0.5 dB steps), tune (semitones), reverse, channels, fade in, fade out and snap. Loop mode always keeps a loop: choosing it makes one over the middle half of the region, and Off is skipped while it is on.
- A tap on the wave asks the app to play the pad. Playheads come from the app with `set_playheads`.
- `mpfree-sampler-preview OUT_DIR` draws the sample screens to PNG files.

### The Warp tab (`mpfree-sampler-ui`)

The pad editor's tab after Wave: where the hits of a warped layer land. It edits the same region as the Wave tab, from the same `WaveState`, and gives the same `WaveAction`s (one undo step a drag, a turn or a run of taps on one row).
- **The picture** (`WarpView`) draws the region in its own beats: bars, beats and the grid from the warp tempo, and the wave as it plays, each column's beats looked up back to source frames, so a pinned hit sits on its grid line. Pins are lines with numbered handles in the ruler; the hits the source's onsets found are ticks along the bottom (lit when pinned). A playhead moving redraws only the strips it left and entered (the engine reports a stretched voice's place in the source, through the pins).
- **Pins.** A tap on the wave pins the hit nearest the finger (within half a grid step, else the frame tapped) to the nearest grid line, or picks its pin if it has one. Dragging a handle moves the pin along the grid; it stops short of its neighbours (`Warp::pin_room`). **Pin hits** pins each hit within 0.45 of a grid step of a line onto it, the nearest where two reach one line (`Warp::pinned_to_grid`): a loop played loosely made tight. **Remove pin** and **Clear pins** take them off.
- **Rows.** Warp and Warp tempo as on the Wave tab (a new tempo drops the pins it leaves no room for), Grid (1/4, 1/8, 1/16, 1/32), Hits (Strongest, Most, All: the onset picker's sensitivity), Pin (the one picked) and Pin beat (a grid step a click).
- **Q-Links.** 1 picks a pin, 2 nudges its beat (a 64th of a beat a detent; SHIFT, a 960th), 3 fine-tunes the warp tempo (a tenth of a BPM; SHIFT, a hundredth) and 4 scrolls when zoomed in. The wheel zooms round the pin picked.
- A layer that isn't warped shows its beats at the tempo turning Warp on would give it, and says to turn Warp to Stretch; repitching, the pins stay but the picture and the sound play straight through.

### The Chop tab (`mpfree-sampler-ui`)

The pad editor's second tab: it cuts what the pad plays (its region, Start to End) into slices and puts them on pads.
- **Methods.** Transient (the source's onsets, at a sensitivity from 0 to 100 %), Beat (on the source's own beat grid, the bar lines the Wave tab draws, every 16th, 8th, beat, 2 beats or bar; offered only when the source has a tempo), Grid (2 to 64 equal slices), Silence (one slice per sound, at a threshold from −72 to −12 dB), Manual and Live (below). Cuts are at least 10 ms apart and from the region's ends; at most 64 slices.
- **Hand edits.** Dragging a slice's marker, Q-Link 2, Split (the slice picked, near its middle) and Merge (with the slice before) change the cuts and turn the method to Manual, so changing the method's setting never silently undoes them. Beat, Grid, Split and hand moves snap to zero crossings unless Snap is off; transient onsets already sit just before each attack. The first marker is the pad's Start and END its End: they stay put (Start and End move on the Wave tab).
- **The cuts live in the tab** until Chop to pads: trying methods changes nothing in the project. Another pad, or a moved Start or End, chops again (a Manual chop keeps the cuts still inside).
- **Live** (Jay, 2026-11-12: live chop to pads). Picking Live keeps the cuts there; the Split button reads Start. Start clears the cuts and sends `ChopAction::Live { on: true }` with the region; the app plays the region once (an audition of the pad's layer) and tells the sampler to mark (`Event::LiveChop`). While it marks, every pad played live (by hand, through Note Repeat or the arp; `Player::live_hit_at`) becomes `Event::Mark` instead of a note, the Sample tab keeps the pad being chopped rather than picking the pad hit, and the engine records the audition voice's source frame at that sample (`Engine::audition_at`: the voice's own position, mapped back to the source when it plays a stretched copy), so a cut is exactly where the sound was, whatever the screen's lag. Marks travel back with the playheads (`Playheads::marks`, the last 8, about 25 times a second) and `ChopTab::live_marks` turns each into a cut: onto the nearest of the source's onsets within the **Pull to hits** window (Off, 10, 20, 40 or 80 ms; the onsets are picked at 60 % sensitivity when Start is pressed), else onto a zero crossing if Snap is on; a cut outside the region, closer than 10 ms to another or past 64 slices is dropped. The take ends when the audition ends (the playheads were marking and aren't), on Stop, on another method, pad, region or tab, or when another audition starts; the log says how many cuts it made. Merge and Split work as on Manual and keep the method Live. Like every chop, the cuts reach the project only with Chop to.
- **Chop to pads** (`ChopAction::ToPads`, applied with `ChopAction::apply`) adds a chop set (markers at Start, the cuts and End) and puts its slices on consecutive pads of the chopped pad's bank of 16, as one undo step (`Project::chop_to_pads`). Each new pad is a copy of the chopped pad (level, envelopes, filter, choke, and its sound's gain, tune and channels) with one layer playing its slice once, named after the pad and numbered from 1. The first pad is the one after the chopped pad if the slices fit after it, else the last run that fits; Q-Link 4 and the Pads row move it. The list says which pads already have a sound ("replaces A5"); more than 16 slices can't go on pads.
- **Put on Keys** (a row of the list; the button then reads "To keys C2–D#2") does what Chop to pads does with each slice a keygroup of one note, from C2 (MIDI 36) up, and the kit's pads then play those notes (`Project::chop_to_keys`, one undo step), so the slices are on the pads and on a keyboard at once.
- **Put on Pads + phrase** (offered only when the source has a tempo; the button then reads "Phrase on A1–A15") does what Chop to pads does and also gives the slices in time, for a clip: see [Chop to a phrase](#chop-to-a-phrase-mpfree-sampler).
- **Q-Links** pick a slice, move its start, turn the method's setting and move the first pad. The wheel zooms round the slice picked; a tap on the wave picks the slice under it.
- **Tap to hear.** A tap on the wave also plays the slice under it once (`ChopAction::Audition`, which the app sends to the engine as `Event::Audition`), as the pad made from it will play it: the pad's level, pan, tune, channels, envelopes and filter, from the slice's first frame, with no loop or fades, whatever the region's play mode. The pad's own playing voices fade out first, so taps don't pile up. A test checks that the tap and the chopped pad sound the same.

### The Play tab (`mpfree-sampler-ui`)

The pad editor's third tab: how the pad plays its sound. It edits the whole pad, never a layer's region (that is the Wave tab's), and `PlayAction::apply` keeps the project's regions whatever the action carries.
- **Layers.** The layer map draws each layer on a velocity axis (0 to 127), one row each, with a line at the last hit's velocity; with a Vel fade, each bar is cut down along the fade's curve inside its edges (`play_widgets::fade_cut`), so overlapping layers show their crossfade. Dragging a layer's left or right edge sets the lowest or highest velocity it plays (layers may overlap; the high edge can't cross the low one). A tap picks the layer the envelope is drawn over. The Layers row says how matching layers play: Stacked (all), Cycle (round robin) or Random.
- **Amp envelope.** Drawn over the picked layer's sound from its Start: attack is linear, decay and release fall exponentially to about −80 dB in their time, as the engine's envelope does (`env_level`). Sustain sits where the sound ends (or after the decay, if that is later) and Release follows it. Dragging A, H, D or R moves that time, S its level; the time axis holds still while a point is dragged. Times go up to 20 s; release is at least 1 ms.
- **Filter.** Its response on a log axis from 20 Hz to 20 kHz, as the pad's state-variable filter shapes it (`filter_db`; 4 poles are two 2-pole stages). Dragging the dot moves the cutoff. Turning the filter on while its cutoff is still at 20 kHz starts it at 2 kHz (a high-pass at 200 Hz), so the change is heard.
- **The Pad list.** Polyphony (mono to 32 voices), Mute group (off, 1 to 16), Stops (the one-way chokes) and Also plays (the links), each Off or a list of pads, Latch (Off or On), Layers, Level (−48 to +12 dB), Pan, Tune (whole semitones, ±48), Vel → level, Vel → start, Vel fade (Off, 2 to 64: `Pad::set_vel_fade`, which also moves layers that meet to overlap by the fade), Keys (Off or On), Low key, High key and Root key, the kit's Key fade (Off, 1 to 24 notes, Mixed when the keygroups differ, "–" without one: `PlayAction::KeyFade`, one undo step), the kit's Pads play (their sounds or notes) and Pads from (an octave a step), Pressure (Level, Pitch, Filter cutoff, and the grain targets for a granular pad) and its Depth, Attack, Hold, Decay, Sustain, Release, Filter (LP, HP or BP, 2 or 4 poles), Cutoff (a third of an octave a step), Resonance and Filter env (±4 octaves). A tap picks a row and its arrows step it; the wheel steps the row picked. Stops and Also plays step a pad at a time (up adds the pad after the highest, never the pad itself; down takes the highest out), but they are quicker from the pads: while either row is picked, a hit on another pad goes into the set or out of it (`PlayTab::takes_pads`, `PlayTab::pad_hit`; each hit its own undo step), the pad shown stays, and the app's hint says so (`SamplePage::press`, `SamplePage::play_takes_pads`).
- **Keys.** Turning Keys on makes the pad a keygroup over the whole keyboard, rooted at the note its first layer's sound is heard at (`SourceView::root_note`, else C4), with at least 16 voices for chords; Low key and High key narrow it. Pads play and Pads from are the kit's (`PlayAction::PadsPlay`, one undo step each): turning the pads to notes starts pad 1 at the C below the pad's root (C3 for a pad that isn't a keygroup). The bar says the pad's keys and what the pads play.
- **The keyboard (keygroup editor).** While the pad is a keygroup or the pads play notes, the page switches to a layout with a keyboard across the top of the left column (`play_tab::KEYS_LAYOUT`, `KeyZones` in `keys_widgets.rs`; a layout file can override it as `<page>.keys`). Every keygroup of the kit is a bar over the keys it plays, in its pad's colour and named by its pad, with its root dotted; overlapping zones take lanes of their own (up to 4). The keys drawn are whole octaves around the roots, the picked pad's zone (up to two octaves either side of its root) and the pads' notes, at least three octaves, and arrows mark zones that go past them. The roots are tinted on the keys, and a bracket under them shows the 16 notes the pads play. The picked pad's zone has a stroke and handles: dragging its left or right edge sets Low key or High key, dragging the root dot sets Root key, each one undo step like the list's rows (`Key::Zone`). A tap on another zone picks its pad (`PlayAction::Pick`), and a key pressed plays the kit's keygroups at velocity 100 until it lifts (`PlayAction::Note`). The caption says the picked pad's keys and root, or how to make it a keygroup.
- **Q-Links** turn Attack and Decay (a doubling every 8 detents, at least a millisecond each; SHIFT: 1 ms a detent), Cutoff (a semitone a detent; SHIFT: a tenth) and Resonance (1 %; SHIFT: 0.2 %). Cutoff and Resonance wait while the filter is off. A tap on a Q-Link's card picks its row.
- **Undo.** Each drag, Q-Link turn, wheel turn or run of taps on one row is one undo step; the app ends it when the finger lifts or the control rests.

### The Grain tab (`mpfree-sampler-ui`)

The pad editor's fifth tab: how the pad's first layer plays as grains (`PlayMode::Granular`, the `mpfree-grain` engine). It edits that layer's region only: its mode and its grain settings (`GrainParams`); everything else is kept. The page is the cloud (left), the touch pad over the Grain list (340 px), and the Q-Link cards with the wheel's card along the bottom.
- **The cloud.** The layer's sound with the grains the engine plays now drawn over it: each grain a short bar at its reading place, as long as a grain is against the region, its brightness the window's value, cyan when it plays backwards. A band shows where grains may start (the position, or where Scan has taken the voice, ± half the spray), and a line shows the voice's reading place. A tap or drag on the sound sets the position. The caption says the position, spray, how many grains play and the scan speed; the corner says how many grains play on all pads (the engine's budget is shared). A layer in another mode says how to make it play grains (Mode: Granular) and draws no grains.
- **The touch pad.** Position across, grain size up (2 ms to 2 s on a log scale). One finger sets both, so a sweep plays like a scrub.
- **The Grain list.** Mode, Scan speed (−2× to 2×, Frozen at 0), Spray, Pitch spray (±12 st), Window (Hann, Tukey 0.5 and 0.2, Trapezoid 0.25 and 0.05, Percussive 4 and 10), Reverse (the share of grains played backwards), Spread (stereo), Quantise (Off, Major, Minor, Pentatonic, Fifths, Octaves or Chromatic: each grain's pitch lands on the scale), Position, Size, Density (1 to 200 grains a second) and Pitch (±36 st). Arrows step a row; the wheel steps the row picked.
- **Q-Links** turn Position (0.5 % a detent), Size and Density (a doubling every 8 detents) and Pitch (a semitone). With SHIFT, Q-Link 1 turns the spray and Q-Link 4 the pitch spray, and Q-Links 2 and 3 turn size and density finer (1 ms, 0.1 a second). A tap on a card picks its row.
- **Undo.** Each drag, Q-Link turn, wheel turn or run of taps on one row is one undo step, as on the other tabs, and each writes one log line with what changed (`grain_tab::describe`).
- **Cost.** Drawing reads a copy of the grains, never the engine's own: `Engine::grains_of(pad, layer, out)` copies them into a fixed slice without allocating. The engine's per-grain cost on the MPC sets how many grains play (`GRAIN_BUDGET`); the cloud shows that number so the budget is visible while playing.

### The Pads tab (`mpfree-sampler-ui`)

Since 12 Nov 2026 a top-level tab of its own, between Play and Arrange (Jay, 15:46Z: "Pads + Browse / Pad switch"; layout spec section 4e). Before that it was the pad editor's first sub-page on the Sample tab. Its bar has a **Browse | Pad** switch (`pads_tab::VIEWS`, `PadsAction::View`). The Pad view is three columns: the pad map (440 px), the Pad list and the kit's sounds (340 px). The Browse view is the pad map (400 px) beside the app's browser (`pads_tab::browse_layout`). The Sample tab's bar reads Wave, Warp, Chop, Play, Grain, FX, Rec, with Send to pad and Chop to pads beside it on every page (`send.rs`, `send::SEND`).
- **Pad map.** The bank's 16 pads in a 4×4 grid laid out as on the MPC (pad 1 bottom left), each with its name, its layers and play mode ("3 layers · Loop"), and the clip it launches. A tap picks a pad for every tab (Wave, Chop and Play edit it next); a tap on the pad already picked plays it while the finger is down. Pads held on the hardware light up, and hitting a pad picks it as on the other tabs.
- **Clips.** The time engine (`mpfree-seq`, `mpfree-play`) owns clips and doesn't launch them from pads yet, so the Pad list says "clip: none" and the map shows no clips. `PadsState::clips` is where the app puts each pad's clip name once the time engine has an accessor for it.
- **Copy, Paste, Clear** work on the pad picked, each one undo step. Paste (named after the pad copied, such as "Paste A1") puts the copy, with its sound, layers and every setting, on the pad picked; Clear leaves it without a sound.
- **Map to keys** (the fourth button, on while any pad of the bank has a sound) makes the bank's pads one keygroup instrument (`PadsAction::MapToKeys` with the bank's pads that have a sound). The app finds each pad's note with `keymap::sound_root` and calls `Project::map_to_keys` (see Keygroups below).
- **The Pad list.** Sound, Mode (One shot, Gate, Loop, Granular; Loop adds a loop where a layer has none), Polyphony, Mute group, Level, Pan and Tune. Its rows step as on the Play tab (`play_tab::stepped`). Stepping Sound puts the kit's next or previous sound on the pad.
- **Sounds.** Every sound in the kit's project, with its length and the pads that use it. **Put on** puts the sound picked on the pad picked (`with_sound`): the first layer plays it from start to end with no fades, the pad keeps its settings and the old sound's gain, tune, channels and play mode, and takes the sound's name. On an empty pad it makes a new one-shot pad.
- **Q-Links 1 to 4** turn Level, Pan, Tune and Polyphony; the **wheel** steps the row picked. A run of turns or taps on one row is one undo step, as on the other tabs.
- **The other tabs** are greyed out while the pad picked has no sound.

### The Sample tab in the pad player (`mpfree-app`)

The pad player's top bar has a Sample tab (Jay's name for the pad editor), last of Play, Pads, Arrange, Synth, Looper, Sample. It shows the pad editor (Wave, Warp, Chop, Play, Grain or Rec, from the pad bar's tabs) for the playing kit's pad that was hit last, or picked on the Pads tab. The Pads tab is driven by the same `SamplePage` (`Editor::Pads`; the Sample tab's editor is kept for when it shows again).
- **Send to pad and Chop to pads.** Send to pad keeps the kit and pad (`SamplePage::sending`); the next pad hit gets a copy of that pad (`PadsAction::Set`, one undo step), and the log says `sample: pad A5 sent to pad A2`. A hit on the same pad, or a kit change, calls it off. Chop to pads opens the Chop tab, or on the Chop tab presses its Chop to pads.
- **Who owns what.** `sampler::Player::new` builds one project per kit (and the Grains kit) and hands them to the screen thread with `take_projects`. The screen thread owns them from then on (`sample_page.rs`); their undo history starts there, so UNDO never takes a loaded kit apart (`Project::clear_history`). The audio is shared with the engine's views (`Arc`), not copied.
- **Edits reach the sound.** An edit changes the project on the screen thread, which then builds the kit's `EngineView` again and sends it to the audio thread in a box (`FromUi::SampleView`). `Player::swap_view` puts it in place (in the engine, if the kit is playing) and leaves the old view in the same box, which goes back (`ToUi::SampleViewBack`) to be freed on the screen thread. One view travels at a time; edits made meanwhile go with the next one. The audio thread never builds, allocates or frees a view; if the screen's channel is full, it keeps the box and tries again next period. Sounds already playing finish as they started; the next hit plays the edit.
- **Controls.** On Wave, Q-Links 1-4 move Start, End, loop start and loop end (SHIFT: one frame a detent); on Warp they pick a pin, nudge its beat, fine-tune the warp tempo and scroll; on Chop they pick a slice, move its start, turn the method's setting and move the first pad; on Play they turn Attack, Decay, Cutoff and Resonance; on Grain position, size, density and pitch (SHIFT: spray, finer size and density, pitch spray); on Pads they turn Level, Pan, Tune and Polyphony. Letting go of a Q-Link, or a second without turning, ends the turn (one undo step). The wheel zooms on Wave, Warp and Chop and changes the row picked on Play and Grain (a turn is one undo step, like a Q-Link's). SHIFT + wheel and - / + pick the previous or next pad with a sound. UNDO and SHIFT + UNDO undo and redo on this tab (the time engine's takes elsewhere). A tap on the wave plays the pad; in Gate, Loop and Granular modes it keeps sounding until the next tap or leaving the tab. Opening the tab while the synth has the pads gives them back to the last drum kit.
- **On screen.** Pad names use the kit's bank letter (kit 2's pad 5 is B5). The playing kit's playheads come from the audio thread about 25 times a second while the tab shows (`Playheads`, fixed size). A pad without a sound shows a page that says so and how to give it one (the Pads tab, Browse, then Load); while the synth has the pads, a page says so.
- **In the log.** Each finished drag or turn writes one `sample:` line with what changed (for example `sample: kit 1 (House) pad A1 Kick: Start 0.000 s -> 0.012 s`), and the session's last lines count the views swapped in.
- **Chop.** Chop to pads changes the kit's project like any edit, so its new view goes to the audio thread the same way. `Player::swap_view` takes which pads have a sound from the view (`EngineView::has_pad`), so the new pads play, and the playing kit's pad lights follow (lit in the kit's colour where there is a sound; the same after an undo). The Play page's pad names follow too (`SamplePage::take_renamed`). The log gets one line per chop, such as `sample: kit 1 (Breaks) pad A5 Break 92: chopped 0.163 s to 4.891 s into 4 slices (Grid) on pads A6 to A9`. A tap on a slice goes to the audio thread as `FromUi::Slice` and plays at the screen's velocity, if the kit is still the one playing (`sampler::Player::audition`); on a pad warped to stretch, the slice is found in the stretched copy.
- **Grain.** While the Grain tab shows, one boxed `Cloud` (up to 128 grains, fixed size) goes back and forth: the screen thread names the kit, pad and layer and sends it (`FromUi::SampleGrains`); the audio thread copies that layer's grains, its reading place and the grains playing on all pads into it (`Player::fill_cloud`, no allocation) with the playheads, about 25 times a second, and sends it back (`ToUi::SampleGrains`). Only one box exists; off the tab it stays on the screen thread, so the audio thread does nothing for it. A cloud with nothing playing is drawn once, not 25 times a second. Edits write lines such as `sample: kit 1 (Breaks) pad A5 Break 92: mode Loop -> Granular` and `... position 0.0 % -> 2.0 %`.
- **Play.** A hit's velocity shows on the layer map. Each finished drag or turn writes one line with what changed, such as `sample: kit 1 (Breaks) pad A5 Break 92: decay 0 ms -> 8 ms`. While the pads play notes, a hit picks the keygroup that plays its note, and Pads play writes a line of its own (`sample: kit 1 (Breaks): the pads play their own sounds`). A key pressed on the keyboard goes to the audio thread as `FromUi::SampleKey { kit, note, velocity, down }` and plays the keygroups (`sampler::Player::key_at`, `key_off_at`: `Event::Key` and `Event::KeyOff`) if the kit is still the one playing; a tap on a zone picks its pad itself, not the pad its note would play. The hint follows the keyboard (`Player::sample_after`).
- **Map to keys.** For each pad the note is its keygroup's root if it has one, else a note in its sound's name or its own ("Pluck C3", "Bass_F#1", "Pad Ab2"), else the pitch heard (`SourceView::root_note`); the log says where the notes came from and names the pads left as they were: `sample: kit 1 (Breaks): mapped to keys: 4 pads from G#1 to C3 (3 by its name, 1 by its pitch), the pads play notes`.
- **Rec.** The line input onto a pad. While the line input is on (the Looper tab's MENU), the Sample page keeps the sampler's `Input` and sends its writing end to the audio thread once, boxed (`FromUi::SampleInput(Some(..))`, `sampler::RecFeed`); each period, right after the looper reads the input, `RecFeed::period` marks the bar lines the transport's block crosses (bar 1 on, not the count-in) and appends `LoopHost::input()` to the buffer, without allocating (counted under the sampler on the Engines page). Turned off, a take still recording ends there and is kept, the page asks for the writer back (`FromUi::SampleInput(None)`), and the audio thread returns it (`ToUi::SampleInputBack`) to be freed on the screen thread. The tab shows L and R meters and the last 30 s of input with the bar lines, the span Skip back would keep and the take being recorded. Record starts a take with the Record list's settings; it keeps recording while other pages show, and lands on its pad (the next empty pad from the pad picked in its bank, or the pad picked) as one undo step, and the editor picks that pad; the Play page's pad names follow. Skip back keeps the last 5 s to 1 min, or the last 1 to 8 whole bars. The log gets lines such as `sample: take armed for pad A6: start next bar, end 4 bars, left + right`, `sample: recorded: Take 1, 1.50 s stereo on pad A6` and `sample: skip back 10 s: Take 2, 10.00 s stereo on pad A7`. While the line input is off the tab says where to turn it on. A period the line input came short on is padded with silence (the looper's short-period count says when), so a gap can land in a take. The line input itself, its jacks and its levels are the time engine's (round 7 heard the left jack); the sampler opens nothing.
- **Resample (Source row).** The Rec tab's first row picks what it records: Line in, Master (after Master safety: what is heard, without the metronome), the Drums, Synth and Loop tracks, Return A (the delay) or one of the playing kit's 16 pad channels, each after its fader (`sample_page::rec_sources`). The page tells the audio thread (`FromUi::SampleSource(RecSource)`), which points the mixer's last capture point at the strip (`mixing::SAMPLER_CAPTURE`, `MixHost::set_rec_source`), starts the buffer afresh, and after the mixer appends what the point took, with the bar lines marked as late as the point hears the block (`MixHost::rec_capture`, `Mixer::capture_latency`). The buffer exists while its source comes in: the line input while it is on, a point in the mix from when it is picked (26.5 MB at 44.1 kHz); back on Line in with the line input off, the writer goes back and is freed. A take keeps its source: the row waits while one is being made. Takes are named after their source (`Master take 3`), and the log says `sample: the Rec tab resamples Master` and `sample: the sampler resamples Master (75 s kept, 26.5 MB)`. Copying a period costs a few microseconds; a free capture point costs nothing.
- **Flatten (step FLAT).** The Rec tab's third button resamples a pad through its own channel, so the pad's inserts, tune, filter and envelopes are printed into a plain sound. The MPC's Flatten Pad does the same (user guide 3.6, p. 185: the pad at velocity 127, after its channel strip, onto the pad's first layer). The Flatten velocity (16 to 127) and Flatten hold (100 ms to 8 s) rows say how it plays. Flatten points the sampler's source at the picked pad's mixer channel: after its inserts and before its fader (so its level and pan stay out), or before its inserts when it flattens onto the pad itself, so nothing is printed twice. It waits until the buffer holds the new source (`RollingReader::restarts`, or a fresh buffer that has started to fill), then arms a take that starts at −60 dB with 2 ms of pre-roll and ends after the Silence row's time below −60 dB (at most the hold plus 20 s). Then it plays the pad once (`FromUi::SampleHit`, as a pad press would, at the velocity) and lets go after the hold (a Toggle pad is hit again). The take lands on the target pad (as Record picks it) as a fresh pad at the centre level, as one undo step. Onto the pad itself, it keeps its mute group, chokes and polyphony. Afterwards the Rec tab's source comes back. Stop ends it and keeps nothing. It gives up after 2 s if the channel doesn't come in or the pad makes no sound. The log says `sample: flatten A5 onto A6: velocity 127, held 1000 ms, from its channel after its inserts` and `sample: flatten A5 kept: Break 92 flat, 931 ms on pad A6`. The button is off while the pads play notes, when the picked pad has no sound or is not one of the kit's 16, when there is no pad to put it on, or while a take is being made (`tests/rec_tab.rs`; the whole flow in the app, including a pad that makes no sound, in mpfree-app).
- **Print N bars (Tail row, step PRINT).** A take with End Length is whole bars, and the Tail row says what it does after them: Cut (on the bar line, as before), Ring out (until it has been under -60 dB for the Silence time, at most 20 s more: a one-shot with its reverb or echo) or Loop (exactly its bars, without a seam, as `record::Tail::Loop` above). With Source on the Master, a track, a return or a pad's channel and Start on Next bar, that is the MPC's Bounce to Sample in real time: everything the strip does, knob moves included. Takes of whole bars (End Length, and Skip back by bars) land warped at the project tempo (`Warp::new`, Stretch), so they follow it from then on; Skip back by seconds and End Stop or Silence land unwarped. The log says what happened: `sample: take armed for pad A6: start next bar, end 1 bar then loop, left + right`, then `sample: recorded as a loop, cut: it was going round: Master take 1, 2.61 s stereo on pad A6, warped at 120.0 BPM` (or `recorded, rang out 1.20 s`, `recorded as a loop, 0.80 s of ringing folded onto its start`, `recorded as a loop, its second time round`). The sampler records in real time from the mixer's capture point; the FX thread's Print (`mpfree-fx::print`) stays the mixer's own freeze.
- **Phrase.** A chop with Pads + phrase also sends a clip of the slices (`FromUi::SamplePhrase`) to the audio loop, which puts it in the armed track's (else Track 1's) first empty slot without launching it (`TimeHost::put_clip`, one take, so the time engine's undo takes it out; the sampler's undo takes the pads). Both ends write a line: `sample: phrase "Break 92 phrase": 15 hits over 8 beats, for the armed track` and `time: phrase: 15 notes in slot 1 of Track 1` (or why not: no empty slot, or pads past A16, which the clips don't play yet).
- **Not yet.** Edits are saved with the project once the app wires the browser (see "Saving with the project" below). FX is greyed out (the FX chain thread builds it). The Grain tab edits the first layer only, and doesn't set tempo sync (`TempoSync`) or the grain gain yet. The Play tab doesn't add or remove layers, set a layer's own level, pan or tune, or the filter envelope's times yet.
- **Pads.** A tap on a pad picks it for every tab; a tap on the pad picked plays it as a hit would (it lights, and lets go when the finger lifts). Copy, Paste, Clear, Put on and each run of turns write one line, such as `sample: kit 1 (Breaks) pad A3: now plays Hat closed` or `sample: kit 1 (Breaks) pad A1: cleared (was Kick 58)`. The Play page's pad names and lights follow, as after a chop.
- **Not yet on Pads.** The clip each pad launches (waits on the time engine), dragging one pad onto another, the Q-Link displays beside the knobs (Jay asked for them; the Hello MPC thread is drawing layouts, and all the sampler's pages will move together).

### Warp and stretch

- **High quality:** `mpfree-stretch` renders a stretched or pitch-shifted copy on a worker, at the project tempo for a warped region. When the tempo changes, the region keeps playing with the real-time stretch below until the new copy is ready, then crossfades to it at the next loop start.
- **Real time:** the granular engine in "stretch" mode (grain size 40-90 ms, overlap 4, scan speed = tempo ratio, pitch 0, position jitter 0), which is a form of synchronous granular stretching (close to WSOLA without the cross-correlation search). Cheaper and lower quality; good for live tempo moves and as a deliberate effect.

#### Warp (`mpfree-sampler::warp`)

- **Model.** A region's `warp: Option<Warp>` says the tempo it was played at (`bpm`, 20 to 999) and how it meets the project tempo (`WarpMethod`): **Stretch** keeps the pitch and changes the length; **Repitch** plays faster or slower like tape and leaves the region's tune out, which would pull it off the beat. Granular regions ignore warp (their grains have tempo sync). The Wave tab's Region list has **Warp** (Off, Stretch, Repitch) and **Warp tempo** (a BPM a step); turning warp on starts at the source's detected tempo, made exact when the region is whole beats of it.
- **Pins.** A warp's `pins` pin hits to beats: source frame `frame` plays on `beat`, counted from the region's start. Between two pins the sound stretches evenly; the start stays on beat 0 and the end where the warp tempo puts it (`Warp::beats`), so a loop keeps its length whatever the pins do. Pins are in order of frame and beat, at most 128, and nowhere make the region play more than 4 times faster or slower than its tempo (`Warp::pins_ok`, checked by `Region::check`). They count only when the region stretches: repitching, it plays straight through. When the Wave tab moves Start or End, each pin stays on its hit, its beat counted from the new start (`Warp::moved`); pins outside the region or that no longer fit go (`Warp::fit`, also on a new warp tempo).
- **Copies.** `Warps` holds the project tempo and the stretched copies made for it, keyed by source, region, length, tune and pin set (`CopyKey::pins`, a hash; 0 for none) (a stretch copy carries the layer's whole tune, up to two octaves, so the length stays on the beat), within a 200 MB budget: past it the least recently used copies no project wants at the tempo go, never one that is wanted. `Warps::missing` says what to make; `Worker` is a thread that makes them in turn and drops them when cancelled (a new tempo cancels the old tempo's copies within one step).
- **Playing.** `EngineView::build_warped` resolves a stretch region to its copy when it is made (loop points and slice taps mapped through the pins with `CopyMap`, fades scaled) and repitches it to the tempo until then; a repitch region always repitches. `Engine::set_tempo` (every period, with the transport's tempo; nothing allocates) moves the step of every warped voice at once, so a held loop follows a tempo change straight away; a copy made for another tempo repitches until the next hit plays the new one.
- **In the pad player.** The Sample page keeps the `Warps` and the worker; a new tempo from the transport rebuilds the views of kits with warped pads and asks for their copies, and each copy that comes back sends a new view and logs a line (how long it took and the memory the copies use). The audio loop calls `Player::set_tempo` before it renders.
- **Process.** `Process` stretches or pitch shifts one layer's region into a new source (to a tempo, by a ratio, by semitones) on a worker; `Project::use_processed` puts it in the layer's place with its loop, fades and warp tempo moved to match, as one undo step that also takes the new source away. A stretched region's pins are made part of the new audio (its hits land on their beats) and the new region has none.

#### The stretch engine (`mpfree-stretch`)

Our own Rust, not Signalsmith Stretch as first planned: no C++ to cross-build for the MPC, MIT like the rest, and the hit handling is ours to tune with the sampler's own hit finder.

- **Map.** A `TimeMap` says where each input frame lands: one ratio, a target length, or warp markers (input frame, output frame), each part between 0.1 and 10 times.
- **Stretch.** A phase vocoder: Hann windows of about 46 ms (2048 frames at 44.1 kHz; 256 to 16384 by setting), read where the map says and written at a steady hop of a quarter window. Bins are grouped round the spectrum's peaks and turn with their peak (identity phase locking, Laroche and Dolson), so partials stay whole.
- **Stereo.** Left and right go through one complex FFT and turn by the same angle, worked out on their sum (or their difference where the sum cancels), so the image and mono compatibility stay as they were (a left-only input keeps its right channel below -60 dB; an out-of-phase pair stays out of phase).
- **Hits.** The hit finder (`OnsetAnalysis`, the Chop tab's) finds the hits; a hit counts only if its brightness (the energy of the change from frame to frame) jumps at least 6 dB, because beating partials can fool the finder and a restart in a steady sound wobbles the pitch. Each hit is then played at its own speed from half a window before it to three quarters after, the stretch is taken up between hits, and the phases start again at the first window that reaches it, so the attack comes out sample for sample as it went in and lands where the map puts it (within 1.5 ms in the tests, the finder's own error).
- **Pitch.** Stretched by the pitch ratio, then read that much faster by a windowed-sinc resampler (Kaiser, 24 zero crossings), low-passed first when it reads faster. Formants move with the pitch, as on a sampler; keeping them is a later setting.
- **Steps.** `Job::new` finds the hits; `Job::run(frames)` does about that many output frames of work and reports progress, so the worker can stop between steps and the old sound plays until the new one is ready. Any step size gives the same output.
- **Cost.** On the workstation (one core of a 2.1 GHz Xeon) a stereo stretch runs at 50 to 70 times real time, a pitch shift at 18 to 40 (an octave up is the dearest: twice the vocoder work and the longest filter). The round 7 calibration puts the MPC at about 6 to 8 times real time for a stretch and 2 to 5 for a pitch shift, so a 4-bar loop at 120 BPM takes 1 to 4 s. Device numbers win; the stretch goes into the next device round.
- **Listening.** `mpfree-stretch` (a workstation tool in `mpfree-sampler`) renders examples from a WAV or a demo chord and beat: slower, faster, twice as long, slower without kept hits, up 5, down 7, up an octave and warped, with a report of each one's time (and an MPC estimate with `--calibration docs/dev/perf/mpc-one-calibration.txt`).

### Keygroups (`mpfree-sampler`)

- **Model.** A pad's `keys: Option<Keys>` (`lo`, `hi`, `root`, MIDI notes) makes it a keygroup: it plays every note from `lo` to `hi`, a semitone higher for each note above `root` (`Keys::all(root)` covers the keyboard, `Keys::one(note)` a single note). The kit's `pads_play` (`PadsPlay::Pads`, or `PadsPlay::Keys { from }` with pad 1 playing `from` and each pad a semitone up, `from` at most 112) says whether a hit plays the pad's own sound or a note; it is in the undo log like any edit. `Project::spread_to_keys` makes a pad a keygroup over the keyboard with chord voices and the pads playing from the C below its root; `Project::keygroups_for(note)` lists the pads that hold a note.
- **Map to keys (`keymap.rs`, `Project::map_to_keys`).** `keymap::note_in_name` reads a note from a name: a letter A to G, then `#`, `s` or `b`, then an octave of -1 to 9, standing alone as a word and at most G9 (the last one wins, so "Piano C3 then E3" is E3; "Break 92", "BD" and "C34" have none). Middle C is C4 (MIDI 60), as everywhere in MPFree. `keymap::sound_root(keys root, name, heard)` picks the note: the keygroup's root, else the name's note, else the pitch heard; when the name and the heard pitch are the same pitch class the heard octave wins (some libraries call middle C C3), and when they disagree the name wins. `Project::map_to_keys(&[(pad, root)])` gives each pad a zone reaching halfway to the next root up and down (`autosample::zones`; the lowest and highest to the ends of the keyboard; pads with the same root share a zone), at least 16 voices, and sets the pads to play notes from the C at or below the lowest root, as one undo step; an empty pad or a pad without a sound changes nothing (`tests/keys.rs`).
- **Engine.** `Event::Key { note, velocity }` and `Event::KeyOff { note }` play every keygroup holding the note; with the pads playing notes, `NoteOn`, `NoteOff` and `Pressure` for a pad are its note. A keygroup voice reads `2^(semitones / 12)` faster (a granular voice adds the semitones to its grains' pitch instead, so its timing stays put), keeps its note so each key lets go of its own, and counts against the pad's polyphony. A hit on a keygroup while the pads play their sounds plays it as recorded. `EngineView::has_pad` follows the mode, so the pad player's lights and `Player::hit_at` do too. A warped keygroup moves with the tempo on top of the note. None of it allocates (the `no_alloc` test plays keys every few periods).
- **Fades (`Pad::key_fade`, `Pad::vel_fade`, `model::edge_gain`).** A keygroup fades in over its first `key_fade` notes and out over its last (0 to 24), and each layer over its first and last `vel_fade` velocities (0 to 64), on an equal-power curve (note `n` steps inside an edge plays at `sin(n / (fade + 1) · π/2)`), so two zones or layers overlapping by the fade sum to the same power on every note. An edge at the end of the keyboard (0, 127) or of the velocities (1, 127) never fades, and a hit on the pad itself (its own sound, not a note) has no key fade. The engine works out each layer's level once, when the voice starts (`Engine::note_on`), so a fade costs nothing per sample and a fade of 0 plays bit for bit as before. With a velocity fade, Cycle and Random take turns within each set of layers that share their velocities (the round robins of one velocity) and every set the hit falls in plays, so auto-sampled round robins still alternate while their velocity layers crossfade; the turn counter wraps at 720720, which every set size up to 16 divides. **One step to a crossfade:** Map to keys and auto-sample leave zones and velocity layers edge to edge, and a fade alone would dip where they meet, so setting a fade also moves the edges that meet to overlap by it, centred where they met (`model::overlap_ranges`; running it again with another fade moves the same edges, 0 puts them back edge to edge; a gap or a stack is left alone). `Project::set_key_fade` does it for every keygroup of the kit as one undo step, `Pad::set_vel_fade` for a pad's layers, round robins together. The app writes `sample: kit 1 (Breaks): key fade 2 notes, the zones that meet crossfade over them`; a Vel fade change is a line of the pad's like any row. Saved with the project (`key_fade`, `vel_fade`; older saves open at 0). Tests: `tests/keys.rs` (the curve, levels measured at the edges, layers crossfading, round robins in sets, limits).
- **Not yet.** A MIDI keyboard into the sampler (the pad player has no MIDI input route to it yet; the Play tab's keyboard plays it on screen), a root's cents (Tune does it by hand) and the MPC's keygroup program import.

### Links and Latch (`mpfree-sampler`)

- **Links (`Pad::links`).** A hit on a pad also plays the pads it links to, at the same velocity, as the MPC's Simultaneous Play (user guide 3.6, p. 187, which allows four; here any of the other 15). `Pad::chokes` are its Mute Targets (the same page). `Engine::hit` plays the pad, then each link through `note_on` as a hit on it would (its layers, chokes, mute group, latch and polyphony), with the voice's `by` set to the pad hit; `Target::Own` matches voices by `by`, so lifting the pad lets go of its links' voices too, pressure on it moves them, and a linked pad hit on its own keeps its own voices. Links go one way and one step (a linked pad's own links aren't followed), a link to the pad itself is dropped when the view is built, and a link past the 16 pads is refused (`ModelError::BadPad`). The voices one hit starts never choke each other (`Engine::spare_from`: chokes and mute groups skip voices started by this hit), so a pad can link to a pad in its own mute group; the next hit chokes them as usual. Links apply to hits on pads only: with the pads playing notes or 16 Levels they do nothing. The fan-out copies the links into a fixed array, so it allocates nothing (`tests/no_alloc.rs` covers it).
- **Latch (`Pad::latch`).** A latched pad's voices ignore lifts (`Engine::release` skips them, for pads, keys and 16 Levels alike); the next hit with the same note lets them go instead of playing (`let_go`: a loop leaves its loop and plays its tail, grains stop and release, anything else releases), as `PlayMode::Toggle` always did for one region; the hit after that plays again. `Event::AllOff` lets latched voices go too. `Engine::latched_pads` gives the pads a latched hit keeps sounding, as 16 bits, and the pad player lights them (`Player::latched_pads`, in the pad light loop of `main.rs`). With Note Repeat, every repeat is a hit, so a latched pad turns on and off with each step.
- **Saved** with the project (`links`, `latch`; older saves open without them). Tests: `tests/links.rs` (links, one way and one step, no choking within a hit, notes, latch for gate, loop, grains, one-shots and keys, AllOff, a latched link), `tests/save.rs`, the Play tab's rows and pad hits in `mpfree-sampler-ui` `tests/play_tab.rs`, and the app's (`hits_on_pads_edit_stops_and_also_plays_and_latch_is_a_row`).
- **Full Level and Half Level** need nothing here: the pad player fixes a hit's velocity before it reaches the sampler (`App::velocity`), and 16 Levels of velocity keep their own.

### 16 Levels (`mpfree-sampler`)

- **Model.** `PadsPlay::Levels { pad, by }`: every pad of a bank plays pad `pad`, pad `k` (0 to 15) at step `k` of `by` (`Levels`). The steps are ours, not a copy of the MPC's: **Velocity** 8, 16, ... 127; **Tune** a semitone a pad with pad 9 as recorded (−8 to +7); **Cutoff** 100 Hz to 20 kHz evenly in octaves (a 2-pole low-pass when the pad's filter is off, else its own type and resonance); **Decay** 25 ms doubling every two pads (to about 4.5 s), falling to silence; **Start** `k / 16` of the region (a granular pad's grain position, `k / 15`). One undo step, like the other `pads_play` changes.
- **Engine.** A hit starts the pad's voices with that step (`Vary`), tagged with their level so each pad lets go of its own; Full Level doesn't flatten velocity levels. Nothing allocates (the no-alloc test swaps in views playing cutoff, decay and start levels).
- **Play tab.** Pads play goes round Their sounds, Notes and 16 Levels (of the pad on show); **Levels by** picks the step. A hit on any pad picks the pad the levels play, and the change writes a line (`sample: kit 1 (Breaks): the pads play 16 Levels of pad A5 by tune`).
- **Not yet.** The MPC's 16 LEVEL button (its note isn't captured yet), Attack and Layer levels, and copying the levels onto pads of their own.

### Tape (`mpfree-sampler`)

- **Wow and flutter.** A pad's `wow` (0 to 1; the Play tab's **Wow & flutter** row, 10 % a step) makes its pitch wander like a worn tape machine: two slow wobbles (0.53 and 0.29 Hz, 15 and 10 cents at full) and a fast flutter (7.3 Hz, 5 cents). Each voice starts its wobbles at its own place, so a chord doesn't wander in step. Granular voices keep their grains' pitch.
- **Tape stop and start.** `Event::Tape { stop, ms }` slows every voice to a halt (or brings it back up to speed) along a straight ramp of `ms` milliseconds, as a tape machine's motor would; below a quarter of the speed the sound fades out, so a halted tape is silent rather than stuck on one sample. Voices wait where they stopped and go on when it starts again, and a hit on a stopped tape waits silent too. It is the sampler's own tape: a tape stop on the whole mix would be a master effect.
- **Cost.** The speed and the wobbles move once per period (or between events), never per frame: each moving voice's step is worked out again from its base step, its pitch pressure and its speed (`retime`). A running tape with no wow leaves the output bit for bit as it was (the hash check over two busy workouts is unchanged), and the no-alloc test stops and starts the tape with wobbling pads.
- **Not yet.** A control for this pads-only tape stop: the Play page's Tape stop throw already stops the whole mix with the FX master tape stop, so this one waits until a pads-only stop is wanted. Repitch that follows the tempo is warp's Repitch; half speed is Tune −12.

### Chop to a phrase (`mpfree-sampler`)

- **What it is.** A loop chopped to pads plays back whole only if something hits the pads in the right places. `phrase::phrase(chop, first, count, frames_per_beat)` gives the slices as hits in beats of the sound's own tempo, from the first slice (`Hit { slice, beat, beats }`); the phrase lasts the slices' span in whole beats (within 0.05 of a beat it rounds, else up). As a clip, the loop then plays at any tempo with each slice as recorded (only the gaps move), and every hit is a note to move, mute, retune or swap: the MPC's chop-to-sequence idea, ours in the details.
- **The clip.** The Sample page makes it (`ChopAction::phrase`, then `phrase_clip`): one note per slice, on the slice's pad at velocity 127, at 960 ticks a beat, named after the pad ("Break 92 phrase"); the time engine checks it (`Clip::check`) when it lands.
- **Not yet.** Keys + phrase (the clip would need a track that plays notes), phrases on pads past A16, and a phrase from a chop already on pads.

### Saving with the project (`mpfree-sampler`, `mpfree-app`)

The kits are the sampler's part of a saved project (owner `sampler`, see `docs/dev/design/browser.md`).

- `save::to_text` writes every kit as `key = value` lines under `kit.K.`: its sounds by file name, its chop sets, its master effect, what its pads play, and every pad's layers, regions, loops, fades, warp pins, grain settings, envelopes, filter, pressure and keys. Each struct is taken apart field by field, so a field added to the model doesn't build until it is saved too. Numbers read back to the same bits.
- `save::from_text` gives the kits back with empty undo histories. A key it doesn't know is skipped and a missing one keeps its default, so older and newer builds' parts open. A missing or broken sound, a pad or chop the model refuses, a bad master effect: each is left out with a note, and the rest opens. Each file is read once, however many kits use it, and the kits share it in memory.
- `wav::write` keeps a sound losslessly in the smallest form that gives every sample back: 16-bit or 24-bit PCM when the samples are exactly that (a line-input take, a 16-bit import), else 32-bit float. Mono stays mono. Read back, it is the same `Source` with the same id. `wav::file_name` is the id (`1f0c2d3e4a5b6c7d.wav`), so the same sound is one file and a file already in the project is that sound.
- `wav::read` takes 8, 16, 24 and 32-bit PCM and 32 and 64-bit float WAV files, mono or stereo, plain or extensible, at 8 to 192 kHz, up to 64 Mi samples; a file cut short gives the whole frames it has.
- `sound_file::read` takes any sound file by what it holds, not its name: WAV (`wav::read`), AIFF (`aiff::read`) or FLAC. `aiff::read` takes AIFF and AIFF-C with 8 to 32-bit PCM (big-endian, `sowt` little-endian, `in24`, `in32`) and 32 or 64-bit float; compressed AIFF-C says which compression it refuses. FLAC is decoded by `mpfree-flac`, our own decoder (no new crates): 4 to 32 bits, every subframe type and stereo coding, an ID3v2 tag in front stepped over. Every frame header's CRC-8 and every frame's CRC-16 is checked, so a damaged frame is an error saying how far in it is, never noise. A file cut short loads the whole frames it has, and stray bytes between FLAC frames are stepped over; either way it comes with a note the log shows. A loaded sound is kept in a project like any other: a 16 or 24-bit FLAC or AIFF is saved as a WAV of the same bits, the same sound.
- Tests: `mpfree-flac` decodes seven files from FFmpeg's encoder (16, 24 and 32-bit; independent, left/side, side/right and mid/side; fixed, LPC up to order 32 and verbatim subframes; wasted bits; `tests/data/make.py` makes them) bit for bit against the signal they hold, plus hand-built streams for what FFmpeg never writes (variable blocks, 8, 12 and 20-bit, escaped residuals, a 33-bit side channel); cuts, damage, tags and stray bytes; and the browser's picture column by column.
- In the pad player, `SamplePage::save_part` gives the text and each sound once; the library's save writes the sounds the project hasn't got before the part (`Library::save_project_with`), so a part never names a missing file. `SamplePage::open_part` reads and decodes the sounds on a thread of its own; on a later tick each kit goes in its place, its view goes to the audio thread like an edit's, the Play page's names follow, and the pads switch to the kit the project was playing.
- The browser's Load puts a WAV, AIFF or FLAC file on the pad shown (one undo step); Load to pad holds it until the next pad hit (`SamplePage::load_file`). Both read and decode on their own thread (`sound_file::read`). A note (a file cut short) goes to the log before the sound lands: `sample: Loop: the file is cut short: its first 2304 frames`.
- Not yet: kit files on their own (`LoadKit`), the factory kits from the browser, MP3 and Ogg.

## Granular engine (`mpfree-grain`)

```text
 GrainScheduler (per granular voice)
   every block: accumulate density × block time; for each due grain:
     pos   = playhead + jitter(spray)            (playhead advances by scan_speed)
     pitch = base + pressure/knob mod + random(pitch_spray), quantised to scale if set
     len   = size (frames), dir = reverse? with probability, pan = random(spread)
     push Grain { pos, inc, remaining, window_phase, window_inc, gain_l, gain_r } into a fixed array
 Grain render: for each active grain, for each frame:
     s = hermite(buffer, pos); w = window_table[phase]; out_l += s·w·gain_l; out_r += s·w·gain_r
```

- **Fixed arrays:** each granular voice has up to 64 grains; there is a global grain budget across voices (start at 256, set by measurement). Past the budget, new grains are skipped, never queued, so the period is never at risk.
- **Windows** are 1024-entry tables (Hann, Tukey with a shape parameter, trapezoid, exponential), read with linear interpolation.
- **Sources:** a region (granular playback mode) or a circular live buffer of 4-8 s (granular effect). Freeze stops writes to the live buffer.
- **Sync:** density and size can lock to tempo divisions, using the transport's frame position.
- **Determinism:** randomness comes from a seeded generator per voice, so offline renders are reproducible in tests.

**Built (S6, workstation half):** `rust/mpfree-grain`, with the tool `mpfree-grain` in `mpfree-sampler` for listening to eight presets on any WAV. What it does, as built:

- `GrainVoice` has a fixed array of 64 grains. `Budget` counts the grains alive across all voices and refuses new ones past its limit.
- Grain sources are `Clip` (a region of a sample) and `LiveBuffer` (a circular buffer with freeze). Grains are placed so the whole read stays inside the readable span, so a grain is never cut short or reads outside its region.
- Windows are Hann, Tukey, trapezoid and exponential, as 1025-entry tables. Pitch can be quantised to a 12-note mask. Density and size can lock to the transport's frame timeline (`TempoSync`), and synced grains start on exact frames whatever the period size.
- Pads play it through `PlayMode::Granular` in `mpfree-sampler`. Each voice slot has its own `GrainVoice`, and one `Budget` (`GRAIN_BUDGET`, 256) is shared by all of them. A region keeps its grain settings in every play mode. Tune adds to the grain pitch, reverse makes every grain play backwards, and the pad's envelope, filter, pan, chokes and polyphony apply as for any other voice. Lifting the pad stops new grains and releases.
- **The granular effect** (`GrainFx`) is an insert on a stereo signal. It keeps the last 0.5 to 30 s in a `LiveBuffer`, plays a `GrainVoice` from it, and mixes the grains back with an equal-power mix that glides over 10 ms. Freeze stops the buffer taking new audio, so the cloud keeps playing what it holds while the dry signal carries on. Audio reaches the buffer in fixed 64-frame chunks counted from the effect's first frame, so the output doesn't depend on the period size; new audio waits at most 1.5 ms before it can be granulated, and freeze takes in what is waiting first.
- **For now it sits on the sampler engine's master.** `MasterFx` in the project holds the mix and grain settings (undoable, with a knob turn merged into one step), and the engine view carries them. `Engine::make_master_fx` makes the effect with 8 s of memory (2.8 MB, off the audio thread), `Engine::set_master_fx` puts it in (it glides in from dry) or takes it out, and `Event::Freeze { on }` freezes it on an exact frame. It runs after the voices on every segment between events, and its grains come out of the engine's grain budget. This is an interim hook: the FX chain (`mpfree-fx`, on the shared `mpfree-node` interface) will own the mixer and master bus, and `GrainFx` becomes one of its nodes there. Tests: `mpfree-grain/tests/fx.rs`, `mpfree-sampler/tests/master.rs` and both no-allocation tests; the listening render is `master-freeze.wav` from `mpfree-grain`.
- **As an FX-chain node.** `GrainNode` (`mpfree-grain/src/node.rs`) wraps a `GrainFx` with 8 s of memory and its own budget of 64 grains, as an `mpfree_node::Node` (id `mpfree.grains`), so it can sit on an insert, a send return or the master chain. Its parameters are in plain units: Mix, Position, Spray, Reverse and Spread in per cent, Size in ms, Density in Hz, Pitch and Pitch spray in semitones; Freeze is a toggle a sequencer can set on an exact frame, and Grains is a read-only meter of the grains playing. `prepare` allocates the memory; `process`, `set_param` and `reset` don't allocate. Parameter events land on their frame, the output is the same at any block size (to within 1e-4), and `reset` clears what it heard. Its tail is the memory plus one grain, endless while frozen and none when fully dry. Tests: `mpfree-grain/tests/node.rs` and `tests/no_alloc.rs`.
- Output doesn't depend on the period size, and the same seed gives bit-identical output. `tests/no_alloc.rs` covers render, start, stop, kill, parameter changes and live-buffer writes.
- Cost measured on the workstation (x86, one core, `cargo run --release -p mpfree-grain --example grain_bench`): about 67 million grain-frames a second on a stereo clip and 59 million on a live buffer, which is 4-5 % of a core for 64 grains at 44.1 kHz. The RK3288 figure is still to be measured, and it sets the budget.

## Analysis (`mpfree-analysis`)

| Analysis | Method | Output |
|---|---|---|
| Peak pyramid | Per channel min, max, RMS as `i16` at block sizes 64, 256, 1024, 4096 frames | `PeakPyramid`, saved as `<source>.peaks` |
| Onsets | 1024-point FFT, hop 256 (5.8 ms); spectral flux on log-magnitude; adaptive threshold = median over ±8 hops × (1 + sensitivity); peak-picking with a 30 ms minimum gap; refine each onset to the nearest preceding low-energy frame | sorted frame positions with strength (so sensitivity can change without recomputing) |
| Tempo | Autocorrelation of the onset strength curve over 60-200 BPM, with a preference curve around 90-120 and octave checks; offered, not forced | BPM and confidence |
| Pitch | YIN on up to 24 windows of 100 ms within 24 dB of the loudest; voiced windows grouped by note, weighted by loudness × periodicity × steadiness (built: `mpfree_analysis::root_pitch`, also per slice via `SourceAnalysis::pitch_of`) | root note and cents, with confidence |
| Zero crossings | On demand within ±N frames of a marker | nearest crossing with matching slope |
| Loudness | Peak, RMS; integrated LUFS later | numbers for normalise |

Analysis results go in the source's cache file with a version number; a newer analyser re-runs old caches in the background.

## Files

```text
MyBeat.mpfree/
  project.toml          plain text, versioned (format = 1), written atomically (temp file, fsync, rename)
  undo.log              append-only command log, one record per line, fsync on each gesture end
  samples/
    3f9a…c2.wav         sources, named by content hash; WAV 24-bit or float, or .flac

```

`project.toml` holds programs, pads, layers, regions, chop sets and settings, referring to sources by hash. A sample can be exported with a small sidecar (`.mpfree.toml`) that carries its regions, chop sets and warp, so edits travel with the file (an owner complaint about the MPC).

## Real-time guarantees and how they are tested

| Guarantee | Test |
|---|---|
| No allocation or free in the audio path | `assert_no_alloc` around `Engine::render` in tests and in a debug build; a counting global allocator in CI fails the test on any allocation during render |
| No locks, files or logging in the audio path | Static test: the `engine` module may not use `std::sync::Mutex`, `std::fs`, `println!`, or `log` (grep-based, like the existing write-site test) |
| Bounded time | Worst-case render benchmarks (all voices, all grains, all filters modulated) on the workstation and on the MPC; the device result sets the voice and grain limits |
| Same output on x86 and ARM | Offline renders hashed and compared, as M6 did for the groove |
| Deterministic | Seeded randomness; renders of a fixed command script are bit-identical run to run |
| Undo is exact | Property test: random command sequences, then undo all, compare with the start |
| Saves survive power loss | Kill-during-save tests on the workstation; the old file is always intact |

## Performance budget

| Item | Budget (first guess, to be measured on the RK3288) |
|---|---|
| Audio period | 2.9 ms; target render under 50 % (1.45 ms) with the full voice and grain load |
| One Hermite voice with envelope and filter | about 1-2 % of the period |
| 64 voices | about 40-60 % of the period, so the default pool may be 48, measured |
| One grain | a fraction of a voice (no filter); 256 grains about one third of the period |
| UI frame | under 15 ms on core 0; waveform redraw only for the changed columns |
| Pad to sound | no worse than the pad player's measured path |

If the budget fails on one core, the engine splits pad buses across cores 2 and 3 with a join before the master, as the earlier research proposed.

**Two cores (`Engine::split`, built).** `engine.split(mpfree_lanes::Config)` splits the voice pool in two: the first half stays on the audio thread, the second goes to a lane (`mpfree-lanes`, a worker that can be pinned to core 2 at SCHED_FIFO 69). Each part of a block (between events, at most 1024 frames) hands the second half to the lane, renders the first, then joins and adds the second half's voices into their pads' pairs in slot order. Everything that decides about voices stays on the audio thread while both halves are home: events, chokes, mute groups, polyphony and stealing see all the voices, and a new voice goes to the half that costs less (playing voices count 8 grains each, plus the live grains), so two granular clouds don't pile up on one core. The grain budget is shared before each part: each half keeps its live grains and gets half of what is free, so together they never pass 256. `render` and `render_routed` wait for the lane no longer than the block lasts; `render_until` and `render_routed_until` take a deadline. A lane that misses it leaves its voices out of that part (`Stats::lane_late`), and events wait in the queue until its half is back, so none are lost; the returning half catches up with the tempo and the tape. Parts under 16 frames, and parts where the second half plays nothing, render on the audio thread. `Engine::lane_stats()` gives the lane's counters. The output is bit for bit the same whether the lane runs on its own thread or in place (`Config::threaded` false), and the same as unsplit but for the voices' order of adding (under 1e-5, with the same steals): `tests/split.rs`. Neither thread allocates or frees: `tests/split_no_alloc.rs` counts both with mpfree-prof's counting allocator. On the workstation (`mpfree-bench --lanes`), the bench's 24-voice sampler case took about 83 µs a block on one core and about 52 µs split, with the worker spinning, as fast as two separate 12-voice engines; with the worker sleeping between blocks, about 70 µs, the wake-up being most of the difference. The device numbers are still to come.

**Measured on the MPC One (round 7, 2026-11-11).** The bench case "Sampler, 20 pads" (16 sample pads with two layers and a low-pass filter each, 4 dense granular pads, 24 voices, a hit every 4 blocks) took 1437 µs on average, 50 % of a period, against the sampler's 25 % budget; with the master grains, 72 %. Per voice that was far slower than on the workstation, and the reasons were ARMv7's: every sample voice frame called an out-of-line read eight times (a clamp and a channel `match` per tap) and converted a 64-bit integer to a float twice (a library call on ARMv7), every grain frame converted between `f64` and `i64` twice (two more library calls), and the live buffer behind the master grains divided a 64-bit number per frame. The voice now reads both channels straight from the data, once, away from the region's edges (`Voice::read2`; the clamped read stays for the edges), takes the fraction from the position's low 32 bits, retunes its filter only when the envelope or pressure has moved it (and the second stage only for 4 poles), and keeps its per-16-frame updates out of the per-frame loop; grains go through `i32` below 2^31 frames; the live buffer keeps its write head instead of dividing. The output is bit for bit what it was (an output hash over 3000 varied blocks, mixed, with master grains and routed, matches on x86 and on ARMv7 under qemu; `the_direct_read_matches_the_clamped_one` and `live_buffer_finds_every_held_frame_after_wrapping_and_clearing` keep it so). On the workstation the 16 sample pads now take 58 µs instead of about 140, and "Sampler, 20 pads" 115 µs instead of 174; under qemu on the ARMv7 build, which counts instructions more than it times the chip, the case drops 31 %, the master grains case 44 % and the dense grain effect 42 %. The bench now also runs the two halves apart: "Sampler, the 16 sample pads alone" and "Sampler, the 4 granular pads alone".

The worst blocks come from the grains: the four granular pads average 50 grains but reach the 256-grain budget, and a block with 256 grains costs about five times the average. The budget is the lever for the worst case and is to be set from the next device bench.

## Failure handling

- **xrun:** count it, show it in the header, keep going. Never stop the transport for an xrun.
- **Worker failure** (bad file, failed stretch): the job reports an error to the UI; the model is unchanged.
- **Arena full:** a recording or load is refused before it starts, with the space needed and the space free; the rolling buffers are never shrunk.
- **UI crash:** the engine keeps playing; the supervisor restarts the UI (later, when the UI is its own process).
- **Power loss:** the last saved project and the undo log replay to the last finished gesture.

## Device safety

Nothing in the sampler writes to the eMMC. Recording, saving and caches write only to the project folder, which on the 3.10 test build is in RAM and later lives on the USB stick or SD card. Every round on the MPC runs the storage hashes before and after, as now. The capture PCM is opened only on the test build, where Akai's app is not running.
